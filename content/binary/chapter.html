二分

PRE、二分的基本方法

（1）概念：从重复值查找认识二分

在有序数组 [2, 4, 4, 4, 7, 9] 中查找 4，找到中间的一个 4，就能回答“是否存在”。如果要求第一个 4 的位置，事情就不同了：命中以后仍要继续向左查找。

排序在这里提供了缩小范围的依据。中间值小于 4，它及左边的值都不可能满足要求；中间值已经大于或等于 4，右边即使还有 4，也不可能更早。每次比较后，我们都能解释为什么可以舍去一部分位置，而不是仅凭模板决定向左还是向右。

二分的共同方法正是这样：确定还要搜索的范围，取得一次足以缩小范围的判断，并保证所需答案没有被舍去。 当每次能舍去约一半候选时，搜索次数才是对数级。后面的题目会把搜索对象从数组位置扩展到容量、时间、第 k 小的数值、跳跃距离和惩罚参数；核心仍是先找清缩小范围的理由。

（2）推导：从一次查找建立边界

先把“找到第一个 4”稍作推广：寻找第一个大于或等于给定值的位置。这样，即使给定值不在数组中，也能得到它的插入位置。

设数组长度为 n，用 lo 和 hi 标记尚未确定分类的半开区间 [lo, hi)。区间外的信息已经确定：lo 左边都小于给定值，hi 及右边都大于或等于给定值。初始令 lo = 0、hi = n，两侧都是空的，因此这个约定成立。

在上面的数组中查找 4，第一次取下标 3，中间值为 4，令 hi = 3；再取下标 1，仍为 4，令 hi = 1；最后检查下标 0，值为 2，令 lo = 1。此时两端相遇，第一个满足条件的位置就是 1。

这里有两个值得保留的细节。遇到相等值时，不能直接结束，因为更早的位置仍可能符合要求；搜索结束也不一定得到一个可访问的元素，返回 n 表示整个数组都不满足条件。若要找“第一个严格大于”，只需重新划定相等值属于哪一侧。成员判断、计数、首尾位置和前驱，都可以从这两个边界得到，正式节会分别展开。

（3）建模：将优化目标转成可行性边界

考虑把 [7, 2, 5, 10, 8] 分成两个非空连续段，希望最大段和尽量小。我们无法直接比较某个数组元素来决定答案，但可以先试一个容量：是否存在一种划分，让每段之和都不超过它？

容量为 17 时，从左向右尽量装入当前段，会得到 [7, 2, 5]、[10]、[8] 三段，两个段不够；容量为 18 时，后两个数可以合为一段，于是两个段足够。一旦某个容量可行，更大的容量也可沿用同一划分，因此可行性只会从“不行”变成“可行”。我们便能搜索首次可行的容量。

这类问题有两层推理。首先，给定容量时，判定程序必须真的能判断是否可行；其次，容量改变时，可行性必须具有上面的单调关系。数组非负时，尽量向当前段装入元素的贪心规则可以证明正确；允许负数以后，超出的段和可能被后续负数抵消，原判定规则就需要重做。外层二分不能补救错误的判定程序。

“最大化最小距离”“完成目标产量所需的最短时间”“边权阈值下是否连通”，都是类似的转换。不同题目真正不同的部分，往往是一次判定怎样完成，以及它为什么正确。

（4）边界：区分单调分界、结构存在性与异号夹逼

前两类问题都可以把候选分成连续的两部分：不满足条件的一段，接着是满足条件的一段。通常所说的单调判定，指的就是这种分界。

有些题目依靠的却是结构。例如寻找局部峰，整列数可以反复升降，不存在统一的“左边全假、右边全真”。算法根据相邻数的大小，证明保留的一侧至少还有一个峰；每次留下的峰未必是同一个。旋转数组中若有大量重复值，一次相等还可能只能安全去掉一个副本，最坏时间会退化为线性。

连续函数求根又是另一种情形。对于 f(x) = x² - 2，区间 [1, 2] 的两端异号，连续性保证其中有根。中点 1.5 的函数值为正，便可保留 [1, 1.5]。这里维持的是异号区间，既不保证一次找出全部根，也不能把“函数发生跳跃、越过零点”当成存在零点的证明。

因此，写二分之前，先说明自己保留答案的理由：是有序边界、结构中的存在性，还是连续函数的异号夹逼。它决定了端点能否丢弃、相等如何处理，以及何时可以结束。

（5）工程：实现前确定搜索范围与终止方式

实现时，先确定搜索的是位置、数值还是某个参数，并找出包含答案的初始范围。没有解时如何返回、最大合法查询位置在哪里，也要同时确定。寻找最后一个可行整数时，如果更新采用 lo = mid，中点须向上取整，否则两端相邻时可能不再前进；未知上界则需要先扩大范围，直到建立可搜索的端点或达到查询上限。

（6）复杂度：搜索代价与判定代价

复杂度也要把判定计算在内。若数值搜索范围宽为 W，二分通常需要 O(log W) 次判定；一次判定要扫描 n 个元素，总成本就是 O(n log W)，还应另加预处理。判定若包含图搜索、匹配或数据结构查询，就代入它们各自的成本。不能看到外层用了二分，就把整题写成对数复杂度。

（7）工程：整数与浮点搜索的表示限制

同样，整数中间式可能比最终答案大，乘积、差值与计数要分别检查类型范围；示例中的 i64 表示有符号64位整数。浮点夹逼则需要考虑舍入、累加误差和中点停滞，固定迭代次数只是在给定范围与输出精度下的实现选择。相关细节会放在实际需要的题型旁讲解。

（8）导读：本章的问题版图与学习线索

本章先从有序数据的边界出发，逐步处理访问受限、下标与值的关系、旋转、配对和局部峰。重点是从数据结构中找出可舍去的范围。

随后进入连续分段、放置间距、产量与时间等答案二分问题，再把判定扩展到图、事件前缀和匹配。读这些题目时，应重点关注“试定一个答案以后，原问题变成了什么”。

累计权重、隐式矩阵、数对距离等问题通过计数寻找第 k 小；LIS和兼容调度则先建立有序状态，再用二分加速定位。字符串、连续根、平均值和几何问题还会改变比较对象或判定形式。

最后，搜索还可以直接进入数据结构内部：利用Fenwick频数、区间摘要或倍增表跳过整块；也可以把多次查询合在时间轴或值域分治中处理。惩罚参数搜索进一步讨论：为什么数量单调仍不足以保证精确恢复原问题。

这些应用会用到贪心、图、动态规划和数据结构。每个题型都会在具体问题中解释组合的必要部分；本章要建立的是选择搜索对象、设计判定和证明更新正确性的能力。

一、有序数据的边界、计数与前驱

（1）推导：用左右边界表达计数与前驱

在有序数组中，找到一个等于目标的元素，未必就完成了查找。例如数组 [1,2,2,2,4] 中，目标 2 出现了三次；若要统计次数，就需要找到这段相等元素的两端。

设数组 a 非降排列，查询值为 key。记 L 为第一个满足 a[i]>=key 的位置，R 为第一个满足 a[i]>key 的位置。于是全部相等项恰好位于半开区间 [L,R)，数量是 R-L。上例得到 L=1、R=4；若 L=R，则目标不存在。插入位置、首尾位置和计数，都可以由这两个边界得到。

前驱也只是边界的另一种用法：不大于 key 的最后一个值位于 R-1，严格小于 key 的最后一个值位于 L-1。只有相应边界大于 0 时，前驱才存在。

（2）Hcode：手写边界查找

两次搜索的区别集中在相等时如何处理。找 L 时，相等元素本身仍可能是答案，继续向左定位；找 R 时，相等元素都应归入左侧，继续向右定位。

std::size_t lower_manual(const std::vector<int>& a, int key) {
    std::size_t lo = 0, hi = a.size();
    // [0,lo) < key；[hi,n) >= key，尚未分类的只有 [lo,hi)。
    while (lo < hi) {
        const auto mid = lo + (hi - lo) / 2;
        if (a[mid] < key) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}
std::size_t upper_manual(const std::vector<int>& a, int key) {
    std::size_t lo = 0, hi = a.size();
    while (lo < hi) {
        const auto mid = lo + (hi - lo) / 2;
        if (a[mid] <= key) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}
std::pair<std::size_t, std::size_t>
equal_manual(const std::vector<int>& a, int key) {
    return {lower_manual(a, key), upper_manual(a, key)};
}
std::optional<int> predecessor_manual(const std::vector<int>& a, int key) {
    const auto end = upper_manual(a, key);
    if (end == 0) return std::nullopt;
    return a[end - 1];
}

lower_manual 返回 L，upper_manual 返回 R。二者都允许返回 n，表示边界位于数组末尾之后。equal_manual 直接组合这两个结果；predecessor_manual 先检查 R 是否为 0，再读取 a[R-1]。

若题目要求闭区间首尾位置，只在返回前把非空的 [L,R) 转成 [L,R-1]；不存在时再输出题定的 [-1,-1]。查找过程中保持同一种半开区间表示，边界情况更容易统一。

（3）Scode：用标准库表达同一组边界

std::pair<std::size_t, std::size_t>
equal_standard(const std::vector<int>& a, int key) {
    const auto range = std::equal_range(a.begin(), a.end(), key);
    return {static_cast<std::size_t>(range.first - a.begin()),
            static_cast<std::size_t>(range.second - a.begin())};
}

equal_range 返回一对迭代器，分别对应 L 与 R，不是两个元素值。需要下标或次数时，在确认迭代器所属范围后再作差。

（4）变型：查询指定时刻之前的最后一条记录

对每个键，保存一份按时间严格递增的 TimedValue 序列。查询时刻为 query，要求返回最后一条满足 time<=query 的记录；若查询早于所有记录，则返回空值。

这仍然是前驱查询：先找第一个 time>query 的位置，再退一格。例如记录时间为 [2,5,9]，查询 7 时上界落在 9，所以应返回时刻 5 的记录；查询 1 时，上界就是开头，没有可返回的过去值。这里不寻找绝对时间距离最近的记录。

（a）Hcode：手写时间前驱查找

struct TimedValue { int time; std::string value; };
// 同一key的记录已按time严格递增；查最后一个time<=query。
std::optional<std::string> time_manual(const std::vector<TimedValue>& a, int query) {
    std::size_t lo = 0, hi = a.size();
    while (lo < hi) {
        const auto mid = lo + (hi - lo) / 2;
        if (a[mid].time <= query) lo = mid + 1;
        else hi = mid;
    }
    if (lo == 0) return std::nullopt;
    return a[lo - 1].value;
}

外层散列表负责找到对应键的历史序列，内层函数负责时间边界。该实现依赖写入时间递增；若允许乱序写入，就需要维护有序位置，简单追加不再足够。

（b）Scode：使用 upper_bound 查找时间前驱

std::optional<std::string> time_standard(const std::vector<TimedValue>& a, int query) {
    // upper_bound比较方向是comp(value, element)，不同于lower_bound。
    auto it = std::upper_bound(a.begin(), a.end(), query,
        [](int time, const TimedValue& entry) { return time < entry.time; });
    if (it == a.begin()) return std::nullopt;
    return std::prev(it)->value;
}

此处 upper_bound 的比较器按 (查询值, 元素) 接收参数；常见 lower_bound 重载使用的 (元素, 查询值) 方向不能直接照搬。先检查返回值是否等于 begin()，再调用 prev()，空历史也就自然得到空值。

（5）工程：返回值所有权与比较规则

在 vector 上，边界定位需要 O(log n) 时间和 O(1) 额外空间。时间记录接口返回字符串副本，还要计入 O(|value|) 的复制时间和结果空间。副本独立拥有字符，原历史销毁后仍可读取；若改成返回索引或引用，则必须保证原容器继续存活，见借用参数与结果所有权。

库边界查找依据比较器定义的顺序与等价关系，不一定等同于 operator==，详见标准库二分的使用条件。

二分库函数与迭代器

lower_bound 和 upper_bound 接收半开范围 [first, last)，返回一个迭代器。对于升序整数，前者定位第一个不小于 key 的元素，后者定位第一个大于 key 的元素；如果不存在，就返回 last。返回的只是位置，解引用前要先检查它是否等于 last。

自定义比较器时，要留意两个函数的参数方向。lower_bound(first, last, key, comp) 以 comp(element, key) 为判断，找它首次为假的位置；upper_bound 使用 comp(key, element)，找它首次为真的位置。查询记录中的一个字段时，回调参数类型和比较方向都要相应调整。

这组函数搜索的是已有的分区，并不替调用者排序。全局有序通常足以满足要求；旋转数组或仅按行、列分别有序的矩阵，展平以后却未必满足。partition_point 也是定位真前缀的结束，前提是这个真前缀已经存在。

空范围是合法输入。若要从返回值向前取前驱，还须先确认它不等于 first。两个迭代器之差可用于计算元素数量；需要转成 int 时，再检查规模是否能由 int 表示。

复杂度中的对数首先指比较次数。vector 支持随机访问，移动到中点也很便宜；对普通前向迭代器，累计移动次数仍可能达到线性。查询 set 或 map 时，优先用容器自己的 lower_bound，它能沿树结构查找，通用算法则不能利用这些内部链接。

依据：C++17 二分算法、分区算法。

参数传递与结果所有权

函数只需读取一个现有容器时，常用 const vector<T>&。它借用输入，不复制容器，也不允许通过这个引用修改元素；但引用不会延长输入对象的寿命，调用者仍要保证对象在使用期间有效。

按值参数则拥有自己的容器，适合需要排序副本、又不希望改变调用者原序的接口。传入左值时可能复制，传入可移动对象时可以转移资源。std::move 本身只是允许按右值处理，是否真正移动，由接收它的操作决定。

返回结果时，也要决定谁拥有数据。返回 string、vector或装有值的optional，调用者可以独立持有结果；返回指针、引用、迭代器或索引，通常还需要原对象继续存活，并保持相应元素或位置有效。返回局部容器的引用不能节省出一个有效结果，因为局部容器会随函数结束销毁。

按值返回可以利用返回值优化或移动，不需要机械地添加 std::move。例如历史记录查询返回字符串副本，是为了让查询结果不再依赖记录容器的后续变化；复制字符串的成本也应计入接口代价。

借用对象仍然存活，不表示旧引用永远可用。容器结构修改后是否失效，要按具体操作判断，见vector的容量与引用失效。

依据：函数调用与参数、返回语句、复制省略、值类别转换。

二、访问受限或上界未知时的查找

（1）建模：把接口返回值转成可搜索的分界

有些问题只提供查询接口，不提供可直接遍历的数组。例如已知共有 n 个版本，只能调用接口判断某一版本是否损坏，并且一旦损坏，后续版本也都损坏。要找第一个坏版本，实际搜索的是 false…false,true…true 的分界。

无需先把每个查询结果存成数组。把接口调用作为判定函数，就能直接在下标上二分。若版本从 1 编号，可令内部下标 i 对应版本 i+1。接口调用可能涉及远端访问，因此复杂度首先应说明调用次数。

如果连上界也未知，先查询 0，再依次探测 1、2、4、8……，直到得到一个满足条件的位置。扩张过程中保存一个不满足的下界 lo；找到满足的上界 hi 后，答案便被夹在 (lo,hi] 中，再作常规二分。

“未知上界”仍须有查询范围。参数 cap 表示允许查询的最大下标；若到达 cap 仍不满足，只能报告此范围内无解，不能据此断言更远处也没有答案。

（2）Hcode：倍增建立上界，再收缩区间

template<class Predicate>
std::uint64_t first_true_manual(std::uint64_t n, Predicate yes) {
    // 搜索[0,n)，返回n表示全假；n本身不调用yes。
    std::uint64_t lo = 0, hi = n;
    while (lo < hi) {
        const auto mid = lo + (hi - lo) / 2;
        if (yes(mid)) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}
template<class Predicate>
std::optional<std::uint64_t>
first_true_unknown(std::uint64_t cap, Predicate yes) {
    // cap是允许查询的最大下标，不保证其中一定有真值。
    if (yes(0)) return 0;
    if (cap == 0) return std::nullopt;
    std::uint64_t lo = 0, hi = 1;
    while (!yes(hi)) {
        if (hi == cap) return std::nullopt;
        lo = hi;
        hi = hi > cap - hi ? cap : hi + hi; // 饱和扩张，避免翻倍溢出。
    }
    // 此时lo假、hi真；不重复探测已知端点。
    while (hi - lo > 1) {
        const auto mid = lo + (hi - lo) / 2;
        if (yes(mid)) hi = mid;
        else lo = mid;
    }
    return hi;
}

已知范围的版本用 n 表示无解，并且不会调用 yes(n)。未知范围的版本则使用 optional：因为 UINT64_MAX 本身也可能是合法答案，不能再拿它兼任无解标记。扩张前先比较剩余可用范围，避免计算 2*hi 时已经溢出。

若答案下标为 p，倍增与二分合计需要 O(log(p+1)) 次探测；若范围内无解，则需要 O(log(cap+1)) 次，额外空间都是 O(1)。已经知道上界时直接二分即可；是否缓存远端查询结果，应由实际重复访问情况决定。

（3）Scode：用访问器表示越界

C++17没有直接遍历无界整数域的标准查找函数。下面仍保留同一搜索过程，只用 vector::at 与 optional 表示“取到值”或“到达数据末尾”。

std::optional<std::uint64_t>
find_unknown_at(const std::vector<int>& hidden, int key, std::uint64_t cap) {
    // 演示题定访问器：长度不向算法公开，只有at越界才表示域结束。
    auto read = [&](std::uint64_t i) -> std::optional<int> {
        if (i > std::numeric_limits<std::size_t>::max()) return std::nullopt;
        try { return hidden.at(static_cast<std::size_t>(i)); }
        catch (const std::out_of_range&) { return std::nullopt; }
    };
    auto pos = first_true_unknown(cap, [&](std::uint64_t i) {
        const auto value = read(i);
        return !value || *value >= key; // 域结束在此合同中等价于+∞。
    });
    if (!pos) return std::nullopt;
    const auto value = read(*pos);
    if (!value || *value != key) return std::nullopt;
    return pos;
}

示例要求隐藏序列 hidden 非降。寻找第一个 >=key 的位置时，数据末尾可看作正无穷，从而保持判定方向；找到位置后，还要检查对应值是否真的等于 key。访问器负责取值与报告域结束，倍增和二分负责定位。

（4）工程：域结束、接口错误与查询状态

真实接口可能分别用状态码、异常或空值表示失败。只有接口约定的越界才能解释为域结束；内存不足、权限错误或I/O失败应继续作为错误处理。判定函数在一次搜索中也必须保持含义不变，不能让捕获的 key 或外部版本状态中途变化，见判定器与lambda捕获。

交互题还需按题目协议刷新输出、处理结束响应；写入换行符本身不保证 flush。

整数类型与中间值范围

类型应根据计算过程选择，而不只看最终答案。两个 int 相乘，会先按它们的运算类型求值，再赋给接收结果的变量。即使接收变量是 long long，也来不及挽回已经发生的溢出；可用 1LL * a * b 或在乘法前显式提升一个操作数的类型。

累加算法也有自己的规则。accumulate 由初值的类型确定累加器类型，因此求64位总和时应给出相应初值。partial_sum 按输入元素类型累加，只把输出容器改成64位仍然不够，需要先让输入参与64位运算。

有符号整数溢出不是可靠的回绕机制，也不会自动变成可捕获异常。Windows上的 long 仍可能只有32位；需要至少64位时可用 long long，需要精确位宽时使用实现提供的 std::int64_t。无符号类型虽然按模回绕，但回绕后的比较可能破坏搜索方向，不能靠改成无符号解决问题。

常见中点写法 lo + (hi - lo) / 2 也有前提：差值必须能表示。若区间含负哨兵，或跨越整个64位范围，就要重新检查这一步。寻找上中点时，同样要检查 hi - lo + 1。C++20的 std::midpoint 不能直接作为C++17程序的接口使用。

若判定只关心总量是否达到 k，可以在达到目标后停止，或把状态饱和到目标值。必须在加法或乘法溢出之前作判断，溢出以后再取 min 已无意义。

正数乘积比较有时可改成除法，例如把 m * m <= x 写成 m <= x / m，但要单独处理 m 为0的情形。

移位也应检查位数和结果范围，不能把 1 << j 当作任意宽的整数幂。

依据：表达式求值、累加、部分和。

判定函数与lambda捕获

在一次二分搜索中，同一个候选值应始终对应同一个事实。判定函数可以使用临时工作区、缓存和提前结束，但每次调用前需要恢复属于本次判定的状态。前一轮遗留的 visited、堆元素或计数，不能悄悄改变下一轮结果。

若数据来自会变化的网络或设备，搜索期间还应固定所查询的版本或快照。否则第一次和第二次判断面对的已不是同一个问题，原先证明的单调性也就不能直接沿用。

lambda的 [&] 捕获让回调借用外部对象，适合避免复制大数组；代价是这些对象必须一直存活到回调用完。局部lambda立即传给同步搜索通常满足这个条件，保存回调并返回给外部则可能留下悬空引用。

[=] 对实际捕获的对象进行值捕获。捕获一个大容器可能发生真实复制，因此它不等于“免费地只读访问”。算法还可能复制函数对象，不应依赖闭包中的一个计数器只存在唯一副本。

异常与判定失败也要区分。只有访问器明确规定的“超出长度”，才适合被当作搜索边界；权限、I/O或普通读取错误，不能一律吞成“当前候选不可行”。

依据：C++17 lambda 捕获、算法要求。

三、固定点与缺失数：利用值和下标的关系

（1）推导：由值与下标的差得到固定点边界

给定严格递增的整数数组，寻找任意一个满足 a[i]=i 的位置，找不到则返回空值。这里没有预先给定的查询键，但可以把值与下标一起考虑。

严格递增的整数至少相差 1，所以 a[i+1]>=a[i]+1，进而有 a[i+1]-(i+1)>=a[i]-i。也就是说，差值 a[i]-i 非降。先找第一个满足 a[i]>=i 的位置，再检查是否相等，便能确定固定点。差值不一定严格递增，例如 [0,1,2] 的差值全部为 0。

（2）Hcode：严格递增时查找差值边界

std::optional<std::size_t> fixed_distinct(const std::vector<int>& a) {
    std::size_t lo = 0, hi = a.size();
    while (lo < hi) {
        const auto m = lo + (hi - lo) / 2;
        // 数学差A[m]-m非降；直接比较避免先做可能溢出的int减法。
        if (static_cast<std::int64_t>(a[m]) < static_cast<std::int64_t>(m)) lo = m + 1;
        else hi = m;
    }
    if (lo < a.size() && static_cast<std::int64_t>(a[lo]) == static_cast<std::int64_t>(lo)) return lo;
    return std::nullopt;
}

实现直接比较提升到宽类型后的数组值与下标，避免在窄类型中先相减。它只返回一个固定点；若要返回全部固定点，可继续对非降差值的零区间寻找左右边界。

（3）变型：允许重复值时的固定点查找

重复值会破坏差值的单调性。例如相邻两个值都为 2，下标却增加了 1，差值就会下降，因此不能继续沿用前面的单边二分。

排序仍能排除一部分位置。设中点为 m、中点值为 v：在中点左侧，若下标 i>v，则 a[i]<=v<i，不可能是固定点；在中点右侧，若 i<v，则 a[i]>=v>i，同样不可能。检查完中点后，只需继续搜索 [lo,min(m-1,v)] 与 [max(m+1,v),hi]。

（a）Hcode：按中点值剪枝并搜索两侧

std::optional<std::size_t>
fixed_duplicate_range(const std::vector<int>& a, std::ptrdiff_t lo, std::ptrdiff_t hi) {
    if (lo > hi) return std::nullopt;
    const auto m = lo + (hi - lo) / 2;
    const auto value = static_cast<std::ptrdiff_t>(a[static_cast<std::size_t>(m)]);
    if (value == m) return static_cast<std::size_t>(m);
    // 重复破坏单调，但排序仍证明这两块之外不可能有固定点。
    if (auto left = fixed_duplicate_range(a, lo, std::min(m - 1, value))) return left;
    return fixed_duplicate_range(a, std::max(m + 1, value), hi);
}
std::optional<std::size_t> fixed_duplicates(const std::vector<int>& a) {
    return fixed_duplicate_range(a, 0, static_cast<std::ptrdiff_t>(a.size()) - 1);
}

以 [0,0,0,2,2,4] 为例，中点 m=2、值 v=0。左侧只剩下标 0，右侧从 3 开始；真正的固定点就是 0。看到 v<m 就删掉整个左半，会漏掉它。

此时两侧都可能继续搜索，最坏时间为 O(n)；每个子区间仍至多为原区间的一半，递归栈深为 O(log n)。

（4）变型：第 k 个缺失正整数

现在要求数组由严格递增的正整数组成。到数值 a[i] 为止，共有 a[i] 个正整数，其中 i+1 个已经出现在数组中，所以缺失数量是 a[i]-i-1。这个数量随下标非降。

令 p 为缺失数量首次达到 k 的位置。第 k 个缺失值之前恰有 p 个数组元素，因而答案为 k+p。例如数组 [2,3,4,7,11]、k=5 时，p=4，答案是 9。若 p=n，答案位于数组尾部之后；空数组则直接返回 k。

（a）Hcode：按缺失数量寻找边界

std::int64_t kth_missing_manual(const std::vector<int>& a, std::int64_t k) {
    // a严格递增、正整数；k>0，且n+k可用int64表示。
    std::size_t lo = 0, hi = a.size();
    while (lo < hi) {
        const auto m = lo + (hi - lo) / 2;
        const auto missing = static_cast<std::int64_t>(a[m]) - static_cast<std::int64_t>(m) - 1;
        if (missing < k) lo = m + 1;
        else hi = m;
    }
    return k + static_cast<std::int64_t>(lo);
}

严格递增时，固定点和缺失查询都只需 O(log n) 时间、O(1) 额外空间。缺失公式计算的是不同的已出现值；若输入允许重复，须先去重或另行统计不同值的数量。

（b）Scode：预先构造缺失数量表，再用库查找

std::int64_t kth_missing_precomputed(const std::vector<int>& a, std::int64_t k) {
    // 明示O(n)预处理：多查询可把gap保留，而非每次重建。
    std::vector<std::int64_t> gap;
    gap.reserve(a.size());
    for (std::size_t i = 0; i < a.size(); ++i)
        gap.push_back(static_cast<std::int64_t>(a[i]) - static_cast<std::int64_t>(i) - 1);
    const auto p = std::lower_bound(gap.begin(), gap.end(), k) - gap.begin();
    return k + p;
}

这里先把全部缺失数量存入 gap，再用 lower_bound 查找。因此一次完整调用仍需 O(n) 时间和空间，并不优于直接计算差值的单次查询。若同一数组要回答许多查询，可保留这张表，使之后每次查找只需 O(log n)。

（5）工程：固定点与缺失查询的类型及返回约定

固定点递归要求容器长度能用 ptrdiff_t 表示；缺失查询要求 k>0，且 n+k 能用 int64_t 表示。应先转换类型再作差，见整数运算与溢出。

重复值版本返回任意固定点。它先检查中点，再递归左侧，不能因此保证返回最左固定点。

四、旋转有序数组的查找与最小值

（1）推导：从有序半区与下降切点定位答案

把一个非降序列切开，再交换前后两段，就得到旋转序列。例如 [1,2,3,4,5,6] 可变成 [4,5,6,1,2,3]。它不再整体有序，但两段内部仍有序，下降处连接着最小值。

找最小值时，比较中点与右端：中点更大，说明最小值在中点右侧；中点更小，说明右侧不能提供更小的切点，应保留中点及其左侧。若两者相等，就无法据此区分方向，只能安全地去掉一个右端副本。

成员查找则先识别哪一半有序，再判断目标值是否位于那一半的值域中。若相等使方向无法判断，同样要先缩去无法提供信息的重复端点。

（2）Hcode：依据有序半区更新范围

std::optional<int> rotated_min_manual(const std::vector<int>& a) {
    if (a.empty()) return std::nullopt;
    std::size_t lo = 0, hi = a.size() - 1;
    while (lo < hi) {
        const auto m = lo + (hi - lo) / 2;
        if (a[m] > a[hi]) lo = m + 1;
        else if (a[m] < a[hi]) hi = m;
        else --hi; // 只能证明丢掉这个副本不会丢掉所有最小值。
    }
    return a[lo];
}
bool rotated_member_manual(const std::vector<int>& a, int key) {
    std::size_t lo = 0, hi = a.size();
    while (lo < hi) {
        const auto m = lo + (hi - lo) / 2;
        if (a[m] == key) return true;
        if (a[lo] == a[m] && a[m] == a[hi - 1]) { ++lo; --hi; continue; }
        if (a[lo] <= a[m]) { // 左半有序。
            if (a[lo] <= key && key < a[m]) hi = m;
            else lo = m + 1;
        } else { // 右半有序。
            if (a[m] < key && key <= a[hi - 1]) lo = m + 1;
            else hi = m;
        }
    }
    return false;
}

元素互异时，每次都能排除一半，时间为 O(log n)。允许重复后，唯一的 0 可以隐藏在 [1,1,…,1,0,1,…,1] 的任意未检查位置，最坏需要 O(n)。这来自输入信息不足，无法仅靠换一种中点写法消除。

成员函数只有在确认中点不等于 key 后才执行相等缩边，因此不会删掉最后一个匹配。空输入分别返回“无最小值”和“不存在”。

（3）Scode：先找出有序分段，再调用库查找

bool rotated_member_standard(const std::vector<int>& a, int key) {
    // 先线性找唯一下降点；两段各自有序，才能分别使用binary_search。
    const auto cut = std::is_sorted_until(a.begin(), a.end());
    return std::binary_search(a.begin(), cut, key) ||
           std::binary_search(cut, a.end(), key);
}
std::optional<int> rotated_min_standard(const std::vector<int>& a) {
    if (a.empty()) return std::nullopt;
    return *std::min_element(a.begin(), a.end());
}

is_sorted_until 定位下降位置，随后对两段有序区间分别调用 binary_search。这一版本最坏需要 O(n) 时间、O(1) 额外空间；它适用于重复值，却没有保留互异输入下的对数优势。min_element 也可作为线性查找最小值的对照。

整个旋转数组通常不满足 binary_search 要求的分区条件，不能省略分段就直接调用。

（4）工程：返回含义与重复下标的约定

最小值接口返回的是值，不保证返回哪个重复最小值的位置；成员接口只返回 bool。若还需要某种“首个下标”，须先明确旋转后按什么索引顺序定义“首个”。数据的排序规则也必须与查询比较规则一致，见标准库二分的使用条件。

五、成对有序数组中的单次值

（1）推导：单次值怎样改变配对位置

有序数组中，只有一个值出现一次，其余值都恰好出现两次。要求找出这个单次值，且时间复杂度为 O(log n)。

例如 [1,1,3,4,4,6,6] 中，3 之前的配对从偶下标开始：1 位于 0、1。经过单次值后，后续配对都从奇下标开始：4 位于 3、4，6 位于 5、6。因此可以搜索配对位置由偶变奇的分界。

把中点 m 对齐到偶下标。如果 a[m]=a[m+1]，这一对仍位于异常之前，答案必在 m+1 之后；否则答案就在 m 或其左侧。这里利用的是配对位置，而不是数值与目标键的大小关系。

（2）Hcode：对齐中点，或按位运算取得配偶

int paired_unique_manual(const std::vector<int>& a) {
    // 非空奇数长有序数组：恰一项一次，其余每项恰两次。
    std::size_t lo = 0, hi = a.size() - 1;
    while (lo < hi) {
        auto m = lo + (hi - lo) / 2;
        m -= m % 2; // 一律从偶下标检查一整对。
        if (a[m] == a[m + 1]) lo = m + 2;
        else hi = m;
    }
    return a[lo];
}
int paired_unique_xor_index(const std::vector<int>& a) {
    std::size_t lo = 0, hi = a.size() - 1;
    while (lo < hi) {
        const auto m = lo + (hi - lo) / 2;
        if (a[m] == a[m ^ std::size_t{1}]) lo = m + 1;
        else hi = m;
    }
    return a[lo];
}

第一种实现把中点向偶数对齐，每次整对地排除。第二种用 m^1 得到配偶下标：偶数加一，奇数减一，再据两值是否相等判断分界方向。二者都需要 O(log n) 时间和 O(1) 额外空间。

（3）替代解法：异或归约的线性解

（a）Scode：用 accumulate 合并异或结果

int paired_unique_standard(const std::vector<int>& a) {
    // 不同算法：成对值的XOR抵消。线性基线，不满足原题O(logn)要求。
    return std::accumulate(a.begin(), a.end(), 0, std::bit_xor<int>{});
}

accumulate 与 bit_xor 让成对值互相抵消，剩下单次值。这是另一种 O(n) 算法，不利用排序，因而不能满足原题的对数要求。C++17标准库没有配对位置的二分函数，利用该结构时仍需实现前面的定位过程。

（4）边界：配对规律依赖哪些输入条件

二分实现依赖非空奇数长度、唯一单次值和其余值恰两次；函数不会再花 O(n) 时间预先验证这些条件。若有多个异常、不同频次或无序输入，配对位置的规律就可能失效。

m^1 操作的是下标，并不要求数组值非负。异或对照也只在相应的奇偶频次条件下成立。

六、局部峰与单峰数组的峰值

（1）论证：保留的一侧为什么仍然有峰

给定相邻元素不相等的数组，找一个严格大于两侧邻居的位置。数组之外视作负无穷，因此端点也可以成为峰。题目允许有多个峰，例如 [1,4,2,5,3] 中的 4 与 5 都满足要求。

比较 a[mid] 与 a[mid+1]。若右邻更高，从右邻开始沿更高的方向走，最终会遇到下降或右边界，途中必有一个峰。因此可以保留右半；左邻方向的更新同理。斜率本身可以反复变化，这个过程依靠的是保留下来的区域一定有峰，而不是一个全局单调的斜率序列。

（2）Hcode：保持两端朝向区间内部上升

std::optional<std::size_t> peak_manual(const std::vector<int>& a) {
    if (a.empty()) return std::nullopt;
    std::size_t lo = 0, hi = a.size() - 1;
    while (lo < hi) {
        const auto m = lo + (hi - lo) / 2;
        if (a[m] < a[m + 1]) lo = m + 1;
        else hi = m; // 有向内的上升/下降边界证书，不是全局斜率单调。
    }
    return lo;
}

向右更新后，新的 lo 高于左侧相邻元素；向左更新后，新的 hi 高于右侧相邻元素。最初由区间外的负无穷保证这两个条件。区间缩成一个位置时，它同时高于两侧，便是所需的峰。算法需要 O(log n) 时间和 O(1) 额外空间。

若数组额外保证严格先升后降，唯一局部峰也是全局最大值，仍可使用此实现；一般局部峰问题不需要这个更强条件。

（3）替代解法：扫描全局最大值寻找局部峰

（a）Scode：用 max_element 取得全局最大值

std::optional<std::size_t> peak_standard(const std::vector<int>& a) {
    if (a.empty()) return std::nullopt;
    // 邻值不等时任一全局最大值必是严格局部峰；此基线O(n)。
    return static_cast<std::size_t>(std::max_element(a.begin(), a.end()) - a.begin());
}

相邻值不等时，全局最大值必高于两侧邻居，所以 max_element 能给出正确答案，但需要 O(n) 时间。

若允许相等，就要重新区分严格局部峰、弱局部峰和全局最大值。例如 [1,1,1,2,1] 中，遇到相等时任意舍弃一侧，可能删掉唯一全局最大值。不同目标需要不同的保留依据。

（4）工程：空输入、严格峰与借用结果

当前接口把空数组扩展为 nullopt；原题保证非空时，可直接解包。若输入不满足邻项不等，也就未必存在严格峰，不能把任意返回下标视为正确结果。

库函数返回迭代器，转成下标后也不拥有原元素；原容器的寿命仍需由调用方保证，见借用与结果所有权。

七、二维有序矩阵中的查找

（1）建模：区分全局有序与行列分别有序

矩阵“有序”有两种常见含义，能够使用的方法也不同。

第一种要求每行非降，且下一行首项大于上一行末项。例如 [[1,3,5],[7,9,11]] 按行展开仍然有序，可以把它视为一个一维数组。虚拟下标 i 对应 a[i/cols][i%cols]，并不需要真正复制矩阵。

第二种只要求每行、每列各自非降。例如 [[1,4,7],[2,5,8]] 展开后为 [1,4,7,2,5,8]，已经无序，不能整段二分。

（2）Hcode：展平二分与阶梯搜索的两种实现

bool matrix_flat_manual(const std::vector<std::vector<int>>& a, int key) {
    if (a.empty() || a.front().empty()) return false;
    const auto rows = a.size(), cols = a.front().size();
    if (rows > std::numeric_limits<std::size_t>::max() / cols)
        throw std::length_error("matrix index domain overflow");
    // 强合同：矩形且按行展平后全局非降；不真正复制mn个元素。
    std::size_t lo = 0, hi = rows * cols;
    while (lo < hi) {
        const auto m = lo + (hi - lo) / 2;
        if (a[m / cols][m % cols] < key) lo = m + 1;
        else hi = m;
    }
    return lo < rows * cols && a[lo / cols][lo % cols] == key;
}
bool matrix_staircase(const std::vector<std::vector<int>>& a, int key) {
    if (a.empty() || a.front().empty()) return false;
    // 弱合同：矩形，各行各列非降。col用“列数”避免无符号-1。
    std::size_t row = 0, col = a.front().size();
    while (row < a.size() && col > 0) {
        const auto x = a[row][col - 1];
        if (x == key) return true;
        if (x < key) ++row;
        else --col;
    }
    return false;
}

展平版本只改变访问方式，随后寻找第一个 >=key 的位置。它需要 O(log(mn)) 时间和 O(1) 额外空间。

阶梯版本从右上角开始。若当前值小于目标，它左侧的整行都太小，可以向下；若当前值大于目标，它下方的整列都太大，可以向左。每步排除一行或一列，所以需要 O(m+n) 时间、O(1) 额外空间。它利用了两个方向的顺序，是另一种搜索算法。

（3）Scode：对每一行独立调用二分查找

bool matrix_row_standard(const std::vector<std::vector<int>>& a, int key) {
    // 只要求各行有序；甚至不要求各行等长或列有序。
    return std::any_of(a.begin(), a.end(), [&](const std::vector<int>& row) {
        const auto it = std::lower_bound(row.begin(), row.end(), key);
        return it != row.end() && *it == key;
    });
}

逐行用 lower_bound 定位后检查相等，any_of 表达“至少有一行命中”。矩形输入的时间为 O(m log n)，额外空间为 O(1)。

这一写法只要求各行有序，甚至允许行长不同，却没有利用列序。行列数量相差很大时，应比较逐行、逐列和阶梯搜索的实际代价，再选择实现。

（4）工程：展平索引与尾后位置的预算

展平前先确认 rows*cols 不会在 size_t 中溢出，并在除以 cols 前排除空矩阵。形状和排序要求应由调用方保证；若每次先扫描全矩阵验证排序，整次调用就不再是对数时间。

尾后迭代器与随机访问要求见标准库二分的使用条件。

八、整数平方根：查找最后一个可行值

（1）建模：把平方根转成最后可行整数

给定非负整数 x，求不超过其平方根的最大整数。例如 x=21 时，4²<=21<5²，答案为 4。这等价于寻找最后一个满足 m²<=x 的非负整数 m，并不要求 x 恰好是完全平方数。

对64位输入，直接计算 m*m 可能溢出。当 m>0 时，可以把判定改写成 m<=x/m；这仍然是同一个整数不等式，却避免了乘法。

（2）Hcode：用上中点寻找最后一个可行整数

std::uint64_t isqrt_manual(std::uint64_t x) {
    std::uint64_t lo = 0, hi = x;
    while (lo < hi) {
        const auto width = hi - lo;
        const auto m = lo + width / 2 + width % 2; // 上中点保证lo前进。
        if (m <= x / m) lo = m; // m>0；乘法m*m可能溢出，改为除法。
        else hi = m - 1;
    }
    return lo;
}

搜索过程中 lo 始终可行，答案位于 [lo,hi]。中点可行就保留它，否则排除中点及右侧；由于可行时写 lo=mid，必须使用向上取整的中点，才能在相邻整数之间继续推进。

x=0 时不进入循环，其余循环的中点至少为 1，不会发生除以零。算法最多检查64次，需要 O(log(x+1)) 时间、O(1) 额外空间，适用于完整 uint64_t 范围。

（3）替代解法：浮点估计后作整数修正

（a）Scode：用 sqrt 估计并检查整数边界

std::uint64_t isqrt_estimate_standard(std::uint64_t x) {
    // sqrt给近似，整数不等式最终确证；不能把浮点转整数当完整答案。
    auto r = static_cast<std::uint64_t>(std::sqrt(static_cast<long double>(x)));
    while (r > 0 && r > x / r) --r;
    while (r < std::numeric_limits<std::uint64_t>::max() && r + 1 <= x / (r + 1)) ++r;
    return r;
}

在 2^64-1 附近，sqrt 的结果可能舍入成 2^32，直接转为整数会比正确答案大 1。因此实现还要向下或向上修正，直到同时满足整数根两侧的不等式。

修正次数取决于初始估计的误差。浮点库函数提供估计，最终答案的确切性来自整数检查，而不是假定所有平台都不需要修正。

（4）工程：宽类型运算与中点表达式

Windows中的 long 常为32位，不能用类型名称推断平方一定放得下。宽类型转换应发生在运算之前。

最后可行值的中点也应避免写成 (lo+hi+1)/2，以免在求中点时产生新溢出，详见整数运算与溢出。

九、最小化连续分段的最大段和

（1）建模：试定容量后怎样判断最少分段数

把一个非负数组按原顺序分成恰好 k 个非空连续段，要求最大的段和尽可能小。排序会改变相邻关系，因此不能先重排数组。

直接枚举切点很困难，但可以换一个问题：给定每段容量 B，至少需要多少段？例如数组 [7,2,5,10,8] 要分成两段。容量 18 时可取 [7,2,5] 与 [10,8]；容量 17 时，按顺序需要三段，便无法满足要求。

容量固定后，从左到右尽量把元素放入当前段，装不下才另开一段。这个贪心确实给出最少段数：任何容量合法的第一段都不能越过贪心的切点；在余下部分继续比较，贪心每用一段都覆盖至少同样长的前缀，所以不会使用更多段。

因此，只要最少段数不超过 k，容量就是可行的。由于元素非负，把一个合法段继续拆开不会增加最大段和；在 k<=n 时，还能把“不超过 k 段”补成“恰好 k 段”。

B 增大只会放宽限制，可行性由假变真。搜索下界是最大元素，上界是总和，寻找第一个可行容量。非负条件在这里不可少：[-5,10,-5] 的总和为 0，若允许负数，最大元素不再是下界，中途超限也不一定意味着整段超限。

（2）Hcode：手写容量判定与二分

先给出之后反复使用的两个整数搜索函数，分别寻找首次满足和最后满足的位置。它们接收非负闭区间 [lo,hi]，要求差值可表示，且区间内确实存在满足条件的值；具体题型负责建立这样的上下界或无解标记。函数本身不检测全假区间，返回一个端点也不能替代有解性证明。

using i64 = long long;

// 闭区间中至少有一个真值；判定为 false...false,true...true。
template<class Predicate>
i64 first_true(i64 lo, i64 hi, Predicate feasible) {
    while (lo < hi) {
        const i64 mid = lo + (hi - lo) / 2;
        if (feasible(mid)) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}

// 闭区间中至少有一个真值；判定为 true...true,false...false。
template<class Predicate>
i64 last_true(i64 lo, i64 hi, Predicate feasible) {
    while (lo < hi) {
        const i64 gap = hi - lo;
        const i64 mid = lo + gap / 2 + gap % 2; // 上中点，避免 lo 卡住。
        if (feasible(mid)) lo = mid;
        else hi = mid - 1;
    }
    return lo;
}

容量题的上界“总和”必可行，因而可直接使用首次满足的函数：

// a 非空、各项非负、1 <= k <= a.size()；总和须可用 i64 表示。
i64 capacity_manual(const std::vector<i64>& a, int k) {
    i64 lower = 0, upper = 0;
    for (i64 x : a) {
        if (x > lower) lower = x;
        upper += x;
    }
    auto feasible = [&](i64 limit) {
        int blocks = 1;
        i64 used = 0;
        for (i64 x : a) {
            // lower 已保证 x <= limit；比较差值避免 used+x 溢出。
            if (used > limit - x) {
                if (++blocks > k) return false;
                used = x;
            } else used += x;
        }
        return true;
    };
    return first_true(lower, upper, feasible);
}

used 保存当前段的和，blocks 保存已经开出的段数。段数超过 k 时即可结束检查。每轮扫描数组一次，总时间为 O(n log(sum-max+1))，额外空间为 O(1)。若全数组为 0，上下界相同，搜索无需执行循环。

（3）Scode：用标准库计算上下界

// 库只接管边界统计；它没有接管“为何贪心段数可作判定”。
std::pair<i64, i64> capacity_bounds_standard(const std::vector<i64>& a) {
    return {*std::max_element(a.begin(), a.end()),
            std::accumulate(a.begin(), a.end(), 0LL)};
}

max_element 与 accumulate 分别计算最大元素和总和，两者都是线性扫描。用这段替换求解函数开头的统计过程即可；容量判定和二分继续复用前面的实现。

（4）工程：累加类型与方案恢复

CSES中 n<=2×10^5，单项不超过 10^9，总和可达 2×10^14，所以必须从累加开始使用64位整数。accumulate 中的 0LL 决定累加器类型，见整数运算与溢出。

判定函数借用原数组，多轮调用不会复制或重排它，参见判定器与捕获的生命周期。若还要输出恰好 k 个切点，需要在恢复过程中为剩余段保留元素；贪心判定得到的最少段数划分未必已经恰有 k 段。

（5）练习：允许零值与大规模分段

Split Array Largest Sum 允许 0；Array Division 的正数与更大规模要求同一证明、不同数值预算。

十、最大化所选位置的最小间距

（1）建模：固定间距后怎样选择最多位置

从给定的一维位置中选择 m 个，使所选位置之间的最小距离尽可能大。原题位置互异，2<=m<=n<=10^5，坐标在 1..10^9。

把位置排序后，任意两点间的最小距离一定出现在相邻所选点之间。于是给定距离 d，只需判断：能否选出至少 m 个位置，使相邻间距都不小于 d？

从最左位置开始，每次选择距离上一个点至少 d 的最早位置。例如 [1,2,4,8,9] 选三个点，d=3 时可以依次选 1、4、8；d=4 时只能选出 1、8，因此不可行。

为什么尽早选择不会损失答案？与任一可行方案逐项比较，贪心选出的第一个位置不更晚；若第 j 个位置不更晚，下一个满足距离的最早位置也不会晚于对方的第 j+1 个位置。因此贪心留给后续选择的空间不会更少。

距离越大，条件越严格，故搜索最后一个可行距离。若总跨度为 span，必须有 (m-1)d<=span，所以可将上界收紧到 span/(m-1)。

（2）Hcode：在有序位置上贪心检查

// sorted_position 已升序，至少两个互异位置；2 <= balls <= n。
i64 spacing_sorted_manual(const std::vector<i64>& sorted_position, int balls) {
    const i64 span = sorted_position.back() - sorted_position.front();
    auto feasible = [&](i64 distance) {
        int placed = 1;
        i64 last = sorted_position.front();
        for (std::size_t i = 1; i < sorted_position.size(); ++i) {
            if (sorted_position[i] - last >= distance) {
                last = sorted_position[i];
                if (++placed >= balls) return true;
            }
        }
        return false;
    };
    return last_true(0, span / (balls - 1), feasible);
}

这段核心接收已经排序的位置。每次检查 O(n)，二分需要 O(n log span) 时间，额外空间为 O(1)。原始位置尚未排序时，必须先完成预处理。

（3）Scode：排序后复用检查函数

// 值传递接管一份位置副本；调用方原序不变，手写核心获得有序前提。
i64 spacing_standard(std::vector<i64> position, int balls) {
    std::sort(position.begin(), position.end());
    return spacing_sorted_manual(position, balls);
}

函数按值接收位置，并在副本上调用 sort，所以调用方原序不变。总时间为 O(n log n+n log span)，副本占 O(n) 存储。

也可以不断用 lower_bound(last+d) 找下个位置，但每次放置都会引入查找成本，不一定优于一次前向扫描。

（4）边界：位置约束改变时重新检查贪心

排序规则只负责建立坐标顺序，选择正确性来自上述领先性证明。是否复制输入则由接口决定，见借用与复制。

若位置改为连续区间、每个点带容量，或点之间另有冲突限制，尽早放置就未必足够。即使距离可行性仍单调，也必须先重新构造正确的判定函数。

（5）练习：给定位置中的最大最小间距

十一、达到目标产量的最短时间

（1）建模：按完成时间统计产量而非逐件模拟

若干机器同时独立生产，第 i 台每完成一件产品需要 t[i] 时间。给定目标产量 target，求最早达到目标的时刻。原题机器数不超过 2×10^5，目标与单件耗时均在 1..10^9。

时间 T 内，第 i 台机器完成 floor(T/t[i]) 件，直接求和即可知道产能是否达标，无需逐件模拟。例如两台机器的耗时为 2、3，在时刻 6 分别完成 3、2 件，合计达到目标 5。

时间增加，累计产量不会减少，因此寻找首次达标时间。即使只让最快的机器工作，min(t)×target 也一定够用，它便是一个可行上界。

（2）Hcode：累计产量达到目标就停止

// times 非空且为正；target >= 1；min(times)*target 可用 i64 表示。
i64 production_manual(const std::vector<i64>& times, i64 target) {
    i64 fastest = times.front();
    for (i64 t : times) if (t < fastest) fastest = t;
    auto feasible = [&](i64 time) {
        i64 remaining = target;
        for (i64 t : times) {
            const i64 made = time / t;
            // 判定只需知道是否达标；保留剩余目标，不必累计完整产能。
            if (made >= remaining) return true;
            remaining -= made;
        }
        return false;
    };
    return first_true(0, fastest * target, feasible);
}

实现用 remaining 保存尚缺的产量。某台机器已经足以补齐缺口时，立即返回可行；否则从缺口中扣掉它的产量。

在当前紧上界 min(t)×target 内，每台机器的产量都不超过 target，完整总和也不超过 n×target<=2×10^14，因此64位足够。采用剩余缺口写法，还能避免在更大搜索范围中累计不必要的大总和。总时间为 O(n log(min(t)×target+1))，额外空间为 O(1)。

（3）Scode：用 min_element 构造上界

i64 production_upper_standard(const std::vector<i64>& times, i64 target) {
    // 返回已证明有效的搜索界；乘法在 i64 中进行。
    return *std::min_element(times.begin(), times.end()) * target;
}

min_element 线性找到最快机器，使用常数额外空间；产能公式与二分过程保持不变。答案空间只需用两个端点表示，没有必要创建一个覆盖全部时刻的 vector。

（4）工程：整数完成时刻与计数范围

产量必须用整数除法计算。浮点估计在整件完成的边界附近可能误判，从而改变二分方向。

搜索上界和累计产量应分别预算。若把上界改成固定的 10^18，快速机器的中间产量和可能超界，不能继续套用当前紧界下的结论，见整数预算。若机器共享资源或任务之间存在依赖，产量也未必能够直接相加。

（5）练习：大量目标产品的完成时间

Factory Machines。试比较“逐件最小堆模拟”和“按时间直接计数”在目标达到 10^9 时的差距。

十二、固定顺序任务所需的最少并行台位

（1）建模：固定台位数后如何模拟完成时间

Cow Dance给出固定的登台顺序和每段演出的时长。K 个台位可以同时使用；某台位结束后，下一位立即登台。要求全部演出在期限内完成，求最少需要多少台位。原题 N<=10^4，单段时长不超过 10^5，期限不超过 10^6。

固定 K 后，每位开始的时间取决于哪个台位最先空闲，因此不能用总时长除以 K 代替过程。维护各台位的结束时间，每次取最小结束时间，加上下一段时长，再放回，就能精确模拟题意。

例如时长为 [4,2,3]，两个台位先安排前两位；第三位在时刻 2 接替空出的台位，最后在时刻 5 完成。一个台位则要到时刻 9 才能完成。

台位增加不会推迟固定队列中任务的完成，所以“能否在期限内完成”随 K 由假变真。原题保证 K=N 可行，可以搜索首次满足的台位数。

这一单调性也可严格比较两套排程。把 K 个台位的可用时间排序为 v，把 K+1 个台位的可用时间排序为 u，保持 u[i]<=v[i]（i<K）。初始全为 0，条件成立。处理同一时长 d 时，有 u[0]+d<=v[0]+d；删去各自最早项再加入新结束时间，较多台位一侧仍有 K 项能逐项匹配到较少台位一侧且不更大，额外一项不会使前 K 小的时间变晚。归纳便知每个任务都不会更晚开始或结束。

（2）Hcode：用最小堆模拟台位释放

class MinHeap {
    std::vector<i64> data;
public:
    explicit MinHeap(int slots) : data(slots, 0) {}
    i64 take_min() {
        const i64 result = data[0];
        data[0] = data.back();
        data.pop_back();
        std::size_t p = 0;
        while (2 * p + 1 < data.size()) {
            std::size_t child = 2 * p + 1;
            if (child + 1 < data.size() && data[child + 1] < data[child]) ++child;
            if (data[p] <= data[child]) break;
            std::swap(data[p], data[child]);
            p = child;
        }
        return result;
    }
    void push(i64 value) {
        data.push_back(value);
        std::size_t p = data.size() - 1;
        while (p > 0) {
            const std::size_t parent = (p - 1) / 2;
            if (data[parent] <= data[p]) break;
            std::swap(data[parent], data[p]);
            p = parent;
        }
    }
};

int stage_slots_manual(const std::vector<i64>& duration, i64 deadline) {
    auto feasible = [&](i64 slots) {
        MinHeap heap(static_cast<int>(slots));
        for (i64 d : duration) {
            const i64 finish = heap.take_min() + d;
            if (finish > deadline) return false;
            heap.push(finish);
        }
        return true;
    };
    // 原题保证 duration.size() 个台位可在 deadline 内完成。
    return static_cast<int>(first_true(1, duration.size(), feasible));
}

堆初始的 K 个 0 表示全部台位空闲。取出一个时间、安排一位演出、放回新的结束时间，堆的大小始终为 K。只要某次结束时间超过期限，就可直接拒绝。

一次判定需要 O(N log(K+1)) 时间，整体最坏为 O(N log²N)，堆空间为 O(K)。

（3）Scode：用 priority_queue 管理结束时间

int stage_slots_standard(const std::vector<i64>& duration, i64 deadline) {
    auto feasible = [&](i64 slots) {
        std::priority_queue<i64, std::vector<i64>, std::greater<i64>> finish;
        for (i64 i = 0; i < slots; ++i) finish.push(0);
        for (i64 d : duration) {
            const i64 next = finish.top() + d; // 取值，不保留跨 pop 的引用。
            finish.pop();
            if (next > deadline) return false;
            finish.push(next);
        }
        return true;
    };
    return static_cast<int>(first_true(1, duration.size(), feasible));
}

greater 使堆顶保存最早结束时间。top() 读取它，pop() 删除旧状态，push() 放入安排下一位后的新状态。三个动作共同完成一次台位更新，详见优先队列与堆接口。

（4）工程：堆元素寿命与台位身份

先复制 top() 的值再 pop()，不能在删除后继续使用指向原堆顶的引用。每次判定都重新构造堆，避免上一次模拟状态进入下一轮。

若还要输出每位演出所在的台位，堆元素须额外保存台位编号；只有结束时间无法恢复这个身份。

优先队列的使用与代价

priority_queue<T> 默认采用 less<T>，堆顶是最大元素。需要最小元素优先时，常写 priority_queue<T, vector<T>, greater<T>>。判断比较器方向时，应检查最终是谁留在堆顶；自定义比较器仍须满足严格弱序。

top() 只观察堆顶，pop() 删除堆顶而不返回它。若后续还需要这个值，应先复制到局部变量再删除。不能保存top返回的引用，再继续使用已经删除或因堆重排而改变的元素。

调用top或pop之前要保证堆非空。违反这个前提时，接口不承诺抛出一个可捕获的异常，不能依赖try/catch来弥补检查缺失。

一次堆调整通常需要 O(log n)，观察堆顶为 O(1)。如果初始数据已经全部存在，基于整个范围调用make_heap可以线性建堆；逐个push的过程与此不同。底层容器仍可能分配内存，所以对数调整次数并不表示操作没有其他成本。

依据：C++17 priority_queue、堆算法。

十三、瓶颈路径：最小化路径上的最大边权

（1）建模：阈值删边把瓶颈路径转成可达性

从网格左上走到右下，路径代价定义为沿途最大的相邻高度差，要求使这个最大差最小。原题行列均不超过 100，高度在 1..10^6。

它不要求步数最少，也不要求高度差总和最小：较长的路线可能每步都平缓，因而具有更小的最大高度差。

给定阈值 B，只允许经过高度差不超过 B 的边。若仍能从左上到达右下，说明存在代价不超过 B 的路径；否则任何路径都要跨过更大的高度差。阈值增大只增加可用边，因此可以二分首次可达的阈值。一次检查只是可达性搜索，BFS无需记录最短距离。

（2）Hcode：用数组队列检查可达性

int path_effort_manual(const std::vector<std::vector<int>>& height) {
    const int rows = static_cast<int>(height.size());
    const int cols = static_cast<int>(height[0].size());
    const int count = rows * cols;
    const int dr[4] = {-1, 1, 0, 0}, dc[4] = {0, 0, -1, 1};
    auto feasible = [&](i64 limit) {
        std::vector<unsigned char> seen(count, 0);
        std::vector<int> queue(count);
        int head = 0, tail = 0;
        queue[tail++] = 0;
        seen[0] = 1; // 入队即标记，队列最多容纳 count 个格子。
        while (head < tail) {
            const int id = queue[head++];
            if (id == count - 1) return true;
            const int r = id / cols, c = id % cols;
            for (int direction = 0; direction < 4; ++direction) {
                const int nr = r + dr[direction], nc = c + dc[direction];
                if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
                const int next = nr * cols + nc;
                const i64 gap = std::llabs(i64(height[r][c]) - height[nr][nc]);
                if (!seen[next] && gap <= limit) {
                    seen[next] = 1;
                    queue[tail++] = next;
                }
            }
        }
        return false;
    };
    // 原题高度在 [1, 10^6]；整个网格在此界下必连通。
    return static_cast<int>(first_true(0, 999999, feasible));
}

格子入队时立即标记，使每个格子最多入队一次，长度为 rows×cols 的队列数组就足够。若到出队时才标记，同一格子可能重复入队，数组容量也就不再有保证。

原题可在 [0,999999] 中搜索，单格网格的答案为 0。设网格为 R×C、高度差搜索宽度为 W，总时间为 O(RC log W)，空间为 O(RC)。

（3）Scode：用 queue 保存待处理格子

int path_effort_standard(const std::vector<std::vector<int>>& height) {
    const int rows = static_cast<int>(height.size());
    const int cols = static_cast<int>(height[0].size());
    const int dr[4] = {-1, 1, 0, 0}, dc[4] = {0, 0, -1, 1};
    auto feasible = [&](i64 limit) {
        std::vector<unsigned char> seen(rows * cols, 0);
        std::queue<std::pair<int, int>> frontier;
        frontier.emplace(0, 0);
        seen[0] = 1;
        while (!frontier.empty()) {
            const auto [r, c] = frontier.front();
            frontier.pop();
            if (r == rows - 1 && c == cols - 1) return true;
            for (int direction = 0; direction < 4; ++direction) {
                const int nr = r + dr[direction], nc = c + dc[direction];
                if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
                const int id = nr * cols + nc;
                const i64 gap = std::llabs(i64(height[r][c]) - height[nr][nc]);
                if (!seen[id] && gap <= limit) {
                    seen[id] = 1;
                    frontier.emplace(nr, nc);
                }
            }
        }
        return false;
    };
    return static_cast<int>(first_true(0, 999999, feasible));
}

queue 负责先进先出的读写，四方向邻接、阈值限制和访问标记仍由搜索逻辑处理。读取队头后先复制到局部变量，再删除该元素，见队列状态与元素寿命。

（4）工程：高度差计算与访问状态

计算高度差时，先提升类型再相减、取绝对值，见表达式的整数预算。每次阈值检查都要使用新的访问状态。

（5）替代解法：DSU 与瓶颈 Dijkstra 的对照

queue与deque的使用边界

std::queue 提供先进先出的队列，常用操作是front、push和pop。std::deque 可以在两端插入和删除，适合维护单调候选队列。容器只负责存取元素，“是否已经访问”“候选是否过期”“队列中的值是否单调”，仍由算法维护。

访问front或back前应检查非空。删除一个元素以后，指向它的引用也不能继续使用，通常应先取出所需值，再删除队首。

deque两端插入会使迭代器失效，但既有元素引用仍可保持有效；中间插入的规则不同。单调队列里常保存原数组的下标，以便直接判断候选是否过期，也避免持有deque迭代器跨越修改操作。

用数组实现队列时，只要容量足以容纳最多入队次数，头尾下标就能以 O(1) 代价推进。vector.erase(begin()) 却需要移动后续元素，不能作为常数时间出队。

单调队列的线性总成本，来自每个候选至多进队、出队一次的分析。deque提供方便的两端操作，但仅选择这个类型，并不能自动得到线性算法。

依据：queue、deque修改。

十四、有序事件前缀的首次成功与首次失败

（1）建模：完整事件前缀怎样形成单调判定

当事件必须按顺序接受时，可以把“采用多少个事件”作为搜索对象。下面两个问题都固定前 t 个事件再作检查，但一个寻找首次成功，另一个寻找首次失败。

NailingPlanks要求按顺序使用前 t 颗钉子，使每块闭区间木板至少被一颗钉子命中。木板数 N、钉子数 M 均不超过 30000，坐标在 1..2M。钉子增多不会让已命中的木板失去钉子，因此成功条件由假变真。

给定 t，先按坐标统计这批钉子，再构造前缀和。木板 [L,R] 被命中，当且仅当 prefix[R]-prefix[L-1]>0。这一坐标范围允许直接计数，无需建立区间树。

借教室则要求依次接受前 t 份订单，每份订单在一段日期内增加非负需求。天数和订单数不超过 10^6，每日容量、订单需求在 0..10^9。一旦某天超容量，后续订单无法减轻负担，所以失败条件由假变真。检查前 t 单时，用差分数组叠加所有区间需求，再恢复每日用量，与容量逐日比较。

这里必须接受整个前缀，不能跳过其中某份订单再寻找任意最大订单集合。

（2）Hcode：查找钉子前缀与首个失败订单

int first_nails_manual(const std::vector<int>& left, const std::vector<int>& right,
                       const std::vector<int>& nails) {
    const int m = static_cast<int>(nails.size());
    auto feasible = [&](i64 prefix) {
        if (prefix == m + 1) return true; // 仅用于表示所有真实前缀均失败。
        std::vector<int> count(2 * m + 1, 0);
        for (int i = 0; i < prefix; ++i) ++count[nails[i]];
        for (int x = 1; x <= 2 * m; ++x) count[x] += count[x - 1];
        for (std::size_t i = 0; i < left.size(); ++i)
            if (count[right[i]] == count[left[i] - 1]) return false;
        return true;
    };
    const int result = static_cast<int>(first_true(1, m + 1, feasible));
    return result == m + 1 ? -1 : result;
}

struct Order {
    i64 demand;
    int left, right; // 0-based 半开天区间；原题 [s,t] 转成 [s-1,t)。
};

std::vector<i64> order_difference(int days, const std::vector<Order>& orders, int prefix) {
    std::vector<i64> difference(days + 1, 0);
    for (int i = 0; i < prefix; ++i) {
        difference[orders[i].left] += orders[i].demand;
        difference[orders[i].right] -= orders[i].demand;
    }
    return difference;
}

int first_failed_order_manual(const std::vector<i64>& capacity,
                              const std::vector<Order>& orders) {
    const int m = static_cast<int>(orders.size());
    auto failed = [&](i64 prefix) {
        if (prefix == m + 1) return true;
        const auto difference = order_difference(capacity.size(), orders, prefix);
        i64 used = 0;
        for (std::size_t day = 0; day < capacity.size(); ++day) {
            used += difference[day];
            if (used > capacity[day]) return true;
        }
        return false;
    };
    const int result = static_cast<int>(first_true(1, m + 1, failed));
    return result == m + 1 ? 0 : result; // 返回申请人 1 基编号；0 表示全部成功。
}

两个求解函数都在真实事件之后增加位置 M+1，并规定那里判定为真，以保证首次满足的搜索一定能停在某个位置。这个位置只表示“所有真实前缀都未满足”，不是额外的真实事件。

对钉子题，返回哨兵表示无法命中全部木板，转成 -1；对订单题，哨兵表示没有失败订单，转成 0。真实订单编号从 1 开始，返回值不能直接作为零基数组下标。

Order 的日期使用半开区间 [left,right)，原题闭区间 [s,t] 应转成 [s-1,t)。差分数组长度为 n+1，因此可以在 difference[right] 写结束标记；尾格不代表真实日期。

钉子题每轮检查 O(N+M)，总时间 O((N+M)log M)、空间 O(M)；借教室每轮 O(n+t)，总时间 O((n+m)log m)、空间 O(n)。

（3）Scode：用 partial_sum 恢复前缀

int first_nails_standard(const std::vector<int>& left, const std::vector<int>& right,
                         const std::vector<int>& nails) {
    const int m = static_cast<int>(nails.size());
    auto feasible = [&](i64 prefix) {
        if (prefix == m + 1) return true;
        std::vector<int> count(2 * m + 1, 0);
        for (int i = 0; i < prefix; ++i) ++count[nails[i]];
        std::partial_sum(count.begin(), count.end(), count.begin());
        for (std::size_t i = 0; i < left.size(); ++i)
            if (count[right[i]] == count[left[i] - 1]) return false;
        return true;
    };
    const int result = static_cast<int>(first_true(1, m + 1, feasible));
    return result == m + 1 ? -1 : result;
}

int first_failed_order_standard(const std::vector<i64>& capacity,
                                const std::vector<Order>& orders) {
    const int m = static_cast<int>(orders.size());
    auto failed = [&](i64 prefix) {
        if (prefix == m + 1) return true;
        auto used = order_difference(capacity.size(), orders, prefix);
        std::partial_sum(used.begin(), used.end(), used.begin());
        // used 尾端多一项用于差分归零，不属于任何真实一天。
        return !std::equal(capacity.begin(), capacity.end(), used.begin(),
                           [](i64 available, i64 required) { return required <= available; });
    };
    const int result = static_cast<int>(first_true(1, m + 1, failed));
    return result == m + 1 ? 0 : result;
}

partial_sum 可以原地生成前缀和，但累加类型由容器元素决定。教室累计需求可达约 10^15，因此差分数组使用 long long。

这里还用四参数 equal 配合自定义关系检查 required<=available。它执行的是逐日容量比较，不是数值相等；比较范围只有 n 个真实日期，不含差分尾格。普通循环能表达同一检查，选择更便于维护的写法即可。

（4）边界：保持事件方向与检查状态一致

若允许撤销订单、负需求或任意跳过订单，失败前缀的单调性可能消失。钉子题允许一颗钉子同时命中多块木板，也不等同于给木板分配互斥资源。

每轮应清空计数或差分数组，按当前 t 重建状态，见重复调用判定器的状态。手写扫描与库前缀累加都须满足累计量的类型预算。

十五、按累计权重查找与随机抽样

（1）建模：把整数票号映回权重区间

给每个元素一个非负整数权重 w[i]，希望第 i 项被选中的概率正比于 w[i]。先把权重变成累计量：prefix[i]=w[0]+…+w[i]。

例如权重为 [2,1,3] 时，累计量为 [2,3,6]。把整数票号1、2分给第0项，3分给第1项，4、5、6分给第2项。均匀抽取1..6中的票号，再寻找首个累计值不小于票号的位置，就得到所选元素。

一般情况下，第 i 项对应 (prefix[i−1],prefix[i]]，恰好含 w[i] 个整数；首项之前的累计量在这个公式中记为0。于是二分负责把票号映回元素，随机数生成器负责等概率产生票号，两者合起来才得到所需分布。

（2）Hcode：构建累计量并查位置

std::vector<i64> cumulative_manual(const std::vector<int>& weights) {
    std::vector<i64> prefix;
    i64 total = 0;
    for (int w : weights) { total += w; prefix.push_back(total); }
    return prefix;
}
// 票号从1开始；查第一个累计值>=ticket，不使用浮点概率区间。
int ticket_manual(const std::vector<i64>& prefix, i64 ticket) {
    int lo = 0, hi = static_cast<int>(prefix.size());
    while (lo < hi) {
        const int mid = lo + (hi-lo)/2;
        if (prefix[mid] >= ticket) hi = mid;
        else lo = mid+1;
    }
    return lo;
}

累计量构建需要 O(n) 时间和空间；此后每次定位需要 O(log n) 时间。原题权重为正。若允许零权重，累计量可能相等，但空的票号区间仍不会被选中；负权重则会破坏累计量的单调性。

（3）Scode：前缀算法、边界算法与整数分布

std::vector<i64> cumulative_standard(const std::vector<int>& weights) {
    // partial_sum按输入value_type累加，先把输入本身转换为64位。
    std::vector<i64> prefix(weights.begin(), weights.end());
    std::partial_sum(prefix.begin(), prefix.end(), prefix.begin());
    return prefix;
}
int ticket_standard(const std::vector<i64>& prefix, i64 ticket) {
    return static_cast<int>(std::lower_bound(prefix.begin(), prefix.end(), ticket)
                            - prefix.begin());
}
int sample_index(const std::vector<i64>& prefix, std::mt19937_64& engine) {
    std::uniform_int_distribution<i64> ticket(1, prefix.back());
    return ticket_standard(prefix, ticket(engine));
}

partial_sum的累加类型由输入元素类型决定。即便输出容器使用64位整数，32位输入的累加也可能先溢出。因此，代码先把权重转换为64位，再计算累计量。

随机引擎通过引用传入，以便连续使用其状态。它应当在抽样开始前初始化一次，不在每次抽样时重新播种。整数随机分布与可复现性说明整数分布和 rand()%total 的区别。

（4）工程：票号范围、总权重与映射核对

定位函数要求票号在 [1,prefix.back()] 内，所以输入不能为空，总权重必须为正。累计总和的类型预算应当在构建时确定。

可以先独立检验“票号→元素”的确定性映射：穷举所有票号，核对第 i 项恰好得到 w[i] 张票。随机抽样的频率只能检验分布表现，不能代替这层正确性推导。权重频繁变化时，重建整份前缀会变贵；后文的树状数组选择可以直接维护动态累计量。

均匀整数抽样与可复现性

uniform_int_distribution<long long>(a, b) 在闭区间 [a, b] 中等概率产生整数，要求 a <= b。它与随机数引擎配合使用：引擎通过引用传入，每次抽样都会推进引擎状态。累计权重抽样可先产生一个均匀票号，再查它落入哪个权重区间。

直接对引擎输出取模，可能让某些余数出现得更多，因此通常应让整数分布完成区间映射。引擎一般在对象或任务开始时初始化一次，随后复用；反复用当前秒数重新播种，反而可能产生重复序列。

固定seed有助于在同一环境中重复实验，但 mt19937_64 不是密码学随机源，random_device 也不保证所有实现都使用硬件熵。不同标准库对分布和引擎输出的映射还可能不同，同seed的抽样序列不能被当作跨库文件格式。

验证权重映射时，先检查每一个合法票号落到的区间是否正确。随机抽样频率是否接近期望比例，可以作为额外观察，却不能替代这种确定性检查。

依据：C++17 uniform_int_distribution、随机数生成。

十六、在值域中寻找重复值或缺失值

（1）建模：用容量与计数定位唯一重复值

给定 n+1 个整数，每个数都在 1..n 内，只有一个数值重复出现。要求找出它，并且不能修改数组、只能使用常数额外空间。数组本身没有顺序，二分的对象应当是可能的重复值，而不是元素下标。

设 C(x) 为不大于 x 的元素个数。若重复值还在 x 右边，1..x 内的数各至多出现一次，所以 C(x)≤x。若重复值出现 r 次，全域只会缺少 r−2 个不同值，少于 r−1 个额外副本。因此，重复值一旦进入1..x，重复带来的增加必然超过缺失造成的减少，得到 C(x)>x。因此，条件 C(x)>x 从重复值开始成立，可以寻找它的首次成立位置。

例如 [1,3,4,2,2] 中，C(1)=1，C(2)=3；计数第一次超过可容纳的不同值数量，发生在重复值2处。这个推理依赖“只有一种数值重复”的限制；任意多重集不一定具有同一性质。

（2）Hcode：计数驱动的值域收缩

template<class Count>
int duplicate_core(int n, Count count_le) {
    int lo = 1, hi = n;
    while (lo < hi) {
        const int mid = lo + (hi-lo)/2;
        // 唯一重复值进入前缀后，数量必超过前缀容量。
        if (count_le(mid) > mid) hi = mid;
        else lo = mid+1;
    }
    return lo;
}
int duplicate_manual(const std::vector<int>& a) {
    return duplicate_core(static_cast<int>(a.size())-1, [&](int x) {
        int count = 0;
        for (int value : a) if (value <= x) ++count;
        return count;
    });
}

duplicate_core负责收缩值域，传入的回调负责计算 C(x)。每轮扫描 n+1 项后排除一半值域，共需 O(n log n) 时间，额外空间为 O(1)。这里获得对数级的是判定轮数，扫描本身仍是线性的。

回调在一次搜索中应表达同一计数事实，详见 判定器与lambda捕获；复用工作区不等于可以残留上一轮状态。

（3）Scode：用标准算法表达计数

int duplicate_standard(const std::vector<int>& a) {
    return duplicate_core(static_cast<int>(a.size())-1, [&](int x) {
        return std::count_if(a.begin(), a.end(), [x](int v) { return v <= x; });
    });
}

std::count_if把计数条件写成谓词，保留原数组，单次仍需线性扫描。它与手写计数共享同一搜索过程和正确性依据。

本题还可把数组值看作后继位置，用 Floyd 环检测在线性时间、常数额外空间内求解。那条路径利用的是函数图结构，而非值域计数。

（4）变型：在欠满整数域中寻找任意缺失值

再看缺失值问题。若记录总数少于整数域的容量，就至少有一个值没有出现。把当前域分成左右两半：左半记录数小于其容量时，左半必有缺失值；否则，左半记录数不少于左半容量，而当前域的记录数仍严格小于总容量，因此右半记录数必小于右半容量，应该保留右半。

这里比较的是记录条数，不是不同值的数量。域 [0,4) 中若有记录 [0,0,2]，左半 [0,2) 虽有两条记录，却仍缺少1；算法并没有证明左半不缺值，而是证明右半一定缺值，因而可以安全保留右半。

据此，每轮保留一个确定含缺失值的半域。下面的实现允许重复记录，目标是返回任意一个缺失值，不是第 k 个缺失值。

（a）Hcode：按容量保留必有缺失值的半域

// values均在[0,universe)，条数<universe；允许重复，返回任意缺失值。
std::uint64_t missing_domain(const std::vector<std::uint32_t>& values,
                             std::uint64_t universe) {
    std::uint64_t lo = 0, hi = universe; // 当前区间计数严格小于容量
    while (hi-lo > 1) {
        const auto mid = lo + (hi-lo)/2;
        std::uint64_t left_count = 0;
        for (auto v : values) if (lo <= v && v < mid) ++left_count;
        if (left_count < mid-lo) hi = mid;
        else lo = mid; // 左半记录数不少于容量；当前域欠满，故右半必欠满。
    }
    return lo;
}

（b）工程：IPv4 容量与多遍输入成本

IPv4 的完整地址域含 2³² 个值。因此，边界和容量用 uint64_t，单条地址仍可用 uint32_t，相关运算见 整数表达式与溢出预算。

这份实现每轮重新统计记录，约需 log₂U 遍扫描，U 是域容量。输入若只能读取一次，就不适用；能够顺序重读时，也应把多遍 I/O 的成本计入方法选择。

十七、行列有序矩阵的第 k 小元素

（1）建模：以值域计数反查第 k 小

给定行、列都非降的矩阵，求按出现次数计数的第 k 小元素。行列分别有序，并不意味着逐行拼接后整体有序，因而不能直接对展平下标二分。

换一个搜索对象。设 C(x) 为矩阵中不大于 x 的元素个数，那么第 k 小正是使 C(x)≥k 首次成立的值。这里保留重复值：如果某个数出现多次，计数会一次增加多项。

要快速计算 C(x)，从左下角开始。当前值≤x时，同列上方直到当前行都满足条件，可以整段计入，然后右移一列；当前值>x时，同一行右侧也都>x，只能向上移一行。每一步都排除尚未处理的一整段，形成楼梯式扫描。

（2）Hcode：值域边界与楼梯判定

// count返回<=x的重数；lo/hi有界且差可表示，k保证存在。
template<class Count>
i64 kth_value(i64 lo, i64 hi, i64 k, Count count) {
    while (lo < hi) {
        const i64 mid = lo + (hi-lo)/2;
        if (count(mid) >= k) hi = mid;
        else lo = mid+1;
    }
    return lo;
}
i64 matrix_count_manual(const std::vector<std::vector<int>>& a, i64 x) {
    int row = static_cast<int>(a.size())-1, col = 0;
    i64 count = 0;
    while (row >= 0 && col < static_cast<int>(a[0].size())) {
        if (a[row][col] <= x) { count += row+1; ++col; }
        else --row;
    }
    return count;
}
i64 matrix_kth_manual(const std::vector<std::vector<int>>& a, i64 k) {
    return kth_value(a.front().front(), a.back().back(), k,
                     [&](i64 x) { return matrix_count_manual(a,x); });
}

设矩阵有 R 行、C 列。一轮计数最多上移 R 次、右移 C 次，耗时 O(R+C)；值域宽度为 V 时，总时间为 O((R+C) log V)，额外空间为 O(1)。

计数可能从 k 以下直接跳到 k 以上。例如多个元素等于同一个值时，不能要求“恰好数到 k”才返回。kth_value统一寻找首次达到 k 的值；乘法表和数对距离也会复用这个边界搜索，但各自需要不同的计数方法。

（3）Scode：每行用上界计数

i64 matrix_kth_standard(const std::vector<std::vector<int>>& a, i64 k) {
    return kth_value(a.front().front(), a.back().back(), k, [&](i64 x) {
        i64 count = 0;
        for (const auto& row : a)
            count += std::upper_bound(row.begin(),row.end(),x)-row.begin();
        return count;
    }); // 每行查边界，检查器比楼梯扫描多一个log因子。
}

另一种计数法是对每行分别调用 upper_bound(x)。该位置与行首的距离，就是这一行≤x的元素数；把各行结果相加即可。

这一版单轮为 O(R log C)，未必比楼梯扫描快。它只要求每行有序，列可以无序；若采用这一较弱条件，还必须另求整个矩阵的最小、最大值，不能继续用左上角和右下角取界。

upper_bound在每一行内使用 二分库的分区与迭代器合同，矩阵的整体计数关系仍由各行结果相加得到。

（4）工程：矩阵形状、合法秩与重复计数

实现要求矩阵非空、各行等长、行列非降，且 1≤k≤R×C。乘积与计数的范围见 整数表达式与溢出预算。判定借用矩阵，不需要每轮复制。

“第 k 个元素”包含重复出现的元素；对输入调用 unique会改变问题。

十八、乘法表中的第 k 小数

（1）推导：不构造乘法表也能逐行计数

求 m×n 乘法表中的第 k 小元素，仍按出现次数计数。表可能很大，但每一行都由简单公式给出，不必真的保存下来。

第 i 行依次为 i、2i、…、ni。不大于 x 的倍数共有 ⌊x/i⌋ 个，还要受这一行的 n 列限制，所以贡献为 min(n,⌊x/i⌋)。将各行贡献相加，就能判断第 k 小是否已经≤x。

不同位置可能得到相同乘积。例如3×3表中的2和3都各出现两次，计数时不能合并。交换两条边让较短边充当行数，则可减少每轮求和项数。

（2）Hcode：解析计数

i64 multiplication_count_manual(int rows, int cols, i64 x) {
    i64 count = 0;
    for (i64 i = 1; i <= rows; ++i) {
        const i64 available = x/i;
        count += available < cols ? available : cols;
    }
    return count;
}
i64 multiplication_kth_manual(int rows, int cols, i64 k) {
    if (rows > cols) std::swap(rows,cols);
    return kth_value(1, 1LL*rows*cols, k,
                     [&](i64 x) { return multiplication_count_manual(rows,cols,x); });
}

设较短边为 min(m,n)。一次计数只扫描这么多行，答案位于1..mn，因此总时间为 O(min(m,n) log(mn))，额外空间为 O(1)。矩阵秩需要读取已存元素；这里直接计算一整行的贡献。

// 替换解析计数循环中一行的贡献，值域搜索与求和主体保持共用。
i64 multiplication_row_standard(int cols, i64 x, i64 row) {
    return std::min<i64>(cols, x / row);
}

完整求解函数用 std::swap把较短边放到行维度。计数循环中的一行贡献可写成 count += multiplication_row_standard(cols,x,i)；辅助函数用 std::min完成列数截断。

单行贡献耗时 O(1)，求和与 kth_value仍沿用上面的实现。标准库没有直接查询隐式乘法表第 k 小的接口；将答案域生成成容器反而丢失了这一问题的空间优势。

（3）工程：乘积上界与每轮扫描规模

原题 m,n≤30000，所以 mn≤9×10⁸；代码依然在乘法前用 1LL提升类型。推广到更大的表时，既要重算乘积与计数的范围，也要评估每轮扫描较短边的时间。改变输入类型本身并不会消除这两项限制。

LC668 · 乘法表中第 k 小的数。

十九、数对距离的第 k 小值

（1）推导：排序后用双指针累计合法数对

给定整数数组，把每个下标对 i<j 的绝对差组成一个多重集，求其中第 k 小。共有 O(n²) 个数对，逐一生成距离往往太贵。可以对距离上限 D 二分，只统计距离≤D的数对数。

先排序数组。固定右端 r 时，满足 a[r]−a[l]≤D 的左端组成一个后缀；右端增大后，最早合法左端只会右移。因此两个指针各走一遍，就能把每个右端贡献的 r−left 个数对累加起来。

例如 [1,1,4] 的三个距离是0、3、3。两个1虽然值相等，却是不同位置；它们之间的零距离和分别连向4的两个距离都要计入。

（2）Hcode：双指针判定

i64 pair_distance_manual(std::vector<int> a, i64 k) {
    std::sort(a.begin(), a.end());
    return kth_value(0, static_cast<i64>(a.back())-a.front(), k, [&](i64 d) {
        i64 count = 0;
        int left = 0;
        for (int right = 0; right < static_cast<int>(a.size()); ++right) {
            while (static_cast<i64>(a[right])-a[left] > d) ++left;
            count += right-left; // 每个索引数对恰计一次，重复值不去重。
        }
        return count;
    });
}

排序耗时 O(n log n)，每次距离判定耗时 O(n)，总时间为 O(n log n+n log V)，V 为最大可能距离。双指针只是在加速计数；第 k 小的定位仍由外层值域二分完成。

（3）Scode：每个左端查一个上界

i64 pair_distance_standard(std::vector<int> a, i64 k) {
    std::sort(a.begin(),a.end());
    return kth_value(0, static_cast<i64>(a.back())-a.front(), k, [&](i64 d) {
        i64 count = 0;
        for (int i = 0; i < static_cast<int>(a.size()); ++i)
            count += std::upper_bound(a.begin()+i+1,a.end(),static_cast<i64>(a[i])+d)
                     - (a.begin()+i+1);
        return count;
    });
}

也可以固定左端 i，查找首个大于 a[i]+D 的位置。该位置减去 i+1，就得到与 i 配对且距离≤D的元素数。

逐左端查上界需要 O(n log n) 时间，比双指针判定多一层对数。小规模时，还可生成全部距离后用 nth_element求出结果来核对，但其二次空间和时间准备成本不适合大输入。

（4）工程：排序副本与数对计数的类型

函数按值接收数组，因此排序的是副本，以 O(n) 额外空间保留调用者原顺序。允许原地修改时，可以改为引用参数。

数对总数最多为 n(n−1)/2，乘法前要提升类型；大坐标的 a[i]+D 和两坐标之差也应先在宽类型内计算。

LC719 · 找出第 k 小的数对距离。

二十、两个有序数组的第 k 小与中位数

（1）建模：把秩查询转成两数组的交叉切分

两个非降数组 A、B 的长度分别为 m、n，允许重复，求合并后第 k 小。直接合并需要线性时间。若只求一个秩，可以改为寻找：前 k 个元素中，应当从 A 取多少个？

设从 A 取 i 个、从 B 取 j=k−i 个，组成左半；其余元素组成右半。每个数组内部已经有序，只需检查两处交叉边界：A的左末不大于B的右首，B的左末也不大于A的右首。两项同时满足时，左半的每个元素都不大于右半，故左半最大值就是第 k 小。

i 还必须让两边实际可取，因此搜索区间为 [max(0,k−n),min(k,m)]。例如 A=[1,4,7]、B=[2,3,8]、k=4，取 i=2、j=2时，左半是1、4与2、3，交叉条件成立，答案为4。

（2）Hcode：交叉边界驱动切分

// k为1基；至少一数组非空，输入元素int，64位哨兵不与真实值混淆。
i64 two_array_kth(const std::vector<int>& a, const std::vector<int>& b, int k) {
    if (a.size() > b.size()) return two_array_kth(b,a,k);
    const int m = static_cast<int>(a.size()), n = static_cast<int>(b.size());
    int lo = std::max(0,k-n), hi = std::min(k,m);
    while (lo <= hi) {
        const int i = lo + (hi-lo)/2, j = k-i;
        const i64 al = i ? a[i-1] : std::numeric_limits<i64>::lowest();
        const i64 ar = i < m ? a[i] : std::numeric_limits<i64>::max();
        const i64 bl = j ? b[j-1] : std::numeric_limits<i64>::lowest();
        const i64 br = j < n ? b[j] : std::numeric_limits<i64>::max();
        if (al > br) hi = i-1;       // A左侧取多了
        else if (bl > ar) lo = i+1;  // A左侧取少了
        else return std::max(al,bl);
    }
    assert(false); // 有序且1<=k<=m+n时不会到达
    return 0;
}
double two_array_median(const std::vector<int>& a,const std::vector<int>& b) {
    const int n = static_cast<int>(a.size()+b.size());
    if (n%2) return static_cast<double>(two_array_kth(a,b,n/2+1));
    return (two_array_kth(a,b,n/2)+two_array_kth(a,b,n/2+1))/2.0;
}

若A左末>B右首，说明从A取多了，应减少 i；若B左末>A右首，则应增加 i。这两种冲突不能同时发生，否则会与A、B各自有序矛盾。边界满足时，取两侧左末的最大值返回。

代码在较短数组上搜索，时间为 O(log(min(m,n)+1))，额外空间为 O(1)。一侧为空时，只需处理相应的边界。

中位数可归为秩查询：总长为奇数，取第 (m+n)/2+1项；总长为偶数，取中间两项的平均。两项先转成64位后相加，避免32位加法先溢出。

（3）替代解法：线性合并后读取所需秩

（a）Scode：用 merge 获得完整合并结果

i64 two_array_merge(const std::vector<int>& a,const std::vector<int>& b,int k) {
    std::vector<int> merged(a.size()+b.size());
    std::merge(a.begin(),a.end(),b.begin(),b.end(),merged.begin());
    return merged[k-1]; // 线性时间/空间对照，不能满足LC4的对数要求。
}

std::merge把两有序范围完整合并，代码耗时、额外空间均为 O(m+n)。它适合需要完整结果的场景，也能用于核对小规模切分搜索结果，但不满足 LC4 的对数复杂度要求。

若只顺序推进到第 k 项就停，可以将合并时间减到 O(k)；当 k 接近总长时仍是线性的。它与上面直接定位切分位置的方法有不同的成本。

（4）工程：合法秩、空侧与域外哨兵

函数要求两数组非降、总长度非零，且 k 是合法的1基秩。当前元素类型为 int，用64位最小值、最大值代替不存在的边界，能够严格包住真实元素范围。

LC4 · 寻找两个正序数组的中位数。

二十一、最长递增子序列：维护每个长度的最小末值

（1）推导：为什么只保留每种长度的最小末值

给定任意序列，选出下标递增、数值也严格递增的最长子序列，通常简称 LIS。原序列没有整体顺序，二分要作用在我们维护的状态上。

对于同样长的两条递增子序列，末值较小的一条更容易接入后面的元素。因此，处理一个输入前缀时，每个长度只需保留一个最小末值：tail[len−1]表示长度为 len 的递增子序列所能达到的最小末值。这个数组是各长度的摘要，不要求它本身来自同一条子序列。

为什么可以在 tail 上二分？考察一条长度 l+1、末值最小的序列。去掉末项后得到一条长度 l 的序列，其末值至少为 tail[l−1]，又严格小于 tail[l]。所以 tail 严格递增。

读到新值 x，设 p 是 tail 中首个≥x的位置。p 之前的末值都小于 x，因而长度 p 的某条序列能够接上 x，成为长度 p+1的序列。更早位置用 x 只会把末值变大，更后位置则没有足够长的合法前驱。因此，只需用 x 替换 p；若没有≥x的位置，就把 x 追加为新长度。

例如依次处理 [3,5,6,2]，tail 从 [3]扩为 [3,5]、[3,5,6]，最后变成 [2,5,6]。长度仍为3，但最后的摘要不是输入中的真实子序列。这也说明恢复答案需要额外保存前驱。

（2）Hcode：保存真实前驱，恢复可行序列

为恢复一条真实序列，另用 tail_index记录每个长度当前的末位置，并用 parent[i]记录位置 i 选定的前驱。先取得前一长度的末位置，再更新当前长度：

template<class Locate>
std::vector<int> lis_core(const std::vector<int>& a, Locate locate) {
    std::vector<int> tails, tail_index, parent(a.size(),-1);
    for (int i = 0; i < static_cast<int>(a.size()); ++i) {
        const int p = locate(tails,a[i]);
        if (p) parent[i] = tail_index[p-1]; // 修改tail前保存真实前驱
        if (p == static_cast<int>(tails.size())) {
            tails.push_back(a[i]); tail_index.push_back(i);
        } else { tails[p] = a[i]; tail_index[p] = i; }
    }
    std::vector<int> indices;
    for (int i = tail_index.empty() ? -1 : tail_index.back(); i != -1; i=parent[i])
        indices.push_back(i);
    std::reverse(indices.begin(),indices.end());
    return indices;
}
std::vector<int> lis_manual(const std::vector<int>& a,bool nondecreasing=false) {
    return lis_core(a,[=](const std::vector<int>& tail,int x) {
        int lo=0,hi=static_cast<int>(tail.size());
        while (lo<hi) {
            const int mid=lo+(hi-lo)/2;
            if (nondecreasing ? tail[mid]>x : tail[mid]>=x) hi=mid;
            else lo=mid+1;
        }
        return lo;
    });
}

每次更新同时记录该长度的真实末位置 tail_index，并让当前项的 parent指向前一长度的真实末位置。处理完后，从最长长度的末位置沿 parent 回溯，就能恢复下标序列。

代码先保存父链，再更新当前长度对应的末位置，使恢复关系明确指向先前处理过的输入位置。时间为 O(n log n)，空间为 O(n)。

（3）Scode：使用库边界查找维护最小末值

std::vector<int> lis_standard(const std::vector<int>& a,bool nondecreasing=false) {
    return lis_core(a,[=](const std::vector<int>& tail,int x) {
        const auto it = nondecreasing ? std::upper_bound(tail.begin(),tail.end(),x)
                                     : std::lower_bound(tail.begin(),tail.end(),x);
        return static_cast<int>(it-tail.begin()); // 变成下标再允许vector增长
    });
}

严格递增时，相等值不能延长序列，所以用 lower_bound替换首个≥x的位置。若目标改为非降子序列，相等值可以延长，应改用 upper_bound替换首个>x的位置；此时 tail 只保证非降，恢复出的相邻值关系也变成≤。

（4）变型：将二维信封嵌套归约为 LIS

俄罗斯套娃信封要求宽和高都严格增加。先按宽升序后，对高度求严格LIS，仍有一个障碍：相同宽度的信封不能彼此嵌套，却可能被高度LIS连续选中。

解决办法是把同宽信封按高降序排列。这样同宽组中至多选一个高度进入严格LIS；不同宽度之间又保持宽递增。二维限制于是归约为排序之后的一维LIS。

（a）Scode：同宽降序排序后复用 LIS

int envelopes_standard(std::vector<std::pair<int,int>> envelopes) {
    std::sort(envelopes.begin(),envelopes.end(),[](auto a,auto b) {
        return a.first != b.first ? a.first<b.first : a.second>b.second;
    });
    std::vector<int> heights;
    for (auto item : envelopes) heights.push_back(item.second);
    return static_cast<int>(lis_standard(heights).size());
}

排序与高度LIS各需 O(n log n)，总空间为 O(n)。同宽时的降序规则是归约的一部分，其比较器应满足 比较器与排序合同。

比较器与排序规则

sort 要求比较器给出严格弱序。可以先记住两个直接要求：一个元素不能比自己更小；比较关系以及由“互相都不小于”形成的等价关系，都应保持传递性。把 < 随手改成 <= 会破坏第一个要求，相等元素也会被判成更小。

比较器应直接比较字段，避免通过 a - b 的正负判断先后，因为减法本身可能溢出。浮点比较中随意加入 epsilon，也可能让近似等价不再满足传递性；输入含NaN时，正常的排序推理同样需要重新检查。

多关键字排序要先区分第一关键字，再在真正相等时比较第二关键字。例如信封问题要求宽度升序、同宽高度降序，目的在于阻止同宽信封被LIS错误串接。pair的默认字典序把第二关键字也升序，不能替代这个规则。

二分查询的要求还要另看。对于一个固定key，lower_bound 要求 comp(element, key) 形成分区，upper_bound 则交换比较参数方向。某个回调若只接受 (Record, Key)，就不能不作调整地用于需要 (Key, Record) 的位置。排序的全域次序和一次查询所需的分区，是相关但不同的条件。

依据：C++17 排序关系、二分合同。

（5）变型：统计最长递增子序列的个数

若要求最长递增子序列的个数，只保留最小末值就不够了。以 [1,3,2,4]为例，末值2比3更容易延长，但经过3和经过2的两条最长链都应计数。

改为按结尾位置记录状态：len[i]是以位置 i 结尾的最长链长度，ways[i]是达到该长度的下标序列数。初始 len[i]=1,ways[i]=1，表示只选当前元素。

枚举满足 j<i且 a[j]<a[i] 的位置，把以 j 结尾的最长链接上 i，候选长度为 len[j]+1。更新分为两种情况：

  • 候选更长：原来的链已不是当前位置的最优长度，应覆盖长度，并令方案数为 ways[j]。
  • 候选同长：两批链都属于最优方案，应在现有方案数上加 ways[j]。

不同 j 给出不同的倒数第二个下标，所合并集合互不相交，不会重复计数。最后取所有 len[i]的最大值，再累加达到该长度的 ways[i]；末下标又一次将全体答案分成不相交集合。相同数值出现在不同下标时，仍可能形成不同方案。

例如 [1,3,5,4,7] 中，以5和4结尾的状态都为长度3、方案数1。处理7时，先接上5得到长度4、1种，再接上4得到同样长的另一种，合计2种。

（a）Hcode：按末位置合并最优长度与方案数

下面实现还对中间计数作饱和处理。其原因在于：题目保证最终答案可表示，却不保证每个较短状态的方案数都可表示。

i64 lis_count(const std::vector<int>& a) {
    if (a.empty()) return 0;
    const int n=static_cast<int>(a.size());
    std::vector<int> len(n,1);
    std::vector<i64> ways(n,1);
    const auto add_count=[](i64 x,i64 y) {
        const i64 cap=std::numeric_limits<i64>::max();
        return y>cap-x ? cap : x+y;
    };
    for (int i=0;i<n;++i) for (int j=0;j<i;++j) if (a[j]<a[i]) {
        // 更长则覆盖旧长度的方案；同长才合并互斥的倒数第二下标。
        if (len[j]+1>len[i]) { len[i]=len[j]+1; ways[i]=ways[j]; }
        else if (len[j]+1==len[i]) ways[i]=add_count(ways[i],ways[j]);
    }
    const int best=*std::max_element(len.begin(),len.end());
    i64 result=0;
    for (int i=0;i<n;++i) if (len[i]==best) result=add_count(result,ways[i]);
    return result; // 若最终答案可表示则精确；无关较短状态过大时饱和。
}

这版算法耗时 O(n²)，适用于 LC673 的 n≤2000。某个前缀可能产生海量短链，后面再出现一条更长、却只有一种方案的链，所以中间状态仍需防溢出。

每次相加达到计数上限就截断。若这样的状态能够延伸为最终最长链，它已有的全部方案都能作同样延伸，最终计数也必达到这个上限。题目保证最终答案较小时，被截断状态就不可能影响最终精确结果。

最小末值适合求长度和恢复一条链；计数DP则保留末位置，以便区分并合并不同方案。更高效的计数法可以使用值域数据结构，结点需同时保存最优长度与对应方案数。

若问题不保证最终计数可表示，就应使用大整数或明确的取模规则；饱和值只能表示“已经足够大”，不能当作精确答案。

（6）工程：容器失效与恢复结果检查

在 push_back之前，先把边界迭代器转成下标。扩容后旧迭代器可能失效；而 reserve只预留容量，不产生可以下标访问的新元素，详见 vector容量、元素与失效。

恢复序列时，应同时检查下标递增和所需的数值关系，不能只核长度。

vector的容量与引用失效

reserve(n) 预留容量，resize(n) 改变元素数量。仅reserve以后，原本不存在的元素并没有被构造，因此不能直接用下标写入它们。需要按下标填充时，先确定size；需要逐项追加时，使用push_back或emplace_back。

重分配会使指向原元素的指针、引用和迭代器全部失效。push_back没有发生重分配时，原元素引用和迭代器仍有效，但原来的end迭代器会失效。插入或擦除还可能移动后缀；例如erase会使擦除位置及其后的迭代器和引用失效。缓冲区没有更换，不等于所有旧位置都仍可使用。

在LIS实现中，先把lower_bound返回值转成下标，再允许push_back。这样后续使用的是逻辑位置，而不是一个可能被扩容破坏的旧迭代器。递归事件分流同理，不应持有某元素的引用后再扩张同一个vector。共享缓冲区若写入互不重叠的范围，也需要明确每层递归负责的范围。

unique 还有一个常见误解：它只合并连续出现的重复值，并返回新的逻辑结尾。例如 [1, 1, 2, 1] 的有效前缀变成 [1, 2, 1]，末尾的1不会被跨位置合并，容器的size此时仍为4。通常还需 erase(newEnd, end) 才真正删除尾部。排序、去重和擦除完成后，旧下标未必还指向原元素；坐标压缩应在这些操作结束后，按值重新查找位置。

依据：vector容量、vector修改、unique。

二十二、带权区间调度：查找兼容前驱

（1）建模：将兼容前驱前缀接入收益 DP

一组任务各有开始时间、结束时间和收益，要求选择互不冲突的任务，使总收益最大。带权之后，“总选最早结束的任务”可能放弃高收益任务。例如时段[1,2]、[3,4]各获利5，[1,4]获利20；按最早结束选择前两项只能得到10。

先按结束时间排序。令 dp[i]表示前 i 个任务的最大奖励。考虑下一任务时，只有两种可能：不选它，保留已有最优值；选它，将其收益加到所有兼容前驱构成的前缀最优值上。

二分的作用是确定这个兼容前缀有多长，而非决定应不应该选择当前任务。选与不选的比较由DP完成。

（2）Hcode：前驱数量直接作为 DP 下标

struct Job { i64 start,end,reward; };
template<class Predecessor>
i64 jobs_core(std::vector<Job> jobs,bool touching,Predecessor predecessor) {
    std::sort(jobs.begin(),jobs.end(),[](Job a,Job b) { return a.end<b.end; });
    std::vector<i64> ends,dp(jobs.size()+1,0);
    for (int i=0;i<static_cast<int>(jobs.size());++i) {
        // p为已处理任务中兼容的个数，可直接作为dp下标。
        const int p=predecessor(ends,jobs[i].start,touching);
        dp[i+1]=std::max(dp[i],dp[p]+jobs[i].reward);
        ends.push_back(jobs[i].end);
    }
    return dp.back();
}
i64 jobs_manual(std::vector<Job> jobs,bool touching=false) {
    return jobs_core(std::move(jobs),touching,[](const auto& ends,i64 start,bool touch) {
        int lo=0,hi=static_cast<int>(ends.size());
        while (lo<hi) {
            const int mid=lo+(hi-lo)/2;
            if (touch ? ends[mid]<=start : ends[mid]<start) lo=mid+1;
            else hi=mid;
        }
        return lo;
    });
}

设当前任务的兼容前驱有 p 个，选择它时使用 dp[p]+reward。这样，二分返回的前缀长度可以直接作为DP下标，不需要再转换为“最后一个前驱的下标”。

查询只在已经处理过的结束时间中进行，以免相同结束时刻把当前任务或未来任务算入前驱。排序与全部查询共耗时 O(n log n)，空间为 O(n)。若要恢复任务集合，可保存每个状态的选择及 p，再从末状态回溯；最优值相等时采用固定选择即可。

（3）Scode：原题端点决定 lower 还是 upper

i64 jobs_standard(std::vector<Job> jobs,bool touching=false) {
    return jobs_core(std::move(jobs),touching,[](const auto& ends,i64 start,bool touch) {
        const auto it=touch ? std::upper_bound(ends.begin(),ends.end(),start)
                            : std::lower_bound(ends.begin(),ends.end(),start);
        return static_cast<int>(it-ends.begin());
    });
}

兼容端点取决于具体问题。CSES Projects 不允许同一天参加两个任务，因此要统计 end<start的任务，用 lower_bound(start)；LC1235允许在结束瞬间接下一项，要统计 end≤start，用 upper_bound(start)。

代码的 touching参数区分这两种规则。CSES允许单日任务，而LC1235仍要求每项 start<end；允许端点接触并不等于允许任意零长度任务。

（4）工程：收益类型、排序副本与移动

总收益可能超过32位，所以收益字段与DP值均使用64位。排序比较器只按结束时间建立严格弱序，相同结束时间不需要额外虚构优先级；它们能否兼容由端点条件决定。

函数按值接收任务，因而在本地副本中排序。随后用 std::move将这份副本交给共同核心，避免为两种边界实现再复制一次；调用者保有的原始任务序列不受影响。

二十三、资源受限的试探：鸡蛋掉落问题

（1）推导：从最坏试投次数反推覆盖楼层

有 n 层楼、k 个鸡蛋。未知的最高安全楼层 f 位于0..n：从1..f层扔下不会碎，从更高楼层扔下会碎。要求无论 f 是多少，都能确定它，求最坏情况下最少的试投次数。

安全与不安全之间确实有单调分界，但每次查询会消耗资源。只有一个鸡蛋时，若第一次在中间层扔碎，较低的许多候选已无法继续区分。因此不能直接把普通二分的查询次数当作答案。

与其直接问“n层楼需要几次”，不如先问“给定次数最多能解决多少层”。定义 cover(d,k)为用 d 次试投、k 个鸡蛋能够保证处理的最大楼层数；处理 c 层意味着可以区分 f 的 c+1种位置。

没有试投次数或没有鸡蛋时，都不能再区分未知楼层，所以 cover(0,k)=cover(d,0)=0。

选择第一投的位置后，两个结果得到不同的剩余资源：碎了还可试 d−1次、剩 k−1个鸡蛋；没碎也还可试 d−1次，但鸡蛋仍有 k 个。

第一投下方最多安排 cover(d−1,k−1)层，上方最多安排 cover(d−1,k)层，再计入当前这一层，得到递推：

cover(d,k)=cover(d-1,k-1)+1+cover(d-1,k)。

这个递推不仅限制了可处理的层数，也给出了可执行的策略：第一投放在“下方可处理层数+1”的位置，两种结果分别进入对应子问题。实际楼层较少时，只须截短一侧。

例如 d=3、k=2，下方能处理2层，上方能处理3层。第一投选第3层：碎了在1、2层继续，没碎在4、5、6层继续，合计能够处理6层。

（2）推导：由覆盖递推得到组合判定

用组合数可以快速计算覆盖量。约定超出 d 范围的组合数为0；将 Pascal 恒等式 C(d,i)=C(d−1,i−1)+C(d−1,i)代入递推，并结合两个零初值，可得：

cover(d,k)=Σ(i=1..min(d,k)) C(d,i)。

也可按试投路径中至多 k 次破损的位置理解这一和式。关键是前面的递推已说明这些区分能力确实能够由合法策略实现。

覆盖量随 d 非降，一个鸡蛋逐层试最多需要 n 次。因此可在 [0,n]内寻找首个满足 cover(d,k)≥n的 d。

（3）Hcode：组合计数作为判定器

// LC887合同：1<=eggs<=100，0<=floors<=10000。
int egg_moves_manual(int eggs,int floors) {
    auto enough=[=](int moves) {
        i64 term=1,sum=0;
        for (int i=1;i<=eggs && i<=moves;++i) {
            term=term*(moves-i+1)/i; // C(moves,i)，尚未饱和时乘积<=floors²
            sum+=term;
            if (sum>=floors) return true;
        }
        return false;
    };
    int lo=0,hi=floors;
    while (lo<hi) {
        const int mid=lo+(hi-lo)/2;
        if (enough(mid)) hi=mid; else lo=mid+1;
    }
    return lo;
}

从 C(d,0)=1开始，利用 C(d,i)=C(d,i−1)×(d−i+1)/i逐项计算。乘法在除法前进行，保持整数精确性；累计覆盖量一旦达到 n，就立即停止。

一次判断至多计算 k 项，二分共需 O(k log(n+1)) 时间、O(1) 额外空间。代码适用范围为 1≤k≤100、0≤n≤10000；n=0时无需试投。

尚未达标时，当前组合项和累计和都小于 n。下一步乘法可用 n²作粗上界，在原题 n≤10000下仍能放入64位。达到 n 后不再计算更大的组合项。

这一预算依赖楼层数上界；若推广到任意64位楼层，需重新设计计算。判定只关心覆盖是否足够，无须保留超过 n 的精确数量。

（4）替代解法：逐次推进覆盖 DP

（a）Scode：饱和覆盖量与倒序更新

int egg_moves_coverage(int eggs,int floors) {
    std::vector<int> cover(eggs+1,0);
    int moves=0;
    while (cover[eggs]<floors) {
        ++moves;
        for (int e=eggs;e>=1;--e)
            cover[e]=std::min(floors,cover[e]+cover[e-1]+1);
    }
    return moves; // 另一算法：按次数增长覆盖DP，不是std提供了鸡蛋求解。
}

另一个做法从 d=0开始逐次增加试投机会，用 vector保存各鸡蛋数量当前能够覆盖的楼层，直到目标达成。std::min将状态饱和到 n，避免存储无用的大值；状态递推仍来自前面的两种试投结果。

鸡蛋数量 e 必须倒序更新，让 cover[e]和 cover[e−1]都还代表上一轮；正序会错误地在同一轮内重复使用新状态。该路径耗时 O(k·答案)，空间为 O(k)。它直接推进覆盖DP，与“组合计数+二分次数”是同题的两种算法。

（5）边界：试探资源与最坏情况目标

目标条件单调，与查询是否可重复且无代价是不同问题。交互题、昂贵测量或破坏性试探都要先确定资源怎样影响后续信息能力。这里求的是最坏情况最少次数；若问期望次数并给出概率分布，需要不同的状态与目标。

二十四、二维矩阵中的局部峰

（1）论证：用中列最大值确定搜索方向

在正值矩形网格中，寻找严格大于上、下、左、右邻居的格子。题目保证相邻值不等，网格之外视作 -1。

一维方法不能直接套到中列的任意格子上，因为选中的格子可能被上方或下方压住。先取中列最大值，就排除了这两个方向的威胁；再比较左右邻居。如果左右也没有更大值，当前格子就是峰。

若右邻更大，它不仅高于当前格子，也高于整条中列。从右邻出发不断走向更大的格子，不可能穿回这条较低的中列，最终会在右侧到达一个峰。因此可以保留右侧，左侧更新完全对称。

（2）Hcode：扫描列最大值，再决定搜索方向

template<class ColumnMaximum>
std::optional<std::pair<std::size_t, std::size_t>>
matrix_peak_core(const std::vector<std::vector<int>>& a, ColumnMaximum maximum_row) {
    if (a.empty() || a.front().empty()) return std::nullopt;
    std::size_t lo = 0, hi = a.front().size() - 1;
    while (lo <= hi) {
        const auto col = lo + (hi - lo) / 2;
        const auto row = maximum_row(col); // 必须是中列最大，而不是随便一行。
        if (col + 1 < a.front().size() && a[row][col + 1] > a[row][col]) lo = col + 1;
        else if (col > 0 && a[row][col - 1] > a[row][col]) hi = col - 1;
        else return std::pair<std::size_t, std::size_t>{row, col};
    }
    throw std::logic_error("invalid matrix-peak contract");
}
std::optional<std::pair<std::size_t, std::size_t>>
matrix_peak_manual(const std::vector<std::vector<int>>& a) {
    return matrix_peak_core(a, [&](std::size_t col) {
        std::size_t row = 0;
        for (std::size_t r = 1; r < a.size(); ++r)
            if (a[r][col] > a[row][col]) row = r;
        return row;
    });
}

设网格有 m 行、n 列。扫描一列需要 O(m)，列范围共缩小 O(log n) 次，总时间为 O(m log n)，额外空间为 O(1)。也可以对称地二分行范围。

相邻值不等使列最大值严格高于上下邻居；远处出现相等值没有影响。每次更新保留的是某个峰必定存在的一侧，不必保持同一个最大点。

（3）Scode：用库寻找当前列的最大行号

std::optional<std::pair<std::size_t, std::size_t>>
matrix_peak_standard(const std::vector<std::vector<int>>& a) {
    // std设施只替换“取中列最大行”；共享的是前面的二分证书和核心。
    std::vector<std::size_t> rows(a.size());
    std::iota(rows.begin(), rows.end(), std::size_t{0});
    return matrix_peak_core(a, [&](std::size_t col) {
        return *std::max_element(rows.begin(), rows.end(), [&](std::size_t x, std::size_t y) {
            return a[x][col] < a[y][col];
        });
    });
}

iota 建立行号数组，max_element 用当前列的元素值比较这些行号，返回最大值所在行。二分方向仍由前面的逻辑决定。

时间仍为 O(m log n)；行号数组使额外空间变为 O(m)，因此这种写法并不比直接扫描省内存。

（4）工程：比较器状态与矩阵输入约定

一次 max_element 调用期间，捕获的 col 不变，比较器也不能修改矩阵，见判定器与lambda捕获和比较器与排序规则。

输入应满足矩形且邻项不等的条件，函数不会逐次重验。空矩阵或零列输入返回空值，不会在空行号范围上读取最大值。

二十五、字符串的字典序前缀与最长公共前缀

（1）建模：把字典序前缀匹配转成连续区间

给定按字典序排序的字符串表，寻找所有以字符串 p 开头的词。例如 car、cart、cat、dog 中，以 car 开头的词构成连续区间 [car,cart]。

把每个词截取至多 |p| 个字符后与 p 比较，结果在词表中依次为负、零、正。分别找到“首次不小于”和“首次大于”两个边界，就能框出全部匹配项。这样不必构造 p 的字典序后继，也就无需假定字符总能安全加一。

（2）Hcode：查找前缀匹配的两个边界

std::pair<std::size_t, std::size_t>
prefix_range_manual(const std::vector<std::string>& words, std::string_view prefix) {
    // compare只看word的前|prefix|个字符；匹配返回0，短于prefix返回负。
    auto compare = [&](std::size_t i) { return std::string_view(words[i]).substr(0, prefix.size()).compare(prefix); };
    std::size_t lo = 0, hi = words.size();
    while (lo < hi) {
        const auto m = lo + (hi - lo) / 2;
        if (compare(m) < 0) lo = m + 1;
        else hi = m;
    }
    const auto first = lo;
    hi = words.size();
    while (lo < hi) {
        const auto m = lo + (hi - lo) / 2;
        if (compare(m) <= 0) lo = m + 1;
        else hi = m;
    }
    return {first, lo};
}

词比 p 短且只匹配它的前半部分时，比较结果为负，不算完整匹配；p 为空时，所有词都匹配。两次搜索共作 O(log n) 次比较，每次最多读取 |p| 个字符，字符处理成本为 O(|p|log(n+1))。输入必须按相同的字典序排列。

std::pair<std::size_t, std::size_t>
prefix_range_standard(const std::vector<std::string>& words, std::string_view prefix) {
    const auto first = std::lower_bound(words.begin(), words.end(), prefix,
        [](const std::string& word, std::string_view p) {
            return std::string_view(word).substr(0, p.size()).compare(p) < 0;
        });
    const auto last = std::upper_bound(first, words.end(), prefix,
        [](std::string_view p, const std::string& word) {
            return std::string_view(word).substr(0, p.size()).compare(p) > 0;
        });
    return {static_cast<std::size_t>(first - words.begin()),
            static_cast<std::size_t>(last - words.begin())};
}

lower_bound 和 upper_bound 分别使用适合自身参数方向的前缀比较器，返回同一匹配区间。

二十六、连续函数的零点与误差控制

（1）论证：连续性与异号如何保证区间含根

连续函数在区间两端取异号值时，介值定理保证区间内至少有一个零点。计算中点后，保留两端仍异号的那一半，就能不断缩小含根区间。函数不必单调，但一次夹逼只保证找到其中一个根。

连续性和异号各自有作用：x² 在 [-1,1] 中有根 0，两端却同号，这种夹逼不能发现它；单调阶跃函数可以两端异号，却因不连续而没有零点。

（2）Hcode：返回实际含根区间

struct RootBracket { double lo, hi; };
template<class Function>
std::optional<RootBracket>
bisect_root(Function f, double lo, double hi, double tolerance = 1e-10, int steps = 200) {
    if (!std::isfinite(lo) || !std::isfinite(hi) || lo > hi ||
        !std::isfinite(tolerance) || tolerance <= 0 || steps < 0)
        throw std::invalid_argument("invalid root interval");
    auto value = [&](double x) {
        const double y = f(x);
        if (!std::isfinite(y)) throw std::domain_error("non-finite function value");
        return y;
    };
    double fl = value(lo), fr = value(hi);
    if (fl == 0) return RootBracket{lo, lo};
    if (fr == 0) return RootBracket{hi, hi};
    if ((fl < 0) == (fr < 0)) return std::nullopt;
    // 调用者保证f连续；异号保证区间中至少有某个根，不要求单调。
    for (int i = 0; i < steps && hi - lo > tolerance; ++i) {
        const double m = lo / 2 + hi / 2;
        if (m == lo || m == hi) break; // 浮点相邻数使细分停止。
        const double fm = value(m);
        if (fm == 0) return RootBracket{m, m};
        if ((fl < 0) == (fm < 0)) { lo = m; fl = fm; }
        else { hi = m; fr = fm; }
    }
    return RootBracket{lo, hi}; // 返回实际夹区，不伪称必已达到所求误差。
}

实现分别判断两端的符号，不通过 f(lo)*f(hi)<0 引入额外乘积。循环可能因为三种情况停止：区间宽度达到容差、达到步数上限，或浮点中点已无法区别于端点。

后两种停止不一定意味着宽度合格，因此返回 RootBracket，由调用方检查实际区间，而不是把函数返回本身视为精度达标。理想求值下，轮数为 O(log((hi-lo)/ε))，还要乘以每次计算 f 的成本。实际求值若连符号都受到严重消去误差影响，外层夹逼也无法修复。

（3）变型：隔离三次方程的三个实根

P1024保证三次方程有三个互异实根，均位于 [-100,100]，两两间距至少为 1。要找全三个根，首先需要三个各自只含一根的区间。

逐个整数小区间判断符号并不稳妥：十进制系数 0.1,-0.6,1.1,-0.6 的数学根为 1、2、3，二进制求值却可能在整数端点留下很小的正负残差，导致重复或漏根。可以改用导数确定分界。

把方程除以三次项系数，写成 x³+B x²+C x+D。导数的两个零点为 t₁,₂=(-B±sqrt(B²-3C))/3。相邻两根之间必有导数为零的位置，这就是Rolle定理。在三根情形下，两个临界点因此与根严格交错：r₁<t₁<r₂<t₂<r₃。因此 [-101,t₁]、[t₁,t₂] 和 [t₂,101] 各含一根，可以依次夹逼。取 ±101 是为了把端点放在已知根域之外，避开根恰为 ±100 的情形。

归一化也消除了整体缩放系数造成的残差尺度差异，long double 与 fma 用来减小Horner求值的舍入。已知根域使归一系数的绝对值分别不超过 300、30000、10⁶。

根间距还提供了分段所需的符号余量：在任意相邻根的中点，到这两个根的距离均至少为 1/2，到第三个根的距离至少为 3/2，所以单首项三次式的绝对值至少为 3/8。两根之间的极值绝对值只会更大，临界点不会任意接近零。三个区间按序且不共享根，无需再用浮点容差去重。

（a）Scode：导数分段、Horner 求值与逐根夹逼

std::vector<double> cubic_roots_by_critical_points(long double a, long double b,
                                                 long double c, long double d) {
    // P1024：三个互异实根在[-100,100]，根间距>=1。
    if (!std::isfinite(a) || !std::isfinite(b) || !std::isfinite(c) || !std::isfinite(d) || a == 0)
        throw std::invalid_argument("invalid cubic coefficients");
    // 归一后不受整体缩放影响；根有界使|B|<=300、|C|<=30000、|D|<=1e6。
    const long double B = b / a, C = c / a, D = d / a;
    const long double delta = std::fma(B, B, -3 * C);
    if (!(delta > 0) || !std::isfinite(delta))
        throw std::domain_error("cubic requires two distinct critical points");
    const long double square = std::sqrt(delta);
    const double first = static_cast<double>((-B - square) / 3);
    const double second = static_cast<double>((-B + square) / 3);
    // Rolle定理给r1<t1<r2<t2<r3；外端取±101，避开根恰在±100的脆弱判断。
    if (!(-101 < first && first < second && second < 101))
        throw std::domain_error("critical points outside problem contract");
    auto f = [=](double x) {
        const long double X = x;
        return static_cast<double>(std::fma(std::fma(X + B, X, C), X, D));
    };
    const double cut[] = {-101, first, second, 101};
    std::vector<double> roots;
    for (int i = 0; i < 3; ++i) {
        const auto bracket = bisect_root(f, cut[i], cut[i + 1], 1e-11);
        if (!bracket || bracket->hi - bracket->lo > 1e-9)
            throw std::domain_error("root bracketing failed");
        roots.push_back(bracket->lo / 2 + bracket->hi / 2);
    }
    return roots; // 三个夹区本身按序、各含一根，不需要epsilon去重。
}

sqrt 与 fma 分别负责临界点计算和数值求值，根的隔离仍依赖上述三次方程结构。

（4）替代解法：利用分段线性关系直接恢复工资封顶值

工资封顶提供了另一个可直接求解的例子。设工资总额为 P(c)=Σmin(salary,c)，给定目标总额 T，求封顶值 c。P(c) 非降，可以二分；但排序后，相邻工资断点之间又是线性的。若低于封顶值的工资和为 S，其余 r 人都被封顶，就有 c=(T-S)/r。例如工资 [20,30,50]、目标 90，得到 c=40。

多次查询可预先建立每个工资断点对应的总额，再用 lower_bound 找到所属区间并代公式。目标大于原总工资时无解；能直接解析恢复时，无须继续迭代。

（5）工程：误差指标与停止条件

位置的绝对误差、相对误差和函数残差不是同一指标，应按题目要求选择停止条件。求平方根时，若 0<x<1，区间 [0,x] 甚至不含根，不能机械沿用整数情况的边界。

机器精度不等于业务容差。本例按P1024两位小数的要求预留计算余量，函数本身不负责输出格式，见浮点夹逼与误差。

浮点二分的精度与停止条件

浮点数只能表示离散的数值。区间很窄时，计算出的mid可能等于lo或hi，继续执行 while (lo < hi) 就可能不再推进。因此，停止条件既要考虑目标精度，也要处理中点等于端点的情况。

固定迭代次数是一种实现选择，需要结合初始区间宽度与目标误差。绝对区间宽度、相对误差和函数残差不是同一件事：函数值接近0，不一定表示横坐标已经足够准确；打印三位小数也只改变显示格式。

求根还需要存在性依据。连续函数两端异号，可以保证区间内有某个根；函数若发生跳跃，即使单调，也可能跨过0而不取0。偶重根又可能不引起符号变化。找到一个根、找到最小根和找到全部根，需要分别分析。

long double 的实际精度由平台决定，名字并不保证80位。应按输入范围、累加项数和函数形式评估误差，必要时保留已经确认可行的一侧，或同时返回夹逼区间。

检查两值是否异号时，可以直接比较符号，避免计算 f(lo) * f(mid) 引入额外乘积溢出。输入含NaN、无穷或不连续点时，应先重新确定问题允许的输入和判断方式。

二十七、带区间限制的平均值优化

（1）建模：减去候选平均值并保留原集合限制

平均值不是元素之和，不能直接靠增加一个元素判断好坏。可以先试一个平均值 λ，把每项变成 b[i]=a[i]-λ。对任意非空集合，都有 sum(a)/count>=λ 等价于 sum(b)>=0，因为元素个数为正。

变换消除了除法，但没有放宽原题允许选择的集合。下面两类题的差别，正体现在变换后仍须保留的区间约束。

（2）建模：长度受限的最大平均值

P1419要求在长度位于 [S,T] 的连续段中最大化平均值，条件为 1<=S<=T<=n<=10^5，元素在 [-10^4,10^4]。

令 P[j] 为变换数组前 j 项的和。若右端为 r，合法的左前缀下标 l 必须位于 [max(0,r-T),r-S]；该段满足平均要求，当且仅当 P[r]-P[l]>=0。因此只需找到合法窗口中的最小 P[l]，检查它是否不大于 P[r]。

只有最短长度限制时，可以一直保留历史最小前缀；加入最长长度后，过早的前缀会失效，需要用单调队列维护一个会滑动的窗口。

（3）建模：删除内部非空段后的最小平均值

Sabotage要求删去一个非空内部连续段，保留首尾，使剩余平均值最小。原题 3<=N<=10^5，每项在 1..10000。

仍令每项减去 λ。记全部变换值之和为 U，被删段的变换和为 V，剩余平均不超过 λ 当且仅当 U-V<=0。所以要检查：内部非空连续段的最大和是否至少为 U。这可以用Kadane算法求出，但必须限定在内部，并且不能允许空段。

（4）Hcode：实现长度窗口与内部非空最大子段

两题的搜索方向相反：最大平均值保留可行下界，最小剩余平均值保留可行上界。下面的浮点核心根据中点结果保留对应半区，不使用整数搜索的加减 1；最多迭代80轮，并在中点无法区别于端点时停止。

// 固定迭代预算，并防止浮点中点已无法前进。
template<class Predicate>
long double real_last_true(long double lo, long double hi, Predicate feasible) {
    for (int step = 0; step < 80; ++step) {
        const long double mid = lo + (hi - lo) / 2;
        if (mid == lo || mid == hi) break;
        if (feasible(mid)) lo = mid;
        else hi = mid;
    }
    return lo;
}

template<class Predicate>
long double real_first_true(long double lo, long double hi, Predicate feasible) {
    for (int step = 0; step < 80; ++step) {
        const long double mid = lo + (hi - lo) / 2;
        if (mid == lo || mid == hi) break;
        if (feasible(mid)) hi = mid;
        else lo = mid;
    }
    return hi;
}
long double max_average_manual(const std::vector<i64>& a, int shortest, int longest) {
    long double lower = a[0], upper = a[0];
    for (i64 x : a) { if (x < lower) lower = x; if (x > upper) upper = x; }
    const int n = static_cast<int>(a.size());
    auto feasible = [&](long double guess) {
        std::vector<long double> prefix(n + 1, 0);
        for (int i = 0; i < n; ++i) prefix[i + 1] = prefix[i] + a[i] - guess;
        std::vector<int> queue(n + 1);
        int head = 0, tail = 0;
        for (int r = shortest; r <= n; ++r) {
            const int enter = r - shortest;
            while (head < tail && prefix[queue[tail - 1]] >= prefix[enter]) --tail;
            queue[tail++] = enter;
            while (head < tail && queue[head] < r - longest) ++head;
            // 合法左前缀范围为 [r-longest, r-shortest]，队头是其最小值。
            if (prefix[r] >= prefix[queue[head]]) return true;
        }
        return false;
    };
    return real_last_true(lower, upper, feasible);
}

long double min_remaining_average_manual(const std::vector<i64>& a) {
    auto feasible = [&](long double guess) {
        long double total = 0;
        for (i64 x : a) total += x - guess;
        // 删除段必须非空，且不得包含 a.front()/a.back()。
        long double current = a[1] - guess, best = current;
        for (std::size_t i = 2; i + 1 < a.size(); ++i) {
            const long double x = a[i] - guess;
            current = current > 0 ? current + x : x;
            if (current > best) best = current;
        }
        return best >= total; // 剩余变换和 <=0，亦即剩余平均 <=guess。
    };
    return real_first_true(1, 10000, feasible);
}

P1419的队列保存前缀下标。新前缀进入时，从后端删去值不小于它的旧前缀；过期下标从前端移除。新前缀的值不更大，下标又更晚，因此更晚过期，对后续查询始终不差。即使值相等，新者仍可取代旧者，这就是代码使用 >= 的原因。每个下标至多入队、出队一次，单次判定为 O(n) 时间、O(n) 空间。

Sabotage中的 current 保存“以当前内部位置结束”的非空最大子段和：前一段和为正才继续接上，否则从当前项重新开始。它从第一项内部值初始化，因此内部全为负数时仍会删除至少一项。单次判定为 O(n) 时间、O(1) 额外空间。

（5）Scode：用 deque 管理窗口，用 transform 生成变换值

long double max_average_standard(const std::vector<i64>& a, int shortest, int longest) {
    const auto limits = std::minmax_element(a.begin(), a.end());
    const int n = static_cast<int>(a.size());
    auto feasible = [&](long double guess) {
        std::vector<long double> prefix(n + 1, 0);
        for (int i = 0; i < n; ++i) prefix[i + 1] = prefix[i] + a[i] - guess;
        std::deque<int> candidates;
        for (int r = shortest; r <= n; ++r) {
            const int enter = r - shortest;
            while (!candidates.empty() && prefix[candidates.back()] >= prefix[enter])
                candidates.pop_back();
            candidates.push_back(enter);
            while (candidates.front() < r - longest) candidates.pop_front();
            if (prefix[r] >= prefix[candidates.front()]) return true;
        }
        return false;
    };
    return real_last_true(*limits.first, *limits.second, feasible);
}

// 将各项减去同一阈值；合法删段仍由非空 Kadane 检查。
std::vector<long double> shifted_values_standard(const std::vector<i64>& a,
                                                 long double guess) {
    std::vector<long double> result(a.size());
    std::transform(a.begin(), a.end(), result.begin(),
                   [guess](i64 value) { return value - guess; });
    return result;
}

deque 提供两端增删，保持值单调和剔除过期项的规则不变；minmax_element 提供原数组的最小、最大值，作为平均值搜索范围。

二十八、固定数量选择的最大总比值

（1）建模：用变换分数优化总和之比

从 n 项中恰好选择 m 项，最大化 sum(value)/sum(cost)，其中每项 cost>0。目标是总和之比，不能预先按单项 value/cost 排序。

例如要选两项，候选为 (value,cost)=(100,1),(900,100),(8,1)。单项比值从大到小是 100、9、8，取前两项的总比值约为 9.90；改取第一、三项却得到 54。

试一个总比值 λ，把每项分数定义为 value-λ×cost。某个选择的总比值不低于 λ，当且仅当它的分数总和非负。又因为必须恰好取 m 项，能得到的最大分数和就是最大的 m 项之和。这样便得到线性或排序即可完成的判定，且随着 λ 增大，可行性由真变假。

（2）Hcode：计算变换分数，再选前 m 项

下面两份实现采用P1570的输入范围：1<=m<=n<=200，每项 value、cost 均在 1..10000，且题目保证最优总比值不超过 1000。因此 0 是可行下界，1000 是包含答案的上界；这里的固定区间不是仅由 cost>0 推出的。

struct Ingredient { i64 value, cost; };

// P1570：1<=choose<=n<=200，1<=value,cost<=10000，最优总比值<=1000。
long double ratio_manual(const std::vector<Ingredient>& items, int choose) {
    auto feasible = [&](long double guess) {
        std::vector<long double> score;
        for (const auto& item : items) {
            score.push_back(item.value - guess * item.cost);
            // 手写插入排序，保持已经生成的变换分数降序。
            std::size_t p = score.size() - 1;
            while (p > 0 && score[p] > score[p - 1]) {
                const auto temporary = score[p];
                score[p] = score[p - 1]; score[p - 1] = temporary;
                --p;
            }
        }
        long double sum = 0;
        for (int i = 0; i < choose; ++i) sum += score[i];
        return sum >= 0;
    };
    return real_last_true(0, 1000, feasible); // 原题保证最优比值不超过 1000。
}

手写版用插入排序得到降序分数，累加前 m 项。最多80轮检查，时间上界为 O(80n²)，搜索时保留最后可行值。若将模型推广到负收益或更大的比值范围，必须随之重建上下界，不能继续照用 [0,1000]。

（3）Scode：用 nth_element 分出最大的 m 项

// 输入范围与手写版相同；[0,1000] 依赖正收益及原题的答案上界。
long double ratio_standard(const std::vector<Ingredient>& items, int choose) {
    auto feasible = [&](long double guess) {
        std::vector<long double> score;
        score.reserve(items.size());
        for (const auto& item : items) score.push_back(item.value - guess * item.cost);
        if (choose < static_cast<int>(score.size()))
            std::nth_element(score.begin(), score.begin() + choose, score.end(),
                             std::greater<long double>{});
        // 前 choose 项是最大的 choose 项，但它们内部没有排好序。
        return std::accumulate(score.begin(), score.begin() + choose, 0.0L) >= 0;
    };
    return real_last_true(0, 1000, feasible);
}

nth_element 按降序把最大的 m 项放到前 m 个位置，但不排序这一部分；只需求和，已经足够。普通重载平均线性，所以单次检查平均为 O(n)，分数数组占 O(n) 空间。m=n 时全部取用，无需分隔。

也可以使用 sort(...,greater<>)，以单次 O(n log n) 的代价取得完整顺序，参见选择算法与重排语义。

（4）边界：保留数量与成本条件

cost>0 保证交叉相乘不改变不等号方向；恰选 m 项意味着即使有些变换分数为负，也不能擅自少选。

若另有总成本上限、物品冲突或相邻限制，直接取前 m 大就不再保证合法，须改用满足这些限制的DP或匹配判定。外层二分不能修复错误的集合选择。

浮点排序使用通常的大小关系，不加入会破坏严格弱序的epsilon比较；求值误差还要计入 λ×cost 的运算，见浮点误差。

nth_element的选择与重排

nth_element(first, nth, last, comp) 让nth位置得到完整排序后应在该处的元素，并将两侧分开：默认less比较时，左侧元素不大于右侧元素；使用greater比较时，数值大小方向相反。两侧内部仍可能无序，因此它提供的是选择结果，而不是完整排序。

若只需要最大的m项之和，可以使用 greater<>，让nth位于begin+m，再累加前m项。m等于总数时直接累加即可，无须再作选择。

这个算法会重排输入。若调用者需要保留原始顺序，就应使用副本或索引；也不能持有某个元素的引用，却默认重排以后这个位置仍对应原来的对象。

普通、非执行策略的重载具有平均线性复杂度，不是最坏线性的承诺。sort 则提供完整顺序，比较次数为 O(n log n)。如果后续还要按顺序继续处理，完整排序可能更合适；只求前m项之和时，组内顺序通常没有价值。

还应把输入的构造成本算进去。把所有数对先物化，再调用nth_element，内存已经达到 O(n²)，不能仅看选择阶段就认为它与隐式计数的方法消耗相同资源。

依据：C++17 nth_element、sort。

二十九、凸多边形中的点定位

（1）建模：用扇形与叉积定位查询点

给定按逆时针排列的严格凸多边形顶点，多次判断查询点在内部、边上还是外部。固定顶点 p₀，向其余顶点连线，就把多边形分成一组按角度排列的三角形。先找到查询点所在的扇区，便只需判断一个三角形。

记查询点为 q，cross(a,b,c) 表示向量 b-a 与 c-a 的叉积；它的符号判断点 c 位于有向直线 a→b 的哪一侧。

首尾两条射线之外的点可以直接排除。在它们之间，按顶点顺序旋转射线，cross(p₀,pᵢ,q)>=0 会先成立、后不成立。因此能够二分寻找包围 q 的两条相邻射线，再检查扇区三角形的第三条边。

（2）Hcode：先检查边界射线，再定位所在三角形

struct Point { std::int64_t x, y; };
enum class Location { outside, boundary, inside };
std::int64_t cross(Point a, Point b, Point q) {
    // 本题abs坐标<=1e9：差<=2e9，两个乘积之差绝对值粗界8e18。
    return (b.x - a.x) * (q.y - a.y) - (b.y - a.y) * (q.x - a.x);
}
bool on_segment(Point a, Point b, Point q) {
    return cross(a, b, q) == 0 && q.x >= std::min(a.x, b.x) && q.x <= std::max(a.x, b.x)
        && q.y >= std::min(a.y, b.y) && q.y <= std::max(a.y, b.y);
}
std::optional<Location> fan_boundary(const std::vector<Point>& p, Point q) {
    if (p.size() < 3) throw std::invalid_argument("polygon needs three vertices");
    const auto left = cross(p[0], p[1], q), right = cross(p[0], p.back(), q);
    if (left < 0 || right > 0) return Location::outside;
    if (left == 0) return on_segment(p[0], p[1], q) ? Location::boundary : Location::outside;
    if (right == 0) return on_segment(p[0], p.back(), q) ? Location::boundary : Location::outside;
    return std::nullopt; // 位于开扇形内，继续定位扇区。
}
Location convex_manual(const std::vector<Point>& p, Point q) {
    // p严格凸、逆时针，去掉末尾重复首点；q同样满足坐标预算。
    if (auto result = fan_boundary(p, q)) return *result;
    std::size_t lo = 1, hi = p.size() - 1;
    while (hi - lo > 1) {
        const auto m = lo + (hi - lo) / 2;
        if (cross(p[0], p[m], q) >= 0) lo = m;
        else hi = m;
    }
    const auto side = cross(p[lo], p[hi], q);
    return side < 0 ? Location::outside : side == 0 ? Location::boundary : Location::inside;
}

叉积为 0 只说明共线，不能说明点落在线段上，所以首尾两条边界射线还要检查坐标范围，排除延长线上的点。

进入开扇形后，二分得到 p[lo]、p[hi]。对有向边 p[lo]→p[hi] 计算叉积，负值表示 OUT，零表示 ON，正值表示 IN。点落在内部对角线上不等于落在多边形边界上，仍应经过这条第三边的判断。

每次查询需要 O(log n) 时间和 O(1) 额外空间，不使用角度函数、开方或浮点容差。严格凸且逆时针保证了射线顺序；凹多边形、顺时针输入、共线冗余点或重复首点都需要先作相应处理。

（3）Scode：用 partition_point 定位角度分界

Location convex_standard(const std::vector<Point>& p, Point q) {
    if (auto result = fan_boundary(p, q)) return *result;
    // 扇形内射线按角度排列，该谓词是true...true,false...false。
    const auto end = std::partition_point(p.begin() + 1, p.end(), [&](Point v) {
        return cross(p[0], v, q) >= 0;
    });
    const auto side = cross(*std::prev(end), *end, q);
    return side < 0 ? Location::outside : side == 0 ? Location::boundary : Location::inside;
}

partition_point 返回真前缀的结束位置。前面的扇形检查保证返回值既不在首条射线之前，也不是尾后迭代器，因此可以读取 prev(end) 和 *end，取得相邻两个顶点。库函数替换的是扇区定位循环，几何判断与前面的实现相同，时间和空间也相同。

三十、互斥选择中的最优阈值：用匹配判定

（1）建模：把第 k 大阈值转成互斥匹配

从一个 n×m 的完整矩阵中选择 n 个元素，要求它们不同行、不同列，使所选数的第 k 大尽可能小。P4251中 1<=k<=n<=m<=250，元素在 1..10^9。

给定阈值 x，“第 k 大不超过 x”等价于“大于 x 的数最多 k-1 个”，也就等价于至少 n-k+1 个被选数不超过 x。记这个需要的数量为 need。

但不能逐行选一个不超过 x 的最小值，因为多行可能争同一列。例如矩阵 [[1,9],[2,8]]，若要求最小化最大值，阈值 2 虽让两行各有一个低值，它们却都在第一列，无法同时选择。

把行、列作为二分图两侧，只保留 A[row][col]<=x 的边，就能保留行列互斥关系。现在的判定是：这些低值边能否组成至少 need 对匹配？阈值增大只会增加可用边，匹配数量不会减少，因而可以二分首次可行阈值。

低值匹配为何足以完成原题？必要性来自任何合法完整选择中的低值边。反过来，已经匹配 need 对后，余下行可以任意配给尚未使用的列：原矩阵没有禁选格，且 m>=n，所以一定补得齐。补出的值即使很大，低值的数量也不会减少。若矩阵存在禁选格，这一步就需要重新证明。

（2）论证：为什么增广路可以完成匹配判定

Kuhn算法寻找一条交替经过未选边、已选边的路径，把原先占用某列的行重新安排到其他列，为新行腾出位置。找到这样一条增广路，匹配数就能增加 1。

若存在比当前更大的匹配，两组匹配的对称差中必有一条增广路。按行逐步加入时，前面的行已经达到最大匹配；新出现的增广路只能从新加入的未匹配行开始。完整搜索所有可达的改派路径，成功就增加一对，失败则当前行前缀仍达到最大匹配。因此最后少于 need 可以确定拒绝，而不只是一次贪心没选好。

（3）Hcode：用增广路检查给定阈值

// 返回至多 need 条低权边组成的匹配：right_owner[c] = row 或 -1。
std::vector<int> threshold_matching(const std::vector<std::vector<int>>& a,
                                    int limit, int need) {
    const int n = static_cast<int>(a.size()), m = static_cast<int>(a[0].size());
    std::vector<int> right_owner(m, -1);
    int matched = 0;
    for (int row = 0; row < n && matched < need; ++row) {
        std::vector<unsigned char> seen(m, 0);
        auto augment = [&](auto&& self, int r) -> bool {
            for (int c = 0; c < m; ++c) {
                if (a[r][c] > limit || seen[c]) continue;
                seen[c] = 1;
                // 空列或能把原主人搬走，就为当前行腾出这个列。
                if (right_owner[c] == -1 || self(self, right_owner[c])) {
                    right_owner[c] = r;
                    return true;
                }
            }
            return false;
        };
        if (augment(augment, row)) ++matched;
    }
    return right_owner;
}

int matching_size(const std::vector<int>& right_owner) {
    int result = 0;
    for (int r : right_owner) if (r != -1) ++result;
    return result;
}

int matching_threshold_manual(const std::vector<std::vector<int>>& a, int k) {
    int lower = a[0][0], upper = a[0][0];
    for (const auto& row : a) for (int value : row) {
        if (value < lower) lower = value;
        if (value > upper) upper = value;
    }
    const int need = static_cast<int>(a.size()) - k + 1;
    auto feasible = [&](i64 limit) {
        return matching_size(threshold_matching(a, static_cast<int>(limit), need)) >= need;
    };
    return static_cast<int>(first_true(lower, upper, feasible));
}

right_owner[c] 保存第 c 列当前匹配的行，-1 表示空列。每加入一行都重新清空 seen，递归尝试改派；达到 need 对即可停止，不必求更多匹配。

朴素Kuhn一次检查的上界为 O(n²m)。在原整数值域中二分，总时间为 O(n²m log W)；这一实现没有使用Hopcroft–Karp的加速。

（4）Scode：离散化阈值，并恢复完整选择

struct MatchAnswer {
    int threshold;
    std::vector<int> column; // 每行最终选择哪一列，构成完整 n 条边。
};

MatchAnswer matching_standard(const std::vector<std::vector<int>>& a, int k) {
    std::vector<int> values;
    for (const auto& row : a) values.insert(values.end(), row.begin(), row.end());
    std::sort(values.begin(), values.end());
    values.erase(std::unique(values.begin(), values.end()), values.end());
    const int n = static_cast<int>(a.size()), m = static_cast<int>(a[0].size());
    const int need = n - k + 1;
    auto feasible = [&](i64 index) {
        return matching_size(threshold_matching(a, values[index], need)) >= need;
    };
    const int index = static_cast<int>(first_true(0, values.size() - 1, feasible));
    const auto owners = threshold_matching(a, values[index], need);
    std::vector<int> column(n, -1), free_columns;
    for (int c = 0; c < m; ++c) {
        if (owners[c] == -1) free_columns.push_back(c);
        else column[owners[c]] = c;
    }
    // 原矩阵完整且 m>=n，未配行可任取未用列；低权边数仍至少 need。
    std::size_t next = 0;
    for (int r = 0; r < n; ++r)
        if (column[r] == -1) column[r] = free_columns[next++];
    return {values[index], std::move(column)};
}

最优阈值必等于某个矩阵元素。sort+unique+erase 把候选压缩到至多 nm 个，再对候选下标二分；匹配判定仍调用同一Kuhn函数。最终取得低值匹配后，将未匹配行分给空闲列，返回每行所选的列号。

完整时间为 O(nm log(nm)+n²m log(nm))，存储为 O(nm+n+m)，递归深度为 O(n)。

（5）工程：匹配性能与递归状态

更大规模可把匹配判定换成Hopcroft–Karp等更快算法，阈值建模不变。每个阈值的 seen 与 right_owner 属于本次检查，不能直接沿用其他阈值的状态。

泛型递归lambda的 self(self,...) 写法见递归回调与调用栈；候选的排序去重负责建立阈值顺序。

递归lambda与调用栈

C++17中，递归可以用命名函数、成员函数、std::function，也可以用带显式self参数的泛型lambda。std::function 通过类型擦除，以统一接口保存不同类型的可调用对象，可能引入间接调用和分配；显式self的写法则不必先经过这种包装。

在 auto dfs = [&](auto&& self, int u) -> bool { … self(self, v); … }; 中，self参数接收当前闭包本身，递归时再把它传下去。返回类型需要时可显式写出。这里的引用捕获仍遵守lambda捕获的生命周期要求，不能因为回调递归就忽略被引用对象的寿命。

若回调借用了局部对象，就不能把它保存到局部作用域之外。递归过程中修改容器时，也要检查原有元素引用是否因扩容而失效。

最后还要估计递归深度。长度为二十万的链式DFS，可能需要同样多的栈帧；沿值域分治则通常只有对数深度。这两类递归不能沿用同一个空间估计。深度过大时应考虑显式栈或迭代，语言标准不保证固定的大递归栈或尾调用消除。

依据：lambda、function。

三十一、动态频数的第 k 个位置：树状数组内查找

（1）建模：用累计频数表示动态秩

给 n 个位置分别保存一个非负频数，允许修改频数，并查询“累计第 k 个单位出现在哪个位置”。例如动态删除序列时，原位置不移动：存活位置记1，删除位置记0，第 k 个存活元素就是前缀和首次达到 k 的位置。

这里的顺序来自累计频数，而非元素值。下面用树状数组（Fenwick tree）维护频数；代码中的 i64表示64位有符号整数，外部位置从0开始。

（2）推导：从树状数组的整块频数直接定位

先看树状数组保存了什么。内部采用1基编号，tree[t]记录最后 lowbit(t)个位置的频数之和，即区间 (t−lowbit(t),t]，其中 lowbit(t)=t&−t。

点修改沿着包含该点的更大块累加；求前缀和时反复减去 lowbit，把前缀拆成互不重叠的块。这些已保存的整块和，也可以用来直接寻找第 k 个单位。

若在位置上普通二分，每次再求一次树状数组前缀和，总时间是 O(log²n)。直接在结构内选择，则可按从大到小的二进制块，一次决定能否跳过整块。

设 accepted是已跳过的前缀长度，k是剩余部分中还要找的秩。始终保证已跳过部分的累计量小于原始目标。下一块的总频数小于 k 时，答案一定在块后，可以接受该块并扣去它的频数；总频数等于 k 时已经包含首次到达的位置，不能整块跳过。

为什么试探时能直接读一个 tree[next]？设当前步长为 step。进入这一轮时，accepted是 2×step的倍数，所以 next=accepted+step的最低有效位恰好是 step；该结点保存的正是紧接已接受前缀的 (accepted,next]。

初始accepted=0，条件成立。拒绝这块时accepted不变；接受时加上step，变成step的倍数。下一轮步长减半后，两种情况又都满足“是新步长两倍的倍数”。因此，每轮读到的确实是下一整块，而非某个不相关前缀。

例如内部1基频数为 [1,0,2,1,0,3,0,1]，要找累计第5个单位：

  • step=8，整块频数8，包含目标，不跳。
  • step=4，前4位频数4，小于5，跳过后剩余秩为1。
  • step=2，尝试位置(4,6]，频数3，包含剩余目标，不跳。
  • step=1，尝试位置(4,5]，频数0，可以跳过，剩余秩仍为1。

此时跳过5个位置，下一个内部位置6就是答案；零基接口返回5。这个过程也展示了零频数块和等于目标时的不同处理。

所有步长处理完后，accepted已经是累计量仍小于原始目标的最长前缀。其后一个位置首次达到目标，所以accepted恰好是答案的零基下标。

删除可以使用负增量，但删除后的每个实际频数仍须非负。若允许实际频数为负，累计量可能回落，上面的排除依据就不再成立。

（3）Hcode：维护频数并按当前秩删除

class FrequencyTree {
    int n;
    std::vector<i64> tree;
public:
    explicit FrequencyTree(int count) : n(count), tree(count + 1, 0) {}
    // pos is zero based; actual frequencies must remain nonnegative.
    void add(int pos, i64 delta) {
        for (int p = pos + 1; p <= n; p += p & -p) tree[p] += delta;
    }
    i64 prefix(int end) const { // [0,end)
        i64 answer = 0;
        for (int p = end; p > 0; p -= p & -p) answer += tree[p];
        return answer;
    }
    int kth(i64 k) const {
        if (k <= 0 || k > prefix(n)) return n;
        int accepted = 0;
        int step = 1;
        while (step <= n / 2) step *= 2;
        for (; step != 0; step /= 2) {
            int next = accepted + step;
            // accepted是2*step的倍数，故lowbit(next)=step，
            // tree[next]恰覆盖1基区间(accepted,next]，没有重叠计数。
            if (next <= n && tree[next] < k) {
                accepted = next;
                k -= tree[next]; // rank among the unaccepted suffix
            }
        }
        return accepted; // length of prefix with count < original k = answer index
    }
};

std::vector<i64> remove_by_rank(const std::vector<i64>& values,
                                const std::vector<int>& ranks) {
    FrequencyTree alive(static_cast<int>(values.size()));
    for (int i = 0; i < static_cast<int>(values.size()); ++i) alive.add(i, 1);
    std::vector<i64> answer;
    answer.reserve(ranks.size());
    for (int rank : ranks) { // 1 <= rank <= remaining size
        int position = alive.kth(rank);
        answer.push_back(values[position]);
        alive.add(position, -1);
    }
    return answer;
}

prefix(end)返回半开区间 [0,end)的频数和。kth按1基秩接收 k，返回零基位置；无效秩返回 n，调用者应先识别这个哨兵，再访问原数组。

remove_by_rank反复选择并将对应频数减1。原数组只用于读取删除值，位置本身不移动，因而不必承担 vector::erase导致的后缀搬移。用 n 次点加初始化后，整套删除耗时 O(n log n)；单次点加或选择均为 O(log n)，空间为 O(n)。

三十二、线段树内查找：从指定位置找首个达标值

（1）建模：用区间摘要排除整块不可能的位置

长度为 n 的数组允许点修改。给定起点 s 和阈值 V，求首个满足 j≥s且 a[j]≥V的位置；不存在则返回 n。

例如 [2,7,1,8] 中，从0开始找首个≥6的位置，答案是1。逐个值的判断真假交替，不能直接对 a[mid]≥V二分。但是，若一个区间的最大值小于6，就可以一次排除整个区间。

线段树为每个区间保存最大值。查询时，最大值不足的整块直接跳过；最大值足够的块再向下查，并优先查左半，便能定位最早答案。

这一方法还可推广到可合并的区间摘要。设 op(a[s],…,a[r−1])表示从 s 开始的聚合结果。合并运算须满足结合律，才能把相邻块的摘要继续合并；空区间用单位值表示。如果条件 f 随右端 r 扩展只会由真变假，就可以在结构内找到它的首次失效边界。

本题取区间最大值，令 f 表示“最大值<V”。扩展区间只会维持或增大最大值，因此条件具有所需的单调性。对数级搜索依赖的是摘要，不要求原数组有序。

（2）Hcode：根据区间最大值逐层定位

class MaxTree {
    int n, base = 1;
    std::vector<i64> tree;
    int descend(int node, int left, int right, int start, i64 target) const {
        if (right <= start || left >= n || tree[node] < target) return n;
        if (right - left == 1) return left;
        int mid = left + (right - left) / 2;
        int found = descend(node * 2, left, mid, start, target);
        if (found != n) return found; // leftmost eligible leaf has priority
        return descend(node * 2 + 1, mid, right, start, target);
    }
public:
    explicit MaxTree(const std::vector<i64>& values) : n(static_cast<int>(values.size())) {
        while (base < n) base *= 2;
        tree.assign(base * 2, std::numeric_limits<i64>::lowest());
        std::copy(values.begin(), values.end(), tree.begin() + base);
        for (int p = base - 1; p > 0; --p) tree[p] = std::max(tree[2*p], tree[2*p+1]);
    }
    void set(int position, i64 value) {
        int p = base + position;
        tree[p] = value;
        while ((p /= 2) != 0) tree[p] = std::max(tree[2*p], tree[2*p+1]);
    }
    i64 range_max(int left, int right) const { // [left,right)
        i64 answer = std::numeric_limits<i64>::lowest();
        for (left += base, right += base; left < right; left /= 2, right /= 2) {
            if (left & 1) answer = std::max(answer, tree[left++]);
            if (right & 1) answer = std::max(answer, tree[--right]);
        }
        return answer;
    }
    int first_at_least(int start, i64 target) const { // absent => n
        return descend(1, 0, base, start, target);
    }
};

搜索先排除完全位于 s 之前的块，再排除最大值小于 V 的块。对于剩余结点，先递归左子树；只有左侧找不到答案时，才进入右侧。

起点 s 只切开一条树路径，答案所在块也只需下降一条路径；中间区域按相邻整块跳过。因此单次查询为 O(log n)，不必遍历所有叶子。建树为 O(n)，点修改为 O(log n)，空间为 O(n)。补齐到二次幂的虚拟叶子不属于原数组，不能作为答案返回。

（4）工程：AtCoder Library 的结构内查找接口

AtCoder Library segtree::max_right/min_left提供了通用的结构内边界搜索。它是外部算法库，不是C++标准库。

在这个库中，用最大值作为摘要合并运算，空区间的单位值 e 取最低整数，再令 f(mx)=mx<V。max_right(s,f)返回区间最大值仍小于 V 的最远半开右端，也就是第一个≥V的位置；无答案时返回 n。

库要求 f(e())=true，并要求同一参数的判断结果稳定、没有副作用。原题元素与V非负，最低整数作为空区间值满足这一条件；V若恰是最低整数，则不能原样使用该调用。更一般的摘要还须保持合并顺序，例如非交换运算不能随意交换左右块。min_left则从右端反向寻找同类边界。

三十三、最近公共祖先与路径边界的倍增查找

（1）推导：把祖先复合转成可接受的倍增跳跃

给定一棵有根树，查询两点的最近公共祖先，即共同祖先中深度最大的结点，简称LCA。可先保存倍增表：up[b][v]表示结点 v 向上走2^b步到达的祖先。

表的递推是两次半程复合：先走2^(b−1)步，再从所得结点走同样距离。它使给定 k 的精确跳跃可按二进制位完成；LCA还要进一步决定哪些跳跃可以接受。

先将较深结点提升到与另一点相同的深度。若两点已相同，它就是答案；否则同时向上，寻找仍处于LCA下方的最远位置。

对某个步长2^b，若两点对应的祖先仍不相同，就可以同时接受这一跳。原因是：两条等深路径一旦在LCA会合，继续向根移动就不会再次分开。祖先不同意味着尚未到达LCA；祖先相同则说明这一跳到达或越过了它。

从大步长到小步长尝试后，两点恰停在LCA的下一层，其父结点就是答案。这是沿上行距离寻找边界，倍增表让每次试探跳过一整段。

（2）Hcode：先等深，再同步提升

class Ancestors {
    std::vector<std::vector<int>> up;
    std::vector<int> depth;
public:
    // Nonempty rooted tree: parent[0]=0, and parent[v]<v for v>0.
    explicit Ancestors(const std::vector<int>& parent) : depth(parent.size(), 0) {
        int levels = 1, n = static_cast<int>(parent.size());
        while ((i64{1} << levels) <= n) ++levels;
        up.assign(levels, std::vector<int>(n));
        up[0] = parent;
        for (int v = 1; v < n; ++v) depth[v] = depth[parent[v]] + 1;
        for (int b = 1; b < levels; ++b)
            for (int v = 0; v < n; ++v) up[b][v] = up[b-1][up[b-1][v]];
    }
    int kth(int v, i64 steps) const {
        if (steps < 0 || steps > depth[v]) return -1;
        for (int b = 0; steps != 0; ++b, steps >>= 1)
            if (steps & 1) v = up[b][v];
        return v;
    }
    int lca(int a, int b) const {
        if (depth[a] < depth[b]) std::swap(a, b);
        a = kth(a, depth[a] - depth[b]);
        if (a == b) return a;
        for (int power = static_cast<int>(up.size()) - 1; power >= 0; --power)
            if (up[power][a] != up[power][b]) {
                a = up[power][a]; b = up[power][b];
            } // accept a jump only while the two ancestors remain distinct
        return up[0][a];
    }
};

当前代码采用CSES的公司编号条件：根为0、parent[0]=0，其余结点满足 parent[v]<v，所以按编号就能先算出父结点深度。一般乱序编号的树，应先通过遍历建立深度，再填倍增表。

预处理耗时 O(n log n)，每次LCA或k级祖先查询为 O(log n)，空间为 O(n log n)。根指向自身只是表内安全哨兵；kth先比较实际深度，超出时返回−1，不把根的自指算作真实祖先。

（3）替代解法：直接求交两条祖先链

int lca_with_find(const std::vector<int>& parent, int a, int b) {
    std::vector<int> chain;
    for (int v = a;; v = parent[v]) {
        chain.push_back(v);
        if (v == parent[v]) break;

（4）变型：单调权值路径上的最浅达标祖先

祖先查询还可能由结点权值产生另一种顺序。若每条边都满足父权不大于子权，根到当前结点的路径权值就非降；给定阈值，可在该路径上寻找首个权值≥阈值的结点，也就是符合条件的最浅祖先。

这里搜索的是路径权值的边界，目标与LCA不同。没有这条权值条件的树，不能直接在根路径上二分。

（a）Scode：维护当前根路径并调用 lower_bound

// weights[parent[v]] <= weights[v]. Query = {node, threshold}.
// Answer is the shallowest qualifying ancestor, or -1.
std::vector<int> threshold_ancestor_queries(
        const std::vector<int>& parent, const std::vector<i64>& weights,
        const std::vector<std::pair<int, i64>>& queries) {
    int n = static_cast<int>(parent.size());
    std::vector<std::vector<int>> children(n);
    for (int v = 1; v < n; ++v) children[parent[v]].push_back(v);
    std::vector<std::vector<std::pair<i64,int>>> at(n);
    for (int id = 0; id < static_cast<int>(queries.size()); ++id)
        at[queries[id].first].push_back({queries[id].second, id});
    std::vector<int> answer(queries.size(), -1), path_nodes;
    std::vector<i64> path_weights;
    std::vector<std::pair<int,bool>> stack{{0,false}};
    while (!stack.empty()) {
        auto event = stack.back(); stack.pop_back();
        int v = event.first;
        if (event.second) { path_nodes.pop_back(); path_weights.pop_back(); continue; }
        path_nodes.push_back(v); path_weights.push_back(weights[v]);
        for (auto query : at[v]) {
            auto it = std::lower_bound(path_weights.begin(), path_weights.end(), query.first);
            if (it != path_weights.end()) answer[query.second] = path_nodes[it-path_weights.begin()];
        }
        stack.push_back({v,true}); // leave event restores the parent's current path
        for (auto it = children[v].rbegin(); it != children[v].rend(); ++it)
            stack.push_back({*it,false});
    }
    return answer;
}

代码通过进入、离开结点的事件维护当前根路径。进入子树时加入结点，退出时恢复，因而不会把兄弟分支的结点带入当前查询。

把查询按目标结点预先分组，到达该结点时在路径权值上调用 std::lower_bound。即使权值重复，首次满足仍对应最浅祖先。树遍历需要 O(n)，q次查询共需 O(q log n)，空间为 O(n+q)。显式事件栈也使长链不依赖递归调用栈容量。

（5）边界：树查询与函数跳跃的边界

两种树查询都要求结点合法、树非空且同根，接口采用零基编号。LCA的“会合后不再分开”推理还依赖两点已经同深。

函数图即使含环，也能用倍增表计算精确k跳；但沿跳跃次数不一定存在所需的单调边界。用于Planets Queries时，表层数应按最大 k 而非树高建立，也不再按树深度拒绝跳跃，见 移位与整数范围。

路径查询拿到边界迭代器后立即转成下标，再进行下一次 push/pop，避免使用失效位置，见 vector修改与失效。原树与权值只读借用，见 借用与生命周期；显式事件栈和递归函数栈的资源区别见 调用栈边界。

三十四、正数环形序列的最少连续分段

（1）建模：从最远合法段构造环上的跳跃

给定一个正数环，每个元素都不超过容量 C。把环切成若干连续段，每段和至多为 C，求最少段数。切点并未给定，因此需要同时考虑从哪里开始和每段延伸多远。

例如 [2,2,3]、C=4。从第一个2开始可分成 [2,2]与[3]，只需2段；从第二个2开始依次贪心却得到3段。固定一种数组展开方式并不够。

先固定切点，贪心地让每段延伸到最远合法位置。设 F(i) 是从 i 出发能到达的最远半开终点。由于元素为正，起点右移只会删去前面的正数，原先合法的终点仍合法，所以 F(i)非降。

用 g_j、p_j分别表示贪心和另一可行划分经过 j 段后的终点。若 g_j≥p_j，则 F(g_j)≥F(p_j)≥p_(j+1)，故下一段贪心仍不落后。由相同起点归纳，贪心用相同段数总能覆盖至少同样远，因而固定起点时段数最少。

为比较所有切点，把环虚拟复制为长度2n。记 next[i]=F(i)，从 i 贪心完成一段就跳到 next[i]。正数保证滑窗右端不后退，O(n)即可建立所有 next。

再保存 next 的2^b次复合。对于起点 s，要覆盖到 s+n；从大到小尝试跳数，只接受跳后位置仍严格小于目标的跳跃，最后再加一段。这样直接定位“尚未覆盖完整环”的最后位置。

（2）Hcode：用最远段建立跳跃表

跳跃核心接收已经建立的 next 表，构造多次复合，并对每个起点求答案。其输入是各起点完成一段后的下一个位置：

int cyclic_min_from_successors(const std::vector<int>& next, int n) {
    int end = 2 * n, levels = 1;
    while ((i64{1} << levels) <= n) ++levels;
    std::vector<std::vector<int>> jump(levels, std::vector<int>(end + 1));
    jump[0] = next;
    for (int b = 1; b < levels; ++b)
        for (int i = 0; i <= end; ++i) jump[b][i] = jump[b-1][jump[b-1][i]];
    int answer = n;
    for (int start = 0; start < n; ++start) {
        int position = start, used = 0, target = start + n;
        for (int b = levels - 1; b >= 0; --b)
            if (jump[b][position] < target) { // remain strictly short of full coverage
                position = jump[b][position]; used += 1 << b;
            }
        answer = std::min(answer, used + 1); // one final segment reaches target
    }
    return answer;
}

下面用滑窗产生 next。窗口 [left,right)保存当前段；右端尽量延伸到容量允许的最远位置，记录后删去左端元素，使下一起点复用已有窗口。

int min_cyclic_parts(const std::vector<i64>& values, i64 capacity) {
    int n = static_cast<int>(values.size()), end = 2*n, right = 0;
    std::vector<int> next(end + 1, end);
    i64 sum = 0;
    for (int left = 0; left < end; ++left) {
        while (right < end && values[right % n] <= capacity - sum) {
            sum += values[right % n]; ++right;
        }
        next[left] = right; // [left,right) is the farthest legal greedy segment
        sum -= values[left % n]; // positive values <=capacity ensure right>left
    }
    return cyclic_min_from_successors(next, n);
}

最后一段可以在目标位置截短，正数保证截短后仍不超容量。试跳时必须使用 <target：若把恰好到达目标的跳也计入，末尾再加一段就会多算。

next在2n处自指，使复合查表始终有界；每个真实位置的单项都能放入一段，保证跳跃严格前进。预处理及全部起点查询共耗时 O(n log n)，空间为 O(n log n)。n=2×10⁵时，当前 int跳表约占29MB，应按实际表大小计入内存。

（3）Scode：用前缀和构造最远终点

int min_cyclic_parts_with_bounds(const std::vector<i64>& values, i64 capacity) {
    int n = static_cast<int>(values.size()), end = 2*n;
    std::vector<i64> prefix(end + 1, 0);
    for (int i = 0; i < end; ++i) prefix[i+1] = prefix[i] + values[i % n];
    std::vector<int> next(end + 1, end);
    for (int i = 0; i < end; ++i)
        next[i] = static_cast<int>(std::upper_bound(prefix.begin()+i+1, prefix.end(),
                                                   prefix[i] + capacity) - prefix.begin()) - 1;
    return cyclic_min_from_successors(next, n);
}

另一种方法先构造前缀和。对起点 i，合法终点满足 prefix[right]≤prefix[i]+C，因此用 std::upper_bound找第一个超界位置，再退一位得到最远合法终点。

段和恰等于容量也合法，故这里选择upper而不是lower。它与滑窗共用同一提升核心；next构造从 O(n)变为 O(n log n)，但全算法仍由 O(n log n)界定。

（4）边界：正数条件与整数范围

实现要求环非空、所有元素为正且不超过 C。负数会同时破坏滑窗的最远段构造和前缀和顺序；若存在单项>C，则应先判无解，不能让窗口停在原地。原题已保证每个单项合法。

原题 Ai≤10⁹、2n≤4×10⁵，前缀和至多4×10¹⁴；加上 C≤10¹⁸后仍可放入64位。滑窗通过 value≤C−sum判断是否可加入，范围分析见 整数表达式与溢出预算。两版都只读借用原数组，见 借用参数。

三十五、并行二分：批量查询最早连通时间

（1）组合：让各查询共用一次时间前缀重放

图有 n 个结点，最初没有边，此后每天加入一条无向边。给出许多点对，分别询问两点最早在哪一天连通。设一共加入 m 条边，有 q 个查询。

对任意一个点对，答案具有时间单调性：一旦连通，以后继续加边就不会断开。因此可以二分日期。但若每个查询的每个中点都从头建图，大量相同的事件前缀会被重复处理。

图的连通状态可以用并查集维护，每个连通块有一个代表元。find寻找代表并压缩路径，unite把较小块接到较大块；两点代表相同，表示当前已加入的边使它们连通。这种结构适合只增边的过程。

并行二分让查询仍各自维护日期边界，却在同一轮共用一次事件重放。先计算每个查询的 mid，把相同日期的查询放进同一桶；并查集从空图开始按日期加边，走到某一天时，统一回答该桶内所有查询。

这里的“并行”指批量安排查询，不是创建线程。共享的是状态构建成本，查询各自的真假边界仍独立变化；状态也不必能写成各条边贡献的简单求和，只要能随事件增量维护即可。

（2）Hcode：按候选日期分桶，共享加边过程

先给出每轮使用的并查集DSU。std::iota将父数组初始化为0..n−1，使各点自成一块；合并时用 std::swap统一小块接大块的方向。

搜索为每问设置 low=-1、high=m+1。前者是虚拟假边界，后者是无解哨兵；真实日期范围是0..m，第0天表示尚未加入任何边。

class DisjointSet {
    std::vector<int> parent, size;
public:
    explicit DisjointSet(int n) : parent(n), size(n,1) {
        std::iota(parent.begin(), parent.end(), 0);
    }
    int find(int x) {
        while (x != parent[x]) { parent[x] = parent[parent[x]]; x = parent[x]; }
        return x;
    }
    void unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return;
        if (size[a] < size[b]) std::swap(a,b);
        parent[b] = a; size[a] += size[b];
    }
};

接着按 mid 分桶。当天应先加入第 day 条边，再回答 day 桶中的查询，使状态恰好包含前 day 条边；第0天的桶在加边前处理。

std::vector<int> first_connection_days(int n, const std::vector<std::pair<int,int>>& edges,
                                      const std::vector<std::pair<int,int>>& queries) {
    int m = static_cast<int>(edges.size()), q = static_cast<int>(queries.size());
    std::vector<int> low(q,-1), high(q,m+1);
    for (;;) {
        std::vector<std::vector<int>> bucket(m+1);
        bool pending = false;
        for (int id = 0; id < q; ++id) if (high[id] - low[id] > 1) {
            pending = true;
            bucket[low[id] + (high[id]-low[id])/2].push_back(id);
        }
        if (!pending) break;
        DisjointSet state(n); // no attempt to undo path compression
        for (int day = 0; day <= m; ++day) {
            if (day > 0) state.unite(edges[day-1].first, edges[day-1].second);
            for (int id : bucket[day]) {
                auto query = queries[id];
                if (state.find(query.first) == state.find(query.second)) high[id] = day;
                else low[id] = day;
            }
        }
    }
    for (int& day : high) if (day == m+1) day = -1;
    return high;
}

判定为真，只缩小该查询的 high；判定为假，只提高它的 low，不为回答一个查询而改变图状态。边界相邻时已经确定首次真日；若最终high仍为m+1，则从未连通，输出−1。

同一点与自身在空图中已连通，因此其答案是第0天。各轮从空图重放，重复边、自环和始终不连通的点对也按同一含义处理。

（3）推演：两次查询如何逐轮分开

例如道路依次加入 (0,1)、(1,2)、(2,3)，查询A=(0,2)、B=(0,3)。初始两问都是 low=-1、high=4。

第一轮mid均为1，只有第一条边，两问都不连通，low均改为1。第二轮mid均为2：加入前两条边后，A连通，high_A改为2；B仍不连通，low_B改为2。A的边界已相邻，B再检查第3天得到连通，答案分别为2和3。

这一过程每轮只扫描一条时间线，没有为A、B各重建一次前缀。若另问(2,2)，它的真边界最终会缩到第0天。

（4）复杂度：共享重放的成本与回滚版本的区别

每轮重建n个父结点需 O(n)，加边和回答查询需 O((m+q)α(n))。共进行 O(log(m+2))轮，因此总时间为 O((n+(m+q)α(n)) log(m+2))，空间为 O(n+m+q)。m=0时仍要检查第0天，轮数界中的常数项不能省掉。

当前实现不撤销路径压缩。若改成递归回滚，需要另行设计可回滚并查集；仅给普通 find加一张撤销列表并不足以保证原有复杂度与状态恢复。

（5）边界：重置状态与只增边条件

C++标准库没有直接的并查集或并行二分接口。这里 std::vector保存查询桶和父数组，std::iota建立初值，std::swap调整合并方向；路径压缩、合并规则与日期边界仍由前面的求解实现处理。

并查集与查询桶都按轮重建，不能把上一轮的状态直接留给下一轮。若加入删边，两点可能连通后又断开，时间单调性就消失；更换DSU的实现也不能恢复这一数学条件。

low=-1而所有真实日期非负，支持这里的中点计算；换成极大整数域时，应重算 差值与中点预算。操作桶与查询向量时，也要避免扩容后复用失效引用，见 vector扩容与引用失效。

（6）练习：多点对的最早连通日期

New Roads Queries。这是一套多问共享状态算法；只有一个钉木板前缀查询时，不必为术语而引入它。

三十六、整体二分：带修改的区间第 k 小查询

（1）建模：用时间事件表达赋值和区间秩

长度为 n 的数组交错执行两类操作：把某个位置赋成新值，以及查询当前闭区间的第 k 小元素，重复出现的值分别计数。所有操作已知，可离线处理。

对一次固定查询，统计“区间内≤v的元素个数”，随值阈值 v 单调增加。但查询发生的时刻不同，一次赋值也可能把答案变大或变小。因此，应沿答案值域分治，同时保留操作时间顺序。

先把每个初始元素写成一次插入。位置赋值则拆为两个相邻事件：删除该位置当时的旧值，再插入新值。这样，在时间顺序上扫描时，区间内当前有哪些值可由增减计数表示。

（2）推导：稳定分流与回滚如何维持查询时刻

进入某个值域 [lo,hi]的子问题时，其中更新事件的数值和查询答案都在这个域内，查询的 rank 表示该域内的剩余秩；位置树状数组从空状态开始。令mid为值域中点，只把值≤mid的更新加入树状数组。

遇到查询，就得到其位置区间内属于左半值域的数量 c。若rank≤c，答案在左半；否则答案在右半，且右半中的秩应减为rank−c。外层按值划分，树状数组则按位置统计，两个轴承担不同作用。

完成一轮判定后，更新按自身值归入左或右子问题，查询按上述结果归入对应一侧。每侧的事件必须保留原相对顺序，使查询只看到此前发生的修改。

进入孩子前，先逆序撤销本结点实际加入的更新，令树状数组回到空状态。逆序撤销还会逐步恢复较早的真实状态，避免在撤销中先减去已被后续删除抵消的初始项。两个孩子都从空统计开始，再按各自保留的时间序列重放。

删除事件的贡献为−1，但实际多重集中各位置的有效频数仍非负；这里不是允许任意负频数的秩查询。

（3）推演：先追踪一次值域划分

以初值 [4,1,3]为例，依次执行：查询全区间第2小Q1，把零基位置1赋为5，再查询全区间第2小Q2。压缩表为 [1,3,4,5]，顶层左半的最大值为3。

顺序扫描初始事件，1和3各向左半计数贡献1，所以Q1看到c=2，进入左半，剩余秩仍为2。接着删除旧值1，新值5不在左半；因此Q2看到c=1，进入右半，并把剩余秩改为1。

回滚后，左子问题在 [1,3]内求Q1的第2小，得到3；右子问题在 [4,5]内求Q2的第1小，得到4。这三个动作——按时间扫描、稳定分流、右转扣秩——分别保证修改时刻、后续重放与答案排序都保持正确。

（4）组合：事件表示、值压缩与稳定递归

（a）Hcode：表示外部操作与内部事件

实现用两类记录分开外部操作与内部事件。RangeOperation保存原始赋值或查询；RankEvent中的 delta表示插入/删除的±1贡献，rank只用于查询的剩余秩。left/right描述位置，value保存压缩后的值下标。

struct RangeOperation {
    enum class Kind { assign, query } kind;
    int left, right, k; // query uses inclusive [left,right]; assign uses left only
    i64 value;        // new value for assign
};
struct RankEvent {
    bool query;
    int left, right; // update uses left as position; query uses inclusive [left,right]
    int rank;        // query only: rank within the current candidate value interval
    int delta;       // update only: +1 insert, -1 delete
    int id, value;   // query output index; update compressed value
};

（b）Scode：排序去重并压缩全部可能值

先收集初值和全部未来赋值，排序去重，得到从小到大的不同值表。value_rank用 lower_bound将真实值映到表中下标；递归只在这些下标上分治，最终再映回原值。

压缩只替换值的表示，不合并元素的出现次数。两个相等元素仍分别产生更新事件。

std::vector<i64> compressed_values(const std::vector<i64>& initial,
                                    const std::vector<RangeOperation>& operations) {
    std::vector<i64> values = initial;
    for (const auto& op : operations)
        if (op.kind == RangeOperation::Kind::assign) values.push_back(op.value);
    std::sort(values.begin(), values.end());
    values.erase(std::unique(values.begin(), values.end()), values.end());
    return values;
}
int value_rank(const std::vector<i64>& values, i64 value) {
    return static_cast<int>(std::lower_bound(values.begin(), values.end(), value)-values.begin());
}

sort排好值序，unique把不重复的值压到前段，并返回新的逻辑末尾；erase删除尾段，才真正缩短容器。随后用 lower_bound取得值下标。仅压缩初值会漏掉未来修改目标，所以收集阶段必须包含所有新值。

标准库承担压缩和范围复制；稳定的时间流、剩余秩变化及回滚规则，仍需要由值域分治算法组织。

（c）Hcode：稳定分流事件并回滚位置统计

位置统计复用前面的 FrequencyTree 的点加与前缀求和；这里只需要这两项操作，不使用它的选秩接口。

std::vector<i64> dynamic_range_kth(const std::vector<i64>& initial,
                                   const std::vector<RangeOperation>& operations) {
    const auto values = compressed_values(initial, operations);
    std::vector<i64> current = initial;
    std::vector<RankEvent> events;
    for (int i = 0; i < static_cast<int>(initial.size()); ++i)
        events.push_back({false,i,i,0,1,-1,value_rank(values,initial[i])});
    int queries = 0;
    for (const auto& op : operations) {
        if (op.kind == RangeOperation::Kind::assign) {
            if (current[op.left] == op.value) continue;
            events.push_back({false,op.left,op.left,0,-1,-1,value_rank(values,current[op.left])});
            events.push_back({false,op.left,op.left,0,1,-1,value_rank(values,op.value)});
            current[op.left] = op.value; // the next assignment must delete this value
        } else events.push_back({true,op.left,op.right,op.k,0,queries++,0});
    }
    std::vector<i64> answer(queries);
    if (queries == 0) return answer;
    std::vector<RankEvent> scratch(events.size());
    std::vector<unsigned char> goes_left(events.size());
    FrequencyTree count(static_cast<int>(initial.size()));
    std::function<void(int,int,int,int)> solve = [&](int lo, int hi, int begin, int end) {
        if (begin == end) return;
        if (lo == hi) {
            for (int i = begin; i < end; ++i)
                if (events[i].query) answer[events[i].id] = values[lo];
            return;
        }
        int mid = lo + (hi-lo)/2, left_count = 0;
        for (int i = begin; i < end; ++i) {
            auto& event = events[i];
            bool left;
            if (!event.query) {
                left = event.value <= mid;
                if (left) count.add(event.left,event.delta);
            } else {
                i64 smaller = count.prefix(event.right+1)-count.prefix(event.left);
                left = event.rank <= smaller;
                if (!left) event.rank -= static_cast<int>(smaller); // residual rank
            }
            goes_left[i] = static_cast<unsigned char>(left);
            left_count += left;
        }
        // Reverse replay restores actual earlier states, including nonnegative frequencies.
        // No query from either child is allowed before this node is fully undone.
        for (int i = end-1; i >= begin; --i)
            if (!events[i].query && goes_left[i]) count.add(events[i].left,-events[i].delta);
        int l = begin, r = begin+left_count;
        for (int i = begin; i < end; ++i)
            scratch[goes_left[i] ? l++ : r++] = events[i]; // stable in each child
        std::copy(scratch.begin()+begin,scratch.begin()+end,events.begin()+begin);
        solve(lo,mid,begin,begin+left_count);
        solve(mid+1,hi,begin+left_count,end);
    };
    solve(0,static_cast<int>(values.size())-1,0,static_cast<int>(events.size()));
    return answer;
}

current保存每个位置当前真实值，每次赋值后必须更新，以便下次删除的确是当时旧值。同值赋值可以跳过。id记录查询的原始编号，最终结果按该编号输出。

每个结点先把分流结果记在 goes_left，再按扫描顺序写入 scratch的左右两段，实现稳定分流。回滚只撤销本轮实际加入的更新，不在每个结点清空整棵树，因此不会额外引入每结点O(n)的初始化。接口采用零基位置、闭区间和1基秩。

递归到lo=hi时，答案值已唯一，可通过压缩表写回。重复值都映到同一坐标，却仍以出现次数参与秩；0、负值或大整数也只是排序对象，不需要在原值上作中点算术。

设赋值数为 A、查询数为 Q，事件总数上界为 E=n+2A+Q，不同值数为 U。压缩需要 O((n+A) log(n+A+1))时间；值域递归每层处理所有事件，每次位置查询/更新为 O(log(n+1))，因此另需 O(E log(U+1) log(n+1))。两部分应相加，即使U=1也仍要读取、整理操作。

空间为 O(E+n+U+log(U+1))。递归深度取决于不同值数，而不是数组长度；共享缓冲区避免为每个递归结点保留整份事件副本。

（5）边界：离线条件、输入范围与借用

实现要求原数组非空、赋值位置合法，每次查询满足 1≤k≤r−l+1；非法秩不在该接口的定义范围内。

离线读取全部操作也是必要条件。若后续输入依赖上一次答案，或查询必须立即响应，应改用在线数据结构。静态问题可以省去赋值事件继续使用这一路径，也可以选择专门的静态结构。

这里复用树状数组的点加与前缀和，没有调用它的 kth。树状数组管理位置轴，值域由外层递归逐层缩小，不能把两个维度的职责混在一起。

实现中的相关C++机制见 稳定事件顺序与分流、递归回调与调用栈、共享缓冲区与vector失效和 压缩表的边界定位。递归捕获的 events等容器存活到求解结束，见 借用与生命周期；扫描时不向events追加，避免重分配使当前元素引用失效。

保留时间顺序的事件分组

partition 将满足谓词的元素放在前面，但不保证两组内部仍按原来的顺序排列。stable_partition 还会保留每组内部的相对次序。手动建立左右两个vector，并按原扫描顺序push_back，也能做到稳定分组，代价是额外存储。

带修改查询里，顺序直接决定查询看到什么数据。一次更新原本位于某查询之前，分组后仍须位于它之前；未来更新也仍应在查询之后。沿值域把事件分开，不表示可以把所有修改先做完，再统一回答查询。

分组依据应先确定清楚。若谓词依赖会在重排过程中改变的状态，同一个事件可能在不同调用中被分到不同组，便不能直接交给普通分区算法处理。

标准stable_partition的额外内存和移动次数依条件而变，不能一概当作无额外空间的线性操作。手动双缓冲便于明确控制空间与顺序；预先知道事件规模时可以reserve减少分配，但仍需遵守vector的元素与引用失效规则。

依据：C++17 分区算法。

三十七、惩罚参数搜索：递减边际收益下的资源分配

（1）建模：把资源使用化成递减收益的全局选择

有 N 个设施，第 i 个初始收益为 A_i。每使用一次，先获得当前收益，再将该设施收益减1。最多使用 K 次，求最大总收益。原题中 A_i、K可到2×10⁹，N可到10⁵。

直接用堆反复选择当前收益最高的设施是正确的，但K次操作可能太多。要消去这一巨大次数，可以把“逐个选取收益”改成“寻找入选收益的分界值”。

设施 i 提供的正收益依次为 A_i、A_i−1、…、1，后一次总不高于前一次。把所有设施的这些收益合并，选择最大的若干项，仍能在每个设施中选成一个前缀，所以确实可以按使用顺序实现。

这个可行性来自递减边际。若某设施前两次收益是1、100，就不能在K=1时跳过1直接取得100；此时同样的排序归约不成立。

全部正收益的数量为 T=ΣA_i。由于允许少于K次，零收益和负收益都不必取，实际应选 K′=min(K,T)个正收益。若K′=0，直接返回0；以下讨论K′>0。

（2）推导：用收益阈值补齐实际使用次数

对阈值 v，设施 i 提供的不小于v的收益有 max(A_i−v+1,0)个。因此定义

C_ge(v)=Σmax(A_i−v+1,0)。

随v增大，这个数量非增。寻找最大的 h，使 C_ge(h)≥K′；h就是第K′大的收益。再记 c_i=max(A_i−h,0)，它统计设施 i 中严格大于h的收益，令 S=Σc_i，E为满足 A_i≥h的设施数，就得到：

S=C_ge(h+1)<K′≤C_ge(h)=S+E。

严格大于h的S项全部取，剩余K′−S项从等于h的收益中补足。大量同值时只取所需数量，而非全部取或全部舍弃。例如 A=[5,5]、K=3，先取两个5，再取一个4，答案为14。

（3）推导：由惩罚目标精确恢复原收益

还可以把阈值理解成每次操作的统一惩罚。设施 i 使用 t_i次的总收益为等差和

U_i(t_i)=t_i(2A_i−t_i+1)/2。

先取消总使用次数限制，再为每次操作扣除λ，得到下列最优化问题：

H(λ)=max Σ[U_i(t_i)−λt_i]，其中 0≤t_i≤A_i。

取非负整数λ后，净边际收益仍然递减：大于0的应取，等于0的取与不取都不改变惩罚后的目标值。

最终取λ=h≥1，正净边际对应严格大于h的S次操作，另有E次零净边际可选。于是从S到S+E的每个整数数量都能实现，而且惩罚后的价值相同。因为K′位于这个区间，就能精确补到所需次数，并还原原目标：

H(h)=Σc_i(c_i+1)/2，原答案=H(h)+hK′。

这里，设施 i 的正净边际依次是 c_i、c_i−1、…、1，所以H(h)是上面的三角数之和；再把实际K′次操作各扣掉的h加回，得到原收益。精确恢复依赖“目标数量可由零净边际补足”，不只依赖数量随惩罚单调。

λ=0需单独理解：只考虑 t_i≤A_i的正收益域，此时最优计数为T，不应额外制造每个设施的一次零收益操作。

（4）Hcode：搜索收益阈值，恢复最大收益

struct MarginalResult {
    i64 value, cutoff, strict_count, equal_count, used_count, penalized_value;
};
MarginalResult maximize_fun(const std::vector<i64>& initial, i64 budget) {
    i64 total = 0, maximum = 0;
    for (i64 value : initial) { total += value; maximum = std::max(maximum,value); }
    i64 used = std::min(budget,total);
    if (used == 0) return {0,0,0,0,0,0};
    auto enough = [&](i64 threshold) {
        i64 count = 0;
        for (i64 value : initial) {
            count += std::max<i64>(0,value-threshold+1);
            if (count >= used) return true; // count only, never total all rewards here
        }
        return false;
    };
    i64 low = 1, high = maximum+1;
    while (high-low > 1) {
        i64 mid = low+(high-low)/2;
        if (enough(mid)) low = mid;
        else high = mid;
    }
    i64 strict = 0, equal = 0, penalized = 0;
    for (i64 value : initial) {
        i64 count = std::max<i64>(0,value-low);
        strict += count;
        equal += value >= low;
        penalized += count*(count+1)/2; // safe at final cutoff, not at arbitrary lambda
    }
    return {penalized+low*used,low,strict,equal,used,penalized};
}

代码在 [1,max A_i+1)内搜索最大可行阈值。二分过程中只统计收益数量，确定最终h之后才计算惩罚价值；总时间为 O(N log(max A_i))，额外空间为 O(1)。

返回结果同时保存原收益、阈值、严格大于阈值的数量、同值数量、实际使用量和惩罚价值，便于核对上述恢复关系。

（5）替代解法：逐次选取最大收益的堆解法

（a）Scode：使用 priority_queue 维护当前收益

i64 fun_with_priority_queue(const std::vector<i64>& initial, i64 budget) {
    std::priority_queue<i64> available(initial.begin(),initial.end());
    i64 answer = 0;
    while (budget-- > 0 && !available.empty() && available.top() > 0) {
        i64 value = available.top(); available.pop();
        answer += value;
        available.push(value-1);
    }
    return answer;
}

堆版本用 std::priority_queue维护每个设施当前最高的收益。取出堆顶后获得该收益，再把减1后的值放回，直到达到次数上限或已无正收益。

建堆后最多进行min(K,T)次操作，耗时 O(N+min(K,T) log N)，空间为 O(N)。它与阈值搜索利用同一个递减边际条件，却是另一种算法；K较小时简单直接，最坏K达到原题上界时则太慢。

堆复制并拥有收益值，不随原数组自动变化，相关机制见 借用与容器所有权。

（6）边界：数量单调为何不足以保证精确恢复

一般情况下，令 F(k)表示恰好选择k项时的最小成本，加上惩罚后得到 G(λ)=min_k(F(k)+λk)。最优数量随λ增大而非增，但某些数量可能从未成为惩罚问题的最优解。

例如 F(0)=0、F(1)=1、F(2)=0，任何λ都不会让k=1成为最优。数量从2跳到0的分界在λ=0；此时 G(0)=0，按 G(0)−0×1 只能算出0，而真实的 F(1)=1，因此不能恢复目标数量的成本。

相反，若F=(4,2,0)，在λ=2时三个数量的惩罚后成本都为4。固定同值策略可能只返回0或2，但中间数量1仍由 G(2)−2×1=2精确恢复。区别在于目标数量能否也在某个惩罚值下取得最优，而不是始终被其他数量的方案压过。

因此，WQS或拉格朗日式参数搜索除了数量单调，还要证明离散凸/凹结构等无间隙条件，并处理同值最优解的数量范围。当前问题由可分离的递减边际给出了直接证明；一般DP则还需要自己的状态设计和高效惩罚问题求解方法。

IOI2016 Aliens官方解答的满分方案还包含区间预处理、交叠成本和凸包优化（CHT）。其中的凸性结论依赖该问题结构，不能直接推广为任意参数搜索的证明。

（7）工程：只在最终阈值计算价值

原题 T≤2×10¹⁴，最终答案≤K×max A_i≤4×10¹⁸，可以放入64位有符号整数。但中间的惩罚价值不一定同样小：N=10⁵、A_i=2×10⁹时，H(0)约为2×10²³，即便K=1，最终答案也仅为2×10⁹。

所以二分只做数量判定，不计算任意λ下的完整H(λ)。在最终h处，S<K′≤2×10⁹，三角数乘积、惩罚和及恢复结果都在64位预算内。最终答案可表示与全部中间式可表示应分别分析，见 整数表达式与溢出预算。

接口要求A_i为正、预算非负且不超原题上界；预算为0时直接返回0。K>T时按K′封顶，避免继续获取非正收益。中点、乘法和累加均在已分析的64位范围内完成。

数量判定只读借用当前used与initial，捕获方式见 判定器与lambda捕获。
