区间上的取舍：覆盖、冲突与收益

先决定保留什么，再决定怎样排序

两份日程都写着起点和终点，你却可能在回答完全不同的问题：合并忙碌时间，要保留的是覆盖位置；安排所有住客，要保留每个请求；只看尽可能多场电影，可以舍弃请求；项目各有收益，则“多选一个”未必更好。端点对只是表示，不能替你决定目标。

本章面向已经能读循环、理解数组和基本复杂度，但还不熟悉C++容器与算法接口的读者。我们从具体任务建立需要保存的信息，在同一条推理旁边读实现。第一次遇到的C++知识用Q编号主讲；后续引用可以返回原处，算法的新理由仍在当前位置讲清。

行进路线分成四步：先把覆盖位置整理成有序并集；再让所有请求同时存在，计算峰值并构造资源分配；然后限制资源，在数量、命中、连续覆盖和收益之间选择方法；最后把已经会用的候选堆用于离线点查询。读完后，应能说出为什么某个状态足够、哪个条件改变会使它不够，以及该换哪种状态。

本章处理预先取得的静态一维区间。任意在线取消、逐区间包含计数、不同资格的资源、多资源加权收益等问题会改变需要维护的信息，章末会标出边界。

相接的两个端点，是否冲突

先比较 [1,2] 与 [2,3]：

任务如何解释端点 时刻2发生什么 同一资源能否连续接受
半开占用 [start,end) 前者已结束，后者刚开始 可以，条件是前者 end <= 后者 start
闭占用 [start,end] 两者都占用时刻2 不可以，条件必须是前者 end < 后者 start

Movie Festival允许结束后立即观看下一场；Room Allocation按整天入住，前一人离店日必须严格早于后一人入住日。Projects也按整天占用。不能把“区间通常写成方括号”当作题目的真实政策。LC435甚至明确约定只接触一个端点不算冲突。

还要区分两种长度。连续线段 [3,3] 的长度为0；它包含一个整数3，因此整数点数为1。闭区间允许这样的单点或单日请求；半开活动必须满足 start < end，本章不把空半开区间当作需要资源的活动。

下面的类型保存端点、负载和收益。返回的 chosen 是原输入的0基下标；room_for 按原输入顺序给出从1开始的房号。我们用一个明确的端点政策，使兼容关系贯穿分配、选择与加权计划。

Q000027 · 怎样把端点和结果组成有名字的值

struct Interval { long long start, end; }; 定义一种有两个成员的类型。Interval{1, 4} 按成员声明顺序初始化出一个值；range.start 取其起点。把它写进 std::vector<Interval>，每个元素就是一份区间值，不再靠“第0列一定是起点”的默契。这里的简单结构没有用户自定义构造函数，可以采用这种聚合初始化。

Allocation{rooms, room_for} 把房数与分配数组一起返回；CoverResult{false, {}} 把“无解”和空方案组合成一个清楚的结果。布尔状态与方案内容各有意义，调用者不能仅看空数组判断失败，因为有些任务的空输入本来就有空答案。

enum class EndpointPolicy { HalfOpen, Closed }; 定义一个独立类型。调用时写 EndpointPolicy::Closed，避免把记不住含义的 true 当作公共政策。它不会自动替算法选择比较符号，后面的兼容函数才落实这条规则。代码置于 interval_decisions 命名空间中；外部可写 interval_decisions::Interval 明确名字来自哪里。C++17规则参见WG21公开草案N4659，聚合初始化与枚举声明。

只关心覆盖位置：一个还没有封口的并集

LC56要求把所有有重叠的闭区间合并。[1,4] 和 [4,5] 共享点4，应得到 [1,5]；[1,4] 和 [5,6] 之间却有连续实数空隙，不能因为端点是整数就合成一段。

最直接的做法是逐点标记，但端点很大时，坐标跨度和区间数量完全不是一回事。我们真正需要处理的是端点改变覆盖的地方。

为什么只需看最后一段

按起点升序排列。扫描时，结果中除了最后一段以外，其余段都已封口：它们与后面的输入之间已经出现空隙。以后输入的起点只会更靠右，不可能再回来填上那个空隙。最后一段保存当前连通覆盖的起点和最远右端。

读入下一段 [s,e] 时只有两种情况：

  • s 大于最后一段的右端：空隙出现，原来最后一段可以封口，把当前段作为新的未封口部分。
  • s 不大于最后一段的右端：两段相接或重叠，左边界已经最小，只需把右端更新为两者的较大值。

这不是“与前一个原始区间重叠就合并”。输入 [1,10]、[2,3]、[9,12] 中，第三段与第二段不重叠，却与尚未封口的并集 [1,10] 重叠。状态必须保存累计右端，不能只保存上一次读到的右端。

每段只处理一次；代价主要是排序，为 O(n log n)，扫描为 O(n)。结果最多有n段。函数按值接收输入，因此排序的是自己的副本，调用者原来的次序保留。

std::vector<Interval> merge_closed(std::vector<Interval> ranges) {
    std::sort(ranges.begin(), ranges.end(), [](const Interval& a, const Interval& b) {
        if (a.start != b.start) return a.start < b.start;
        return a.end < b.end;
    });
    std::vector<Interval> result;
    for (const Interval& current : ranges) {
        if (result.empty() || result.back().end < current.start)
            result.push_back(current);
        else
            result.back().end = std::max(result.back().end, current.end);
    }
    return result;
}

这里的标准设施是 std::sort、std::vector 和取较大边界的 std::max；合并的状态与判断仍由我们写。std::set_union 合并的是已经排序的元素序列，不能把“两个端点值属于集合”解释成“两个时间区间的几何并集”。

Q000028 · vector的元素、大小和预留空间有什么区别

std::vector<T> 保存一段连续的T元素。size() 是已存在的元素数，合法下标为 0 到 size()-1；capacity() 是不重新分配存储可容纳的元素总数，额外还能追加的是 capacity()-size()。reserve(n) 只预留容量，不创建或移除元素：原本空的vector调用后仍为空，不能直接写 v[0]；原本已有的元素则仍然存在。需要创建n个初始为0的整数时，用 std::vector<int> v(n, 0)；需要逐个追加时，用 push_back(value)。

两个本章这样使用默认分配器的vector，可以用成员 a.swap(b) 交换各自持有的序列，操作为常数时间，不是逐个复制元素。后面的滚动DP据此让上一层和当前层交换角色；交换后名字a、b所指的两份序列已经互换，不能继续按交换前的角色理解。

empty() 判断有没有元素；back() 取最后一个元素，调用前必须非空。表达式 result.empty() || ... result.back() ... 利用 || 从左到右的短路：左边已为真时不会求右边，从而不访问空容器。operator[] 不做越界检查；它适合已经由循环边界和算法不变量证明合法的位置，不能把一次运行没有崩溃当作下标正确。

size() 返回无符号的大小类型。空vector的 size()-1 不是−1，而是无符号回绕后的大数。需要倒序时，可以先把已证明处于目标int可表示范围的大小转换为 int，再从 n-1 开始；或使用不会先减空大小的循环形式。这里的规模保证是转换成立的原因，不能推广为任意大容器都可转成int。

Q000029 · 参数按值和const引用，怎样影响修改与寿命

参数 std::vector<Interval> ranges 是函数拥有的局部vector。传入一个普通变量会复制元素；函数可以重排这份副本。参数 const std::vector<Interval>& ranges 借用调用者的vector，省掉整份复制；const 禁止通过该引用修改元素。它不表示整个程序里永远没有别的途径修改那个对象。

for (const auto& range : ranges) 逐个借用元素用于读取，避免每次复制。若写成 auto range，则每次得到元素副本；修改副本不会修改原数组。需要独立保存一个值时复制反而正合适，例如先复制堆顶、再删除堆顶。

借用不能超过被借用对象的寿命。尤其不能返回指向函数局部vector元素的引用。vector因增长而重新分配后，原来指向元素的引用、指针和迭代器都会失效；即使没有重新分配，插入和删除也可能使操作位置及其后的位置失效。代码因此不在保存元素引用的同时追加到同一个vector；需要跨操作保留的信息用值或原id保存。本章返回vector和结果结构本身，调用者得到自己的值，不依赖已经销毁的局部存储。

Q000030 · 迭代器为何把范围写成左闭右开

v.begin() 指向第一个元素，v.end() 指向最后一个元素之后的位置。[first,last) 包含first、不包含last；空范围正好有 first == last。end可以用于比较和表示边界，不能用 *end 读取元素。

vector迭代器支持随机访问：begin()+i 定位到下标i，两个同一vector的迭代器相减得到距离。因此 sort(v.begin(),v.end()) 恰好处理全部元素。后面二分返回end时，可以用差值取得“所有元素都在边界之前”的数量，不能先解引用它。

++it、--it 移动一个元素位置；--begin() 同样不合法。有序集合的迭代器是双向的，支持前后走一步，却不支持 it+5 或 it1-it2。这会影响通用二分算法的实际移动代价，见后面的 Q000037 · lower_bound与upper_bound怎样给出查询边界。std::reverse(first,last) 则交换范围两端并向中间推进，反转元素次序；它修改范围内的值，不是产生一份新的容器。

Q000031 · 排序比较器怎样表达顺序，而不制造错误

std::sort(first,last,comp) 用 comp(a,b) 回答“a是否严格排在b之前”。本章常用lambda写一个就近的比较函数：[](const Interval& a, const Interval& b) { return a.start < b.start; }。[] 表示不捕获外部变量；事件比较器中的 [policy] 按值保存这一政策，函数体可以读取这份副本。参数用const引用读取，见 Q000029 · 参数按值和const引用，怎样影响修改与寿命；写成 const auto& 的泛型lambda让编译器从传入元素推导参数类型，本章仍然比较同一种事件值。

比较器必须形成严格弱序：对象不能严格小于自己；前后关系应可传递；被比较器视为等价的关系也应可传递。把 < 写成 <= 会让相等对象也“小于自己”，违背要求。若要“起点升序，同起点终点降序”，应先比较起点，不同时返回起点比较；相同才返回终点的反向比较。两项完全相同可以互不排在对方前面。

不要写 a.start-b.start < 0。减法可能先溢出，直接比较不需要承担这种风险。sort 不保证比较器等价元素保持原顺序；只有确实需要稳定性时才用 stable_sort。本章多解允许任意合法顺序的地方，不靠偶然排序次序制造唯一答案。C++17草案的排序要求见 [alg.sorting] 与 [sort]。

Q000032 · 先确定运算类型，再计算长度和总量

存到 long long 不会让已经发生的int运算自动变宽。若a、b是int，long long x = a+b; 先以int相加，再转换结果；需要在运算前写 static_cast<long long>(a)+b 或 1LL*a。本章把端点、负载和收益本身存成long long，使后续差值与累计在该类型里进行。

本章面向这些题站通常提供的int至少32位、long long至少64位的环境。C++17并不保证int一定为32位；它的最低范围只有16位，不能在那样的实现上仍把200000个下标装进int。

参考接口通常限定端点绝对值不超过 10^9，区间或查询不超过200000，单项负载和收益不超过 10^9。所以连续跨度最多 2×10^9，闭整数区间点数最多 2×10^9+1，累计负载或收益最多 2×10^14，均在至少64位的long long范围内。房数与原id不超过200000，在目标环境中可用int。两个原题例外另有清楚上界：LC452允许完整32位有符号端点，stabbing_points 只比较和保存提升为long long的端点，没有对两个32位极端值做减法；LC1751按n与预算的乘积限制规模，项目数可超过200000，具体数值推导在预算选择一节。不能用统一的便利界限缩小原题合同。

static_cast<int>(value) 明确请求转换，不证明数值一定可表示。LC1235最多50000个项目、单项收益最多10000，总收益不超过 5×10^8，所以它的入口可以把核心long long结果转回int；CSES Projects的收益上界则为 2×10^14，应保留long long。两种平台签名不同，不能仅因都叫“项目选择”复制转换。

std::max(a,b) 与 std::min(a,b) 根据比较返回两者之一；用于更新 end = std::max(end, next.end) 时，读取比较结果并赋回端点。它们不会改变两个实参。不同整数类型混用可能使模板推导失败，也可能在别处触发有符号/无符号转换；统一表达式类型比事后强转结果更清楚。有符号溢出不是可依赖的回绕算法。

输入已经整理好，就利用已有结构

LC57的既有区间已经按起点排序，彼此没有公共点。加入一段 [s,e] 后，不需要把所有区间重新排序。

先复制右端严格小于s的那些段；它们完全在新段左边。然后连续读取与正在扩展的新段相接的区间，更新两端，直到下一段起点大于当前右端。把扩展后的新段加入结果，最后复制右侧其余区间。三段处理顺序对应三个连续的输入区域，总共只扫一遍，为 O(n)。

std::vector<Interval> insert_closed(const std::vector<Interval>& disjoint, Interval added) {
    std::vector<Interval> result;
    int i = 0, n = static_cast<int>(disjoint.size());
    while (i < n && disjoint[i].end < added.start) result.push_back(disjoint[i++]);
    while (i < n && disjoint[i].start <= added.end) {
        added.start = std::min(added.start, disjoint[i].start);
        added.end = std::max(added.end, disjoint[i].end);
        ++i;
    }
    result.push_back(added);
    while (i < n) result.push_back(disjoint[i++]);
    return result;
}

已有的互斥性是这个算法能只合成一个中间区间的理由。如果既有输入内部本来还有重叠，直接套这个入口不一定得到规范并集，应先用上一节的完整整理。

得到规范并集后，可以继续利用它，而不必重新对原区间做两两检查：

  • 连续覆盖长度：累加每段 end-start。若任务问整数点数，闭区间改为 end-start+1；这是不同的度量。
  • 点是否被覆盖：在并集里找最后一个起点不大于查询点的段，再检查查询点是否不大于该段右端。找不到这样的段即未覆盖。前驱的安全取得会在 Q000037 · lower_bound与upper_bound怎样给出查询边界、Q000038 · multiset怎样保留重复状态并只删除一个 讲清。
  • 哪些位置空闲：相邻并集段之间的空隙就是候选空闲段；给定查询窗口时还要裁剪窗口两端。连续闭区间 [a,b] 与 [c,d] 之间的空隙是开区间 (b,c)，不能把b和c也报为空闲。
  • 一段目标是否全部被覆盖：若起点落在某个规范并集段内，只需再检查该段右端能否达到目标终点。目标若跨过两个不同并集段，必然经过中间空隙。

这些查询复用了并集已经完成的工作。它们不能回答“原来有几个人同时占用”，因为合并已经丢掉了重数。

保留身份时，怎样判断包含关系

Nested Ranges Check问的是每条原区间是否包含别的区间、是否被别的区间包含。答案必须回到原输入位置，不能先合并。

将区间按起点升序、同起点按右端降序排列。当前段之前的所有段，起点都不晚于当前起点；因此当前是否被包含，只差“之前是否存在一个足够大的右端”。一个前缀最大右端就足够回答。相同起点时让长段排在前面，正是为了让它能包含后面的短段。

反过来，从右往左扫描。当前之后的所有段起点都不早于当前起点；若后缀中最小右端不大于当前右端，就存在被当前段包含的区间。两遍扫描都不需要保存所有历史端点：存在性问题由一个极值概括即可。

bool compatible(long long end, long long start, EndpointPolicy policy) {
    return policy == EndpointPolicy::HalfOpen ? end <= start : end < start;
}
struct IndexedInterval { Interval range; int id; };
std::vector<IndexedInterval> indexed_ranges(const std::vector<Interval>& ranges) {
    std::vector<IndexedInterval> result;
    result.reserve(ranges.size());
    for (int i = 0; i < static_cast<int>(ranges.size()); ++i)
        result.push_back({ranges[i], i});
    return result;
}
bool by_start(const IndexedInterval& a, const IndexedInterval& b) {
    if (a.range.start != b.range.start) return a.range.start < b.range.start;
    if (a.range.end != b.range.end) return a.range.end > b.range.end;
    return a.id < b.id;
}
bool by_end(const IndexedInterval& a, const IndexedInterval& b) {
    if (a.range.end != b.range.end) return a.range.end < b.range.end;
    if (a.range.start != b.range.start) return a.range.start < b.range.start;
    return a.id < b.id;
}

这些小工具给区间补上原id、表达端点兼容，并建立按起点或终点的顺序。它们没有替我们决定应保存并集、极值还是候选集合。

Containment containment_flags(const std::vector<Interval>& ranges) {
    auto ordered = indexed_ranges(ranges);
    std::sort(ordered.begin(), ordered.end(), by_start);
    const int n = static_cast<int>(ordered.size());
    Containment result{std::vector<int>(n, 0), std::vector<int>(n, 0)};
    if (n == 0) return result;
    long long largest = ordered.front().range.end;
    for (int i = 1; i < n; ++i) {
        result.contained[ordered[i].id] = ordered[i].range.end <= largest;
        largest = std::max(largest, ordered[i].range.end);
    }
    long long smallest = ordered.back().range.end;
    for (int i = n - 2; i >= 0; --i) {
        result.contains[ordered[i].id] = ordered[i].range.end >= smallest;
        smallest = std::min(smallest, ordered[i].range.end);
    }
    return result;
}

排序为 O(n log n)，两遍扫描为 O(n)，索引与输出需要 O(n) 空间。这里按原题保证，没有两条完全相同的区间。若允许完全重复，副本互相包含，按单条顺序扫描会让组内首尾得到不对称答案；应把相同端点分组处理，不能直接声称当前接口已支持。

“有几个”又是新的问题。一个最大右端只能告诉你至少有一个，不知道有三个还是三十个。Nested Ranges Count需要保留端点分布，可以进一步研究压缩坐标后的频数与秩查询；本章实现的是包含存在性。

Q000033 · pair、auto和类型别名怎样表达一份状态

std::pair<A,B> 把两个值放在一起，用 .first 和 .second 访问。默认比较是字典序：先比first，first等价才比second。堆里保存 (释放时刻,房号)，就能在时刻相同的情况下继续按房号比较；算法只要求找到一个最早释放房间，并不要求这种平局选择才正确。

auto 根据初始化表达式推导类型，不能据它判断是引用。auto item = heap.top(); 得到一份值副本；const auto& item = heap.top(); 借用原元素，后面若删除堆顶，借用不能继续使用。跨越容器修改要保存哪些信息，仍遵守 Q000029 · 参数按值和const引用，怎样影响修改与寿命。

using Release = std::pair<long long,int>; 为这个类型取一个别名，没有创建对象，也没有产生一种不同于pair的新类型。实际释放状态仍按pair的规则比较。离线查询中的 Candidate 则把“整数长度、右端点”两项组合，含义不同，所需字典序相同。

所有请求都保留：只在端点更新占用

Restaurant Customers要求最大同时在场人数。每次进入令计数加1，每次离开减1；两个相邻事件之间没有任何变化，因此不需要访问中间的每个时刻。

将所有事件按坐标排序，扫描累计量并记录最大值。它保留的是重数，故 [1,5] 与 [2,4] 不能预先合成一条 [1,5]。合并仍知道哪里有人，却不知道中间曾有两个人。

同一坐标的事件，先加还是先减

对闭占用，时刻x结束的请求与时刻x开始的请求同时在场：先加入开始量、记录峰值，再移除结束量。单点 [x,x] 也必须贡献一次占用。对半开占用，结束者已经释放：先减后加。若把闭区间同坐标的增减合成一个净变化再记录最大值，就可能把仅在这个点发生的峰值消掉。

从单位人数换成带宽或乘客数，只需把增减量换成正负负载w，活动量仍是之前事件的累计和。Car Pooling规定同地点先下客后上客，应采用半开政策；计算峰值后，比较是否超过容量即可。带权负载必须全部接纳，和后面“选择哪些带收益项目”是不同目标。

long long peak_load(const std::vector<LoadInterval>& ranges, EndpointPolicy policy) {
    std::vector<std::pair<long long, long long>> events;
    events.reserve(2 * ranges.size());
    for (const LoadInterval& range : ranges) {
        events.push_back({range.start, range.load});
        events.push_back({range.end, -range.load});
    }
    std::sort(events.begin(), events.end(), [policy](const auto& a, const auto& b) {
        if (a.first != b.first) return a.first < b.first;
        return policy == EndpointPolicy::Closed ? a.second > b.second : a.second < b.second;
    });
    long long current = 0, peak = 0;
    for (const auto& event : events) {
        current += event.second;
        peak = std::max(peak, current);
    }
    return peak;
}

总共2n个事件，时间 O(n log n)、额外空间 O(n)。负载与累计类型见 Q000032 · 先确定运算类型，再计算长度和总量。原Restaurant Customers保证所有到离时间互不相同，所以其样例不能替我们检验重复端点政策；重复端点由上面的占用模型决定。

如果只需单位峰值，还可以分别排序全部起点和终点，用两个指针按相同事件顺序扫描；它保存同一个计数不变量。若坐标范围很小，可以在每个坐标累计差分再做前缀和，代价变成 O(n+U)，U是坐标域大小。闭离散日程常在 end+1 撤销负载，但必须确认这个坐标存在且加1不会溢出；不能将这一技巧无条件用于连续时间。坐标可达十亿时，按域长分配数组通常比按事件排序更浪费。

从峰值数值，走到一份实际房间安排

Room Allocation不仅问最少房数，还要求按原输入顺序输出每个住客的房号。只算出峰值，尚未完成分配。

先按入住时间排序。每个已使用房间只需记录最后一位住客的离店时间：更早的住客都排在他之前，不影响下一次是否可接。每次查看释放最早的房间。若它与当前请求兼容，就重用这个房号、更新释放时间；若连它都不兼容，其他房间只会释放得更晚，只能开新房。

为什么新开的每一个房间都不可避免

设当前将第r个房间第一次打开。前r−1个房间的最后请求都未释放，因为连最早释放者也不兼容；这些请求又都已经开始，因为我们按起点处理。所以在当前起点上，至少r个请求同时占用，任何安排都需要r个房间。

算法确实只在这个情形开新房，因此它用的房数既不小于峰值下界，也没有超过任何可行安排必须支付的数量。它同时给出合法构造：同房连续请求都通过了端点兼容判断。这里“取最早释放”用于判断是否存在可重用房间；后面固定资源选择的目标会要求另一种取法。

需要动态取最小释放时刻，反复全排序每个房间会浪费工作。二叉小堆让最小值始终在根；入堆与出堆只修复一条祖先或后代路径。

手写堆：真正修复父子关系

把堆放在vector里，下标i的父亲为 (i-1)/2，左右孩子为 2*i+1 和 2*i+2。小堆的不变量是每个父亲都不大于孩子，并不要求整段数组已经排序。这个局部关系足以推出根是全局最小：沿任何点到根的路径，值只会不增。

插入先追加在最后，只有新点到根的路径可能破坏关系。只要它小于父亲就交换并上移，其余父子关系不变。删除根时，先用末尾元素填根并移除末尾；现在只可能在根向下破坏。每次与两个孩子中较小者比较，必要时交换，再继续向下。先选较小孩子，才能保证交换后留在上面的值也不大于另一个孩子。

using Release = std::pair<long long, int>;
class ReleaseMinHeap {
    std::vector<Release> data;
public:
    bool empty() const { return data.empty(); }
    Release top() const { return data.front(); } // requires !empty()
    void push(Release value) {
        data.push_back(value);
        int child = static_cast<int>(data.size()) - 1;
        while (child > 0) {
            int parent = (child - 1) / 2;
            if (!(data[child] < data[parent])) break;
            std::swap(data[child], data[parent]);
            child = parent;
        }
    }
    void pop() { // requires !empty()
        data.front() = data.back();
        data.pop_back();
        int parent = 0, n = static_cast<int>(data.size());
        while (2 * parent + 1 < n) {
            int child = 2 * parent + 1;
            if (child + 1 < n && data[child + 1] < data[child]) ++child;
            if (!(data[child] < data[parent])) break;
            std::swap(data[child], data[parent]);
            parent = child;
        }
    }
};

树高为 O(log(r+1))，因此上浮或下沉的堆序修复最坏只走这么多层，取根为 O(1)。但这份push还先调用vector的push_back：某次扩容会搬移已有的r项，使那一次完整push花到 O(r)；把一串追加共同计算，push_back为摊销常数，故完整push为摊销 O(log(r+1))。pop不扩容，为最坏 O(log(r+1))。全部n次房间更新的总代价仍为 O(n log(n+1))，不能把它误写成每次vector追加都有最坏常数保证。空堆不能取根或删除根；调用者先检查。索引运算和循环边界的合法性来自当前元素数，不来自vector容量，参见 Q000028 · vector的元素、大小和预留空间有什么区别。

Allocation allocate_manual(const std::vector<Interval>& ranges, EndpointPolicy policy) {
    auto ordered = indexed_ranges(ranges);
    std::sort(ordered.begin(), ordered.end(), by_start);
    Allocation result{0, std::vector<int>(ranges.size())};
    ReleaseMinHeap releases;
    for (const IndexedInterval& current : ordered) {
        int room;
        if (!releases.empty() && compatible(releases.top().first, current.range.start, policy)) {
            room = releases.top().second;
            releases.pop();
        } else room = ++result.rooms;
        result.room_for[current.id] = room;
        releases.push({current.range.end, room});
    }
    return result;
}

排序加n次堆操作使总时间为 O(n log n)，堆最多r≤n个房间。输出保存原id，因此排序并不改变最终房号数组的输入顺序。下面两版使用同一个分配算法，只替换堆操作的实现层。

Q000034 · class怎样守住一份结构的不变量

手写堆的class把存储数组放在private区域，只让public操作访问。class中未写访问标签前默认private，struct则默认public；本章类型表用struct公开成员，堆用class限制存储访问。调用者可以push、top、pop，却不能任意修改中间元素，使“父亲不大于孩子”在类外被破坏。这种封装把算法证明的边界变清楚：每个公开操作接收合法堆，并返回合法堆。

成员函数后面的 const，例如 bool empty() const，表示通过该对象执行这个函数时不修改它的非mutable成员；所以可从const对象调用。函数中的局部下标仍然能变化，它与对象的存储状态不同。std::swap(a,b) 交换两个值；堆在交换后移动下标，不会把一个已经改变位置的元素引用一直留着使用。

这里手写的 top() 返回Release值副本，直接读取其中字段不会借出内部元素。这个类只承担当前需要的堆，不是通用容器课程。它没有承诺任意删除、迭代器或自动检查所有误用；本章调用方式负责满足非空前置。只剩根时pop后数组为空，下滤循环不进入，也不会访问空数组的根。

标准设施替换了哪一层

std::priority_queue 把堆与存储封装成适配器。我们仍然按起点处理、决定何时开房并恢复原id；标准库承担动态优先级维护。

Allocation allocate_standard(const std::vector<Interval>& ranges, EndpointPolicy policy) {
    auto ordered = indexed_ranges(ranges);
    std::sort(ordered.begin(), ordered.end(), by_start);
    Allocation result{0, std::vector<int>(ranges.size())};
    std::priority_queue<Release, std::vector<Release>, std::greater<Release>> releases;
    for (const IndexedInterval& current : ordered) {
        int room;
        if (!releases.empty() && compatible(releases.top().first, current.range.start, policy)) {
            room = releases.top().second;
            releases.pop();
        } else room = ++result.rooms;
        result.room_for[current.id] = room;
        releases.push({current.range.end, room});
    }
    return result;
}

Q000035 · priority_queue的比较方向、top与pop怎样配合

模板参数 std::priority_queue<T, std::vector<T>, std::greater<T>> 依次指定元素、底层存储和比较器。默认 std::less<T> 会让较大的值在top；换成 std::greater<T> 才让较小的值在top。若T为pair，字典序行为见 Q000033 · pair、auto和类型别名怎样表达一份状态。比较器必须符合 Q000031 · 排序比较器怎样表达顺序，而不制造错误 的严格弱序要求。

top() 返回堆顶的const引用，不能直接修改它；修改优先级可能破坏堆。pop() 只删除，不返回被删值。需要保留房号或结束时刻时，先 auto item = heap.top(); 复制，再pop，然后按新时刻push。不要把引用绑定到top后pop，再读取那个引用。

适配器只开放堆顶、增删、size和empty等操作，没有vector的capacity接口，也不提供随意遍历、按值删除或任意前驱查询。它非常适合此处反复取最小值，却不会自动满足后来固定k资源的问题。C++17接口见WG21 N4659，priority_queue的 [priority.queue]。

若希望自己持有vector，而只让标准库维护堆序，可以使用堆算法：

Allocation allocate_heap_algorithms(const std::vector<Interval>& ranges, EndpointPolicy policy) {
    auto ordered = indexed_ranges(ranges);
    std::sort(ordered.begin(), ordered.end(), by_start);
    Allocation result{0, std::vector<int>(ranges.size())};
    std::vector<Release> releases;
    const std::greater<Release> later;
    for (const IndexedInterval& current : ordered) {
        int room;
        if (!releases.empty() && compatible(releases.front().first, current.range.start, policy)) {
            room = releases.front().second;
            std::pop_heap(releases.begin(), releases.end(), later);
            releases.pop_back();
        } else room = ++result.rooms;
        result.room_for[current.id] = room;
        releases.push_back({current.range.end, room});
        std::push_heap(releases.begin(), releases.end(), later);
    }
    return result;
}

Q000036 · 堆算法为何还需要push_back和pop_back

std::push_heap(first,last,comp) 假定 [first,last-1) 已是合法堆，把最后一个新元素加入堆。它不替vector追加元素，因此先push_back，再对扩大后的范围调用push_heap。

std::pop_heap(first,last,comp) 假定范围非空且为堆，把根移到 last-1，并修复 [first,last-1)。它不缩小vector；要真正删除，再调用pop_back。若需要根的值，应在删除前保存。前后操作的比较器必须一致，不能构造小堆后按默认大堆比较弹出。

std::make_heap 可把已有整段元素一次建堆，比较次数为线性；从空堆逐个加入的上界则为 O(n log n)。此处分配随扫描逐个产生新状态，push_heap/pop_heap恰好对应这种更新。它们是标准库实现的堆操作，和前面的手写上浮/下滤有清楚分工。规则见N4659的 [alg.heap.operations]。

只保留一部分：最早结束的请求先选

现在资源只有一个，任务也可以不接。Movie Festival要求看尽可能多场完整电影，时间长短不带额外收益。

“最早开始”可能先拿一场跨越整天的电影，挡住几场短片；“最短时长”可能选一段跨在两场可连续观看的电影之间，也挡住两场。局部看起来节省时间，不等于给后续留下的可行集合更好。

按结束时刻升序考虑：若当前电影与已选最后一场兼容就选，否则跳过。第一次选最早结束者，后面不断重复这个决定。

交换证明真正需要保住什么

取任意一个最多场次的最优计划，设它的第一场为o，贪心的第一场为g。因为g全局结束最早，end(g) <= end(o)。把最优计划第一场换成g，其余场次仍可接在g后面：它们原来接在o后面，而g没有更晚结束。数量没少、可行性没坏，所以至少存在一个最优计划以g开头。

固定g后，剩下的候选正是能接在g后面的电影，问题形式没有改变。对余下部分重复同样交换，最终得到贪心计划同样达到最优数量。证明保住的是“数量相同且结束不更晚”，没有说g的时长最短或收益最高。

std::vector<int> choose_activities(const std::vector<Interval>& ranges, EndpointPolicy policy) {
    auto ordered = indexed_ranges(ranges);
    std::sort(ordered.begin(), ordered.end(), by_end);
    std::vector<int> chosen;
    long long last_end = 0; // read only after chosen becomes nonempty
    for (const IndexedInterval& current : ordered) {
        if (chosen.empty() || compatible(last_end, current.range.start, policy)) {
            chosen.push_back(current.id);
            last_end = current.range.end;
        }
    }
    return chosen;
}

时间 O(n log n)，选择数组最多n项。初始 last_end=0 不是断言第一个请求从0以后开始；它只在chosen非空后才读取，首个请求由短路条件直接接受。返回的是实际计划；最少删除数直接是 n-chosen.size()，不必重造一种“删除算法”。如果原题已经按结束时间排序，如Codility MaxNonoverlappingSegments，扫描本身只需 O(n)。

接触政策仍必须一致。电影或LC435按 end<=next.start 接续；闭区间互斥选择用严格 <。下面的点命中问题使用闭区间，不能把两种数量直接混算。

用点命中每一段，为什么也看右端

LC452让一支竖直箭命中所有包含其横坐标的气球区间。要选的是点，要覆盖的是每条闭区间；这既不是合并，也不是保留最多任务。

取最早结束的尚未命中区间 [s,e]，在e放一个点。为什么可以把这一点永久定下来？任何完整方案都必须在 [s,e] 内放某点p。考虑所有尚未处理区间：它们的右端都不小于e。若某条原来包含p，那么其左端不大于p≤e，右端又不小于e，因此它仍包含e。把p移到e，不会丢失它原来负责的剩余区间，还可能命中更多。

删去被e命中的区间，继续处理。排序后只要当前左端大于最后选点，才需要新点；若等于，闭端点仍算命中。

std::vector<long long> stabbing_points(std::vector<Interval> ranges) {
    std::sort(ranges.begin(), ranges.end(), [](const Interval& a, const Interval& b) {
        return a.end < b.end;
    });
    std::vector<long long> points;
    for (const Interval& current : ranges)
        if (points.empty() || points.back() < current.start) points.push_back(current.end);
    return points;
}

总时间 O(n log n)，输出即命中见证。每次迫使我们新选一点的那条区间，与此前这些“迫使新点”的区间两两无公共点；一个点不可能同时命中其中两条，所以它们的数量给出下界。算法恰好使用同样多的点，因而达到最少。

这也说明：采用相同闭区间相交政策时，最大两两不相交区间数等于最少命中点数。但 [1,2] 与 [2,3] 在电影式接续里可以选两场，在闭区间命中里一点2就够；政策不同，不能把两个答案强行认作相同。

用片段覆盖整段目标，要改成最远推进

Video Stitching允许把片段剪开，要求覆盖 [0,T] 的全部时间。这里选的是区间，必须覆盖的是整个连续目标。假设已有连续覆盖 [0,covered]，所有起点不大于covered的片段都可以与它接上；下一次应从这些候选中选右端最大的片段。

例如目标 [0,5]，片段 [0,1]、[0,4]、[1,2]、[2,3]、[3,5]。按最早结束选会先耗费 [0,1]，接着仍要继续补；直接选 [0,4] 再接 [3,5] 只用两段。“早点结束给后面让路”在这里没有价值，因为重叠不构成冲突，我们要的是更远的覆盖。

一轮内全部看完候选，才提交选择

设本轮能接上的最远右端为f。任何完成目标的方案，其下一段也必须从当前连续覆盖接出去，不然covered右侧会留下空隙。若它下一段只到r≤f，用我们选的片段替换，不会缩短本轮能覆盖到的位置。原方案后续每段若有助于继续向右，都仍可从更远前沿接上；已经被f覆盖的片段可以直接省掉。因此存在一个不比最优方案更差的方案，先走到f。

按起点排序后，用指针读完 start<=covered 的全部候选，并取其中最大end。不能读到第一条可接片段就立即提交，因为同一轮后面可能有更远的。提交后，所有本轮候选都已被f支配，不必回头。若f没有严格大于covered，就没有任何片段能跨过当前边界，目标无解。单点片段不能推进连续覆盖。

CoverResult minimum_cover(const std::vector<Interval>& ranges, long long target) {
    auto ordered = indexed_ranges(ranges);
    std::sort(ordered.begin(), ordered.end(), by_start);
    std::vector<int> chosen;
    long long covered = 0;
    int next = 0, n = static_cast<int>(ordered.size());
    while (covered < target) {
        long long farthest = covered;
        int selected = -1;
        while (next < n && ordered[next].range.start <= covered) {
            if (ordered[next].range.end > farthest) {
                farthest = ordered[next].range.end;
                selected = ordered[next].id;
            }
            ++next;
        }
        if (selected == -1) return {false, {}};
        chosen.push_back(selected);
        covered = farthest;
    }
    return {true, chosen};
}

函数返回最少片段的一组原id；失败时 possible=false 且不返回一份看似完整的局部方案。排序 O(n log n)，扫描 O(n)。它只承诺 T>0；若目标本身长度为0，应先按具体任务决定是否需要一个命中点或根本不需片段，不能沿用正长度问题的无解分支。

LC1326可把第i个水龙头转成 [i-ranges[i],i+ranges[i]]，再用同一机制覆盖 [0,n]。其端点为有界整数时，可先对每个左端保存最远右端，再按坐标推进，得到线性于坐标域的实现；这只是同一个最远推进的另一种候选整理方式。一般坐标仍适合排序。草带喷头等几何任务还需要先证明圆的哪一段真正覆盖整条带宽，不能只把圆的左右极点当作有效区间。

固定k个资源，为什么不能继续只取最早释放

Movie Festival II有k个人，要最大化总观看场数。与最少房间问题相比，所有电影不必被接受，人数却不能无限增加。

仍按电影结束时间处理。每个已使用的人只记录其最后一场的结束时刻。当前电影开始于s：在所有能接它的人中，找释放最晚的人，把他的释放时刻替换为当前结束。这样保留更早空闲的人，给后面可能开始更早、却结束更晚的电影。

以k=2和电影 (1,2)、(1,5)、(6,7)、(3,8) 为例。先接前两场后，两人分别在2和5空闲。接 (6,7) 时，两人都可用；若消费释放2的人，剩下的释放5者无法接 (3,8)。若先消费释放5者，释放2者仍能接 (3,8)，四场全部保留。结束顺序不代表开始顺序，不能把“后处理的电影”误认为“一定更晚开始”。

若没有兼容的人，但已使用人数还小于k，可以启用一个新的人；否则跳过当前电影。只存已经使用者，便不需要虚构负无穷结束时刻来代表尚未使用的人。

把整个后续安排换过去，才完成多资源证明

我们逐场维护这样一个事实：存在某个全局最多场次的计划，它在已经处理的电影上，与贪心的接受、拒绝和人员分配一致。开始时前缀为空，显然可以找到一个最优计划。

设当前电影为j，开始s、结束e。所有尚未处理电影的结束都不早于e，而半开电影有s<e。因此在任何一个人的后续安排里，j之前都不可能再塞进一场尚未处理的电影：那场若先结束才能接j，其结束应不晚于s<e，与处理顺序矛盾。若使用闭占用政策，即使允许s=e的单日任务，前驱也必须结束严格早于s，仍然严格早于e，同一论证继续成立。

有兼容旧人员时。 贪心选其中释放最晚者r，记释放时刻为 t_r。考虑与当前前缀一致的一个最优后续计划：

  • 若它没有选j，看r上第一场未来电影x。如果r后面为空，直接加入j就能增加总场数，与最优矛盾；因此必有x。将x替换为j：j能接在 t_r 后面，且e不晚于x的结束，所以x后面的整条安排仍能接上。总场数不变。
  • 若它已将j分给r，就不用改。
  • 若它把j分给另一个旧人员q，j必是q的第一场未来电影。q也兼容j，而r选的是最晚兼容者，所以 t_q<=t_r。将q从j开始的整条未来安排，与r的整条未来安排互换。j可以接在r后面；r原来的第一场若存在，本来就与 t_r 兼容：半开时起点 >=t_r，闭占用时起点 >t_r。因为 t_q<=t_r，同一兼容关系在q上仍然成立。两条链内部次序都没有改，所有电影和场数都保留。
  • 若最优计划把j分给一个尚未使用的人，也可交换两人的未来安排：尚未使用者没有前缀限制，能接r原来的尾链，j则能接r。

没有兼容旧人员，但还能启用新人员时。 把新人员记为r，视为没有前缀约束。若最优计划没选j，用同样的“替换r的首场未来电影”操作；若已选j，它不可能接在任何不兼容的旧人员之后，因此只能分给一个尚未使用者，将人员名字交换即可。

没有兼容人员且k人已全部使用时。 在任何与前缀一致的计划中，j都不能成为某人的第一场未来电影；前面又证明不能先加别的未来电影再接j，所以只能拒绝它。

三种情形都能把贪心当前决策纳入某个同样好的全局最优计划，归纳便贯穿全部电影。这个证明用到了同质资源、半开活动的正时长或闭活动的严格接续、完整接受和数量目标。收益不同、人员有资格限制、在线到达后不能重排，都不能直接引用它。

std::vector<int> choose_k_resources(const std::vector<Interval>& ranges, int k, EndpointPolicy policy) {
    auto ordered = indexed_ranges(ranges);
    std::sort(ordered.begin(), ordered.end(), by_end);
    std::multiset<long long> releases;
    std::vector<int> chosen;
    for (const IndexedInterval& current : ordered) {
        auto after = policy == EndpointPolicy::HalfOpen
            ? releases.upper_bound(current.range.start) : releases.lower_bound(current.range.start);
        if (after != releases.begin()) {
            --after;
            releases.erase(after);
        } else if (static_cast<int>(releases.size()) >= k) continue;
        releases.insert(current.range.end);
        chosen.push_back(current.id);
    }
    return chosen;
}

这里需要“最大兼容前驱”，所以使用有序多重集合。总时间为排序加n次有序查询与更新，即 O(n log(n+1)+n log(k+1))，存储 O(n+k) 包括排序副本和选择结果。用 k+1 写法也涵盖k=0：此时不选任何电影，不会尝试取得空集合前驱。

Q000037 · lower_bound与upper_bound怎样给出查询边界

在默认升序范围中，lower_bound(first,last,x) 返回第一个不小于x的位置，upper_bound(first,last,x) 返回第一个严格大于x的位置。前者之前全部 <x，后者之前全部 <=x。范围中可以没有x，也可以有多个x；找不到这样的后缀元素时返回last。空范围也返回last，不能解引用。

若要最后一个 <x 或 <=x 的元素，分别从上述边界取前驱；只有边界不等于begin时才能先减一。若只要边界之前的数量，vector中直接与begin相减即可；数量可以为0或整个范围长度，不必先取得一个元素。

通用二分的真正前提是范围对当前比较表达式已分区；整体升序是本章足以保证它的条件。自定义比较器下，lower_bound调用形如 comp(element,value)，upper_bound调用形如 comp(value,element)，方向不能随意换。C++17保证对数次比较；vector的随机访问又使移动保持对数，而双向迭代器不自动拥有这个移动复杂度。成员 available.upper_bound(x) 可利用关联容器的有序结构以对数复杂度定位，不应改成通用 std::upper_bound(available.begin(),available.end(),x) 后仍声称总步数对数。范围和差值见 Q000030 · 迭代器为何把范围写成左闭右开。

Q000038 · multiset怎样保留重复状态并只删除一个

两个不同的人可能同时在5空闲，所以必须保存两个5。std::set 只留一个等价键，std::multiset 允许多个。“等价”按比较器定义：a不严格小于b，b也不严格小于a；本章默认整数比较下，它就是数值相等。边界和前驱按 Q000037 · lower_bound与upper_bound怎样给出查询边界 取得，闭占用与半开接续对应不同的边界。

找到一个释放时刻后，用 erase(it) 删除这一个副本；erase(value) 会删除所有等价键，可能把其他人的状态也删掉。插入新的结束时刻再交给容器重新排序，不能原地修改迭代器指向的键。关联容器插入不使既有迭代器失效，删除只使被删元素的迭代器和引用失效；删除后的it不能继续读取。

插入和成员边界查询为 O(log k)；按迭代器删除单个元素为摊销常数。容器的存储实现由标准库负责，我们手写的是资源选择与更新逻辑，不是在此实现平衡树。重复键与成员接口见N4659的 [associative.reqmts]、[multiset.overview]。

数量换成收益：为什么必须保存多个最优前缀

现在每个项目有收益。两段连续短项目各收益1，一段同时覆盖它们的长项目收益3，最早结束的数量贪心只得到2。若改成先选最高收益，也会被“一段收益3长项目，对上两段各收益2的短项目”击败。固定一个局部排名，无法判断今天放弃一点收益能换来多少后续机会。

Projects问最大总收益，按闭日程只可在结束日严格早于下一开始日时相接；LC1235允许结束即开始。我们在同一个前缀模型里保留这项差异。

按结束时刻排序，给前i个项目定义 dp[i]：只使用这i个项目，能取得的最大收益。dp[0]=0，表示没有项目可选。设当前是排序后的第i个项目，收益w，开始s；在之前i−1个项目中，与它兼容者恰好构成一个前缀，长度记为p。

为什么只剩取与不取两类，而不是遗漏其他安排

任何最优计划都要么不选当前项目，要么选它。

不选时，全部选择来自前i−1个，最好值就是 dp[i-1]。选它时，所有先前项目的结束都必须与s兼容；结束已排序，因此合法候选恰好是前p个。它们之间的最佳选择为 dp[p]，加上当前收益得到 w+dp[p]。反过来，前p个的最优计划确实能与当前项目拼接，所以这个值不仅是上界，也真实可达到。

于是 dp[i]=max(dp[i-1],w+dp[p])。从小到大计算，所需前缀都已算好；不再枚举指数多的完整子集。难点是证明“剩下的合法集合恰好是一个前缀”，而非仅把取/不取写成一个max。

看一组闭日程：A为 [1,2] 收益4，B为 [2,4] 收益7，C为 [3,5] 收益5，D为 [6,7] 收益3。它们已经按结束日排序：

当前项目 兼容前缀长度p 不取当前项目 取当前项目 最佳前缀收益
A 0 0 4+0 4
B 0 4 7+0 7
C 1 7 5+4 9
D 3 9 3+9 12

B不能接A，因为两者都占用第2天；C能接A，D再接上A和C，得到12。若同样四对数字改为允许结束即开始，B的兼容前缀变为1，A接B就有11，再接D得到14。只改接触政策，前驱与最优方案都可能改变，外层递推却不用改。

前驱长度，既可以手写边界，也可以用标准算法

若每次从当前项目往左找兼容者，单次最坏 O(n)，总共 O(n²)。结束数组有序，可以用边界搜索把单次压成 O(log n)。

不能因为结束时刻递增，就用一个只前进的指针依次生成全部p。闭区间 (1,3)、(5,6)、(2,7) 已按结束排序，它们的兼容前缀长度却为 0、1、0：第三项开始得更早，前驱又退回去了。有序的是被查询的结束数组，不是查询阈值start；每项单独做边界查询没有这个错误假设。

这里直接返回兼容前缀长度p，范围为 [0,count]，不使用“找不到返回−1”的索引。维护半开未决范围 [lo,hi)：lo之前都兼容，hi及以后都不兼容；mid兼容时把lo推到mid+1，否则把hi缩到mid。每次严格缩短，结束时lo=hi正好是第一个不兼容位置，也是兼容项数。

int compatible_prefix_manual(const std::vector<long long>& ends, int count,
                             long long start, EndpointPolicy policy) {
    int left = 0, right = count;
    while (left < right) {
        int middle = left + (right - left) / 2;
        if (compatible(ends[middle], start, policy)) left = middle + 1;
        else right = middle;
    }
    return left;
}

端点政策决定判定：半开接续把 end<=start 放入兼容前缀，闭占用只允许 end<start。这种差别在标准函数中体现为upper_bound与lower_bound：

int compatible_prefix_standard(const std::vector<long long>& ends, int count,
                               long long start, EndpointPolicy policy) {
    auto after = policy == EndpointPolicy::HalfOpen
        ? std::upper_bound(ends.begin(), ends.begin() + count, start)
        : std::lower_bound(ends.begin(), ends.begin() + count, start);
    return static_cast<int>(after - ends.begin());
}

这两种边界的设施合同已在 Q000037 · lower_bound与upper_bound怎样给出查询边界 主讲。这里新增的算法事实是：闭日程把lower_bound之前的项作为前驱前缀，半开接续把upper_bound之前的项作为前驱前缀；范围只限当前项目之前，不把当前或未来项目混进自身前驱。

表里存值，沿决定恢复一份计划

两种前驱子程序接入同一份DP：

正文的dp在源码中名为 best；前i个项目对应 best[i]，当前项目本身位于 ordered[i-1]。predecessor[i] 保存兼容前缀长度，take[i] 记录这一格是否严格通过选当前项目得到更大收益；平局保留跳过。

Plan weighted_core(const std::vector<Job>& jobs, EndpointPolicy policy, bool library_search) {
    struct IndexedJob { Job job; int id; };
    std::vector<IndexedJob> ordered;
    for (int i = 0; i < static_cast<int>(jobs.size()); ++i) ordered.push_back({jobs[i], i});
    std::sort(ordered.begin(), ordered.end(), [](const IndexedJob& a, const IndexedJob& b) {
        if (a.job.end != b.job.end) return a.job.end < b.job.end;
        if (a.job.start != b.job.start) return a.job.start < b.job.start;
        return a.id < b.id;
    });
    const int n = static_cast<int>(ordered.size());
    std::vector<long long> ends;
    for (const IndexedJob& current : ordered) ends.push_back(current.job.end);
    std::vector<long long> best(n + 1, 0);
    std::vector<int> predecessor(n + 1, 0), take(n + 1, 0);
    for (int i = 1; i <= n; ++i) {
        const Job& current = ordered[i - 1].job;
        const int p = library_search
            ? compatible_prefix_standard(ends, i - 1, current.start, policy)
            : compatible_prefix_manual(ends, i - 1, current.start, policy);
        predecessor[i] = p;
        const long long with_current = best[p] + current.reward;
        best[i] = best[i - 1];
        if (with_current > best[i]) {
            best[i] = with_current;
            take[i] = 1;
        }
    }
    std::vector<int> chosen;
    for (int i = n; i > 0; ) {
        if (take[i]) {
            chosen.push_back(ordered[i - 1].id);
            i = predecessor[i];
        } else --i;
    }
    std::reverse(chosen.begin(), chosen.end());
    return {best[n], chosen};
}
Plan weighted_manual(const std::vector<Job>& jobs, EndpointPolicy policy) {
    return weighted_core(jobs, policy, false);
}
Plan weighted_standard(const std::vector<Job>& jobs, EndpointPolicy policy) {
    return weighted_core(jobs, policy, true);
}

weighted_manual 与 weighted_standard 是同一算法的两种前驱实现，不是两种动态规划，也没有标准库替我们推导整题。布尔选择只切换查找子程序；取/不取的状态含义、转移与回溯完全共享。

恢复从i=n开始：若当前dp值来自跳过，就令i减一；若选择当前项目能得到当前最优值，就把其原id记入计划，再跳到它的兼容前缀p。每次i都变小，最终到0。回溯首先遇到晚项目，所以最后反转结果，得到时间顺序。平局时可以固定偏向跳过或选择，只要得到同样收益的合法计划；题目并没有唯一的下标序列。

排序和全部前驱查询为 O(n log n)，DP和回溯为 O(n)，存储 O(n)。收益累积需要 Q000032 · 先确定运算类型，再计算长度和总量 的64位上界；0收益项目可以被跳过，最优值仍正确。若增加“最多选k个项目”，状态还要表达已经使用多少名额；这里的一维dp不能直接回答。

再限制总项数：k个名额不是k个资源

LC1751要求一个人完整参加活动，最多选k项，最大化总收益；结束日仍然占用。这与Movie Festival II的k个同时可用资源完全不同：名额限制的是整个方案的总项数，不会在活动结束时恢复。三个互不相交活动用一个人就都能参加，但预算k=2时最多只能挑两个。

上面的前驱关系继续适用，新增的只有预算状态。定义 value[c][i]：在前i个项目中，最多取c项的最大收益。无项目或预算为0时答案都为0。对当前项目，仍按是否选它分类：

  • 不选：value[c][i-1]，预算不变。
  • 选：获得当前w，余下只能从兼容前缀p里最多取c−1项，得到 w+value[c-1][p]。

取两者较大就是完整转移。这里是“最多”，不必选满k；一项高收益活动可能比好几项互相冲突的活动更好，0预算也不代表无解。

先预计算所有项目的前驱p，再让c从1递增，每层让i从1递增。当前层需要它左侧的值，以及上一预算层的任意前缀值。两条vector已经够用：previous[p] 保存上一预算层，current[i-1] 保存本层左侧；一层算完，交换两条vector的内容，继续下一层。每一层都从0列开始并覆盖其他各列，所以不必把旧数组逐格清零。

long long bounded_weighted(const std::vector<Job>& jobs, int max_jobs, EndpointPolicy policy) {
    std::vector<Job> ordered = jobs;
    std::sort(ordered.begin(), ordered.end(), [](const Job& a, const Job& b) {
        if (a.end != b.end) return a.end < b.end;
        return a.start < b.start;
    });
    const int n = static_cast<int>(ordered.size());
    std::vector<long long> ends;
    for (const Job& job : ordered) ends.push_back(job.end);
    std::vector<int> predecessor(n, 0);
    for (int i = 0; i < n; ++i)
        predecessor[i] = compatible_prefix_standard(ends, i, ordered[i].start, policy);
    std::vector<long long> previous(n + 1, 0), current(n + 1, 0);
    const int limit = std::min(max_jobs, n);
    for (int budget = 1; budget <= limit; ++budget) {
        current[0] = 0;
        for (int i = 1; i <= n; ++i)
            current[i] = std::max(current[i - 1], ordered[i - 1].reward + previous[predecessor[i - 1]]);
        previous.swap(current);
    }
    return previous[n];
}

为什么不能让选当前项目时也读取本预算层的p？因为那样没有支付这一个名额。两条兼容单日活动收益4和5，预算1应得到5；若用 w+current[p]，就会错误得到9。也不能只保留前缀i的相邻两行：p可以跳到很远的前缀，上一预算层的那些值仍然需要。预算外层的滚动安排，正好保留了这些依赖；完整二维表也能按合法依赖顺序计算，只是占更多空间。

时间为 O(n log n+nk)，滚动表与前驱等辅助存储为 O(n)。LC1751给出 1<=k<=n 且 nk<=10^6，所以n本身可到 10^6，不能错误假定它也只到200000。另一方面 k²<=nk<=10^6 推出k≤1000，单项收益≤ 10^6，最多取k项使答案≤ 10^9，原题int返回值在 Q000032 · 先确定运算类型，再计算长度和总量 的目标环境内可表示；核心依然用long long计算。这个滚动接口只返回收益，没有保留前面完整DP用于恢复方案的全部决定，因此不承诺返回一组下标。

反复问一个点：保留最短的仍有效候选

LC1851给很多查询点q，每次求包含q的原区间中，整数点数 end-start+1 最少者；没有则返回−1。注意要找原区间，不是并集中的最短段。合并会丢掉 [4,4] 这样的好答案。

每次把所有区间扫一遍，需要 O(nm)。所有查询预先给出时，可以先按点值升序处理，并带上查询原id。区间也按起点排序；查询点走到q，就把所有 start<=q 的区间加入候选。这样不必每次重新检查左端。

候选按 (整数长度,右端) 放入小堆。加入只保证左端已到达，右端还可能已过期。回答前不断删除 end<q 的堆顶，直到堆空或堆顶仍覆盖q。

为什么只清理堆顶，不清理整个堆

堆里可能埋着已经过期的长区间，但它排在当前堆顶后面，不可能提供更短答案。只要堆顶有效，它就是所有已加入区间中长度最小的有效候选；任何更短元素都应排到它前面，已被检查并删除或就是它自身。

一个区间右端小于当前q后，对所有后续不减的查询点也都会过期，所以删除是永久安全的。若不先排序查询，删除给较大点无效的区间后，再处理较小点就可能丢掉正确答案；“离线重排”正是这次状态简化成立的条件。

std::vector<long long> minimum_query_lengths(const std::vector<Interval>& ranges,
                                           const std::vector<long long>& queries) {
    auto ordered = indexed_ranges(ranges);
    std::sort(ordered.begin(), ordered.end(), by_start);
    std::vector<std::pair<long long, int>> points;
    for (int i = 0; i < static_cast<int>(queries.size()); ++i) points.push_back({queries[i], i});
    std::sort(points.begin(), points.end());
    using Candidate = std::pair<long long, long long>; // (integer length, right endpoint)
    std::priority_queue<Candidate, std::vector<Candidate>, std::greater<Candidate>> candidates;
    std::vector<long long> answer(queries.size(), -1);
    int next = 0, n = static_cast<int>(ordered.size());
    for (const auto& point : points) {
        while (next < n && ordered[next].range.start <= point.first) {
            const Interval& range = ordered[next++].range;
            candidates.push({range.end - range.start + 1, range.end});
        }
        while (!candidates.empty() && candidates.top().second < point.first) candidates.pop();
        if (!candidates.empty()) answer[point.second] = candidates.top().first;
    }
    return answer;
}

每个区间最多入堆一次、出堆一次，查询排序为 O(m log m)，总时间 O(n log n+m log m+(n+m)log n)，额外空间 O(n+m)。同一个查询值重复出现可以各自恢复到原位置，算法不要求查询互异。堆设施复用 Q000035 · priority_queue的比较方向、top与pop怎样配合；这里的新依据是候选进入、永久过期与目标最小值，并不是房间分配的最优性证明。
