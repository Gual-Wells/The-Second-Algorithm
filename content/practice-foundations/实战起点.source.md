# 实战起点：状态、范围与实现选择

同一个“找数”任务，可能需要找完整边界、匹配以前的状态，或只保留目前最好的几个候选。本章把问题条件、手写算法和C++已有设施接在一起：知道要维护什么，也知道用什么类型、范围和操作把它写出来。

本章代码采用C++17。完整源码为[实战起点.cpp](实战起点.cpp)。所有函数都保持原输入，除非接口另有说明；长度、长度加一和迭代器偏移必须可表示，申请的存储必须可用。涉及求和时，前缀、区间和、`prefix-target`与答案还须能由`long long`表示。代码不通过先溢出再补救来实现数学整数运算。

## 1. 找到等值范围：位置比“找到没有”包含更多信息

给非降数组`{1,2,2,2,5}`和目标2，返回`[1,4)`。这同时回答了首个位置、出现次数和插入位置。输入可空、可有重复；没有目标时两端相等，例如目标3得到`[4,4)`。下面先把读取代码所需的C++写法接到这个具体任务上。

<a id="q000001"></a>
### Q000001 · 函数如何接收输入、借用对象并返回结果

函数签名写成“返回类型、函数名、括号中的参数”，花括号里是执行体。`lower_manual`的输入包含`const std::vector<int>& a`与`int target`：后者接收一个整数值；前者通过引用借用调用方的整数数组，函数不必复制全部元素，`const`限制通过这个接口修改数组。`T&`允许修改原对象，`const T&`用于只读；这与写成`T`、获得自己的对象值不同。

`return`交出结果并结束本次调用。返回`std::vector<int>`时，调用方得到拥有元素的结果对象；返回一个局部vector是正常的值返回，不必为了避免复制改成局部引用。局部对象离开函数后被销毁，返回对它的引用会留下失效的借用。引用不自动拥有或延长外部对象的寿命。

代码前面的`#include`引入对应标准库声明；`std::`说明名字来自标准命名空间，例如`std::vector`。本章自己的函数放在`namespace practice`中，调用可写`practice::lower_manual(a,2)`；这只是名字的归属。`auto result = ...`让编译器根据右侧推导变量类型，不代表无类型；按值的`auto`会取得一个值，需要继续借用时应明确写引用。

<a id="q000002"></a>
### Q000002 · vector里哪些位置已经有元素

`std::vector<int>`是拥有整数元素的连续容器；尖括号内是元素类型。`std::vector<int> a{3,7}`含两个数3和7，而`std::vector<int> a(3,7)`含三个7。`std::vector<long long> p(n+1,0)`真正创建n+1个0，之后才可以给这些下标赋值。

`size()`是已有元素个数，`empty()`判断是否为0；合法下标从0到`size()-1`。`a[i]`不做范围检查，空vector不能用`a[0]`、`front()`或`back()`读取元素；`front/back`分别访问首尾。`push_back(value)`追加一个元素，`pop_back()`删除最后一个且不返回它；调用pop_back以前也必须确认容器非空。

`reserve(n)`只预留容量，size仍可能是0，不能因预留过就写`a[0]`。`resize(n)`才改变元素数；对int扩大的新位置会得到0，缩小则移除多余元素。追加通常摊还O(1)，一次扩容可能搬迁所有已有元素；需要输出k项时，可以创建k个位置再赋值，也可以逐次追加。

`for (int value : a)`依次取各元素的整数值；`for (int& value : a)`中的value是原元素的引用，给它赋值会修改数组。这里的冒号表示范围for，不是条件判断。

<a id="q000003"></a>
### Q000003 · 半开区间和迭代器怎样描述一段数据

`[left,right)`包含left、排除right，长度是`right-left`；两端相等就是空范围。长度n的数组整体是`[0,n)`，因此n可以表示边界，却不是可以读取的元素下标。

标准算法常接收迭代器：`a.begin()`指向第一个元素的位置，`a.end()`是最后一个元素之后的位置。空容器的二者相等。`*it`读取迭代器所指元素，只有它确实指向元素时才合法；end不能解引用。vector支持随机访问，所以`a.begin()+k`能直接定位边界，`it-a.begin()`得到偏移。相减的迭代器必须属于同一有效范围；这个差是有符号的差值类型，代码在确认范围有效后才转为下标。

`std::vector<int>(first,last)`从该范围复制元素。`std::copy(first,last,out)`则向out开始的已有位置赋值，目的位置必须足够；仅reserve的vector还没有这些位置。vector扩容会使旧迭代器、指针和引用失效，删除也可能改变后续位置；本章先完成需要的计算，不把旧句柄留到修改后再用。

<a id="q000004"></a>
### Q000004 · 为什么结果类型很宽，计算仍可能溢出

`int`用于本章的单个输入数，`long long`用于可能大得多的累计值；`using i64 = long long`只是给同一类型起一个简短别名。`std::size_t`是容器长度使用的无符号类型，`std::ptrdiff_t`是迭代器差常用的有符号类型，它们需要`<cstddef>`。

表达式的计算类型由参与运算的操作数决定。`long long result = x*y`不能阻止两个int先乘溢出；需要先把一个操作数扩宽，例如`1LL*x*y`。本章`p[i]+a[i]`左侧已经是i64，累加从这一步就在宽类型中进行；这仍以结果可表示为前提，并不获得任意精度。

无符号长度也会改变边界写法。空数组的`size()-1`会回绕成很大的值，因此手写二分直接使用右边界n，倒序堆循环先检查计数大于0再减一。若参数可能是负数，应先判断，再通过`static_cast<std::size_t>(k)`明确转换；强制转换本身不是合法性检查。代码中的`static_cast<std::ptrdiff_t>(k)`同样依赖k是合法可表示的范围偏移。

<a id="q000005"></a>
### Q000005 · 手写边界查找怎样排除候选并保证终止

首个`>=target`的位置叫左边界。维护`[left,right)`：left之前都小于目标，right及其之后都不小于目标；初始`left=0,right=n`，两侧已排除部分均为空。中点若小于目标，它和左侧都可删去，令`left=mid+1`；否则中点仍可能是答案，令`right=mid`。

循环只在`left<right`时执行，此时中点一定能读取。两个分支都会缩小候选范围，结束时left和right重合。全数组都小于目标时返回n，不读取`a[n]`。首个`>target`的右边界沿用同一依据，只把判定改为`<=target`。不要通过查`target+1`来替代它，目标已经是int最大值时会溢出。

一次返回两个位置，用struct把公开字段组合成`Positions`。`return {left,right}`按字段顺序构造这个结果，调用方通过`result.first`、`result.last`读取。

{{boundary-result}}

{{boundary-manual}}

两次查找仍为O(log n)，额外空间O(1)。返回`Positions{first,last}`后，`last-first`就是出现次数；只有`first<last`才存在首末命中位置，最后命中是`last-1`。这一前提保护了空结果，不能无条件减一。

<a id="q000006"></a>
### Q000006 · 标准二分返回什么，怎样对应题目答案

`<algorithm>`中的`lower_bound(first,last,x)`返回首个不小于x的迭代器，`upper_bound`返回首个大于x的迭代器；没有候选就返回last。只问存在可用`binary_search`返回bool；需要两条边界可用`equal_range`，其结果是一对迭代器，字段为`first/second`。库已经负责边界循环，题目所需的次数、下标或不存在政策仍由调用方转换。

{{boundary-standard}}

例如同一输入可分别调用`equal_positions_manual`与`equal_positions_standard`，得到同一`[first,last)`。它们属于同一有序边界方法的不同实现；标准接口承诺结果和复杂度，不要求内部逐行复制手写循环。

本题输入按数值非降，保证每次比较能把范围分成两部分。若改成记录字段或降序，排序与查找须采用相应一致关系；比较器在[[Q000015]]主讲。vector上的二分为O(log n)；非随机访问迭代器的移动成本不能只凭比较次数是对数就忽略。

## 2. 保留边界摘要，再匹配以前的状态

静态查询已经给出左右端点；目标和问题却要自己找所有可能端点。二者都使用前缀，但维护的信息和目标不同。

<a id="q000007"></a>
### Q000007 · 前缀状态怎样回答给定区间

令`p[i]`是前i项之和，`p[0]=0`，则`[left,right)`的和为`p[right]-p[left]`。`a={2,-1,3}`得到`p={0,2,1,4}`，查询`[1,3)`得到`4-2=2`。负数不破坏这个恒等式；这里不需要数组有序或和单调。

{{prefix-manual}}

{{range-query}}

预处理O(n)，每次查询O(1)，存储O(n)。查询空区间会得到0。原题若给1-based闭区间`[a,b]`，应传入这里的`[a-1,b)`；转换发生在接口边界，不改变前缀定义。函数要求合法区间与有效前缀数组，不承诺对任意越界参数返回某个值。

<a id="q000008"></a>
### Q000008 · partial_sum为什么需要先扩宽输入

`<numeric>`提供`partial_sum`计算逐项前缀，但其内部累计对象的类型取**输入迭代器的值类型**。直接把vector<int>交给它，即使输出是vector<long long>，中间累计仍可能先在int中溢出。例如两个2,000,000,000的前缀已超出常见32位int范围。

下面先将元素复制到i64存储，再对这段宽类型输入做原地partial_sum，保留最前面的空前缀0。赋值本身允许int到long long扩宽；算法支持输出起点与输入起点相同。

{{prefix-standard}}

空输入时只保留一个0，参与copy和partial_sum的范围都是空的。它和[[Q000007]]有相同结果及O(n)量级，库版本多一遍复制；选择它是为了使用已存在的前缀操作，并非声称一定更快。普通总和可用`accumulate(begin,end,0LL)`；其中初值参与决定累计类型，`0`与`0LL`不能随意互换。

<a id="q000009"></a>
### Q000009 · 怎样用unordered_map给状态配上数据

`std::unordered_map<Key,Value>`是按键查值的标准哈希表，头文件是`<unordered_map>`。`unordered_map<i64,i64>`可把一个前缀值映射到出现次数。小而确定的值域可以用[[Q000002]]中的数组位置计数；可能很大、可负的前缀值则不适合直接拿数值作下标。

几种操作各有目的：`table.find(key)`只查询，未找到返回`table.end()`；`table[key]`在缺失时插入默认构造的映射值，本章整数映射值初始为0，因此`++table[key]`适合统计。只想知道存在性时不要用`[]`，否则查询也改变状态。`table.emplace(key,value)`尝试插入，在键已存在时不覆盖原值；`table[key]=value`则表达覆盖或新增。

find返回迭代器，`auto it = ...`让编译器推导它的类型。`it->second`读取映射值，`it->first`是键；箭头用于通过迭代器访问其所指的键值对象。必须先确认`it!=table.end()`。下面的代码读完it以后才插入，不跨越可能发生重哈希的插入长期保留这个迭代器。

哈希相同不代表键相同，容器仍按相等关系识别键；这不是允许将不同前缀混为一类。每次操作通常期望O(1)，最坏可为O(n)，全章会据此区分期望线性与最坏界。这里使用标准表，没有手写一个具有完整泛型、扩容和异常合同的哈希容器。

<a id="q000010"></a>
### Q000010 · 目标和计数为什么先查询、后记录

任务改为统计和为target的**非空连续片段**，允许正数、零和负数。最直接的手写方法是固定左端，逐步延长右端并维护当前和；每对端点只检查一次，O(n²)、额外空间O(1)。

{{exact-count-enumeration}}

更快的方法把`p[right]-p[left]=target`改写为`p[left]=p[right]-target`。对每个当前右端，查询此前出现过多少个对应状态；重数正是这些左端的数量。不必再枚举每个左端。

{{exact-count-hash}}

`frequency[0]=1`记录位置0的空前缀，使从第0个元素开始的非空段也能找到。**先查后记**保证只匹配更早位置；反过来会在target=0时把当前前缀和自己组成空段。`{0,0}`有3个非空零和段，也说明状态不能只记“是否出现”。

哈希法期望O(n)、空间O(n)，最坏时间O(n²)。枚举版适合小输入和独立对照；像CSES Subarray Sums II的大规模输入需要高效方法。这里比较的是两种算法，标准哈希表只帮助维护第二种算法的字典，并没有一个标准库函数直接完成整题。不能因为程序里出现unordered_map就省掉前缀关系的推导。

<a id="q000011"></a>
### Q000011 · 同一前缀关系为什么要保存频次、最早或最近位置

把目标从数量改为最长长度，匹配的键不变，但不能继续只存频次。固定右端right，`right-left`在left最小时最大，因此同一状态保留最早位置，用[[Q000009]]的emplace避免覆盖。求最短则保留最近位置，每轮查询后覆盖。

更新最长值时，`std::max(answer,length)`选择较大者；这个两参数模板要求两项推导为同一类型，本例都是size_t。它返回对其中一个参数的只读引用，这里立即赋给answer，不保存这个借用。不能未经类型判断就把有符号0与任意无符号长度混在同一次模板推导里。

{{exact-lengths}}

两个函数以0表示没有非空解，合法段长度一定大于0，因此不会混淆。它们都期望O(n)时间、O(n)空间，哈希最坏时间另计；保持[[Q000010]]的查询顺序。此时无需为了题面换了“最长/最短”就再创造一套外层窗口；真正改变的是历史信息的含义。

## 3. 只保留最小k项：手写结构、库适配器与另一种算法

本节统一任务：输入n个int，**升序返回最小k项，重复按重数保留，原输入不变**。`{4,1,1,-2}`、k=3得到`{-2,1,1}`。k=0返回空，k>n也按本接口返回空；这不区分“合法空结果”和“非法k”，需要区分时应重新设计返回合同。若题目要求原下标或稳定选择同值记录，那是额外目标。

<a id="q000012"></a>
### Q000012 · 数组怎样成为可插入、可取出的堆

大根堆把最大元素放在根，但不把整个数组排好序。使用0-based数组时，位置i的孩子为`2*i+1`和`2*i+2`；非根的父亲为`(i-1)/2`。维护父值不小于孩子值，便能沿父子关系推出根是全体最大，重复值也允许。

新增元素先放末尾，再与父亲比较、必要时交换，向上修复。删除根时，用末项补根、移除末项，再与较大的孩子比较并向下修复；若只比较其中一个孩子，可能让另一个更大孩子继续违反堆关系。两个修复只走一条树高为O(log n)的路径。

已有一组元素时，可从最后一个非叶节点向前下滤。叶子本身已经是堆，下层修复好后才处理上层；各高度节点数不同，总建堆成本O(n)，不能简单用n乘每个节点的最坏高度。代码的倒序写法也避免无符号计数减到负数，见[[Q000004]]。

下面是实际手写结构：`class`把数据和操作组织起来，默认成员私有，`public:`后是调用方可用的接口。`data_`是每个堆对象独立拥有的vector；构造函数与类同名、没有返回类型，冒号后的`data_(first,last)`在执行函数体前初始化成员。`=default`让空构造使用成员的默认行为；函数末尾的`const`表示这个成员函数不修改对象。

{{max-heap-manual}}

`top/pop/replace_top`要求非空；调用者先满足这个前提，不执行空堆访问来猜结果。这里int只按数值比较，手写的是堆算法而非vector内存管理。动态push涉及的vector容量成本遵循[[Q000002]]，不能把堆修复的对数步数解释成每次扩容也只搬对数个元素。

<a id="q000013"></a>
### Q000013 · 怎样用大小为k的堆保留最小k项

先用前k项建一个大根堆。此后若新值不小于堆顶，现有k项已经都不比它大，它可以舍弃；若新值更小，就替换堆顶并恢复堆。每处理一个元素，堆都保留已读部分的最小k项，根是其中最大的、最先可以被替换的候选。

{{topk-manual}}

等值时跳过新项不会改变结果的重数：堆中始终有k个候选，只是没有承诺保留哪个同值下标。为了升序输出，每次取出的最大值从答案末尾往前填；不能把尚未排序的堆数组直接作为升序结果。

建堆O(k)，扫描O((n-k)log(k+1))，输出排序O(klog(k+1))，额外堆空间O(k)，返回值占O(k)。k=0提前返回，公式用k+1避免把边界写成log 0。这个任务所需的删除只发生在根，不需要支持任意位置删除或改键。

<a id="q000014"></a>
### Q000014 · priority_queue和标准堆算法各管理什么

`<queue>`中的`std::priority_queue<int>`已经管理底层容器与堆性质，默认最大值先出。`top()`读堆顶、`push(value)`插入、`pop()`删除但不返回、`empty/size`查询状态。top返回的借用不应留到pop以后使用；本实现先把整数复制进答案，再删除。按范围构造会将输入放入自己的容器并建堆。

{{topk-priority-queue}}

它和[[Q000013]]使用同一候选策略、同一输出合同及同一复杂度量级；区别是[[Q000012]]中的父子修复已经由库承担。priority_queue没有提供按任意键直接删除或修改优先级的成员，遇到那种需求须另想结构或处理策略。

如果希望自己保留vector，`<algorithm>`还提供堆操作这一层：`make_heap`把范围建成堆；`push_heap`要求新值已经放在范围最后，只负责修复；`pop_heap`把堆顶移到范围最后并修复剩余前缀，不缩短容器。以下函数先加入一个数，再删除一次最大值，返回的仍是堆，不保证全体有序。

{{heap-range-operations}}

make_heap的比较量线性，push_heap/pop_heap的比较量为对数；底层vector追加的存储行为仍见[[Q000002]]。只有容器操作和堆操作共同完成，才真正新增或删除一个元素。

<a id="q000015"></a>
### Q000015 · 比较器与函数对象怎样决定先后关系

比较器接收两个对象并返回bool。给sort的比较器`comp(a,b)`为true表示a应排在b之前；它必须描述严格弱序，包含自身不在自身之前、严格关系传递，以及“不分先后”形成的等价关系也传递。`a<=b`不满足第一点，不能当作sort比较器；相同值是否相等与排序是否分先后也不是同一个问题。

`std::less<int>`按`<`比较，`std::greater<int>`按`>`比较。priority_queue把按该关系最后的一类放在top，因此less得到数值大根堆，greater得到数值小根堆。也可以自定义具有`operator()`的对象：`LaterNumber{}(2,5)`像调用函数一样执行它；`const`的含义见[[Q000012]]。

{{comparator-object}}

声明`std::priority_queue<int, std::vector<int>, LaterNumber>`时，三个模板参数依次指定元素类型、保存元素的底层容器类型、比较器类型。`LaterNumber`是类型，`LaterNumber{}`才创建该类型的对象；库用比较器对象决定堆中先后关系。

这里没有“给比较器取名为Later就自动倒序”的规则，真正决定行为的是返回表达式。以后按记录的多个字段排序，可以先比较第一字段、平局再比较下一字段；各分支必须保持一致关系。lambda也能写比较器，例如`[](int a,int b){return a>b;}`，空`[]`表示不捕获外部变量，本章用具名对象把接口完整展示出来。

<a id="q000016"></a>
### Q000016 · nth_element为什么还需要配合排序

同一最小k项任务还可以先做选择分区。`std::nth_element(first,nth,last)`将nth位置放成全范围排序后应处的位置，并使左侧没有比右侧更大的元素；**左右两边各自不保证有序**。当k<n时取`nth=begin()+k`，前面恰好k项就是所需多重集，再把这k项排序以兑现本节的升序输出。

`std::sort(first,last)`原地排列这段范围，默认按`<`升序，也可接收[[Q000015]]的比较器。它与nth_element都修改传入范围而不返回一个新容器，都要求随机访问迭代器；本例vector满足要求。对k项排序需要O(klog(k+1))次比较；本题只输出数值，没有要求同值记录保持原来的相对次序。

{{topk-selection}}

`auto work=a`在这里取得独立vector副本，随后改变的是work，见[[Q000001]]。k=n时没有必要做选择，直接排序；k=0和k>n已在复制以前返回。重复元素可以出现在分区两边，但前k项的数值重数仍符合目标。

非执行策略的nth_element平均线性，加上复制O(n)和前k项排序，平均时间O(n+klog(k+1))；该接口没有承诺本版选择过程的最坏线性。为了保留原输入，本实现额外使用O(n)存储；缩小size不意味着原来为n项取得的容量就一定释放。只需第k小数值时不用再排序前缀，只需前k项有序还可考虑partial_sort；这些输出要求需要先区分，不能把几个API当同义词。

## 4. 从参考函数落到一次实际作答

<a id="q000017"></a>
### Q000017 · 怎样接入核心代码与标准输入输出

核心代码模式通常给出类名、方法名、参数与返回类型，平台负责把测试数据变成参数；应保持它指定的签名，返回所需值。以下是本章最小k项任务的适配示例，不声称它就是所有平台的固定模板。外层接受平台给出的可写引用，内核仍可以通过[[Q000001]]的只读引用读取；有符号k先判断负数，再转换。

{{core-entry}}

ACM模式则要自己读取与输出。以本章统一练习格式为例：首行n和k，随后n个int，输出一行升序结果、以空格分隔；k=0时输出空行。下面的完整入口调用同一内核，输入合同为可由int表示的非负n、k，以及足量的int元素；申请存储仍须成功。

{{acm-entry}}

`std::cin >> n >> k`将数据写入变量，表达式可在条件中检查读取是否成功；`std::cout << value`输出值。`' '`和`'\n'`分别是空格和换行字符。这里范围for用`int&`把每次读取写入真实元素，含义见[[Q000002]]。源码用宏保护这个main，便于同一文件被验证程序包含；定义`PRACTICE_FOUNDATIONS_STANDALONE`时可单独编译此入口，不定义时只提供可调用函数和类。

实际题目若是读到EOF、先给测试组数、使用行文本、要求原下标或另一种无解输出，应按其题面改入口与合同，不能只复制本例的n、k读取。算法内核、平台签名与文本格式是相连但不同的责任。

<a id="q000018"></a>
### Q000018 · 同题多实现怎样比较条件和成本

选择版本先对齐目标，再比较资源。手写不等于放弃所有容器，使用标准设施也不意味着整题算法已由库完成。

| 当前问题 | 可以并列的实现 | 选用时真正有区别的条件 |
|---|---|---|
| 完整等值范围 | [[Q000005]]与[[Q000006]] | 同一边界方法；是否需要自己实现循环、怎样转换结果 |
| 静态区间摘要 | [[Q000007]]与[[Q000008]] | 同一前缀关系；中间类型、复制次数与代码组织 |
| 任意符号目标和 | [[Q000010]]的枚举与历史匹配 | 不同算法；大输入的时间要求与哈希期望界 |
| 长度而非数量 | [[Q000011]] | 保存信息的意义改变，不能只改最后一行返回值 |
| 升序最小k项 | [[Q000013]]、[[Q000014]]、[[Q000016]] | 两种堆实现是同一策略；选择分区是另一方法，保留输入时占O(n)副本，堆只保留O(k)候选 |

验证应使用能区分条件的输入：空数组、全相等、混合正负、全负、目标为0、k为0或n、极大整数和超过32位的累计。小数组可直接枚举所有区间，最小k项可与独立排序结果比较；实现通过这些检查，仍要保留方法的成立理由和输入合同。

本章没有把一般窗口、动态区间、任意图算法或完整泛型容器都装进一个外壳。这里建立的是可继续使用的路径：从问题条件决定状态，再选择自己的算法与现有设施，最后让类型、范围和接口兑现同一个目标。
