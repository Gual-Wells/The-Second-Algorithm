# 类型与调用

求职C++实战总册 · 具体问题、机制与参考实现

<a id="initialization"></a>
## 1 构造的到底是什么

### 1.1 默认初始化、值初始化与列表初始化

`T x;` 不等于“清零”，`T x{};` 也不能无条件翻译成“所有成员清零”。自动局部标量默认初始化后没有可读的初值；具有静态存储期的对象先经历零初始化。类的值初始化还取决于默认构造函数是否由用户提供。下面 `Record{}` 得到零成员，`UserCtor{}` 则只执行空构造函数，不能读取其尚未初始化的 `count`。

{{init-forms}}

选括号还是花括号，先看**要表达参数还是元素**。`vector<int>(3,7)` 是三个 7，`vector<int>{3,7}` 是两个元素。类有可行的 `initializer_list` 构造函数时，列表初始化通常优先考虑它；若该候选最终需要窄化，可能直接报错，而不是退回你期待的另一个重载。对对象用 `{}` 可以避开 `T x()` 被解析成函数声明，但不能因此把所有 `()` 机械替换。

### 1.2 为什么 unique_ptr 不能直接列成初始化列表

`initializer_list<T>` 背后是一组 `const T` 元素。容器从列表取元素时面对的是 `const T&`，不能调用通常接受 `T&&` 的移动构造；`unique_ptr` 又禁止复制。因此，“每个元素明明都是临时量”仍然不够。改用正常的移动插入，或先建可移动的数组再使用移动迭代器。

{{list-owner}}

`initializer_list` 自身是指向后备数组的轻量视图。不要从函数返回对局部后备数组的列表，也不要把它当作长期拥有元素的容器；复制列表对象不会复制元素，更不会自动取得后备数组的独立寿命。

<a id="deduction"></a>
## 2 推导与转换：值、引用和候选函数

### 2.1 auto 保留什么，去掉什么

`auto x = expr` 按值推导，通常去掉顶层引用与顶层 `const`，数组和函数还会退化为指针。需要借用就明确写 `auto&`；只读借用可写 `const auto&`。这里的“顶层”指对象本身：去掉 `const` 指针自身的常量性，不会去掉它指向对象的 `const`。

{{auto-deduction}}

`auto&&` 的结果取决于初始化表达式，左值使它折叠成左值引用。无论变量声明为 `T&` 还是 `T&&`，**有名字的变量表达式都是左值**；把它继续交给右值接口还需显式表达转移意图，见[对象与资源](对象与资源.html#move)。

花括号有一条值得单独记住的版本差异：C++17 的 `auto x{1}` 是 `int`，`auto x={1}` 是 `initializer_list<int>`；`auto x{1,2}` 非法。旧资料可能仍写前者是列表；现代编译器还可能把缺陷修正追溯应用到旧标准模式，因此不能用一次 `-std=c++14` 实验倒推历史规则。

### 2.2 decltype 与返回类型：一个括号可能改变所有权

对没有括号的变量名，`decltype(x)` 取它的声明类型；对一般表达式，左值对应 `T&`、将亡值对应 `T&&`、纯右值对应 `T`。因此 `decltype((x))` 与 `decltype(x)` 不能混用。

{{decltype-return}}

`auto` 返回类型通常按值推导；`decltype(auto)` 则保留返回表达式的 `decltype` 结果。它适合需要保留引用的转发包装，也会忠实保留错误的引用。`borrow_first` 只能在容器仍活着、相应元素引用没有失效时使用；函数返回成功不意味着它创建了独立数据。另一个易混处是调用端：`auto x = borrow_first(a)` 仍会复制，`auto& x = borrow_first(a)` 才借用。

### 2.3 explicit、nullptr 与被删除的精确匹配

`explicit` 构造函数允许直接初始化，例如 `Count c(3)`、`Count c{3}`，阻止 `Count c=3` 等隐式转换；复制列表初始化也不能选用 explicit 构造函数。`explicit operator bool` 则能用于 `if`、`while` 等上下文布尔判断，但不能任意隐式转成整数。

{{explicit-null}}

表示空指针时用 `nullptr`，不要依赖 `NULL` 在具体实现中展开成什么。它解决“0 被当成整数重载”的问题，不能解决多个指针重载之间本来就存在的歧义。

{{deleted-overload}}

`=delete` 不是把函数从候选集中抹掉。先进行重载决议，最佳候选若被删除，再报错。这可以拦截不希望发生的隐式转换，但上面的单个 `double` 重载并不是完整的“只接受 int”类型约束；泛型约束另有适合的实现。

## 3 整数表达式：先决定计算类型，再决定结果类型

### 3.1 扩宽乘法、下标比较与负数取模

`long long result = a*b` 不能阻止 `a*b` 先在 `int` 中溢出。转换至少一个**操作数**，让运算从一开始就在足够宽的类型中进行。`std::accumulate` 同样由初始值参与决定累加类型，`0` 与 `0LL` 会不同。下面乘法用于不超过 32 位的 `int` 输入，结果可由 64 位有符号整数容纳；它不是任意两个 64 位整数的防溢出乘法。

{{integer-width}}

负数与 `size_t` 比较时，通常会先转成无符号数；`-1 < a.size()` 因此不表达你想要的数学关系。先排除负数再比较。若比较任意两种有符号／无符号宽度，C++20 可用 `<utility>` 的 `std::cmp_less` 等函数；不要未经范围判断就把一个宽整数强转为窄整数。

C++ 整数除法向零截断，余数与被除数同号：`-3/2 == -1`，`-3%2 == -1`。判断奇数用 `%2!=0`，不要用 `%2==1`。需要数学意义的非负模时，在正模数下调整负余数。除数为零，以及有符号最小值除以 `-1` 这类商不可表示的情况，都不能拿来运行“观察结果”。

### 3.2 位移宽度属于左操作数

`1 << 40` 的左操作数仍是 `int`；后面再赋给 `uint64_t` 已经太迟。先构造足够宽的无符号 1，并单独处理“取满 64 位”时不能移位 64 次的边界。

{{bit-width}}

移位量为负或不小于提升后的左操作数位宽，属于未定义行为。对位模式操作优先选明确宽度的无符号类型；不要用 C++17 中实现定义的“负有符号数右移”代替可移植的算术规则。这里采用目标平台提供的 `uint32_t`／`uint64_t`，分别恰好为 32／64 位。

### 3.3 多个修改表达式：先把顺序写出来

函数参数的位置不规定求值顺序。C++17 中不同实参的初始化彼此不交错，所以 `f(i++,i++)` 与旧标准下的未排序修改不同，但谁得到旧值仍未指定。若参数的业务含义是“第一个编号、第二个编号”，把两次操作拆开。

{{sequencing}}

花括号初始化列表的子句有从左到右的顺序。也别把 `a << b` 的运算符写法与 `operator<<(a,b)` 的函数调用写法视为在所有求值顺序规则上都完全相同。可读的有名中间结果通常比背一组顺序谜题更直接。

## 4 借用何时有效，接口该返回什么

### 4.1 引用绑定与临时量的寿命

`T&` 绑定可修改左值；`const T&` 还能绑定临时量；`T&&` 主要绑定右值。绑定时发生的类型转换可能先制造一个新临时对象，因此“参数是 const 引用”不保证整个调用没有构造或复制。引用初始化完成后不能改绑，`ref=other` 修改的是原对象。

{{ref-lifetime}}

直接用局部引用绑定临时对象，可以在适用规则下延长临时对象寿命；这份延长**不会沿函数形参、返回引用或另一个引用继续传递**。临时对象传给引用参数，通常只活到包含调用的完整表达式结束。返回局部对象的引用不会延长寿命；`new` 表达式初始化器中的临时引用绑定也不随堆对象一起长寿。构造函数初始化列表把临时量绑定到引用成员是另一类非法写法，不能用“引用能延寿”解释过去。

同样检查 `string_view`、指针、迭代器：它们描述借用，不拥有数据。拥有者还活着也未必够；字符串扩容、容器重分配或元素删除还可能使借用失效。长期保存结果时，返回或复制成拥有值最清楚。

### 4.2 const 重载与引用限定：左值借用，右值交出值

一个访问器同时服务可修改对象、只读对象和临时对象时，仅有 `const`／非 `const` 两个重载还不够。下面让左值返回引用，让右值返回一个独立字符串，避免调用者借用已经销毁的临时 `Text`。

{{ref-accessor}}

`const` 重载由对象的常量性参与选择，不能只靠返回类型重载。实现较复杂时可提取共同私有辅助逻辑；不要为复用两行代码随意 `const_cast`。有些接口从右值返回 `T&&` 以减少移动，但该引用仍借用原对象，只适合寿命被严密限制的链式操作，不能自动变成可长期保存的结果。

### 4.3 成员初始化顺序：声明决定依赖

成员按类内声明顺序初始化，**不按构造函数初始化列表的书写顺序**。若 `values_` 要使用 `size_`，就把后者声明在前面；把列表写得漂亮不能修复反过来的声明依赖。

{{member-init}}

`const` 成员、引用成员、没有默认构造函数的成员需要合适的初始化器。在构造函数体内赋值，已经晚于成员初始化。引用成员也要求外部对象活得足够久：`Batch` 不拥有 `audit_count_`。委托构造函数由目标构造函数负责整个成员初始化，不能再混列一组自己的成员初始化器。

## 5 贯穿实现：可解析、可递增的 IPv4 值

### 5.1 前置返回新对象，后置返回旧值

把四个八位数编码成一个 32 位无符号数，可以直接比较、递增和还原输出。构造时先检查范围，不把 300 静默截成 44。前置 `++a` 修改并返回自身引用，后置 `a++` 先保存旧对象，再递增并按值返回旧对象。

{{ipv4-value}}

这里明确选择模 `2^32` 递增：最大地址的下一个值是零。这是值类型的运算契约，并不意味着闭区间遍历也可以任其回绕。若业务禁止跨越最大地址，就把检查加入递增接口；别依赖有符号溢出达到相同效果。

### 5.2 输入先校验，再提交

流提取要处理三类失败：提取不完整或整数溢出、分隔符错误、数值越界。先读入临时变量，全部成功后再赋给目标；这样失败不会把已有地址改成半个新结果。

{{ipv4-parse}}

`operator>>` 读取一个值，允许后面继续有别的数据；它也允许通常的格式化输入空白。`parse_ipv4_record` 则要求整条记录在可选尾随空白后结束。若题目要求严格无空格、禁止前导 `+`／前导零等网络地址语法，需要在词法层另外实现，这份流解析不冒充那种严格语法。

### 5.3 闭区间：到达末值立即停，再考虑递增

`for(a=first; a<=last; a++)` 在 `last` 是最大无符号值时不会终止：最后一次递增回到零，条件依然成立。将“已经输出末值”作为退出条件，且放在递增之前。

{{ipv4-range}}

`first==last` 正好访问一次，逆序范围报错，包含最大地址也能终止。遍历时间仍与地址数成正比：修复边界不意味着枚举几十亿个地址就变得便宜；需要计数或分块时，应直接计算数量或使用范围结构。
