# 文本与文件

C++ 实作 · 有界字符串、解析、流与持久数据

文本处理首先要分清三个条件：输入是字符范围还是 NUL 结束的字符串，结果是借用原数据还是独立保存，解析失败后是拒绝还是接受已读前缀。条件确定后，许多“字符串题”可以归并为同一组短实现。代码为 C++17。

## 1 有界文本与所有权

### 裁剪与切分：返回 view 还是 string

trim 只移动边界，不必复制字符；切分可返回多个 string_view，也可立即复制成独立 string。下面把分隔参数解释为“任意一个分隔字符”，不是多字符分隔串。

{{trim-split}}

`split_view("a,,b,",",",false)` 得 `a,b`；keep_empty=true 得 `a,空,b,空`。空输入对应零项或一项空字段，沿用同一开关；分隔字符集为空时不切分。扫描 O(n·d)，d 为分隔字符集长度，固定的小分隔集可视为 O(n)；更大的字符表可改为查表。

**返回 view 不延长输入寿命。** `auto parts=split_view(std::string("a,b"),",")` 在该语句结束后已悬空；要长期保留用 split_owned，或让原 string 继续存活且不发生使地址失效的修改。trim 对全空白／空串必须单独处理 npos，再裁剪；不能拿 npos 去 remove_prefix。

### 连接：避免对迭代器偷偷提出额外要求

统一用“第一项前不输出分隔符，其余项前输出”即可处理空输入，不需要 `last-1`，也不需要先遍历一次数长度。

{{join-input}}

因此同一个函数能连接 vector、forward_list、istream_iterator。连接流输入只走一遍；分隔符也是有长度的 string_view，包含内嵌 NUL 时不会凭空截断。元素通过 `operator<<` 格式化，输出长度与格式化代价计入总成本。

### 有界视图不能只传 data

令原 string 是 `01.12.2017 | 02.12.2018`，view 只覆盖前10个字符。view.data() 仍指向原字符串开头；交给“读到 NUL”的接口，会把后面的第二个日期也读进去。即使底层地址都有效，结果已经超出视图范围。

需要保留长度时选择 `[begin,end)` 重载或显式地址＋长度接口；若目标只有 C-string 接口，先构造 `std::string(view)` 再传 c_str。`string_view::operator[](size())` 不合法，不能套用 string 允许读取末尾 NUL 的规则。下面的正则代码全部按范围传入。

## 2 解析与变换

### 字符分类：明确是哪一种“空白”和“字母”

删除当前 C locale 定义的空白，使用 cctype；按英文字母统计，则可以明确写 ASCII 范围，不让 locale 隐式改变目标。向 isspace/isalpha/tolower 一类函数传字符时，先转换为 unsigned char；负的 signed char 不在有效输入域。

{{character-policy}}

这里 trim_ascii 使用六种 ASCII 空白，频次将大小写英文字母合并，其他字节忽略；没有字母时比例全为0。它们不等价于 Unicode 文本分词／大小写折叠，中文或 UTF-8 码点级任务需要其他处理。

### 严格整数解析：同时核对错误与终点

from_chars 不分配 string，不跳过前导空白。下面接口要求整个输入恰好是一个整数，而不是“开头能读出一个数”。

{{strict-integer}}

`42` 合法，`42x`、前导空格、`+42`、超范围值被拒绝；有符号类型允许负号，无符号类型不接受负号。指定 base=16 时也不自动吃掉 `0x` 前缀。需要允许两端空白，可以先明确 trim；需要接受部分解析，则保留返回 ptr，并定义剩余部分如何处理。

stoi/stol 也可以解析，但它们使用异常且可能只处理前缀，仍要检查已消费长度；不要仅因没有抛异常就认定整串合法。from_chars 的浮点语法／精度是另一分支，本篇不把整数实现冒充通用数值解析器。

### 十六进制编解码：字节不是有符号字符数值

编码把一个字节拆成高低两个四位值；解码每两项组成一字节。输入输出都以长度为准，所以支持字节0，也不受 char 默认有无符号的影响。

{{hex-codec}}

解码接受大小写 hex，奇数长度或非法字符返回 nullopt；空串是合法的空结果，不等同于解析失败。本接口不接受空白或 `0x`。如果题目要求允许这些形式，应在入口定义清洗／分组规则，不能任意忽略未知字符。

特别是 string_view 的奇数末项，直接读 i+1 会访问 size 位置；先检查偶数长度才是正确处理，不通过执行越界代码猜测平台会返回什么。

### 正则：整串校验、局部查找与替换

校验一条 `名称:非负计数`，用 regex_match；找文本中的某一处，用 regex_search；修改所有匹配片段，用 regex_replace。正则识别形状，整数范围仍交给 from_chars 核对。

{{bounded-regex}}

替换中的 `$3-$2-$1` 是捕获组重排。这里日期例程只识别“2位.2位.4位”的文本形状，不验证闰年或月份日期；例如 `99.99.9999` 也会被重写。若题目要求合法日历日期，必须加语义校验，不能把正则匹配当成日期正确证明。

正则适合有明确语法的字段与局部变换；完整 URL／复杂协议不宜从一个教学表达式外推。重复使用的表达式可预编译，具体复杂度取决于表达式与实现，不能一概宣称正则都是 O(n)。

## 3 流与数值

### 读取操作成功，才推进结果

EOF 是一次读取之后的状态，不是下一次必定能读到数据的预告。`while(!in.eof())` 容易在末尾额外处理一次旧值。下面逐行读取保留空行，逐记录读取则把“只有名字没有数值”和非法数值视为错误。

{{stream-read}}

文本末尾没有换行的最后一行仍会被读取；只有一次读取失败后才结束。`operator>>` 会跳过前导空白，getline 不跳过；两者混用时，前一次提取留下的换行会让下一次 getline 得到空串。若确实要放弃该行余下内容，先 `ignore(max_streamsize,'\n')`；`getline(in >> ws,line)` 会连空行和前导空格一起吞掉，只有符合题意时才用。

### 格式设置会留在流里

fixed、precision、fill 等会影响后续输出；setw 主要影响下一次相关格式化输出。辅助函数不应无意改变调用者之后的数值格式，下面保存并恢复它自己改动的状态。

{{stream-format}}

例如在同一个流里先输出保留两位的金额，再输出普通浮点，第二段仍沿用调用者原来的 flags／precision。这个 guard 只负责这些格式项，不声称恢复 locale、错误位或任何任意流状态。

### accumulate 的初值决定类型

输入是 double，不代表累积器自动变成 double。`accumulate(values.begin(),values.end(),0)` 的累积类型仍是 int，逐步赋回时会截断小数；整数求和也同理，0LL 才把累积器放到 long long。

{{fold-type}}

这里只扩宽累计类型，不保证所有输入总和都不会溢出。accumulate 按输入顺序折叠；不能随意把允许重排的其他并行聚合替换上来，浮点加法的顺序会影响结果。

## 4 文件与记录

### 二进制记录：保存字段，不保存 string 的内部指针

直接 `write(reinterpret_cast<char*>(&object),sizeof object)` 不能把 vector／string 的动态内容存下来；即使类型可按字节复制，padding、字节序与布局也不自动成为跨平台文件格式。

下面自行定义一条简单记录：4字节小端 id、4字节小端名称长度、对应字节数的名称。名字可以为空或含 NUL。读取区分记录边界 EOF 与半条记录截断，并在分配名称前检查长度。

{{binary-record}}

这是8位字节平台上的明确字段格式，不是保存任意 C++ 对象的万能模板；实际长期文件还可以增加 magic／version 等格式标识。用 fstream 操作时打开 binary 模式，避免文本模式转换；内存 stringstream 中的字节不用另作“文本转二进制”。名称字节的编码由调用双方约定，本例不暗示 UTF-8 校验。

### 目录遍历与路径操作

路径拼接用 path 的 `/`，取文件名用 filename，取扩展名用 extension，不手工猜斜杠或按最后一个点随意截断整个路径。下面递归统计普通文件与按文件名匹配，均不跟随符号链接，并在访问失败时让异常返回调用者。

{{filesystem-query}}

递归遍历本身不承诺条目顺序，要求稳定结果就显式排序。上述统计是各路径条目报告的文件大小之和，不是去重后的物理磁盘占用；硬链接仍可能重复计数。匹配中 filename().string() 使用平台字符串转换，完整跨平台 Unicode 文件名策略尚未在这里实现。

若改为忽略无权限目录，要明确选择 directory_options／error_code 路径；“读不到所以当0”会把部分统计伪装成完整结果。跟随目录链接时还需考虑环，不能无条件打开 follow_directory_symlink。

### 内容变换与文件替换是两步

过滤空白行先写成纯流变换，既可测试也可用于两个不同文件。输出保留每条非空白行的原内容，为每条补一个换行；它会规范化最后一行换行，若需保留原文件逐字节布局，应换用另一个目标。

{{stream-transform}}

不要把输入文件原路径直接以 trunc 打开成输出，也不要为了 rename 成功先删除唯一原件。可靠原位替换需要同目录临时文件、写入／关闭检查和目标平台的替换语义；本篇只完成内容变换，不把尚未研究完的跨平台原子替换与恢复包装成一个“安全保存”函数。
