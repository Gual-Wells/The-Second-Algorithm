# 泛型与约束

求职C++实战总册 · 具体问题、机制与参考实现

## 一、让通用函数保留输入的真实含义

### 数组传进模板后，长度为什么丢了

按值推导`T`时，数组通常退化为指针；按数组引用接收，可以保留元素类型和长度。`const`数组的元素限定也保留。指针不携带原数组长度，不能对传入指针再用`sizeof`恢复。

```cpp
template<class T, std::size_t N>
constexpr std::size_t array_bound(T (&)[N]) noexcept { return N; }

template<class T> struct TypeTag {};
template<class T> TypeTag<T> deduce_value(T);
template<class T> TypeTag<T> deduce_reference(T&);
// decltype(deduce_value(array)) is TypeTag<Element*>.
// decltype(deduce_reference(array)) retains Element[N].
```

`array_bound("abc")`是4，包含结尾NUL；它不是字符串内容长度。普通接口优先用`std::size`或明确的范围，数组引用用于确实需要编译期长度的实现。[C++17推导规则](https://timsong-cpp.github.io/cppwp/n4659/temp.deduct.call)

### 包装一层调用，如何不把引用、移动或返回类型弄丢

包装器的函数对象和实参都用推导的转发引用，再分别`forward`；命名的`args`本身是左值。返回`decltype(auto)`保留被调用者的引用结果；这不会延长结果所借用对象的寿命。`std::invoke`同时支持普通函数、函数对象和成员指针。

```cpp
template<class F, class... Args>
decltype(auto) invoke_forward(F&& f, Args&&... args)
    noexcept(std::is_nothrow_invocable_v<F, Args...>) {
    return std::invoke(std::forward<F>(f), std::forward<Args>(args)...);
}

template<class T, class... Args>
std::unique_ptr<T> make_one(Args&&... args) {
    static_assert(!std::is_array_v<T>, "single object only");
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}
```

`make_one`只演示单对象工厂的关键实现，日常直接用`std::make_unique`。`const T&&`和类模板已确定的`T&&`不自动成为转发引用；`forward`也不能把错误的借用接口修成拥有接口。

### 批量追加：为什么整数能用，unique_ptr却失败

接收`Args&&...`后仍然直接写`push_back(args)`，会把每个命名实参当左值。下面保留各自值类别，空参数包什么也不做。逗号折叠保证这些**追加动作**从左到右，不能据此推断函数调用之前各实参的求值顺序。

```cpp
template<class Container, class... Args>
void append_many(Container& target, Args&&... args) {
    (static_cast<void>(target.push_back(std::forward<Args>(args))), ...);
}
```

这不是批量事务：第三次追加抛异常时，前两项可能已经加入。`initializer_list`里的元素为const，也不能拿`insert({…})`普遍替代此接口来移动一组独占对象。

### 任意多个条件：短路与空参数包

`&&`和`||`折叠保留短路：一旦结果确定，后面的谓词不再调用。空包的all为true，any为false；逗号折叠的空包是无操作，不能把这些规则推广到所有运算符。

```cpp
template<class Predicate, class... Values>
bool all_satisfy(Predicate&& predicate, const Values&... values) {
    return (static_cast<bool>(std::invoke(predicate, values)) && ...);
}
template<class Predicate, class... Values>
bool any_satisfy(Predicate&& predicate, const Values&... values) {
    return (static_cast<bool>(std::invoke(predicate, values)) || ...);
}
```

如果题目要求“多个值是否都在容器里”，谓词可捕获容器并调用查找。外层折叠不改变底层复杂度：对关联容器反复`std::find`仍可能比成员查找更慢。

### 多参数最小值：返回引用、首参数类型和公共类型是三种合同

返回引用可能借用临时实参；把结果固定为第一个实参的类型，又可能截断后面的值。下面选择**按值返回，并先转换为公共类型**；一个参数也能处理，不为零参数编造最小值。

```cpp
template<class Compare, class First, class... Rest>
auto minimum_value(Compare compare, First first, Rest... rest) {
    using Value = std::common_type_t<First, Rest...>;
    Value best = static_cast<Value>(std::move(first));
    [[maybe_unused]] auto consider = [&](Value value) {
        if (std::invoke(compare, value, best)) best = std::move(value);
    };
    (static_cast<void>(consider(static_cast<Value>(std::move(rest)))), ...);
    return best;
}
```

公共类型也有自己的数值转换规则，例如有符号与无符号混合仍需先明确题意。比较器必须在转换后的值域上满足所需关系；这不是自动获得数学意义正确的“任意类型最小值”。

## 二、类型条件改变实现时，如何选择分支

### 类型萃取：const到底限定哪一层

`const int*`的指针对象本身不是const，`int* const`才是；引用本身也不是可加顶层const的对象。数组需要区分已知界与未知界。修改类型时同样要说清：移除所有指针层，不意味着移除最终对象的const。

```cpp
template<class T> struct IsConst : std::false_type {};
template<class T> struct IsConst<const T> : std::true_type {};

template<class T> struct IsArray : std::false_type {};
template<class T, std::size_t N>
struct IsArray<T[N]> : std::true_type {};
template<class T> struct IsArray<T[]> : std::true_type {};

template<class T, bool = std::is_pointer_v<T>>
struct StripPointers { using type = T; };
template<class T>
struct StripPointers<T, true> : StripPointers<std::remove_pointer_t<T>> {};
template<class T> using StripPointersT = typename StripPointers<T>::type;
```

实际项目优先用`<type_traits>`现成设施。这里的特化用于理解机制；`StripPointersT<const int* const*>`得到`const int`，不是`int`。alias template语法自C++11就存在；标准库大量`_t`别名与`_v`变量形式的引入时间分别需要核对，不能一概写成C++17。

### 同一个类模板，某类实参需要不同存储

下面的偏特化只改变`const char*`值的存储策略，把C字符串复制为独立字符串。主模板与特化是不同定义，不能假定主模板的成员会自动继承过来。C++17的推导指引负责从构造实参选模板参数，不负责延长指针寿命。

```cpp
template<class K, class V>
struct KeyValue {
    K key;
    V value;
    KeyValue(K k, V v) : key(std::move(k)), value(std::move(v)) {}
};

template<class K>
struct KeyValue<K, const char*> {
    K key;
    std::string value;  // Own the value, rather than retaining the C string.
    KeyValue(K k, const char* v) : key(std::move(k)), value(v) {}
};
template<class K, class V> KeyValue(K, V) -> KeyValue<K, V>;
```

C字符串输入须有效且NUL终止；本例只把value转为拥有存储，key仍遵循`K`的合同。完整题若要求key和value都采用拥有策略，应统一设计存储类型，而非不断叠加互相交叉的特化。**类模板可以偏特化；函数模板不能偏特化，应考虑重载或约束。**

### 有没有size成员：检测与真正调用分开

`void_t`把表达式是否成立转成特化选择；`declval`只用于未求值语境。`if constexpr`丢弃不选的依赖分支，普通运行时`if`不能让一个非法分支不参与编译。

```cpp
template<class T, class = void>
struct HasConstSize : std::false_type {};
template<class T>
struct HasConstSize<T, std::void_t<decltype(std::declval<const T&>().size())>>
    : std::true_type {};

template<class T>
std::size_t observed_size(const T& value) {
    if constexpr (HasConstSize<T>::value)
        return static_cast<std::size_t>(value.size());
    else
        return 1;
}
```

检测成功只说明这个表达式成立。本例还要求结果能转换为`size_t`，且转换符合任务语义；若作为公开通用库，需要把这些要求一起写进检测或概念。SFINAE不吞掉任意错误：函数体或另一个被实例化类型内部的错误，可能仍是硬错误。[C++17立即语境规则](https://timsong-cpp.github.io/cppwp/n4659/temp.deduct#8)

### 多个成员同时存在，怎样明确优先级

“有first就用first，否则second，否则third，最后回退”为有顺序的选择，不能只写三个互相重叠的`enable_if`。继承标签让更高等级的精确匹配优先，低等级只是后备；被选中的接口保持原来的引用和返回类型。

```cpp
template<int N> struct Priority : Priority<N - 1> {};
template<> struct Priority<0> {};

template<class T>
auto priority_impl(T&& value, Priority<3>)
    -> decltype(std::forward<T>(value).first()) {
    return std::forward<T>(value).first();
}
template<class T>
auto priority_impl(T&& value, Priority<2>)
    -> decltype(std::forward<T>(value).second()) {
    return std::forward<T>(value).second();
}
template<class T>
auto priority_impl(T&& value, Priority<1>)
    -> decltype(std::forward<T>(value).third()) {
    return std::forward<T>(value).third();
}
template<class T> int priority_impl(T&&, Priority<0>) { return 4; }

template<class T>
decltype(auto) get_priority(T&& value) {
    return priority_impl(std::forward<T>(value), Priority<3>{});
}
```

这里的优先级来自可行候选与转换关系，不能背成“普通函数永远胜过模板”的总规则。[原始实现题](https://www.ida.liu.se/~TDDD38/exercises/SFINAE/)

### typename、template和this->分别在解决什么

第一个告诉解析器依赖名字是类型，第二个指出依赖成员是模板；第三个把名字查找带到依赖基类，避免它在模板定义时只绑定到外层同名实体。

```cpp
template<class Store>
typename Store::value_type first_stored_copy(Store& store) {
    return store.template get<0>();
}

template<class T> struct BufferBase {
    std::vector<T> values;
    void add(T value) { values.push_back(std::move(value)); }
};
template<class T> struct Buffer : BufferBase<T> {
    void add_twice(T value) {
        this->add(value);
        this->add(std::move(value));
    }
};
```

`Store`在本例约定有`value_type`及`get<I>()`，不是所有容器都具有这个接口。模板实现放在头文件，或安排明确的显式实例化；分文件症状另见[翻译与链接](翻译与链接.html)。

### 通用swap为什么常见using std::swap再不限定调用

这使默认实现可用，同时给参数关联命名空间里的定制`swap`参与机会。直接`std::swap`会绕开这些ADL重载；这与向`std`随意添加重载不是一回事。

```cpp
template<class T>
void swap_values(T& left, T& right) noexcept(std::is_nothrow_swappable_v<T>) {
    using std::swap;
    swap(left, right);
}
```

是否不抛异常也按实际可选择的swap判断。自定义类型的swap应处理自身资源合同；仅把名字写成swap不会自动产生正确交换。

## 三、编译期计算与异构结构

### constexpr函数不等于每次都在编译期运行

同一函数可接收运行时输入；用在`static_assert`、模板实参等要求常量表达式的位置，才必须完成常量求值。C++14起的constexpr函数已经可以用循环，不必把一切写成递归模板类型。

```cpp
constexpr unsigned long long fibonacci(unsigned n) {
    if (n > 93) throw std::out_of_range("uint64 Fibonacci index");
    unsigned long long a = 0, b = 1;
    for (unsigned i = 0; i < n; ++i) {
        if (i + 1 == n) return b;
        const auto next = a + b;
        a = b;
        b = next;
    }
    return a;
}
static_assert(fibonacci(10) == 55);
// A constexpr declaration permits constant evaluation; this use requires it.
using FiveSlots = std::array<int, fibonacci(5)>;
```

此实现限制到能用至少64位无符号整数表示的F93，避免为演示常量计算引入溢出。C++20的`consteval`用于要求调用立即求值，是另一种接口选择；不能靠“打开优化”代替语言要求。

### tuple元素类型不同，为什么要生成编译期索引

`std::get<I>`的I是编译期值，不能用普通循环变量直接替代。`index_sequence`把位置变成参数包，既保留各元素类型，也能处理空tuple；分隔符由索引决定，不依赖不可靠的“最后再删一位”。

```cpp
template<class Tuple, std::size_t... I>
std::string tuple_text_impl(const Tuple& tuple, std::index_sequence<I...>) {
    std::ostringstream out;
    out << '(';
    ((out << (I == 0 ? "" : ", ") << std::get<I>(tuple)), ...);
    out << ')';
    return out.str();
}
template<class... T>
std::string tuple_text(const std::tuple<T...>& tuple) {
    return tuple_text_impl(tuple, std::index_sequence_for<T...>{});
}
```

只是把tuple交给一个可调用对象时，优先考虑`std::apply`；需要按位置生成不同表达式时，再显式展开索引。

## 四、组合实作：固定容量泛型队列

### 类型、容量、对象生命周期和成员模板怎样共同落地

这个队列的合同是**满时拒绝写入**，与满时覆盖最旧项的环形缓冲不同。容量是非类型模板实参；`optional<T>`槽位区分“有存储”与“已有T对象”，因此T不必可默认构造。

```cpp
template<class T, std::size_t N>
class StaticQueue {
    static_assert(N > 0, "positive capacity required");
    std::array<std::optional<T>, N> slots_{};
    std::size_t head_ = 0, size_ = 0;
public:
    StaticQueue() = default;
    StaticQueue(const StaticQueue&) = default;
    StaticQueue(StaticQueue&&) = default;
    // Element-wise assignment could break the coupled slot/head/size invariant
    // if an element assignment throws. This reference interface omits assignment.
    StaticQueue& operator=(const StaticQueue&) = delete;
    StaticQueue& operator=(StaticQueue&&) = delete;
    bool empty() const noexcept { return size_ == 0; }
    bool full() const noexcept { return size_ == N; }
    std::size_t size() const noexcept { return size_; }

    template<class... Args>
    T& emplace(Args&&... args) {
        if (full()) throw std::length_error("queue full");
        auto& slot = slots_[(head_ + size_) % N];
        T& item = slot.emplace(std::forward<Args>(args)...);
        ++size_;  // Commit the count only after construction succeeds.
        return item;
    }
    T& front() {
        if (empty()) throw std::out_of_range("queue empty");
        return *slots_[head_];
    }
    const T& front() const {
        if (empty()) throw std::out_of_range("queue empty");
        return *slots_[head_];
    }
    void pop() {
        if (empty()) throw std::out_of_range("queue empty");
        slots_[head_].reset();
        head_ = (head_ + 1) % N;
        --size_;
    }
    void clear() noexcept {
        for (auto& slot : slots_) slot.reset();
        head_ = size_ = 0;
    }
    template<std::size_t Extra>
    StaticQueue<T, N + Extra> copy_and_expand() const {
        static_assert(Extra > 0, "add at least one slot");
        static_assert(N <= std::numeric_limits<std::size_t>::max() - Extra,
                      "capacity overflow");
        static_assert(std::is_copy_constructible_v<T>, "copying requires copyable elements");
        StaticQueue<T, N + Extra> out;
        for (std::size_t i = 0; i < size_; ++i)
            out.emplace(*slots_[(head_ + i) % N]);
        return out;
    }
};
```

索引用有界head和size表达，不让计数无限增长。成功构造新项之后才增加size；pop立即结束被移除元素的寿命。`copy_and_expand<M>`返回不同容量的类型，仅调用这个成员时要求T可复制；move-only元素仍可用于普通入队和出队。

此参考接口支持复制／移动构造，**省略赋值操作**：逐槽赋值若中途抛异常，槽位与head/size可能不再对应，不能因为每个成员本身可赋值就默认组合对象也保持不变量。扩成完整容器需要另行设计赋值与异常合同；不把这个小型实现冒充`std::deque`替代品。

返回front引用时，调用者仍须遵守元素寿命。若移动一个已有元素或从队列内部引用构造新项，T自身的失败行为也会影响旧元素；不能据“size最后更新”承诺所有场景的强异常保证。[固定队列题](https://www.ida.liu.se/~TDDD38/exercises/Static_Queue/)与Exercism、覆盖式ring的区别保留在[容器与范围](容器与范围.html)。

## 五、C++20约束与接口演进

### 概念怎样把要求放到调用边界

`requires`可检查表达式、类型及结果类型等要求；用const对象检查size，才不会接受只有可修改对象才能调用的size。组合概念应复用已经命名的原子要求，让重载关系明确。

以下代码要求C++20。

```cpp
template<class T>
concept ConstSized = requires(const T& value) {
    { value.size() } -> std::convertible_to<std::size_t>;
};
template<ConstSized T>
std::size_t constrained_size(const T& value) {
    return static_cast<std::size_t>(value.size());
}

template<class T> concept Integral = std::integral<T>;
template<class T> concept SignedIntegral = Integral<T> && std::signed_integral<T>;
template<Integral T> constexpr int integral_kind(T) { return 1; }
template<SignedIntegral T> constexpr int integral_kind(T) { return 2; }
```

`integral_kind(-1)`选择更强的有符号整数约束。编译器按约束的结构和原子身份比较，不证明任意数学命题；“`sizeof(T)>4`显然比`>=4`强”不自动建立两个独立重载的包含关系。[C++20约束偏序](https://timsong-cpp.github.io/cppwp/n4861/temp.constr.order)

概念检查通过也不能证明比较器是严格弱序、view没有悬空、size永不返回负值。语法要求与用户须满足的语义仍需共同构成合同。

### 两个auto参数不表示同一个类型

缩写函数模板的每个auto引入独立的模板参数；需要同类型推导时仍可使用显式模板参数。若要求“都能转换到某个公共类型”，则是第三种合同。

```cpp
inline auto add_independent(const auto& a, const auto& b) { return a + b; }
template<class T>
auto add_same(const T& a, const T& b) { return a + b; }
// add_independent(1, 2.5) works; add_same(1, 2.5) has conflicting deduction.
```

### 类型擦除后，为什么move-only闭包放不进std::function

一个捕获`unique_ptr`的闭包可以移动，却不可复制；泛型调用不要求把它擦除成`std::function`。后者的可复制目标要求不能由“这个lambda能调用”替代。

```cpp
inline auto counter_task(int first) {
    return [value = std::make_unique<int>(first)]() mutable {
        return (*value)++;
    };
}
// auto task = counter_task(3); task();  // Owning, move-only concrete type.
// std::function<int()> erased = counter_task(3);  // Not a copyable target.
```

C++23有`std::move_only_function`。下面是对应的拥有式擦除接口，运行环境还须具备该标准库功能；它不是把闭包捕获悄悄改成共享拥有。

```cpp
inline std::move_only_function<int()> erased_counter(int first) {
    return counter_task(first);
}
```

## 六、给调用计时也要保留原接口

测量间隔用单调的`steady_clock`，时间点之差先保留duration，再转换单位。实参同样需要转发引用；按值接收`Args...`后再forward，会把被复制的局部对象当作右值，而不是恢复原来的传参方式。

```cpp
template<class F, class... Args>
std::chrono::nanoseconds measure_call(F&& f, Args&&... args) {
    const auto start = std::chrono::steady_clock::now();
    std::invoke(std::forward<F>(f), std::forward<Args>(args)...);
    return std::chrono::duration_cast<std::chrono::nanoseconds>(
        std::chrono::steady_clock::now() - start);
}
```

本例只测一次调用并舍弃返回值；调用抛异常时原异常传播，不返回时长。一次测量也不是性能基准，线程调度、优化与测量开销需要在真正性能问题中另行控制。
