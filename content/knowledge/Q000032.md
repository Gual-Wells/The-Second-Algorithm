# 先确定运算类型，再计算长度和总量

存到 `long long` 不会让已经发生的int运算自动变宽。若a、b是int，`long long x = a+b;` 先以int相加，再转换结果；需要在运算前写 `static_cast<long long>(a)+b` 或 `1LL*a`。区间示例把端点、负载和收益本身存成long long，使后续差值与累计在该类型里进行。

区间示例面向这些题站通常提供的int至少32位、long long至少64位的环境。C++17并不保证int一定为32位；它的最低范围只有16位，不能在那样的实现上仍把200000个下标装进int。

首次区间示例的参考接口限定端点绝对值不超过 `10^9`，区间或查询不超过200000，单项负载和收益不超过 `10^9`。所以连续跨度最多 `2×10^9`，闭整数区间点数最多 `2×10^9+1`，累计负载或收益最多 `2×10^14`，均在至少64位的long long范围内。房数与原id不超过200000，在目标环境中可用int。两个原题例外另有清楚上界：LC452允许完整32位有符号端点，`stabbing_points` 只比较和保存提升为long long的端点，没有对两个32位极端值做减法；LC1751按n与预算的乘积限制规模，项目数可超过200000，仍须按该题自己的乘积约束核算。以上是区间示例的数值合同，不是以后题型的通用限制；不能用统一的便利界限缩小原题合同。

`static_cast<int>(value)` 明确请求转换，不证明数值一定可表示。LC1235最多50000个项目、单项收益最多10000，总收益不超过 `5×10^8`，所以它的入口可以把核心long long结果转回int；CSES Projects的收益上界则为 `2×10^14`，应保留long long。两种平台签名不同，不能仅因都叫“项目选择”复制转换。

`std::max(a,b)` 与 `std::min(a,b)` 根据比较返回两者之一；用于更新 `end = std::max(end, next.end)` 时，读取比较结果并赋回端点。它们不会改变两个实参。不同整数类型混用可能使模板推导失败，也可能在别处触发有符号/无符号转换；统一表达式类型比事后强转结果更清楚。有符号溢出不是可依赖的回绕算法。
