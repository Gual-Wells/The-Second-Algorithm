# 整数类型与中间值范围

类型应根据计算过程选择，而不只看最终答案。两个 int 相乘，会先按它们的运算类型求值，再赋给接收结果的变量。即使接收变量是 long long，也来不及挽回已经发生的溢出；可用 `1LL * a * b` 或在乘法前显式提升一个操作数的类型。

累加算法也有自己的规则。`accumulate` 由初值的类型确定累加器类型，因此求64位总和时应给出相应初值。`partial_sum` 按输入元素类型累加，只把输出容器改成64位仍然不够，需要先让输入参与64位运算。

有符号整数溢出不是可靠的回绕机制，也不会自动变成可捕获异常。Windows上的 long 仍可能只有32位；需要至少64位时可用 long long，需要精确位宽时使用实现提供的 `std::int64_t`。无符号类型虽然按模回绕，但回绕后的比较可能破坏搜索方向，不能靠改成无符号解决问题。

常见中点写法 `lo + (hi - lo) / 2` 也有前提：差值必须能表示。若区间含负哨兵，或跨越整个64位范围，就要重新检查这一步。寻找上中点时，同样要检查 `hi - lo + 1`。C++20的 `std::midpoint` 不能直接作为C++17程序的接口使用。

若判定只关心总量是否达到 k，可以在达到目标后停止，或把状态饱和到目标值。必须在加法或乘法溢出之前作判断，溢出以后再取 min 已无意义。

正数乘积比较有时可改成除法，例如把 `m * m <= x` 写成 `m <= x / m`，但要单独处理 m 为0的情形。

移位也应检查位数和结果范围，不能把 `1 << j` 当作任意宽的整数幂。
