边界与答案：把搜索条件写进代码

在有序数组中找到一个值，和找到“所有相等值到哪里结束”，是两个不同的任务。生产需要多久、把数组切成几段才合适，看上去又没有可供查找的数组。本章把这些任务连成一条路线：先确定要找的边界，再证明一次判断能排除哪一段，最后检查这个判断有没有正确表达原题。

我们依次解决四个实际任务。它们需要的C++设施就在相邻实现处解释；同一知识问题后面只引用Q编号。代码使用C++17，函数位于参考源码的 boundary_feasibility 命名空间；平台作答入口见末节。算法函数均只读取输入，不排序、不修改数组。它们接受各原题给出的合法输入；这份参考接口没有额外承诺如何处理非法 k、零机器周期、负香蕉数或损坏的输入流。

任务 要找的边界 一次判断的工作
LC34，出现位置 第一个不小于目标的位置；第一个大于目标的位置 查看中间元素
LC875，Koko 第一个能在限时内完成的速度 累计每堆所需整小时
CSES1620，Factory Machines 第一个达到目标产量的时间 累计同时工作的机器产量

找到一个相等值，还没有找到出现区间

LC34原题给出非降序整数数组和目标值，返回其第一次、最后一次出现的下标；不存在时返回 [-1,-1]。数组可以为空，长度至100000，元素和目标在±10^9内，要求O(log n)时间。下标从0开始。

例如 [5,7,7,8,8,10] 中目标8的答案是 [3,4]。第一次碰到8就返回，只能说明找到了一个见证；它不能排除这个8左边和右边还有其他8。从找到的位置线性扩散，在全部相等时又会退回O(n)。

把问题改成两个位置：first 是第一个满足 value >= target 的位置，after 是第一个满足 value > target 的位置。不存在这样的位置时，位置取数组长度n。于是等于目标的元素恰占 [first, after)；非空时原题的答案是 [first, after-1]，空时返回缺失标记。这里n是一个合法边界，但不是合法元素下标。

对第一个边界，非降序性使条件按顺序只能是“假……假，真……真”。维护 [left,right) 这段还需要检查的元素，并保留两条已经知道的事实：[0,left) 都小于目标，[right,n) 都不小于目标。因此所求边界在位置区间 [left,right] 内，允许等于right。

设 middle = left + (right-left)/2。如果 values[middle] < target，它以及左边的候选都不可能是首个不小于目标的位置，令 left=middle+1。否则middle可能恰是答案，不能跳过它，令 right=middle。每步使剩余元素数严格减少；当left等于right，两条已知事实夹出唯一边界。空数组一开始就满足这个停止条件，不需要访问任何元素。

Q000019 · const std::vector<int>& 怎样借用输入

std::vector<int>是元素类型为int、长度可以变化的标准容器；std::说明这个名字来自标准库。函数参数写成 const std::vector<int>& values，其中 &使values引用调用者已有的容器，而不为本次调用复制全部元素；const使函数通过这个参数只能观察容器，不能给元素赋新值或改变长度。若去掉 &，参数成为独立的按值副本，读取n个元素前就可能多出O(n)复制与存储；若只去掉 const，引用仍不复制，但接口允许修改调用者的内容。

引用本身不拥有输入，也不会替调用者长期保存数据。本章函数只在调用期间读取它，既不返回输入引用，也不把引用留给后续调用，因而没有让借用超过输入寿命的需求。平台给出的非const引用参数可以传给这里的只读引用参数；“平台允许修改”不要求实现必须修改。C++引用规则可定位到工作草案的引用条款；这里仅使用C++17已有的左值引用机制。

Q000020 · 容器长度为什么要先核对再转成 int

values.size()返回容器的无符号长度类型，并不保证就是int。直接把它与可能为负的有符号下标混算，会触发类型转换，不能凭数学直觉判断比较结果。本任务已经证明 0 <= n <= 100000，在目标平台的int范围内，于是用 static_cast<int>(values.size()) 显式转为同一种下标类型。这个转换表达“范围已核对”，不负责自动检查或修复一个过大的长度。容器长度与差值类型的区别不能靠省略类型声明消失。

values[i]读取第i项，只在 0 <= i < n 时有效；它不是自动返回空值的越界查询。循环中只有 left < right 才计算并读取middle，这保证 left <= middle < right <= n，所以不会读取 values[n]。返回值允许为n的承诺属于边界函数；调用者不能把这个承诺误读成n处也有一个元素。

int lower_bound_manual(const std::vector<int>& values, int target) {
    int left = 0;
    int right = static_cast<int>(values.size());
    while (left < right) {
        const int middle = left + (right - left) / 2;
        if (values[middle] < target) {
            left = middle + 1;
        } else {
            right = middle;
        }
    }
    return left;
}

第二个边界沿用同一论证，只把“还在左侧”的判断换成 <= target。有序性此时保证 [0,left) 不大于目标，[right,n) 大于目标。这里直接表达 > target 的边界，不把查询改写成 target+1；后者会额外依赖目标的整数范围。

int upper_bound_manual(const std::vector<int>& values, int target) {
    int left = 0;
    int right = static_cast<int>(values.size());
    while (left < right) {
        const int middle = left + (right - left) / 2;
        if (values[middle] <= target) {
            left = middle + 1;
        } else {
            right = middle;
        }
    }
    return left;
}

Q000021 · 怎样把两个下标作为一个有值的结果返回

本参考接口返回 std::array<int,2>：类型中同时写明元素为int、数量恒为2。return {first, after-1}; 按两个位置初始化返回对象；调用者得到自己的结果值，不会引用已经离开函数的局部变量。结果的两项用 [0] 和 [1] 访问。return {-1,-1};同样是一个两项结果，而不是两个独立返回值。array的定长与初始化合同说明了这里选择它的理由。

花括号的意义还取决于目标类型。稍后的平台适配返回 std::vector<int>，return {a,b};会建立含这两个元素的容器。建立有n个元素的输入容器则写 std::vector<int> values(n)；不能替换成 values{n}，后者会选择列表初始化并建立只含n这一个数的容器。不要让表面相似的括号改变题目输入规模。

std::array<int, 2> occurrence_range_manual(
        const std::vector<int>& values, int target) {
    const int first = lower_bound_manual(values, target);
    const int after = upper_bound_manual(values, target);
    if (first == after) {
        return {-1, -1};
    }
    return {first, after - 1};
}

first==after正是出现区间为空，不必为检查缺失而解引用first。两个边界查找各O(log n)，合起来仍是O(log n)；几个下标和两项返回值占O(1)额外空间。输入长度转换见 Q000020 · 容器长度为什么要先核对再转成 int，结果形式见 Q000021 · 怎样把两个下标作为一个有值的结果返回。

标准设施直接完成哪一层

Q000022 · equal_range 的两个迭代器怎样变成答案

标准算法用一对迭代器表达半开范围：values.begin()指向首项，values.end()表示末项之后的位置；空容器两者相等。迭代器是定位元素和边界的对象，*it才是取出它所定位的元素。end能参与比较和边界计算，但不能解引用。

在本题的非降序int范围上，std::lower_bound(begin,end,target)返回首个不小于目标的位置，std::upper_bound返回首个大于目标的位置；找不到则返回end。std::equal_range一次返回包含这两个边界的pair对象，.first和.second分别取它们。代码中的 const auto bounds让编译器从调用结果推导这个局部对象的类型，并使bounds不能被重新赋值；auto并没有把它变成可装任意类型的动态变量。

vector的迭代器支持相减。bounds.first-values.begin()是从首项到边界的元素个数，不是字节数；其有符号差值类型在已证明的规模内才能转换为int，见 Q000020 · 容器长度为什么要先核对再转成 int。本函数未更改容器，迭代器一直在本次调用里使用；如果在取得它们后让容器重新分配存储，再继续使用旧迭代器，就不能沿用这里的有效性判断。

这个库合同最弱的条件是相对于相应比较表达式已经分区，非降序是本题直接提供的充分条件；它不会先替你排序一个乱序数组。非执行策略版equal_range的比较次数为对数级；对于vector，定位移动也是对数级，不能把结论不加分析地移到只有顺序移动的迭代器上。可核对N4659的28.7.3与当前草案equal_range条款；这里不使用ranges或新版本重载。

std::array<int, 2> occurrence_range_standard(
        const std::vector<int>& values, int target) {
    const auto bounds = std::equal_range(values.begin(), values.end(), target);
    if (bounds.first == bounds.second) {
        return {-1, -1};
    }
    const int first = static_cast<int>(bounds.first - values.begin());
    const int after = static_cast<int>(bounds.second - values.begin());
    return {first, after - 1};
}

这和手写版实现的是同一对边界的合同。库设施取代的是边界搜索本身；把半开范围变成原题输出仍由调用者完成。binary_search只回答是否存在，不能替代本题所需的两个位置。这个标准设施版本在本题仍为O(log n)时间、O(1)额外空间。

先用几种输入检查自己的边界解释：空数组；目标比所有元素小或大；只有一个元素且相等或不等；所有元素相等；目标缺失但插入点在中间。它们分别检查“边界可取n”“末端不是元素”“重复值不能提前返回”等不同事实。

Koko：没有数组，也能问第一个可行位置

LC875原题给出若干堆香蕉。每小时只能选择一堆，以整数速度s吃最多s根；这一堆提前吃完后，该小时不能继续吃另一堆。求h小时内吃完的最小正整数速度。原题保证 1 <= n <= 10000、n <= h <= 10^9、每堆数量在 [1,10^9]。输入不变，返回一个速度；原题条件保证存在答案。

在 [3,6,7,11]、h=8的情况下，速度3需要 1+2+3+4=10小时，速度4需要 1+2+2+3=8小时。不能把所有香蕉先求和再向上整除：速度4下总量27似乎只需7小时，却忽略了不能把一小时剩余能力转移到另一堆。

对一堆p，所需小时是 ceil(p/s)。p和s都是正整数，写成整数计算即 (p+s-1)/s。把各堆小时相加得到H(s)。若s增加，每项都不会增加，所以 H(s)<=h 的可行性只能从假变真。现在边界不是输入下标，而是速度轴上的第一个真值。

Q000023 · 范围 for 怎样读取元素，怎样写回元素

for (int pile : piles)依次从容器取得元素，每次用该元素的值初始化一个局部int变量pile。它不复制整个容器，但pile是当前元素的副本；给pile赋值不会修改容器。这里元素很小且只需读取其数值，按值循环变量足够。

如果目的是读入数据到容器，稍后的 for (int& value : values)使用元素的引用，每次输入写进真正的元素。只读较大对象时可以选择 const T& 避免复制，而本章的int不需要为这个目的增加引用。引用的借用规则见 Q000019 · const std::vector& 怎样借用输入。这些循环只遍历已有容器，不在循环中改变容器长度，也不借此取得修改期间迭代器仍有效的保证。范围for的展开规则可用来理解这种按值与按引用的区别；本章没有临时范围的寿命扩展需求。

Q000024 · 宽结果必须从哪一步开始使用宽整数

先根据输入推导范围，再选择类型。本章单个输入和小规模下标使用平台至少32位的int；C++并不保证所有实现的int恰为32位。long long至少能提供64位有符号整数范围，足以容纳本章推导出的10^18上界。它不是任意精度数；有符号整数计算溢出不能当作可靠的循环取模。类型范围可核对整数类型条款。

赋值目标很宽，不会自动让之前的窄表达式变宽。例如两个int相乘后才赋给long long，乘法已经按操作数类型计算。1LL是long long字面量；1LL * a * b从第一个乘法就用宽类型。中点写 left+(right-left)/2，还要证明本章的非负left/right及其差均可表示；不能将这行当作覆盖任意正负端点的万能防溢出公式。

Koko的完整小时总和理论上可达10^13，使用宽累计更直接。原题搜索范围中 p+s-1最多1999999999，并未超过32位有符号范围；不要把单项公式必溢出当成选宽类型的理由。但公开判定函数允许任意正的int速度，调用者不一定把速度限制在10^9内，因此实现写 1LL*pile+speed-1，在第一次相加前就已经提升类型。若只在末尾写-1LL，前面的pile+speed仍先按int计算，不能满足这个更宽的helper合同。整数除法对正数截去小数部分，这正是向上整除变形所需的条件。

bool koko_can_finish(const std::vector<int>& piles, int hours, int speed) {
    long long used_hours = 0;
    for (int pile : piles) {
        used_hours += (1LL * pile + speed - 1) / speed;
        if (used_hours > hours) {
            return false;
        }
    }
    return true;
}

累计一旦超过h就可以返回false，剩余各堆只会增加小时数。这是判定内部的提前结束，不会改变H(s)是否达标。函数返回bool；搜索层只使用这一个“候选能否完成”的答案，不需要得到精确的超时总量。

先给搜索一个确实包含答案的区间

速度至少1。令上界为最大堆大小：这个速度下每堆只占一小时，共n小时，而原题给出 n<=h，所以该上界确实可行。不能只因为某个常数“看起来很大”就跳过这一证明。

维护闭的候选位置区间 [left,right]，始终包含最小可行速度，并且right可行。中点可行时，最小可行速度不大于它，保留middle，令right=middle；中点不可行时，所有不更大的速度也不可行，令left=middle+1。剩下一个候选时它就是最小可行值。这里同样使用middle和middle+1，却依赖速度判定的单调性，不能从数组下标版只抄循环外形。

Q000025 · 取极值和求和时，标准设施返回什么

std::max_element(first,last)返回最大元素所在的迭代器，std::min_element返回最小元素所在的迭代器；它们不把输入排序或改写。非空时用 *取该位置的值；空范围则返回last，不能解引用。本章三个优化任务都保证非空，因而这些使用成立。遍历查找极值需要O(n)时间、O(1)额外空间。迭代器的定位与末端规则见 Q000022 · equal_range 的两个迭代器怎样变成答案，极值设施可核对最小最大元素合同。

稍后的 std::accumulate(first,last,0LL)来自 <numeric>，从给定初值开始逐项累加，返回累计值。初值同时确定累计类型：0会使这里的类型成为int，最后再赋给long long也来不及修复已经发生的窄累计；0LL使本章需要的累计在long long中进行。类型与中间结果见 Q000024 · 宽结果必须从哪一步开始使用宽整数。accumulate合同中的新版本细节不用于扩展本章C++17接口。

int koko_min_speed(const std::vector<int>& piles, int hours) {
    int left = 1;
    int right = *std::max_element(piles.begin(), piles.end());
    while (left < right) {
        const int middle = left + (right - left) / 2;
        if (koko_can_finish(piles, hours, middle)) {
            right = middle;
        } else {
            left = middle + 1;
        }
    }
    return left;
}

单次判定O(n)，答案范围是1到P（最大堆），总时间O(n log(P+1))，额外空间O(1)。max_element取上界也花O(n)，应计入但不改变总量级。没有C++17标准函数会替你推导H(s)、合法速度范围并直接给出这个答案；库在这里承担取上界，搜索和题目判定仍是真实手写算法。

Factory Machines：并行产量不是逐项耗时

CSES1620原题给出n台可同时工作的机器，第i台每生产一个产品耗时 period[i] 秒，求生产至少t个产品所需的最短整数时间。原题 1<=n<=200000、1<=t<=10^9、1<=period[i]<=10^9。程序读取n/t和机器周期，输出一个时间；参考函数返回long long且不修改输入。

例如周期 [3,2,5]、目标7。在时间8时，三台机器分别完成2、4、1个，共7个。判断时间T能否达标，应算 floor(T/period[i]) 的和；机器并行，不是先等一台做完再累计它的工作时长。这与Koko逐堆占用整小时的向上整除恰好不同。

每个机器产量随T非降，因此总产量到达t后不会因为延长时间而失效。先正确建立这个判定，再沿用“找第一个真”的区间缩减。类型、遍历和借用只需回看 Q000024 · 宽结果必须从哪一步开始使用宽整数、Q000023 · 范围 for 怎样读取元素，怎样写回元素、Q000019 · const std::vector& 怎样借用输入。

只累计决策需要的信息

答案不需要知道所有机器在一个极大候选时间下精确生产了多少。令 produced是尚未达标的累计量，因此始终满足 0<=produced<t。新机器产量为made；若它已经达到缺口 t-produced，立即返回true；否则再相加。这样累计值始终小于t，也避免“先把所有产量加到溢出，再与t比较”。

这里要分清搜索器和公开判定函数的范围。稍后搜索器只检查 T<=m*t（m为最快周期），且每台周期均不小于m，所以每台产量至多t，总产量至多 n*t<=2*10^14；在这个紧搜索范围内，使用long long精确加完也不会溢出。提前返回仍能少算不影响决策的信息。

公开的 factory_can_produce 则接受任意非负long long时间，调用者可以脱离这个搜索区间使用它。例如周期都是1而时间为10^18，各台结果能表示，所有结果直接相加却可能超出64位范围。先与剩余缺口比较再相加，使这个较宽的helper合同也成立。不能把脱离搜索的极大候选当作紧界搜索实际必然遇到的溢出。

bool factory_can_produce(const std::vector<int>& periods,
                         long long target, long long time) {
    long long produced = 0;
    for (int period : periods) {
        const long long made = time / period;
        if (made >= target - produced) {
            return true;
        }
        produced += made;
    }
    return false;
}

可行上界从一台机器就能得到

设最快机器周期为m。即使其他机器都不用，它在 m*t 秒也能完成t个产品，所以 [0,m*t]一定包含答案，右端可行。原题 m<=10^9,t<=10^9，乘积至10^18；用 Q000024 · 宽结果必须从哪一步开始使用宽整数中的宽表达式计算。这个上界利用了实际输入，通常比固定写10^18更紧，也保留了明确的可行证据。

long long factory_min_time(const std::vector<int>& periods, long long target) {
    const int fastest = *std::min_element(periods.begin(), periods.end());
    long long left = 0;
    long long right = 1LL * fastest * target;
    while (left < right) {
        const long long middle = left + (right - left) / 2;
        if (factory_can_produce(periods, target, middle)) {
            right = middle;
        } else {
            left = middle + 1;
        }
    }
    return left;
}

搜索期间right始终可行；middle可行便收右端，否则排除它及其左侧。时间0在本题目标为正时不可行，但它可以作为候选区间的左端；循环不会对周期0做除法，因为原题已排除该输入。总时间O(n log(m*t+1))，额外空间O(1)。取最快周期用到的设施见 Q000025 · 取极值和求和时，标准设施返回什么。

两个具有区分力的检查是：仅一台周期10^9、目标10^9，答案应为10^18；大量周期1的机器、目标很小，在较大候选时间下应迅速返回true而无需精确加完总产量。前者检查乘法和答案宽度，后者检查判定只需保留的量。

Array Division：搜索正确以前，先证明判定正确

CSES1085原题给出正整数数组，分成恰好k个连续、非空子数组，最小化其中最大的段和。原题 1<=n<=200000、1<=k<=n、1<=x[i]<=10^9。所有元素都必须使用且保留原顺序，不能排序。返回最优的最大段和，参考函数不修改输入。

样例 [2,4,7,3,5]、k=3，可以分成 [2,4] [7] [3,5]，最大段和8。为了判定一个候选上限L是否可行，不必先寻找最优分割：只需要回答是否存在一种恰k段、每段和均不超过L的分法。

如果L可行，任何更大的上限也可行，直接沿用原分法即可。这个单调性来自任务定义，本身还没有证明某段贪心代码能回答判定。二分搜索不能替错误的判定补救。

给定上限，贪心为什么得到最少段数

首先任何单个元素大于L都不可能安排进任何段。其余情况下，从左到右尽量延长当前段；如果再加入一个元素就超过L，才在它前面切开新段。正数使得段一旦超出上限，继续往右加元素也不能使它重新达标。

比较任意合法分法和贪心分法：贪心第一段是从开头出发、和不超过L的最长前缀，所以它的终点不会早于另一分法第一段的终点。假设贪心前r段至少覆盖到另一分法前r段的终点。对下一段，若贪心已覆盖另一分法第r+1段终点，结论已成立；否则，从贪心当前起点到那个终点，是另一分法第r+1段的一个后缀。移掉前面的正元素只会减小和，所以这个后缀仍不超过L，贪心下一段至少也能延伸到那里。归纳可知，同样段数下贪心覆盖得不会更短，因此它需要的段数最少。

但原题要求恰k段，而这个过程计算最少段数。二者如何接上？若最少段数超过k，当然无法使用k段。若只用了b段且b<k，由于k<=n，至少有一个多元素段可继续切开；正数使切开后的两个段和都不大于原段和。反复切开直到恰k个非空段，每段依旧不超过L。因此在本题中，最少段数不超过k恰好等价于所需的存在性判定。

这也解释了为什么不能要求贪心自己“刚好切出k段”。例如 [1,1,1,1]、k=3、L=2，贪心只需两段，但切成 [1] [1] [1,1]仍然合法。反过来，也不能依靠空段补数量；本题不允许空段，证明用的是拆分已有多元素段。

bool division_can_split(const std::vector<int>& values,
                        int max_blocks, long long limit) {
    int blocks = 1;
    long long current_sum = 0;
    for (int value : values) {
        if (value > limit) {
            return false;
        }
        if (current_sum + value > limit) {
            ++blocks;
            current_sum = value;
            if (blocks > max_blocks) {
                return false;
            }
        } else {
            current_sum += value;
        }
    }
    return true;
}

代码将当前段和保存在long long，段数使用至多n的int；相加上界不超过原数组总和，至 2*10^14，符合 Q000024 · 宽结果必须从哪一步开始使用宽整数。单项超限检查在构造段之前完成；当前段容纳不下才新增一段，所以不会制造空的开头段。遍历方式见 Q000023 · 范围 for 怎样读取元素，怎样写回元素。

用两项必然界限包住最优值

最优上限至少是最大元素M，因为每个元素必须属于某一段；全部元素总和S是可行上界，因为先取整段，再按上述拆分证明分成恰k段即可。由原题推导 S<=2*10^14，不能用int累计。最大值和宽累计的设施选择见 Q000025 · 取极值和求和时，标准设施返回什么。

long long division_min_largest_sum(const std::vector<int>& values,
                                   int exact_blocks) {
    long long left = *std::max_element(values.begin(), values.end());
    long long right = std::accumulate(values.begin(), values.end(), 0LL);
    while (left < right) {
        const long long middle = left + (right - left) / 2;
        if (division_can_split(values, exact_blocks, middle)) {
            right = middle;
        } else {
            left = middle + 1;
        }
    }
    return left;
}

每次判定O(n)，在整数范围 [M,S]中找首个可行值，总时间O(n log(S-M+2))、额外空间O(1)。k=1返回S，k=n返回M，两种极端不必另写算法分支；它们可以直接验证整套合同是否闭合。

加入负数时，究竟哪一步失效

若允许负数，“上限L存在合法分割”仍会随着L增大而保持可行；沿用原分法的论证没有消失。失效的是本章这个正数贪心及其界限证明。例如 [4,-3]、k=1、L=1，整段和为1，实际可行，但“单个4超过L便失败”的判定给出false；最大元素4也不再是答案的必要下界。不能把修复它理解成换一个二分模板。需要为新合同重新研究判定和边界，本章不扩展到负数分割优化。

用结果检查条件，避免只检查循环相像

边界搜索值得独立检查的是：返回的位置左侧是否全部不满足、右侧是否全部满足；优化任务还要检查返回值确实可行，若它大于合法下界，前一个整数值确实不可行。只有“两个版本给出同一个数”仍可能共享同一错误条件。

LC34可用线性扫描作为独立参考；Koko小输入可逐小时吃香蕉并枚举速度；Factory小输入可逐秒推动每台机器的倒计时；Array Division小输入可枚举n-1个相邻间隙中的k-1个切点，直接比较每种合法分法的最大段和。这些模型故意避开了被测算法的二分循环及贪心判定。

本章四题不覆盖所有二分问题：它们依赖的是单调谓词及可证明的判定。旋转数组、浮点精度停止、动态前驱删除等任务需要另立合同。上机时先写下原题的输入、输出、范围与修改政策，再写出“某候选为什么可行”的独立函数；当这句话和代码都成立，边界缩减才有依据。
