## 原题实际合同

[ABC216E Amusement Park](https://atcoder.jp/contests/abc216/tasks/abc216_e)：N个设施，初始Ai为正整数；使用时先获得当前收益，再把该设施收益减1；最多操作K次。约束 `1≤N≤10^5`、`1≤K≤2×10^9`、`1≤Ai≤2×10^9`，输出最大总收益。原题第二个样例明确允许少于K次，不能强制消耗到负收益。

[官方英文题解3122](https://atcoder.jp/contests/abc216/editorial/3122)采用隐式序列取大值与二分思路。但其定义“至少m的值不少于K”之后，对端点真假和minimum方向的叙述存在明显相反笔误，后文还混用了计数变量。因此本报告不复制它的二分方向，以下从原题自行推导、验证。

## 判定与恢复公式

每个设施的正收益依次为 `Ai, Ai−1, …, 1`。忽略0与负收益不改变“至多K”的最优值。令

`T = ΣAi`，`K' = min(K,T)`。

截取前t次正收益（`0≤t≤Ai`）的效用为

`Ui(t) = t(2Ai−t+1)/2`。

### 一、作为阈值选择

定义 `C_ge(v) = Σ max(Ai−v+1,0)`，它随v非增。搜索

`h = max { v∈[1,max Ai] : C_ge(v) ≥ K' }`。

`C_ge(1)=T≥K'`，`C_ge(max Ai+1)=0<K'`；可维护“左真右假”。不应找最小真，因为那总会退到1而失去第K大阈值的意义。

令

`ci = max(Ai−h,0)`，`S = Σci`，`E = #{ i : Ai≥h }`。

ci是第i个设施中**严格大于h**的收益个数；E是等于h的收益总数，每个符合条件的设施恰有一个。由h定义，

`S = C_ge(h+1) < K' ≤ C_ge(h) = S+E`。

因此严格大于h者全取，再取 `r=K'−S` 个h。恢复式可写为

`answer = Σ[ci(2Ai−ci+1)/2] + (K'−S)h`。

不必构建长度可能达2×10^14的序列，也不必逐次堆取K次。复杂度 `O(N log(max Ai))`，存原数组 `O(N)`。

### 二、作为完整的可分离惩罚oracle

将数量限制去掉，给每次操作扣惩罚λ，研究

`H(λ) = max Σ[Ui(ti)−λti]`，`0≤ti≤Ai`。

这里是忽略非正原始收益之后的等价有限决策域；λ是非负整数。每个设施的净边际依次为 `Ai−λ, Ai−1−λ, …`，故所有正净边际均取，零净边际可取可不取。在 `λ=h≥1` 时：

- 最少计数为S；最多计数为S+E；
- 取任意r个零净边际，所有整数数量 `[S,S+E]` 都真实可达；
- 所有这些方案的惩罚后价值相同，且 `H(h)=Σci(ci+1)/2`。

于是有更紧凑的恢复式

`answer = H(h) + hK' = Σci(ci+1)/2 + hK'`。

这不是凭“数量单调”盲减惩罚：我们已经展示每个目标数量都有真实同值最优方案。最优计数随惩罚非增，只是搜索所需；目标数量处无对偶间隙，是精确恢复另需的事实。本题的可分离递减边际给出了这一事实的直接证明。

λ=0时，在已截断的有限正收益域内，全部T次都取即可；不要把λ=h时的E公式无条件搬到λ=0，凭空加出每个设施的一次零收益操作。实际搜索h≥1，因此实现不需要触碰这条额外语义。

## 为什么这是离散凹特例，不能推广过度

每个Ui的新增收益递减。把各设施边际合并按值下降排列，前K'个构成可行的操作前缀：如果选了某设施较后的收益，其前面的收益都更大，已被先选。因此全局最优值F(k)的差分也是非增，属于离散凹情形。相同阈值上的各项可任选补足，使所有目标数量被支持。

如果某设施边际变成 `[1,100]` 而非递减，K=1时不能跳过第一次直接取得100；“全体边际取前K”就给出不可行答案。它对应一个目标数量不被惩罚最优解支持的简单例子，说明可分离并不单独足够，递减边际/相应凹性才承担关键作用。

原独立挑战的 `F=(0,1,0)`（最小化）反例继续有效：最优数量可随惩罚单调，但目标1在下凸包之上，不能精确恢复。`F=(4,2,0)`则展示共线数量被固定同值政策跳过仍可恢复。这些结论应在本题之后上升到一般数量约束问题，不能因为本题每个零净边际可独立补足，就宣称任意DP也可以任意补数量。

Aliens官方满分方案仍适合说明一般DP oracle还涉及其他工作：具体成本、去包含区间、交叠与CHT，以及目标数量价值函数的凸性。原官方末页只列凸性定理、没有展开完整证明。本章可以明确它是不同复杂度层次的应用边界，不能只贴一个WQS模板就说Aliens已经解决。

## 64位预算：答案安全不等于每个中间oracle都安全

在原题约束下：

| 量 | 上界/判断 | 实现含义 |
|---|---|---|
| 正收益项总数T | `N×max Ai ≤ 2×10^14` | `int64_t`安全，int不安全 |
| 最终选择次数K' | `≤2×10^9` | 来自K限制 |
| 最终答案 | `≤K'×max Ai ≤4×10^18` | 小于signed64最大值 `9223372036854775807` |
| 最终S | `<K'` | 只在最终h成立，不能假设每个mid都成立 |
| 最终ci(ci+1) | `<4×10^18` | 在int64中乘，再除2安全 |
| 阈值恢复hK' | `≤4×10^18` | 必须64位乘法；最终合计仍≤4×10^18 |
| 未截断的所有正收益总和 | 最坏 `200000000100000000000000` | 约2×10^23，signed64会溢出 |

**建议实现的二分判定只累计数量，最终阈值才计算收益。**计数2×10^14本身安全，可选择饱和到K'提前结束。不要在每个mid顺带累计全量收益/惩罚收益：例如N=10^5、Ai=2×10^9、K=1，真实答案仅2×10^9，但λ=0时H(λ)达上述2×10^23。

若实际示范“任意λ的完整oracle同时返回H和值数”，H聚合须用足够宽的整数（如GCC/Clang的`__int128`，并明确非ISO标准设施）；不能拿最终答案fits来辩护。若采用上述计数搜索＋最终恢复，原题无需宽于64位。中点加法、`Ai+h+1`、`2Ai`及乘法都先提升64位，不能int算完再赋给long long。

## 必须能通过的语义例子

- `A=[5,5], K=3`：h=4，严格大于阈值有2项，补1个4，答案14；只取严格大者得10，全取≥阈值者得18且超次。
- `A=[2,3], K=2021`：K'=5，h=1，答案9；不得强制用完K。
- `N=10^5, Ai=2×10^9, K=1`：最终极小选择量与巨大全oracle的溢出反例。
- 大量相同Ai、K正好压在某收益层、K=T及K>T：检查严格/非严格计数和补足政策。
