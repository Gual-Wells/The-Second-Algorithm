# 根审阅：具体接口病例

2026-10-27，在收到研究目标v1后选择[Core Guidelines R.37](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rr-smartptrget)的完整代码病例作反查。作者此前读取该页面的R.30与相关规则入口，未用此病例构造范围；它仍不是“全新机制”或模型从未见过的材料。

问题：从一个可被被调用链重置的共享拥有者取得`T&`，调用内部若释放最后一份强拥有关系，借用就会悬垂。`const shared_ptr<T>&`只限制经这一引用重绑外壳，不给调用过程新增一份强拥有关系；类型拼写不能独自证明整个调用期间保活。

修复：调用之前先取得本地强拥有副本，再从该副本借用；副本本身不能被调用链重置。此处“aliased”指拥有者变量可能经别名被修改，不等同于shared_ptr的别名构造函数。

本病例用于检查正式稿是否把普通借用、条件保留和保活前提讲清；不要求为此扩展一整套共享指针或并发章节。不执行悬垂分支来猜输出；对正确版本可用销毁计数与作用域核验。成稿审阅及实际验证结果在完成后追加，不预填通过。

成稿后结果：根实际读取完整作者稿与源码，原文的借用期限原则能解释此病例，但条件保留段只强调省复制，容易漏掉重置别名。已补就近的`if (auto pin = owner) use(*pin);`与两层拥有说明，没有新增长模板。作者重建同权威阅读版，根复跑C++17主测试及隔离编译探针通过；本病例以规则及合同分析复核，没有执行不安全分支，也不冒称专门的运行寿命证明。
