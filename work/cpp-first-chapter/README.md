## 研究目标 v1（范围基线，已接受）

推荐围绕**对象如何持有、借用、复制和转移，以及这些选择怎样体现在函数与类接口中**形成第一章。暂名为“对象、资源与接口”，题名和阅读分区均可因深入研究调整。目标是让已有CS基础的读者能直接实现、修正和比较实际接口，不是从指针语法上基础课，也不是把“值类别／RAII／智能指针”各写成术语表。

推荐来自实际问题关系，而非沿用旧《对象与资源》文件：Stanford官方A5要求修复拥有动态数组的User复制行为并显式禁用移动；A7要求实现独占句柄和拥有链表；GotW91从普通使用、消费、重置和条件保留区分参数。这些任务共同问“谁负责对象、这次调用改变了什么、调用后谁仍可使用资源”。Book中的字符串view任务进一步显示借用与返回值不能从类型拼写孤立判断。异常提交与对象存活则是实现这些接口时必须处理的真实分支。

## 推荐范围与实质边界

工程需继续深入并讲清以下相连问题，不把这些条目机械改成固定正文目录：

- 普通值对象优先借助string、vector等自管理成员；何时默认操作已经足够，何时需要独占资源句柄，何时需要具有独立内容的深复制值对象。三个合同分别成立，不能用一句“拥有内存就必须写深复制”统括。
- 以一个可拥有数据的短实现解释构造与赋值区别、深复制、复制赋值失败提交、自复制；再以独占句柄解释禁止复制、移动、源状态与自移动。移动操作缺失、被delete及const源是会改变调用选择的近邻条件。
- 函数接口中的只读／可写借用、空值政策、消费、重新绑定、工厂返回值与按值接收后移动入成员；区分命名右值引用仍是左值、std::move转换与实际移动。返回局部对象与返回借用不同，C++17直接构造与可选NRVO分别核对。
- const拥有句柄、const被指对象、const引用是不同限制。新读的课程自制unique_ptr会传播const，标准unique_ptr并不采用同一接口；示例必须明确自己的合同。
- string_view与引用返回的借用期限、临时对象和持有者修改／销毁的影响、view的长度；用保留拥有结果或适当限定成员接口解决实际问题，而不运行悬垂代码猜结果。不展开完整ranges适配链。
- 共享所有权仅保留真正需要跨调用保留对象、条件保留与弱观察的接口选择；控制块与裸指针不能混同。不扩成自制shared_ptr、并发引用计数或完整图系统。
- RAII资源清理与显式报错责任；构造中途失败、先准备再提交及析构清理。这些服务于本章对象合同，不扩成全部异常语言规则。

暂不纳入完整多态体系、allocator／pmr、对象表示与placement new、协程、线程同步、完整泛型容器、文件持久化与全部重载排序。后续读件若证明某一条件直接影响本章接口正确性，应反馈并增补必要边界，不能以这段暂排清单挡住新证据。

## 已发现会改变作者实现的问题

1. A7骨架的`operator*() const`返回`const T&`、箭头返回`const T*`，而标准unique_ptr观察器返回T引用／pointer；这是教学接口与标准接口差异，不是标准unique_ptr的const传播保证。
2. A5明确delete移动成员。工程需分别处理“没有声明移动所以可复制回退”和“移动候选存在但被delete”，不能照着“std::move一定搬走资源”写解说。
3. Professional的“移动后都不要再用”过强，且拥有动态内存也不强制所有类型可深复制；本章以自己声明的不变量及库合同解释，不复制过强口诀。旧候选分析已有此问题，本次重读再次确认它影响本章主线。
4. 旧ring的异常反例说明多个成员各自有效不等于整个对象不变量保持；本章需要有真实失败提交例子，不能只以int正常路径通过替代异常分析。
