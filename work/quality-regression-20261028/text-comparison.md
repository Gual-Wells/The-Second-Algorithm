# 正文对照审计：从专题参考到四题讲义的得失

审计日期：2026-10-28。实读基线：`main@4d9fe9024b80fd6abf1ad45e94a966f6d36e2600`。本记录只做研究，不修改正文、模型或发布。文中行号均指本次工作树的 `.source.md` 或 `.cpp`；它们供定位，不是长期稳定身份。

## 读取范围与判断边界

实际读完当前 `AGENTS.md`、四份 `protocol/` 共同协议和 `docs/CONTENT_MODEL.md`；读完以下六份作者稿，并逐行读当前与前版的完整 C++ 源码：

- `content/boundary-feasibility/边界与答案.source.md`、同名 `.cpp`。
- `content/practice-foundations/实战起点.source.md`、同名 `.cpp`。
- `content/contiguous-ranges/连续片段.source.md`。
- `content/binary-search/{二分查找,组合判定,进阶扩展}.source.md`。

另定向核对旧 C++ 中的边界、速度、分段、生产、负数最短段、均值/中位数变换、树内定位与批量前缀代码，确认正文所称方法确有对应实现。仓库实际源码后缀为 `.cpp`，没有这几章的 `.source.cpp`。未重跑测试、未检查本轮线上载体、未进行真实读者实验，因此不从这里得出正确率、学习耗时或掌握率结论。

按当前协议，产品目标是“为求职算法上机建立统一实战参考”，不是从零教语法；同时又明确不能假定读者已会实际所需的 C++。旧稿是历史素材，不能因为旧稿存在就算当前已覆盖，也不能因为旧稿较广就直接恢复为正式章。这两个约束同时成立。

**主要判断：能从正文证实的是教材形态和可迁移面的明显收缩，不能证实“新稿每一处讲解都比旧稿差”。** 新稿在题目合同、分段判定的局部证明和原题入口上有真实进步；但它把原先按条件关系组织的参考面压成四个均求首个可行值的任务。C++说明和工程接口变得更完整，而相邻算法变体、不同方法之间的选择面减少。若目标仍是实战参考教材，这个变化足以解释“更认真、更多验证，却更不像可查可迁移的教材”的体验；绿色测试不能反证这个判断。

## 一、相同任务对照：出现区间

### 新稿增加了论证与原题落地

`边界与答案`“找到一个相等值，还没有找到出现区间”（16—24行）先给 LC34 原题合同，指出“第一次碰到8就返回”只给一个见证，线性向两侧扩散会在全相等时退化；再把输出拆成首个 `>=target` 和首个 `>target`，最后陈述已排除区间的不变量和缩短理由。这里的“为什么不能提前返回”和“元素区间半开、答案位置可含右端”比旧稿的紧凑版本更明确。

相应代码 `边界与答案.cpp:17—70` 分开呈现 lower、upper、原题缺失政策和 `equal_range` 版。LC34 平台适配见正文212—216行及源码182—190行，读者能够看见参考接口 `array<int,2>` 怎样转换为题目要求的 `vector<int>`。这是可上机性的实质改进。

### 旧稿保留了更强的同方法迁移面

`二分查找`“1.1 查值、插入位置、首末位置”（33—59行）在同一对 L/R 后面直接列出：查值、首末位置、次数、前驱/后继、值域计数、最近元素；又区分“去重后的稠密排名”和“保留重复的严格较小元素数”。它不是为每个背景再写一套循环，而是告诉读者**已经求出的两个边界还能回答什么**。

该节还用 UVa12965 提醒“能二分计数，不代表总目标单调”（57行）：下降项与上升项之和不能直接当作单调目标。这是与当前题紧邻、能阻止误迁移的算法反例。新稿84行的空数组、全相等、缺失等输入很好地检查 LC34 合同，但没有形成同等强度的查询关系表；两者承担的学习作用不同。

`实战起点`第一节给出通用半开结果 `[first,last)`，`实战起点.cpp:13—49` 的 `Positions` 在目标缺失时保留插入位置；正文62、67—73行说明次数、最后命中和库设施层次。新稿原题返回值将空结果折叠为 `[-1,-1]`，更贴 LC34；它仍公开 lower/upper 函数，**不能说能力已经从代码中删除**，但正文不再主动展开通用结果的复用关系。

因此不应在“解释更清楚”和“参考价值更大”之间选一个假答案：新稿的单题论证更完整，旧专题的同方法复用更强。未来应把这两种能力接在一起，而不是以删掉变体换取深度，或以一张表替代首次证明。

## 二、同族任务对照：速度、并行产量、连续分段

### 新稿的最强优势是分段证明，不是测试数量

`二分查找`“4.1 连续分段，使最大段和最小”（288—294行）给了正确的非负条件、`[max,sum]` 范围、“最少段数<=k”以及继续拆成恰 k 段的说明；但“从左尽量装满”为什么真的得到最少段数主要作为结论出现。

`边界与答案`“给定上限，贪心为什么得到最少段数”（172—178行）明确比较贪心与任意合法分法，通过“贪心前 r 段覆盖得不会更短”的归纳建立最少段数，再单独证明“至多 k”与“恰好 k 个非空段”如何接上，并用 `[1,1,1,1]、k=3、L=2` 否定“贪心必须刚好切出 k 段”。这一段比旧稿局部更深，值得保留为正文质量的正样本。

新稿192—194行还把负数的故障分开：存在性仍随 L 单调，失败的是贪心和最大元素下界；`[4,-3]、k=1、L=1` 同时击穿单项超限检查和下界。这比笼统说“负数不能二分”准确。旧 `组合判定:9—15` 已有同样重要的分离，还并列“最小化最大段和”和“最大化最小段和”，给 `[4,4,-3]`、`[3,3,-3]` 两种失败；新稿深化了其中一个方向，缩减了另一个方向。

### 速度与机器的新旧关系更接近“展开”，不是新方法发现

`二分查找`“4.3 按元素累计”（308—338行）把耗时、产出、操作次数并列表达，`[3,3]、速度2` 明确反驳先合并再向上取整；“4.4 多机器并行生产”（342—346行）又区分并行产出与逐项耗时。

新稿 Koko 的 `[3,6,7,11]、h=8`（90—92行）和 Factory 的 `[3,2,5]、目标7`（138—140行）同样把上取整耗时与下取整产量讲清，补上原题限制、上下界论证、宽整数推导、独立 check 函数和实际提交入口。这些增补有用。可是新稿的三个优化任务始终都采用“假→真、找最小可行值”；旧稿同一区域还让整数切割、最小间距最大化展示“真→假、找最大可行值”，连同中点推进和无正解的政策一起呈现（296—330行）。

**损失不是少了几个题名，而是少了会改变搜索方向、结果政策和判定含义的近邻比较。** 若希望四题形成一个入门单元，现范围可以成立；若把它当一个较完整的二分实战参考章，它留下的缺口不只是“以后再多做题”。但这也不意味着应该把所有旧题重新塞回第一章：局部比较可留在本节，复杂判定和特殊结构可以分到实际完成的相邻单元。

### 数值说明出现了合同扩大带来的正文成本

新稿 `Factory Machines` 146—148行谨慎承认：在 `T<=m*t` 的实际搜索范围内，总产量最多 `n*t<=2*10^14`，long long 精确累加也不会溢出；随后为接受任意非负 long long 时间的公开 helper 推导缺口累计。代码 `factory_can_produce` 的确按这个较宽合同实现（源码105—117行）。Koko 110行同样区分原题范围和允许任意正 int 速度的 helper。

这比虚构原题溢出更诚实，应保留事实区分；但它也揭示一种正文增长来源：作者先把辅助函数合同扩大，再必须花篇幅解释本题搜索不会遇到的风险。这个选择的教学收益需要与相邻变体竞争，而不应自动成为必修深度。可以收紧 helper 到真实调用合同，或把通用 helper 的额外保证作为可定位的旁支；不能以“严谨”名义无限扩展主线。

## 三、最强旧样本：连续片段展示的是推理关系，不只是更多实现

整体组织上，最强旧样本是 `连续片段.source.md`。它的优势来自同一对象在条件变化后的状态重用与替换，不能归因于21个代码块或更大的题数。

1. “目标和的数量”先从 `p[r]-p[l]=target` 得出应查的历史键；随后“最长留最早，最短留最近”（74—88行）固定键不变，仅改变保存的摘要。读者能看到**目标改变怎样决定数据含义**，不是每题都从标题重新开讲。
2. “非负和计数”（128—132行）保留正数、零、有符号三种条件：零使一个右端可能对应多个合法左端，`{0,0}` 否定每次只加1；负数则使已排除左端重新可能有用，引回历史前缀。这是条件驱动的分叉。
3. “非负和最短段”（134—140行）用 `{1,-1,5}`、target=5 说明普通收缩漏解；“含负数的最短阈值段”（194—205行）没有止于“不可用”，而给出替代结构及两种永久删除证明：已经为该起点取得最短可能终点；更晚且前缀不大的新起点支配旧起点。对应源码374—391行的两个 while 与两种证明一一对应。
4. “最长无重复段”116行并入正数互异最大和，又以 `{-5,1}` 反驳有符号版本的直接替换；“固定长度、互异、最大和”（56—62行）则展示边界不变、和与频数合成状态。它们证明近邻变体可以提高迁移而不制造一份新模板。
5. 固定窗口极值与负数最短阈值都用单调队列，却在205行主动区分队首删除原因：下标过期，与已经取得该起点最短可用答案。这比把数据结构名等同于方法有更强的算法辨识度。

这个旧样本也有明确不足：正文默认读者认识 `optional`、`unordered_map`、`emplace`、`deque`、类型转换等；没有当前模型要求的系统 C++ 主讲定位；不少任务没有完整原题输入上界与平台入口。结尾213行还提醒固定窗口内核不等于生成式大输入的完整提交。它因而**不能原样成为满足当前要求的最终教材**。合理继承的是这种条件/目标/摘要/替代方法的关系结构，同时修补必要 C++ 和可作答接口。

## 四、算法深度不等于把第一章装成百科

`组合判定`和`进阶扩展`提供了两类新稿没有保留的思考层次：

- `组合判定`“子段目标：改写成前缀差”（52—58行）：平均值阈值变成 `a[i]-x`，长度上限 U 决定需要窗口内最小前缀还是一个累计最小值；下中位数用 `[1,2]` 指出严格正与非负的差别。接着“受限选集”（62—68行）说明同样变换若不允许连续跳过两项，判定需 DP，不能取所有正收益。这里的深度是**同一数学变换与不同合法集合之间的关系**。
- `组合判定`“可达区间逐关传播”（140—150行）：Slalom 固定速度后扩张上一门可达区间再相交，明确不是静态求所有门交集，也不是逐对门各自可行；缩放坐标后精确整数化。模型、状态充分性、单调方向、数值处理均连在一起，是该稿单题中较强的样本。
- `进阶扩展`11、19—21、27—33行依次比较普通下标二分 O(log²n) 与树状数组试跳 O(log n)、重复区间最大查询与线段树直接下降、每个查询独立重建与按 mid 分桶共享操作前缀。它在回答**什么信息能省掉外层重复工作**，不只是再给更难模板。

这些是值得后续研究承接的真实概念层次，不代表它们都必须进入首章。旧稿的问题也在此暴露：`组合判定`一份稿横跨图、匹配、DP、几何、计数，正文常以极短文字承接很长代码；`进阶扩展`默认读者知道树状数组、并查集、线段树，并未充分讲解它们自身机制。若对尚不熟悉这些结构的读者一次发布，很可能只有“看见一份正确答案”，仍未形成思考能力。不能用旧稿覆盖更广掩盖这些跳跃。

因此应采用“研究确认的关系完整”来形成章界：一个单元至少完成它声称要建立的比较关系；超过本单元知识跨度的内容，成为有实体承载和清楚前置的后续单元。不是固定每章四题，也不是一章复刻旧二分全部目录。

## 五、C++的必要补足与主线抢占：两代均有问题，形态不同

`实战起点`比更早专题真正增加了手写/标准设施/不同算法的选择：目标和枚举对历史哈希（115—125行），手写堆对 priority_queue（145—181行），再对 `nth_element+sort`（199—207行）。正文227—237行的比较表说明的是输出顺序、保留原输入、O(k) 与 O(n) 存储等实际条件；这部分不能作为“无用C++”删掉。

但其第一节在第一次边界实现前先放 Q000001—Q000004，依次讨论函数签名/返回/命名空间/auto、vector 的构造/容量/增删、迭代器/copy/失效、整数与转换（14—47行），读者要跨过一长段通用设施才回到边界循环。第三节还从最小 k 项扩展到手写完整堆类、比较器、函数对象、lambda 等。它兼有基础速成页和实战参考页的职责，不是可以无条件恢复的黄金版本。

新稿减少到8个Q，且把算法证明移出Q标题，这使正文不再把每个算法问题也当作一个 C++ 卡片，是结构上的改善。但新稿第一题仍需经过借用、长度转换、结果容器、迭代器、auto、失效、标准保证，第二题又先后插入范围 for、整数、极值与累计。知识确有用，**只是“只完整讲一次”解决了重复存储问题，没有自动解决首次阅读时的注意力分配。**

特别是 `边界与答案`70—78行从 equal_range 的题目用途延伸到分区最弱条件、非随机访问的移动成本；144—148行又区分原题搜索与泛用 helper。这些可能是参考教材有价值的旁支。若正文与代码之间只有一条必须全部顺读的路径，它们会和当前算法推理争抢主线；本审计没有检查读者界面，故不声称已有折叠、跳转或排版一定失败。

较好的粒度应按实际知识问题拆：让读者在当前代码附近能获得足以读懂和使用它的解释，把深化合同的旁支明确可定位，同时保留唯一权威主讲。不要把“完整解释”实现成每次第一次出现就把所有边界搬进主叙事；也不要倒退到旧稿默认全懂 API。Q编号数量、跳转存在和引用校验都不能替这项编辑判断作证。

## 六、从参考函数到上机作答：当前版本确实前进了一步

`实战起点`核心模式与 ACM 模式是统一练习格式（214—224行），提醒真实平台签名和输入政策会变化，但不是某个明确原题的全部入口。更早专题多为函数内核，`连续片段`213行也主动承认生成与聚合需要另处理。

`边界与答案`196—230行为两个 LeetCode 原题和两个 CSES 原题给了各自接口，解释函数依赖、命名空间和互斥入口。它在“我看懂参考代码，但不知道该交什么”这个具体障碍上比旧稿更好。宏选择不是所有算法教材都必须采用的组织形式，但本稿对其用途和不会同时提交多个 main/Solution 的解释是实在的。

这一优势不能换算成“已能独立解近邻新题”。新稿232—236行给出线扫、逐小时/逐秒模拟、枚举切点的独立核验思路，帮助读者理解检查什么；但稿内没有让读者先尝试未展开近邻任务、再比较不同推理的活动，也没有读者迁移结果。旧稿的大量题目同样没有这种读者证据。这里只能判“入口更可用”和“迁移关系呈现更多/更少”，不能判某位用户已掌握。

## 七、对未来范围、体量与粒度的具体含义

本次对照支持以下改进方向；它们是待研讨的作者决策，不是新的发布门禁，也不授权本轮改稿。

1. **先确认交付形态。** 若目标是现协议中的实战参考，保留新稿扎实的首次证明与原题适配，同时恢复可查的近邻关系。四题首真路线可以作为首个学习单元，不应凭“第一章”名义独自承担完整二分参考面的期待。若目标改成循序入门讲义，需用户明确接受，不能以编号重构悄悄发生。
2. **按关系而非题数定体量。** 出现区间至少研究边界结果如何映射存在、计数、插入和近邻；答案搜索至少研究首真/末真、可行上界/无解政策、判定正确与单调性不同等会改变代码的关系。哪些应同章承载、哪些延后，要由新研究和实际阅读组织决定，不预设固定清单都必须进第一章。
3. **保留一个完整证明，压缩真正重复的搜索外壳，把空间给新判断。** 当前三个优化题的循环可以解释一次；后续重点放在向上取整耗时、向下取整并行产量、贪心分段各自新增的模型与失败条件。压缩外壳不等于删掉判定推理，也不一定要抽成读者还不熟悉的泛型函数。
4. **反例要有后续作用。** 有些反例只用于划界，如负数分段可以合理留待后续；但一整个主题若总以“这时需另研究”收尾，读者只学到禁用条件。`连续片段`从140行失败例走到194—205行替代结构，是值得重复使用的设计：选择若干关键条件变化，真正完成一个替代方法，而不是每个变体都只留一条警告。
5. **C++补足应服从真实操作问题。** 保留类型、范围、借用、初始化、API结果和失效；审视扩大 helper 合同产生的额外必读说明。不能把算法深度不足靠更多语言边角补齐，也不能为了算法页面紧凑再次默认读者会所有设施。
6. **研究交接应指出哪项新关系值得占正文。** 只列已读原题、Q、实现和测试不足以防止这种回归。更有区分力的讨论对象是：当前章让读者在什么条件变化后知道要改哪份状态、哪条比较、哪种结构，以及哪项改变已经给了真正替代方案。此项判断需要正文样本支持，不能换成新一轮评分表或“通过审阅”标签。

最终可保留的组合并不矛盾：`连续片段`的关系组织，`二分查找`的查询映射与边界对照，`组合判定`的模型差异，`实战起点`的实现成本比较，加上`边界与答案`更完整的原题合同、局部证明和提交入口。它们应成为新研究中的候选证据，不是自动拼接成一份越来越大的第一章。
