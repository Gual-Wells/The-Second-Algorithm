# 第二算法质量回归：研究结论与讨论方案

2026-10-28。当前算法发布基线为 `4d9fe9024b80fd6abf1ad45e94a966f6d36e2600`。本轮只研究，不改正文、有效协议、代码、出版登记或线上版本。当前文件及跨项目参考身份见 evidence-snapshot.json。用户尚未补充其最不满意的具体段落，因此以下是可由现有正文/工艺验证的诊断，不冒充已穷尽个人体验。

## 结论

严重回归主要发生在产品定位、章界发现和迁移价值：逐步把面向已有计算机基础的算法实战参考，转译成一个低扩散、易解释和验证的小型首章，再在所选四题内部完成审阅。代码正确性和局部证明有所提升，参考面、条件变化与方法选择关系却变薄。不能用较少题数独自证明回归，也不能因若干段落更深便否定整体体验。

上轮根Agent的放行判断有实质偏差：实际做过稿件/源码阅读和语义审阅，但主要问“这四题是否正确、连贯、代码与解释一致”，没有充分问“这个范围和组织是否承担了用户要的实战参考价值”。这不是审阅造假，而是被审命题偏窄。

## 流程根因

1. **取舍目标漂移。** 用户要求补实际C++设施认知，并未要求算法降难度或把首章缩为入门进度。上轮根Agent要求候选比较首章负担，研究记录随后因多个不变量/新结构而退后top-k，再提出四题。这个取舍有理由，但理由主要由编辑框架给定，未经足够产品反证；不能倒写成用户的减量要求。
2. **成熟范围反查在合并中弱化。** `90a59c8:protocol/ALGORITHM_TRACK.md`第5节明确先分析没有参与分类的外题，再反查章界。统一后仍保留“独立反查”字样，但具体动作被压缩，实际审阅先看作者稿，再核同四原题；局部正确性独立不等于上游范围判断独立。
3. **资料使用与目标不相称。** 本轮不是只读题干：读过Codility、MIT/CMU、N4659，根Agent也记录读CP4四页。但新作者/候选研究没有深读本地教材正文，题目合同和条文核对强，教材层面的问题组织、替代方法与条件谱系较弱。书目取得不能等于教材投入生产。
4. **工程门禁被赋予了过多产品含义。** CLI真实验证当前登记/字节/源码依赖/目标退出状态；代码明确不认证语义。门禁没有错报自己能力，错误在最终将其与有限语义accepted合并成整体质量充分的判断。测试应保留，不能用更多断言补偿选题和教材质量问题。
5. **分工并行没有带来目标判断的分离。** 作者、验证者、审稿者实际做了不同工作，也修出了真实错误；他们共享同一选择框架和题目集合，因而可能各自局部合格而共同漏掉产品目标。根Agent仍须持续承担整章编纂与最终判断，不靠新增角色数量解决。

从零重开确实切断旧稿、旧任务状态与旧通过结论，符合用户要求；它没有消除相同编辑框架。应从零的是本次作者稿和任务，不是有效的产品要求、资料能力和成熟工艺。更多取证、反证与未确定项见[process-forensics.md](process-forensics.md)。未找到模型降档、算力不足或平台问题造成本次回归的证据，不作这类归因。

## 第二语言项目的可迁移教训

有效参照来自第二语言最新检出，不拿旧maintenance脏工作树当当前协议。其10/24回归复盘确认新旧教材字节相同、仍同模型且推理设置上调，实际退化发生在逐词补查/协同创作被有缺口的批量集合、短注和自动范文回填替代；校验在缩小集合内自证完整。“真实材料影响故事”也曾被误作现实参与目标充分实现。

最有价值的纠偏有三项：独立原件范围向成品反查；实际候选相较基准的学习增量取优；冻结前反证是否因方便取材/主题整齐/容易表达而降级。其明确区分“起点支架”和“整体挑战上限”，与算法C++不足不能泛化为算法初学正相对应。

不能照搬：每义1–5语境、全义词典覆盖、VIX选择规则等是另一产品合同；算法方法关系自然共享无需禁止。DIGRX候选未采用，压缩收益有限且用户停止；新真实语境方案工程已部署，但首份全章效果尚未验证。不能称这些已解决一切，更不应把每天多候选竞赛、固定反选数或强制多轮迭代引入本项目。[完整跨项目证据及状态边界](second-language-lessons.md)。

## 建议改变的部分：先讨论，不实施

### 1. 固定产品要求，放开章界

在AGENTS/共同协议保留原始读者与能力目标：已有计算机基础，需要系统辨别题目条件、推导和选择方法，主动发现并正确使用C++设施。首章不是算法初学等级；C++说明是实现支撑，不自动决定算法上限。内聚/易读/Q唯一/格式统一均不能自动交换掉关键条件变化和方法比较。章数、题数、长度仍由真实关系研究决定，不设新最低数量。

### 2. 恢复资料驱动的问题关系研究

优先补RESEARCH_DEPARTMENT中可执行的范围反查，而不是复制旧双线。对真正改变方法的条件、不同目标及替代实现，从原题、教材相关节与方法资料形成关系；资料取得和实际读件继续区分。外部挑战应先独立分析再看当前作者分类，可接纳也可合理排除，不为多一个挑战强塞正文。研究成熟后再决定章边界，不能预先将算法结构差异认定为不适合首章。

### 3. 改编纂任务，不只改发布协议

先建立实际推理和实现选择，再抽出必要C++问题主讲。一个完整论证可以服务多种近邻任务；没有额外收益的换皮不扩写，改变正确性或选择的差别不能被归为换皮。保留新稿的扎实证明与真实作答，补回查询复用、方向/无解变化、反例与必要替代。主讲只一次不禁止新题必要的推理和条件回顾；先从作者稿组织上解决，不默认靠折叠、删解释或改UI降低可读性负担。

### 4. 产品验收与代码验收分别落责

现有编译、独立oracle、CI、源码装配、包与部署保护继续承担工程职责。另由承担产品判断的编纂者证明：这份稿使读者能辨认什么、为什么选此法、条件变化后如何换法、实际设施如何选择。不能以审稿者身份、报告accepted或题号链接代替。外题探针若只能靠评审者已有知识解出，不能反称是该章已经教会；须定位到文本提供的依据，缺失如实说明。这不是新增个人水平测试或每日练习任务。

## 最自然的验证实验

先不重做整章或宣布恢复旧稿。用同一“有序边界”小节做工艺试样，保持原题正确、Q唯一和代码验证为共同底座，比较：现有组织；由原始目标与实际资料重新形成的“首次证明+边界可复用查询+改变条件时的选择”组织。

只比较实际读件的学习增量、推理充分性、方法辨别、设施选择与阅读连续性，允许更长或更短。不得先规定必须多少题、多少分、多少字，也不因小试样有效就自动把它发布成正式第一章。先对具体成品讨论，再据有效做法修协议与作者交接。

## 外部教学研究的使用边界

[IES学习指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)支持让完整示例、独立应用和深层解释形成联系；它不是本项目的题量或章长标准，不据此追加用户固定作业。

[Margulieux等2020研究](https://link.springer.com/article/10.1186/s40594-020-00222-7)在265名入门编程学生中发现分目标示例有近期小测收益，但平均已参加考试成绩未显示同等显著改善。这提醒“讲解更分步/局部更顺”不能直接等于长期迁移；不能将该Java入门研究视作用户个人水平或C++算法学习效果的直接实证。

[EPI Judge官方说明](https://github.com/adnanaziz/EPIJudge)把评测框架定位为教材伴随物，提供程序桩、边界/性能测试与本地运行工具；它不是教材充分性的自动判定器。本轮另定向读取本地EPI2015物理198–202页的方法组织：静态/动态、预处理收益、比较关系、库设施和近邻变体。OCR只作组织研究，未拿其代码当新C++权威，未复制商业正文。

这些外部证据支持改进的方向，不直接证明本次回归的唯一成因；本项目因果判断仍以正文差异、生产记录和用户反馈为主。
