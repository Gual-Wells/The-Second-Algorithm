## LC673：饱和为什么保持合法最终答案的精确性

实际新实现先判断 `y > cap-x`，再选择 cap 或 x+y；局部同长度合并与末端结果聚合均调用该函数。所有计数初始为 0/1，经复制与饱和加法后仍在 `[0,cap]`；所以 `cap-x` 可表示，且不会先执行溢出的和。

设真计数为 W，存储计数为 min(C,W)。非负计数满足：

```text
min(C, min(C,x)+min(C,y)) = min(C,x+y)
```

`len` 的比较与更新完全不依赖 ways；更新为更长链时只是复制，等长时只是非负求和。因此逐状态归纳得到 `storedWays=min(C,trueWays)`，末端同理返回 `min(C,trueFinal)`。当前 C 为 `LLONG_MAX`，高于 LC673 保证的 `INT_MAX`，故原题合法最终结果返回精确值。这个证明不需要假设所有较短局部计数也很小；它依赖无负计数、无减法/抵消、长度状态不被饱和值影响。

正文的另一解释也正确：若某个已截断短状态能延伸为全局最优链，它的所有前缀方案可接同一后缀，从而全局方案数也至少达到截断值；在合法小最终值的输入里，这种状态不会参与最终最优长度。若改成带符号计数、减法容斥、取模、按 ways 改变状态选择，就不能转借这份结论。

独立构造合法 241 项：前 80 个递增正值各两份，随后追加 81 个递增负值。前段局部方案数达 2^80，但最后最长链唯一，答案应为 1。以 `-std=c++17 -O1 -ftrapv` 实际运行当前新代码：

```text
before-valid-final-one
count=1
probe_exit=0
```

没有 signed-overflow trap。建议同时保留两个具有不同作用的回归：19 组各三份（最终 3^19，合法大 32 位结果）；63 组各两份（末端合计 2^63，仅用于饱和机制的扩展测试，不声称满足 LC673 最终值保证）。已把建议发给根。

## 逐型实质核对

### 值域容量异常

唯一重复的频次可以大于 2，其余值可缺失。若重复频次 f，则额外副本 f−1，缺失值总数 f−2；因此一旦前缀包含重复值，其总计数一定超过前缀容量，原文的单调证明成立。没有将这个证明泛化到任意多重复值。

`missing_domain` 每轮只计当前左半域中的记录；即使有重复，也因当前总记录数少于容量而能保证至少一边继续欠满。它返回任意缺失，不误称第 k 个缺失。IPv4 全域 2^32 的边界使用 uint64；半开域和差值中点没有上界加一溢出。

### 权重反查

票号 1..总权重配首次累计≥票号，前导/中间/末尾零权重都不会分配票。`partial_sum` 先把输入提升为 i64，再做扫描，纠正了“输出类型宽便足够”的常见错误。整数分布独立于边界逆查询，生成器按引用维持状态；没有用一次随机频率充当正确性证据。

### 三个隐式秩

- 矩阵：楼梯 count 累计按元素重数；行列双有序支持左下扫描与左上/右下取界。逐行 upper_bound 自身只需行序，但整函数的取界仍按强合同，正文明确提醒修改，不会偷偷承诺弱合同整函数合法。
- 数对：D≥0 使左指针最多到 right，自身不进入对数；重复值产生多个零距离索引对。差值在 i64 中形成，标准版 `a[i]+D` 也先提升，INT_MIN/INT_MAX 最大距离 4294967295 不截断。
- 乘法表：每行 min(n,floor(x/i))，不去重复积，乘法前提升；原约束 m,n≤30000 保证计数与乘积安全，未冒称任意 64 位表都可直接套用。

三个 count 通过最小 x 使累计≥k 查秩，而不是要求累计恰好等于 k。`kth_value` 的 `hi-lo` 合同明确；本章 int 元素产生的负/正跨域差值也仍可由 i64 表示。

### 双数组切分

合法区间 `[max(0,k−n),min(k,m)]` 保证另一数组分割也合法；较短数组只递归交换一次。64 位哨兵严格超出 int 元素域，没有与真实值相撞。一个数组可空，总体非空；偶数中位的两项先以 i64 相加。merge 是明确标注的线性不同算法，未冒充 LC4 的对数解。

### 有序 DP 与恢复

前驱在修改 tail 之前保存，来源都在更早下标；严格/非降分别用 lower/upper，保存的链可以真实恢复，不把 tail 当原子序列。信封同宽按高降序，防止同宽延长。LC673 计数与 tail 摘要是不同状态，当前已用上述饱和规则修正局部大计数。

可再紧凑补两句推理，但不构成当前功能阻塞：长度 L+1 的任一严格递增链，去掉末项后得到更小尾值的长度 L 链，所以最小 tail 随长度递增；首次 tail≥x 的前一长度可接 x，而更长状态不能，因此只需替换该位置。正文已有支配含义和正确实现，补这一点可以让“摘要有序”不只停留在断言。

### 加权调度

前驱只在已处理 ends 中查，p 是兼容数量直接索引 dp。CSES 使用 `<start`，LC 使用 `≤start`；同结束时间无需虚构第二排序规则。touching=true 的 LC 合同仍 start<end，正文没有错误宣称允许零长事件。CSES 单日任务与 64 位累计均可处理。恢复方案的方法虽只简述，足以据 dp 选/不选和 p 实现，未宣称当前返回函数已返回任务集合。

### 资源反演

鸡蛋判定的组合递推每次尚未达标时上一 term<n、moves≤n≤10000，乘法粗界 n²，安全结论有原合同限制。覆盖 DP 倒序 e，避免同轮新值污染上一轮；饱和后的 int 加法最多约 20001，在原 floors≤10000 范围安全。floors=0 返回 0，eggs≥1 的前提明确。

## 新增独立极值探针

为避免只复跑作者已有的小数值随机用例，另编 D 盘 `selection-extreme-cross.cpp`，用 GCC 16.2.0、`-std=c++17 -O1 -ftrapv`，返回：

覆盖：

- INT_MIN/−1/0/INT_MAX 上全部 2×3 合法行列非降矩阵，用物化排序核所有 k。
- 这四个极值组成的全部长度 6 数组，物化所有距离、核两版所有秩。
- 两数组各至多五项的全部非降多重集，物化排序核所有 k 与中位。
- 含零权重、两份 INT_MAX 的票号映射与 64 位累计。
- 2^32、UINT64_MAX 半开欠满域，返回结果直接查不在记录中。
- 20 万个互不冲突的单日任务、每项奖励 10^9，预期 2×10^14。
- 三蛋 0..10000 楼层按步长 17，用直接展开 `d+C(d,2)+C(d,3)` 逐次枚举 moves 作独立 oracle。
