## 1. 必修：十进制系数使整数端点零判断失败，实际漏根

函数 `cubic_roots_by_unit_scan` 用 `fl==0` 收集整数端点，否则仅在单位区间两端异号时夹逼。下列是合法原题数学输入：

```cpp
cubic_roots_by_unit_scan(0.1, -0.6, 1.1, -0.6);
```

对应 `0.1(x−1)(x−2)(x−3)`，三个根恰为 1、2、3，均在 [-100,100] 且间距至少 1。本机 GCC 16.2.0，`-std=c++17 -O2` 的独立实际探针输出：

```text
coeff=0.10000000000000001,-0.59999999999999998,1.1000000000000001,-0.59999999999999998
roots=1 0.99999999997089617
```

再试同一数学多项式整体缩放：

```text
(0.3,-1.8,3.3,-1.8) -> roots=1，约3.0000000000291038
(0.7,-4.2,7.7,-4.2) -> roots=2，1与约3.0000000000291038
```

浮点系数与 Horner/fma 求值残差使整数处不再恰为 0；两个在数学上相邻单位端点的根，数值扰动后可落向同一个单位区间，端点同号就被漏掉。不是输出最后一位舍入的问题，而是三根只返回一/两根。现有测试基本采用整数系数与二进制可精确表示的半数，没覆盖此类情况；原套件绿色不能关闭这个功能缺口。

修复不应仅把 `==0` 换成任意固定绝对 epsilon，因为乘整体常数不会改变根，却会改变所有残差。应明确系数规范化、尺度相关的端点零/误差政策，或采用更稳定的三根分隔方案；增加十进制系数、根在扫描端点、整体缩放的实际回归，并同步修改正文对“整数端点直接收集”的说法。不能靠泛称“求值须可靠”而继续把当前符合原题的输入放行。

探针位于 D 盘 task artifact：`boundary-cross-probe.cpp`，未编辑生产源码。

## 2. 小修：时间记录的返回复制成本

`ordered-boundaries` 工程段笼统写“两版时间 O(log n)、额外空间 O(1)”，但 `time_manual/time_standard` 返回 `optional<string>`，要复制结果字符串。metadata 已正确写为 `O(log n+|value|)`、`O(|value|)`。

建议把该句限定为纯数组边界/迭代器查询，并明确字符串结果另加复制成本。正文接着解释了为何返回副本，但不能因此省掉成本表达。

## 3. 小修：元数据与真实设施不一致

`matrix-membership.standardRole.explanation` 写“各行 lower_bound 后核等”，真实 `matrix_row_standard` 使用 `any_of+binary_search`；正文本身写的是 binary_search。改元数据说明即可，无算法问题。

## 4. 可直接补清的合同/证明

- 未知访问示例 `find_unknown_at` 应显式写 `hidden` 非降；本质是找到第一个≥key 后核等。未知长度只是访问政策，不会自动建立谓词单调。代码和测试实际都按此正确前提使用。
- 二维峰当前解释已抓住“中列最大”和某侧存在更高候选。为让连续多轮的证明闭合，可以再点明：被排除的分隔列所有值都低于保留侧的某个候选，形成外侧墙；之后找更大值的路径不会穿回这条较低分隔列。这能解释中列有更高邻居时为何仍可安全缩边，不需另加算法或前置章节。

这些不是要求大改框架；当前问题、注释和必要推理总体已经真实到位，没有靠列名字/模板替代证明。

## 已核的数学与实现细节

- **重复固定点**：左右递归分别剪到 `min(mid−1,a[mid])` 与 `max(mid+1,a[mid])`；允许两个子区间、最坏线性，栈深仍对数，未假称重复输入也 O(log n)。
- **未知域极值**：cap 是可查询的最大下标；可返回 UINT64_MAX，optional 区分真最大值与无解；饱和翻倍和已知端点不重问的逻辑成立。
- **旋转退化**：相等时只缩边，未承诺折半；库先找下降点再查两条有序段，诚实 O(n)。成员命中先返回，缩边不会删掉唯一答案。
- **局部峰/二维峰**：一维不偷换全局斜率单调；二维先取列最大，保证纵向条件，标准版只替换取列最大行号。空输入、单行/列和邻接不等合同有明确去向。
- **矩阵合同**：全局行序的虚拟展平与仅行列有序的阶梯/逐行查找不同；未对弱合同误调 flatten。乘法索引、零列除法处理合理。
- **整数根**：上中点和除法判定覆盖 uint64；x=0 不进除法；sqrt 标准版再用整数不等式修正，不把估计当证明。
- **通用根夹逼**：区间/连续性/有限值/停止原因分清，返回实际夹区，没有因步数上限达到而假报容差。缺陷定位在“进一步找全三根”的扫描包装。
- **字符串成本**：截断比较保持与排序一致的字典序；短词不误认完整前缀，空前缀全匹配。朴素二分 LCP 的最坏字符成本 O(L log L)、建议系统 q² 因子与返回拥有字符串均有交代。
- **凸定位**：开扇形保证 partition_point 结果可以取相邻两射线；边界射线另验线段范围，内部对角线不误报 ON。差在64位中形成，两个乘积之差粗界 8×10^18 在 int64 内；未用多块绝对面积和放大预算。
