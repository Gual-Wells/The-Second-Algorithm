## 当前建议

在下列三个候选群中，优先建议“把可行性变成边界：从有序数据到答案搜索”。这是工作主题，不是先行锁定章名。关键学习线是：确定搜索域 → 明确单调布尔判断及边界语义 → 保持不变式并严格缩小区间 → 判断返回值的题目含义 → 推导判定成本和数值上界。

理由不是二分“基础”或“常考”，而是它同时满足以下实际要求：LC34提供可直接比较的手写与标准设施实现；LC875把数组下标域转到不需存储的整数答案域；CSES Factory Machines要求独立标准输入输出作答，并揭示搜索上界的选择如何影响判定累加的数值安全。三题共享边界方法，但每次都必须重新证明题目判定。这使第一章有深度，而不依赖很多互不相干的算法。

有界Top-k是强备选。如果整合后的首章目标更偏“真实维护一个结构，并准确选择标准设施”，它可以优先；要收窄为保留当前最优k个候选，不一并展开哈希计数、quickselect全家族、调度、双堆和图算法。

## A组原题证据：从显式序列到隐式答案域

### LC34：Find First and Last Position of Element in Sorted Array

[原题](https://leetcode.com/problems/find-first-and-last-position-of-element-in-sorted-array/description/)实际取得题意、空数组示例与全部约束：非降整数数组；长度0至100000；元素及目标在正负10^9内；目标不存在返回`[-1,-1]`；要求O(log n)。

教学价值：一般“找到一个相等值”无法回答重复区间。分别找首个`a[i] >= x`与首个`a[i] > x`，天然暴露左右边界、尾后位置以及“未找到”的合同。使用`target + 1`找右界并非必要，且会把可复用实现绑定到整数可加且不会越界的条件。当前题目上界为10^9，不能谎称其`target + 1`本身必然溢出；应讲清通用实现不需要这个额外前提。

建议真实实现：手写边界循环；标准设施`lower_bound`+`upper_bound`，再主动指出`equal_range`直接给等价区间。`binary_search`只返回存在与否，无法直接代替本题结果。三者不必各抄一整套重复提交代码；保留完整可运行的两条实现路径，并就地给出`equal_range`接口替换及合同。

条件变化：空数组、全相等、目标比全部元素小/大、无相等但落在内部。边界位置始终可以等于n；它不是能解引用的元素。算法新增解释是边界本身，不需要先安排一章“C++迭代器大全”。

### LC875：Koko Eating Bananas

[原题](https://leetcode.com/problems/koko-eating-bananas/description/)取得题意及约束：1至10000堆；每堆1至10^9；`piles.length <= h <= 10^9`；每小时只处理一堆，剩余不足速度也消耗该小时；求最小正整数速度。

本次推导：速度k的小时需求是逐堆上取整之和；k增大时需求不增，因此`hours(k) <= h`形成首次为真的边界。合法速度域可取`[1, max(piles)]`；原题`h >= 堆数`保证右端可行。若只把全部香蕉总量除以h，遗漏“一小时不能换下一堆”的合同。若把h改成少于堆数，则原题的存在性论证失效，不能继续返回原上界冒充答案。

实现与数值价值：逐堆需求总和可到10^13，32位累加不够；64位完整累加在原题范围内安全，也可在小时数超过`h`后直接判不可行。原题单个`pile + k - 1`在32位有符号范围内，但不能因此把整个sum也写成int。用`pile/k + (pile%k != 0)`可避免把向上取整绑在加法上界上。`std::max_element`可求搜索上界，它只替代求最大值，未替代整题搜索。

标准设施边界：C++17没有直接把巨大隐式整数域交给`lower_bound`的一键接口。为了凑库版本而分配10^9个整数或实现自定义计数迭代器，均偏离本题。这里保留手写核心搜索，准确说明存储/求上界设施即可。

### CSES 1620：Factory Machines

[原题](https://cses.fi/problemset/task/1620)取得完整输入输出和约束：1至200000台机器；目标产品数1至10^9；每台耗时1至10^9；机器并行；输出最短整数时间。原题同时展示1秒时间限制，但不能由此声称任意C++17实现已经通过。

本次推导：时间T内产量为`sum(T/k_i)`；可行性随T单调。最快一台单独生产全部目标给出右界`min(k_i)*target <= 10^18`。必须同时推导累加上界：若只测试这个紧上界内的T，每个商至多为target，故总和至多`n*target <= 2×10^14`，64位完整累加安全。若为了方便改用固定通用上界10^18，则存在`k_i=1`的输入，商之和可到2×10^23；不能仍说“long long总够”。后一路径只需知道是否达到target，可在达到后停止或按剩余需求做饱和判定。这个差异比重复列几题相同的二分更有价值。

与LC875的联系和变化：同样寻找首次可行，但一个判定是逐项向上取整的资源消耗上限，另一个是逐项向下取整的并行产能下限；边界不需要存成数组。两题不能仅因循环外形相似就共享未经说明的判定函数。

实际作答要求：完整`main`解析n、target和机器时间，输出一个整数；算法接口不保留题外全局状态。既给LC函数/类接口，也给CSES完整提交，避免把参考函数误标成可直接提交所有平台。

### Codility MinMaxDivision：作为范围外沿，不立即纳入必修

[原题](https://app.codility.com/programmers/lessons/14-binary_search_algorithm/min_max_division/)取得C++接口`int solution(int K, int M, vector<int>& A)`及约束：N、K为1至100000；M为0至10000；元素处于0至M；划成K个连续块，允许空块，最小化最大块和。页面重复显示多语言版本，本次只算一个题目。

它引入了真正需要额外论证的贪心判定：给定块和上限，非负条件使尽可能向当前块装元素可最小化所需块数；允许空块使“至多K个非空块”足以对应K个块。若改成允许负数，最优值对上限的可行性本身仍然单调，但这个线性贪心判定可能失效；例如`[5,-4]`上限1时，先看到5就判不可行会错。不要把“允许负数导致不能二分”作为错误结论。

不立刻必修的原因：它不是再换一个判定公式，而是引入连续分段、贪心最优性与空块语义，可能让首章出现第二条大证明线。可以作为研究已读、待后续教学反馈决定的扩展；不能把它记作已经教学。

## C组原题与课程证据：有界Top-k是强备选

### 一组可收窄的任务

[LC215](https://leetcode.com/problems/kth-largest-element-in-an-array/description/)本轮取得：1<=k<=n<=100000；值在正负10000内；求排序后第k大，重复值计名次，追问不整体排序。保留k个最大元素、以其中最小值作为淘汰边界，直接引出小根堆；不应误用默认大根堆保留k项。

[LC703](https://leetcode.com/problems/kth-largest-element-in-a-stream/description/)取得：初始长度0至10000，1<=k<=初始长度+1，值在正负10000内，最多10000次add。它要求维护对象状态，并在每次add后返回第k大；构造时可能只有k-1项，但首次add后就有足够项。这是原题保证，不能为了“通用接口”不加说明地假定构造时已满k。

[Stanford CS106B Data Sagas，2021-02-25更新页](https://web.stanford.edu/class/archive/cs/cs106b/cs106b.1214/build/assignments/6-data-sagas/)实际读到HeapPQueue部分及Streaming Top-k部分。该作业先实现二叉堆，再作为堆的使用者完成流式top-k；要求O(k)空间、O(n log k)时间，返回按权重降序的记录，记录不足k时全返回。它提供了“关键结构手写→作为抽象设施使用”的直接教学先例，但作业为训练动态内存而要求手动分配，本项目无需继承该教学限制。项目可用vector存储堆，手写上浮下滤即可。

### 首章可行范围与必须阻止的扩散

候选主线：一次输入/在线输入如何保留前k名；手写小根堆及不变式；标准heap算法替代结构维护；priority_queue封装；批处理时识别nth_element的另一种选择。首个真实任务可用LC215，随后LC703改变在线合同，再以自定义输入流的完整main验证输出前k项的接口。

库和手写关系应做清：`pop_heap`把堆顶移到范围尾部并维护较短堆，它不删除vector元素；`priority_queue::pop`没有返回值；优先级比较器及默认方向不能靠“看起来像sort比较器”猜。自定义记录是否同分稳定、需要输出顺序还是只返回集合，必须来自每个任务合同。

`nth_element`不是手写堆的同方法库版，且不保证两侧整体有序；C++17不带执行策略的重载平均线性，不能宣传最坏线性。`partial_sort`/整体sort作为方案选择面可以主动指出，不应全部展开成首章必修实现。LC215允许值域较小，计数法还是另一个可行算法；本次没有把“不同方法存在”变成把所有方法讲全的义务。

[LC347](https://leetcode.com/problems/top-k-frequent-elements/description/)也已读取：长度1至100000；值正负10000；k不超过不同值个数；答案唯一，返回顺序任意，追问优于O(n log n)。它要先把值转换成频次再选择，触发计数表示和静态聚合。因此本次把它放在外沿：不要用“也是Top-k”把哈希/桶排序整块一起引入首章。

[CSES Room Allocation](https://cses.fi/problemset/task/1164)已读取：至200000位客户，1<=到达<=离开<=10^9，离开日必须严格早于下一次到达才可复用，输出最少房间数及按原输入顺序的房间号，允许任意有效分配。它虽可用小根堆，却新增资源分配贪心、原序恢复与非唯一解验证，不应作为Top-k章节顺手添加的“堆变体”。

## 已核的C++17设施合同与Q触发面

本次使用N4659（2017版工作草案文本），没有以当前C++26草案的接口或强化约束代替C++17。以下是实际打开的条文；这些阅读不是编译或运行验证。

- [二分算法总则](https://timsong-cpp.github.io/cppwp/n4659/alg.binary.search)、[lower_bound](https://timsong-cpp.github.io/cppwp/n4659/lower.bound)、[upper_bound](https://timsong-cpp.github.io/cppwp/n4659/upper.bound)：前置条件是对具体表达式已分区；完整排序是常用充分条件。比较次数对数，非随机访问迭代器的步进仍可能线性。上下界比较器参数方向不同；equal_range要同时满足两种分区条件。
- [sort等](https://timsong-cpp.github.io/cppwp/n4659/alg.sort)：sort改写范围且比较次数O(n log n)；不能把某个实现的introsort作为标准指定算法。partial_sort只保证选出的前段有序，其余次序不指定。
- [排序关系](https://timsong-cpp.github.io/cppwp/n4659/alg.sorting)：一般排序类Compare要求严格弱序；不应写`<=`作比较器。二分条文有其单独要求，不能将sort与所有二分调用的比较器要求粗暴合并。
- [heap操作](https://timsong-cpp.github.io/cppwp/n4659/alg.heap.operations)：push_heap需要前n-1项先为堆；pop_heap需要非空堆，结果较短范围继续为堆；make_heap线性比较上界。维护同一范围时必须使用一致排序关系。
- [priority_queue](https://timsong-cpp.github.io/cppwp/n4659/priority.queue)：默认底层vector、默认less，top返回常量引用，pop返回void。需要取出值时先保存值，再pop；不能把top引用当成独立取出的值跨pop保留，也不能写成pop返回元素。
- [nth_element](https://timsong-cpp.github.io/cppwp/n4659/alg.nth.element)：保证目标位置及两侧关系；通常重载平均线性，未承诺完整排序。

若采用A组，必要Q应按实际问题语义键登记，交由整合者去重和赋号：

1. 函数参数为何用`const vector<int>&`：只读借用、避免复制、调用期间寿命；不要借此开一章所有值类别。
2. `[first,last)`、`end()`、迭代器解引用与位置差：尾后不指向元素；先判尾后再读取；迭代器差不是无条件int。
3. `lower_bound/upper_bound/equal_range`的返回合同、比较方向、分区前提及复杂度。
4. 搜索变量、累加变量与表达式实际类型：先提升再乘、整数除法/余数、上界推导；Factory Machines需把搜索上界和累加上界联系起来，不能只报一个类型名。
5. 仅当确有代码需要时解释lambda捕获、谓词参数与寿命；不为复用一个循环先强迫读者学习泛型框架。

这些是待归并的问题语义，不是已分配Q。Q只承载C++知识，题目的单调性、不变式、上下界与贪心正确性仍应在实际算法处完整论证。
