## 最终建议：边界章的任务与界限

工作题名可继续修订。首章建议围绕三个推理台阶组织，不以一定要塞满多少题作要求。

1. **LC34：值的出现区间。** 本次直接读到非降序输入、空数组、缺失返回`[-1,-1]`、O(log n)要求、n至100000、整数在±10^9。手写首个`>=target`与首个`>target`的位置，得到半开出现区间，再适配题目闭区间输出。`lower_bound`、`upper_bound`、`equal_range`有真实代码对照；缺失与`end()`要先检查再解引用。不能把`binary_search`的布尔结果说成位置，也不应靠`target+1`去拼出第二边界。算法新推理在主稿解释，库参数、迭代器和返回物在首次使用处完整主讲。
2. **独立成本判定：LC875与CSES1620中选一主讲，另一保留为条件迁移或验证探针。** LC875是各堆向上整除求总耗时，CSES1620是各机器向下整除求总产量；前者求最小速度，后者求最短时间。它们共享“第一个可行答案”，判定式和数值上界不能互换。LC875在原题约束下总小时数可达10^13，宽累计直接对应数学量；`pile+speed-1`在其各自至10^9的原题约束下最多1999999999，并没有必然超32位有符号上界。CSES1620可行上界`m*target`至10^18（m为最快周期）；结合每台周期>=m，紧搜索内精确产量总和至多`n*target<=2*10^14`，64位可以安全累计。提前达到目标即返回可减少工作；若公开helper允许脱离紧搜索的任意非负64位时间，则还需按较宽合同保护累计，不能把该外部极大候选冒称紧搜索自身溢出。二者都无必要排序，不得为使用`lower_bound`而先排序或造一个长达10^18的数组。
3. **Codility MinMaxDivision：边界存在不等于判定正确。** 本次补读官方原题C++签名与约束：非负数组，N/K至100000、值上限M至10000，恰分K块且允许空块，目标最小化最大块和。给定候选上限后，尽量延长当前块的贪心需证明得到所需块数最少；只证明“上限变大更容易”不够。允许空块使“最多K个非空块”与题面K块相容；不能偷换成其他平台“恰K个非空块”的合同。全零、K>N等边界应自然处理。负数例`[4,-3]`与上限1可用来说明单个元素超上限就判失败的判定已失效，但“存在可行分割”的单调性本身仍在：错误的是这个贪心oracle，不是单调定义突然消失。

此路线的三种条件迁移依次是：已存储的有序值→没有数组的整数答案域→单次判定本身也需算法正确性。它比仅多做十个`lower_bound`变形更有实战迁移价值，同时只需要一套边界缩减思想。手写代码只实现真实核心，不扩成所有二分模板的比较。

建议主任务实际取LC34、CSES1620、MinMaxDivision。理由是CSES1620补充独立OJ标准输入输出和真实64位/饱和计数合同；LC875作为补充迁移对照，不必重复一整段相同搜索循环。若工程发现64位题令首次Q负担过大，可改LC875为主，但要记录真实范围变化，不把两者都默认为已承载。

设施角色必须如实：LC34有整段查询替代；答案域搜索保留手写，`min_element`/`max_element`/`accumulate`只协助界限与累计选择，不是整题库解。C++17为基线，不为展示`ranges::iota`或`midpoint`强行升标准。N4659的`partition_point`要已有分区范围，不能拿它当任意整数域`first_true`。直接查询的数组“有序”是充分条件；库`lower_bound`实际只要求针对查询条件分区，完整排序不是最弱合同，但首章不能因此混入大量无序特例。

首章应排除：旋转数组/山峰、矩阵多维搜索、浮点精度二分、动态前驱与删除、带权分割DP、负数分段优化、通用自定义迭代器。它们可能改变可排除依据或判定，不属于这一章自然免费扩展。

待整合者统一分配的Q语义键：只读引用与复制、半开范围/迭代器末端、size与有符号下标/差值、整数累计及中间表达式类型、lambda与谓词、算法返回物和容器接口、`accumulate`初值决定累计类型（仅最终代码使用时讲）。比top-k路线少了随机性设施、两种结构及持久对象状态。算法循环不变量本身不拆成C++ Q。

核验建议：LC34小数组有序多重集合与目标穷举，独立线扫对照两边界与无解；答案域小实例枚举所有候选答案，对比最小可行值，同时验返回值可行和前一值不可行；MinMaxDivision用独立枚举切点/小规模DP核对贪心所需块数和最终优化值，尤其零、K>N、单元素、阈值恰好等情况。CSES1620使用最大合法输入核对上界和提前返回路径；不以二分版本互相一致代替oracle正确性。

新增实际读取：[Codility lesson14目录](https://app.codility.com/programmers/lessons/14-binary_search_algorithm/)、[官方BinarySearch PDF](https://codility.com/media/train/12-BinarySearch.pdf)3页文本（数组末个不大于目标、结果二分、覆盖孔洞判定）、[MinMaxDivision原题](https://app.codility.com/programmers/lessons/14-binary_search_algorithm/min_max_division/)题干、例子、C++接口与约束。同一题多语言重复段落只算一次；官方Python代码不能不经合同分析照搬C++，它的中点写法也不是C++防溢出保证。

## 备选top-k路线的深入合同分析（最终未首推）

### 主任务A：数组第 k 大，先明确所需的顺序信息

原题：[LC215](https://leetcode.com/problems/kth-largest-element-in-an-array/description/)。题意、两个例子与约束已实际读取：`1 <= k <= n <= 100000`，值域为 `[-10000,10000]`；重复值参与排序名次，目标不是第 k 个不同值。

原创参考接口应明确：1基 `k`，返回一个值；离线算法允许原地改变数组；调用者若需保留原输入，复制的 O(n) 存储单独计入。不要声称平台题面替所有参考接口约定了修改政策。有效 `k` 由原题保证；如另设通用接口接受无效 `k`，必须明确失败合同和测试，不能默默越界。

实质方法：完整排序作容易检查的基线；只保留目标所在分割的一侧；维护容量为 k 的最小堆；利用本题很窄的已知值域进行计数选择。计数选择是条件不同的算法，不是 `nth_element` 的包装，也不能从本题外推成任意整数通用解。它可以成为短而完整的条件分支，若体量过大则明确列为已研究未承载，不假称核心方法穷尽。

手写选择建议用 `< pivot / == pivot / > pivot` 的三路原地分割；全部相等或大量重复值应整块消去。教材必须解释边界如何移动、每轮为何缩小，不能从仅适用不同元素的课堂伪代码直接搬成重复值实现。随机化需说明随机选择来自算法，不能以“输入通常随机”代替保证；期望 O(n) 与最坏 O(n²) 分开。固定中央位置枢轴也不能仅凭随机数据测试就声称期望线性。

设施路径使用 C++17非执行策略版 `std::nth_element`，对应选择目标而非保证与手写版本内部算法相同；它给目标位置和两侧顺序关系，不把两边排好。取第k大可用升序位置 `n-k`；这与“取前k个元素”的切分边界 `begin()+k` 要分别说清。`k==n` 时不能把 `end()` 当有效答案位置解引用。

### 主任务B：选前 k 个记录，比较的是键而不是整个对象

原题：[LC973](https://leetcode.com/problems/k-closest-points-to-origin/description/)。已读题意、例子和约束：`1 <= k <= n <= 10000`，坐标在 `[-10000,10000]`；返回点的次序任意；原题保证所选答案唯一（输出次序除外）。

需要先证明距离平方与非负距离保持次序，避免为比较引入不必要的平方根。原题数值上界是 `2*10^8`；如果原创接口采用更大坐标范围，必须重新推导并在乘法之前扩宽，不能把超出原题的溢出担忧伪装成原题必然发生的问题。记录中存在相同距离时，比较器允许等价；不必为了调用排序强行加坐标平局排序，但如另设确定输出合同必须明说。

沿用A的选择理由，新增的是记录键、比较器、返回集合与排列不唯一。可运行实现宜提供手写选择与 `nth_element` 两条有区分力的路径；如果为控制规模只在A完整实现泛化核心，B必须有真实调用和平台作答，而非仅写“同理”。在库调用处解释 lambda/函数对象、按引用读取点的意义。不要把面向读者的主干扩成泛型库设计课。

`std::partial_sort` 应作为输出合同改变后的比较：若现在要求“前k个还要按距离排列”，局部排序才完成所要求的额外顺序；不能声称LC973要求排序，或把它和 `nth_element` 的后置条件混为一谈。若正式承载此变体，给它独立任务/验证合同；否则只做设施选择说明，不登记虚假的完整实现。

### 主任务C：数据逐次到达，只维护会影响第 k 大的候选

原题：[LC703](https://leetcode.com/problems/kth-largest-element-in-a-stream/description/)。已实际读类接口、两个例子和约束。初始化序列可空；`1 <= k <= nums.length+1`，所以初始化时可能只有 k-1 个值，但第一次 `add` 后已有至少 k 个；最多10000次 `add`，值与新值在 `[-10000,10000]`。

核心不变量：当前堆保存已见数中最大的 `min(k, seen_count)` 个（按重复次数）；满 k 后最小值就是第k大。必须论证为何丢弃较小候选不会影响未来结果，比较器方向由“需要淘汰谁”推导。使用全部已见数据重排虽能求值，却没有体现有限候选维护；应把它放作验证参考或清楚标代价的基线。

手写路径用 `vector<int>` 存储有限最小堆，真实实现上滤/下滤、构造与加入，不重造动态数组。设施路径用 `std::priority_queue<int, vector<int>, greater<int>>`；`top()`只观察，`pop()`只删除的角色须在第一次使用时解释，不能写 `int x = q.pop()`。`make_heap`/`push_heap`/`pop_heap`可比较开放区间与容器适配器的控制层次，但不能把调用库堆算法命名成手写下滤。首章不需要所有三层各复制一套完整实现。

## 规模与组织建议

## 核验交接：针对真实差异设检验

这些是下一阶段必须落实的检查方向，本文没有编写或运行实现，不能登记为已通过。

- A：对小数组穷举（含重复、负值、全部相等、单元素）及每个有效 k，用独立完整排序得到值；手写分割还检查多重集合不变和选择后两侧合同。用有序/逆序/重复密集和100000规模验证终止与资源边界；随机实现固定多种种子重放，不能用计时证明渐进复杂度。
- B：用独立排序距离得到阈值；检查返回数量、点的多重集合来源和没有遗漏更近点。不对任意输出顺序作文本相等；平局跨阈值测试如超出原题唯一答案保证，应明确标为原创接口扩展。`partial_sort`若承载，额外检查选中前缀排序。
- C：逐步用全部已见值独立排序求第k大；每次加入后检查容量和堆合同。覆盖空初始化（仅k=1合法）、k-1初始化、重复值、单调增减、负值、连续新最大/新最小、多对象互不污染。不能把违反原题的“第一次add后还不足k”当平台本身的无解情形。
- 分别编译所有声明为C++17的路径，结果验证必须实际调用每个实现。代码形成后再做独立语义审阅；两种快选互相相等不能代替独立参考。
