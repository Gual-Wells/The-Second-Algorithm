## 跨题归并得到的关键设计

1. **容器选择必须落实到修改和查询。** 不单独产出“vector 是动态数组”之类低信息内容；用预知数量填充、擦除中推进、统计/查询/有条件更新等实作表现区别。成员 `find` 与通用 `std::find` 的差异是索引访问复杂度与键语义，而非调用长短。
2. **把算法与容器修改分开。** remove 只返回新的逻辑尾部；范围大小仍在。尾部对象有效但值不作保留语义承诺，不能断言每个实现都复制某种固定尾部。再由对应容器 erase。
3. **泛型接口不能靠错误 tag 假装成立。** 自定义 iterator 要有实际所需操作/复杂度；single-pass 输入不能先 distance 再读；output iterator 不能写成 `out++ = value`。join/zip 的多种输入容器正好构成同一实现族。
4. **用所有权与范围长度统一本组视图题。** string_view/span 是借用接口；view 是范围适配概念，含 owning_view；borrowed_range 解决某类范围临时对象销毁后的迭代器可用性，不能保证原始存储还在。filter_view 还可能依赖父 view 对象，不是得到 iterator 后可随意丢掉 view。
5. **文本题先定义可见输入政策，再选 API。** 是否保留空字段、空白的定义、hex 奇数尾处理、是否允许前导加号/空白、数值后缀是否允许等，确实对应不同题型；它们不是额外的形式化免责声明。
6. **持久数据格式与内存表示分开。** Cookbook 有先讲简单对象、再按字段/长度处理非平凡对象的正向设计，但“可按字节复制”不能推出跨编译器/架构可移植文件。教学实现需要字段大小、长度与读入成功语义；不必先造庞大序列化框架。
7. **进阶训练由实际作业补足，而非只有短代码。** CS106L HashMap 将迭代、const key、访问接口、复制移动、rehash 等串起来；TDDD38 deque 强调分块存储与元素地址稳定。后者明确简化异常安全和逐元素构造/析构，不能据作业完成声称掌握标准容器所有要求。

## 独立代码实验

`library_boundary_checks.cpp` 是本组新写的 C++17 小实验，`library_views_checks.cpp` 是 C++20 小实验；不复制教材整段参考答案。现有 GCC **16.2.0** 编译、运行均通过，输出与 flags 记录在 `experiments.json`，二进制位于 D 盘 `.local/cpp-research/library/`。

C++17 实验覆盖有界 view 与 C-string 接口的正常域反例；空/单遍 join；异构 zip 与数组输出；不重叠分组；remove/erase；try_emplace 重复键不消耗 move-only 实参；查询/默认插入；reserve不改变size；accumulate 初值类型；严格 from_chars；cctype 有效输入域。

C++20 实验覆盖 vector<bool> 代理与快照、惰性 filter 与能力下降、临时 vector 的 owning_view、borrowed_range/ranges::dangling、span 的元素 const 性。后者包含当前标准库的修正实现状态，**不把 GCC16 的成功推广成所有原始 C++20 实现都具有同样支持**。

没有运行未定义行为来预测输出；没有把两份小实验说成完整 STL 测试套件。C++23 的 adjacent、chrono 时区数据等尚未执行本地复现。

建议先将“容器与范围实作”“文本处理实作”“流与文件实作”作为可调整的编写切片，先补足数据结构任务中的实际 API，再输出精简的正向模板与必要变种。可借鉴教学作业做少数长实作，但默认任务应直接可记忆与观察实现，不能变成课程式铺垫。本文本身不承担教程正文。
