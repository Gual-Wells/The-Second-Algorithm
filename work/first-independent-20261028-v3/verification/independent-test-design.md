# 新第一章：独立核验设计

测试权威：`tests/cpp/interval_decisions_test.cpp`。此设计依据本轮 `research/implementation-contract.md`，先于核心实现编写；没有读取旧正文、旧tests或旧验证结论。研究报告已经参与章界建设，因此本测试不继续冒充独立范围反查；它承担独立模型与实际实现核验。

## 模型与可区分的失败

| 被测能力 | 独立模型/合法见证 | 能识别的区别 |
|---|---|---|
| 并集/有序插入 | 对所有区间建立闭相交图，求连通分量的端点包络；插入后重新建图 | 未按输入顺序、链式连接、单点、接触合并；没有复写被测排序扫描 |
| 包含存在性 | O(n²)两两包含比较 | 同左/同右端点排序政策、原序回写；遵循无完全重复区间合同，不假装测了合同外重复语义 |
| 峰值负载 | 对每个原端点直接求全部区间在该点的成员关系与负载总和 | HalfOpen/Closed同刻差别、单点闭区间、64位累计；没有事件排序oracle |
| 三版房间分配 | 直接最大并发为最小数值；逐原输入下标核房号及同房两两兼容 | 最优房数、任意合法编号、原序、三堆真实行为；不以三版相等代替独立正确性 |
| 单资源选择 | 枚举全部子集，逐对兼容求最大数量；见证原ID唯一且兼容 | 数量目标、端点严格性、零长闭任务、选择回溯/索引错误 |
| 固定k资源选择 | 枚举全部子集，端点直接并发深度≤k判可着色，并求最大数量 | 找最大兼容前驱与错误使用最早释放资源的差别；k=0；没有另一份同贪心reference |
| 最少命中点 | 枚举输入端点的所有点集，检查每个闭区间被命中 | 目标与数量选择不同；闭端点接触、重复、单点 |
| 最少片段覆盖 | 枚举区间子集；检查[0,T]全部基本单元的内部及边界，使用二倍整数坐标 | 连续实段覆盖而非仅整数点覆盖；缺口、零长不能推进、无解必须清空部分见证 |
| 手写/标准前驱 | 对排序ends的前count项线性数满足严格/非严格谓词的元素 | count前缀、重复结束、空前缀、等值边界；不互相当reference |
| 两种带权计划 | 枚举全部子集、两两兼容并直接累加收益；核计划原ID、真实收益与最优值 | 不是另写同一DP；零收益、多解、原序、端点、64位总收益 |
| 最多k项带权收益 | 同一子集枚举，只有兼容且子集大小≤预算时参与最大值；每个小案例核所有预算0..n | 与预算DP转移无关的oracle；区分最多/恰好、零预算、错误读取本预算层而超用名额 |
| 离线最短覆盖查询 | 对每个原序查询扫描所有区间，求闭整数长度最小值或-1 | 查询重排/回写、重复查询、过期堆顶、闭单点与长度+1 |

测试同时检查调用者输入保存。见证不强求唯一选法、房号或排列。子集oracle仅用于小规模；大规模用有解析结果的构造，不让指数枚举冒充性能测试。

## 样本边界

- 穷举端点{-1,0,1,2}上所有合法区间多重集合，大小0至5。Closed含单点；HalfOpen排除空区间。用确定性旋转/逆序使原序不总等于排序序。不宣称穷举所有排列。
- 固定种子随机样本两种端点政策各900例，n从0至9，端点集中[-4,4]并保留重复；HalfOpen相等端点扩为正长。收益有0、不同收益和10^9集中情形。
- 定点样本包括接触端点、重复区间与闭单点、固定k尾链反例、覆盖最早结束反例、数量/收益竞争、±10^9端点。另单独核空查询及LC452原题完整int32端点范围；该函数只比较端点，不把全局±10^9长度/负载合同扩大到其他接口。
- n=200000构造包括逆序互不重叠区间与完全重叠区间。检查三堆、大输出形状、查询、计数、DP与2×10^14负载/收益。耗时只报告实测，不设环境无关的秒数通过线。规模样本不构成正确性枚举替身。
- 预算DP新增四个定点小案例：三个互相兼容的闭单点/半开正长活动（预算1不能累加多项），以及完全冲突的两政策样本（预算大也不必选满）。按LC1751的单项≤10^6限制构造预算版jobs；原无预算收益的10^9溢出检查保持原值。
- 两政策分别运行n=1000000、k=1的逆序正长活动，答案为最大单项10^6；以及n=1000、k=1000的全部兼容/全部冲突构造，答案分别为10^9和1000。二者均满足nk≤10^6，不把原其他helper的n≤200000限制错误移植到新API。预算版另测空输入、k=0及不修改调用者jobs。

## 独立推理核对：多资源尾链

固定k数量选择按任务结束时刻处理，状态是每个已使用资源的尾时刻。不能只保持一个最早空闲资源。对于当前任务[5,6]，若资源尾为1、4，应消耗4而保留1；后续按结束时刻遇到[2,7]时，尾1仍可接它。该反例已列定点输入，并由子集深度oracle求最优值。

合法性方面：同一资源始终形成按兼容条件连接的时间链，若返回子集深度超过k即失败。最优值oracle用区间的最大并发等于最小所需资源这一结构事实，不套用正在验证的“最大兼容尾”选择规则；前者由按开始时刻着色达到深度下界证明，后者还需要自己的交换论证。

独立推演得到一套成立的完整归纳框架：将尚未使用资源也看成空链，维护一个全局最优方案，使每条资源链的已处理前缀与贪心完全一致。空链在证明中比所有实际释放时刻更早；代码无须制造数值哨兵。

1. 当前任务a按结束时刻最早。若一个一致最优方案选了a，则a必是其所在链h的第一个未处理任务：其他未处理任务结束不早于a，不可能先于a并仍兼容（HalfOpen有正长度，Closed即使单点也要求严格分离）。
2. 若贪心能接a并选最大兼容尾g，而最优中a在另一链h，则h的尾不晚于g。交换g、h全部未处理后缀：g能接a；h的前缀不晚于g原前缀，所以仍能接g原后缀。没有改变任务集合、数量、唯一性或链内部次序，且已固定前缀保持原样。于是可使最优也在链g接a。
3. 若最优原先没有a，考虑链g第一个未处理任务x。用a替换x，因end(a)≤end(x)，前缀和后继仍兼容，数量不变；如果g没有未来任务，直接插入会超过全局最优数量，故这种情形不可能发生。由此也能使最优在g接a。
4. 若贪心拒绝a，则各k条前缀均不能接a；若一致最优含a，按第1点它应是某链第一个未处理任务，和不可接矛盾。因此拒绝也保持一致最优。

这证明存在性与最优性，不只是“保留更早空闲资源更灵活”的直觉。端点相等必须贯穿整个链兼容谓词，Closed单点不破坏第1点，HalfOpen空任务被合同排除。测试oracle没有使用这套尾链贪心证明来生成最优值。

另外独立核对“最少房间=最大并发”结论：按开始时刻处理，若必须新开第r间，已分配r−1间的尾任务都已开始，且结束时刻在Closed下≥当前开始、HalfOpen下>当前开始。它们和当前请求在该点同时活跃，形成r的下界；算法又构造了r间的合法分配，所以达到该下界。闭单点同样成立。固定k的子集oracle借用的是此区间图结构事实，而非最大兼容尾的选择规则。

本次预算扩展时正文已经落盘，实际读取了 `fixed-resource-exchange` 从不变量到三种情形和归纳结论，以及最少房间的并发下界段。正文已具备上述尾链交换框架，且明确Closed单点与HalfOpen正时长前提，数学论证成立。曾向root指出一个应精确化的措辞：互换旧人员q、r后缀时，“r原首场开始不早于t_r，因此不早于t_q，故可接”对Closed应保留严格性。root已实际改为原首场与t_r兼容（半开≥、闭>），t_q≤t_r保证同一兼容条件仍成立；我再次读取修改后的原段，严格性缺口已补。该定点证明核验不能扩大成全章通过。
