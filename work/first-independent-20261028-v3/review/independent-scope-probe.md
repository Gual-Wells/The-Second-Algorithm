## 2. 独立形成的问题关系

“输入是区间”不足以决定算法。上述原件至少给出以下几条真正改变目标、状态或证明的关系；以下方法说明是读件后的数学分析，不能理解为对应题面附有官方题解。

### 数量、删除与收益：一个排序键不能统一目标

P1的单位价值、完整占用、单资源，使最早结束的可选项能够替换某个最优解的第一项而不压缩后续可用时间。P2的删除数直接为n减最大保留数，几乎不增加前置，应作为已得结果的实用复用，而不必重讲整套证明或另造一章。

把目标换为收益，最早结束不再保存最优值：自行构造半开模型 `(1,3,1)、(3,5,1)、(1,5,10)`，数量贪心得2，收益最优为10。反过来，单项最大收益优先也不对：`(1,5,9)` 会挡住价值各6的 `(1,3)、(3,5)`。这不是整数类型或边界修补，而是状态和论证改变。

对于按结束排序的加权问题，可以令 `F[i]` 是前i项的最优收益，`p(i)` 是可与i衔接的前缀长度，则有 `F[i]=max(F[i-1], value[i]+F[p(i)])`。状态足够的原因是“选i”后所有先前选择都在兼容前缀内，而前缀最优状态已包含它们的竞争；不能只用“DP模板”代替这一步。U1另给按时间倒扫的价值状态，说明结束排序前驱DP不是唯一组织法，不应把坐标压缩或二分函数本身当作算法本质。

P10与P11是有区分力的一对：前驱分别要求 `end < start` 与 `end <= start`。在有序结束序列上，这正好改变 lower/upper边界选择，而不是统一写一个“二分上一项”。端点必须先由原题合同确定。[Projects](https://cses.fi/problemset/task/1140/)、[Job Scheduling](https://leetcode.com/problems/maximum-profit-in-job-scheduling/)

还应警惕“前驱可以用一个单调指针”的不充分说法。按结束排序的 `(1,3)、(5,6)、(2,7)`，闭日语义下的前驱数为 `0,1,0`，并不单调；需要二分，或另有正确的排序/事件组织。收益求和也不能因端点能存int就用int：P10的保守上界是2×10^14。

### 占用峰值、最少资源和固定资源择优：三种输出不能混写

P3求全体区间某时刻的数量峰值；P4要给全部区间分配最少房间并输出标签。峰值是不可绕过的资源下界；按开始排序，若所有已用资源都未释放，当前请求与它们同时占用，新增资源恰有下界证据。维护最早释放的资源能高效生成方案。只给一个峰值数字没有完成P4；但峰值与分配不应作为互不相干的“差分题”和“堆题”。U2直接研究了这条关系。[UMass讲义](https://people.cs.umass.edu/~marius/class/cs311-sp19/lec6-nup.pdf)

P5是给定k个资源后最大化接受数量，不是最少资源；仍不能照搬单资源的一个 `lastEnd`。一种候选机制是按结束排序，对每项寻找“不晚于开始的最大释放时刻”，保留更早释放的资源给可能开始更早的后续项。这里的“后续”按结束排序，不保证开始更晚。

这个资源选择差异有很小的反例：k=2，半开模型 `(1,4)、(1,6)、(6,7)、(4,8)`。按结束顺序处理到 `(6,7)` 时，若复用释放于4的资源，只能总收3项；复用释放于6的资源，可总收4项。按开始排序处理“全部必须分配”时，任意已释放资源都可用；不能把那里的“任选”移植到按结束排序的择优问题。P5支持在同一问题族内实际解决一个改变资源数后的分叉，成本是维护有序多重状态，而不是另一门完整图论课。[Movie Festival II](https://cses.fi/problemset/task/1632/)

独立小枚举核实上述例子的最优值确为4、错误策略为3；这只是反例验证，不是对候选机制的完整正确性证明或生产实现验收。正式成稿仍须给出交换/状态支配论证，并说明重复释放时刻必须保留多份资源身份。

### “覆盖”必须先回答谁选谁、是否保留重叠、覆盖什么

P6选择点，让每个输入闭区间至少包含一个选点。最早结束的尚未命中区间迫使解在它内选点，将该点推到它的右端不会伤害仍未处理、右端更靠后的可命中区间；这是刺穿/命中问题。它不要求把整段数轴都涂满。[452原题](https://leetcode.com/problems/minimum-number-of-arrows-to-burst-balloons/)

P7/P8则选择输入区间，把目标 `[L,R]` 连续覆盖；在已覆盖前缀的边界处，必须从已能接上的候选里选能伸得最远的一个。选择方向与不相交数量调度恰相反。U3的证明比较替换后覆盖到的区域，而不是比较空闲时间。没有能让边界严格向前推进的候选，就是真实缺口，返回无解。[Toronto Q2](https://www.cs.toronto.edu/~deepkush/teaching/373s22/hwk/practice_midterm1_Fall20T1_solutions.pdf)、[Video Stitching](https://leetcode.com/problems/video-stitching/)

P8给出一个有价值、低增量的模型转换：位置i和半径r变为 `[i-r,i+r]`，裁到目标边界即可进入覆盖问题；不能把“只覆盖所有整数喷水点”当作连续花园已覆盖。其有界整数起点还允许按左端桶记录最远右端，与排序扫描属于同一贪心的实现组织对照；是否采用桶，应受坐标规模约束。[Taps](https://leetcode.com/problems/minimum-number-of-taps-to-open-to-water-a-garden/)

P9求的是全体输入的并集分量，不进行最少选取。它给出了很便宜的复用：并集总长度、空隙、目标区间是否已经被并集覆盖。闭区间 `(1,3)、(2,5)、(4,6)` 能合成一个分量，却至少需要两个刺穿点；“连成一片”不等于“大家共有一点”。单个连通分量也不等于最少覆盖只需一个输入区间。[Merge Intervals](https://leetcode.com/problems/merge-intervals/)

在一致的**闭区间**模型下，最少刺穿点数与最多两两不相交区间数相等：按最早右端选点时，每次触发新点的区间彼此严格分离，给出点数下界，同时选点构成同样数量的上界。这是从两个贪心结果几乎不增加结构即可得到的解释价值。不能把它未经端点校准就等同于P1那种允许接触衔接的数量答案；`[1,2]、[2,3]` 的刺穿点数是1，而接触可衔接的调度数量是2。此等价关系是本次推导，不是声称452题面给出了对偶定理。

### 两种k：容量与总预算是不同轴

P5的k是同时可用观众数，每个观众可看多项；P12的k是单人总共至多选择几项。二者都出现“最多k”，但不能共用状态。P12可把加权前缀状态增加预算，形成 `F[i][c]=max(F[i-1][c], value[i]+F[p(i)][c-1])`；其n×k≤10^6使这条增量有实际复杂度依据，预处理前驱后可做O(nk)转移。按预算外层处理时也可保留两层前缀数组，而不是盲目声称“前驱DP都能只保留相邻两行”。[1751原题](https://leetcode.com/problems/maximum-number-of-events-that-can-be-attended-ii/)

是否把预算版本做核心可以另行判断，但合理理由应讨论这项新状态与主题目标，不应仅因为它标Hard、引入DP维度或首章要短而排除。至少需要明确k的语义及“至多”和“恰好”的区别；原题正值收益也不保证能选满k。

### 静态性还带来离线查询；不是必须上区间树

P13的输出不是选择一个全局最优子集，而是每个查询点的最短包含区间。将查询按值排序并保存原序号，将左端不晚于当前点的区间加入候选堆；候选按长度优先，堆顶右端小于查询点就弹出。离线单调推进保证过期项不会重新有效，堆中非顶端的过期项可以延迟删除。该机制既不同于求并集，也不同于按最早结束安排资源；但若本章已有排序、堆和失效条件，新增前置有限。[1851原题](https://leetcode.com/problems/minimum-interval-to-include-each-query/)

P14/P15则区分“存在”与“计数”：左端升序、同左端右端降序后，前缀最大右端/后缀最小右端足以做布尔包含判断；精确计数需要右端的秩与前缀频数等更丰富的摘要，极值已经不够。CSES禁止完全重复区间，所以一般化到重复输入时必须另外分组处理，不能把原题通过当作重复已覆盖。[Nested Ranges Check](https://cses.fi/problemset/task/2168/)、[Count](https://cses.fi/problemset/task/2169/)

## 3. 哪些近邻值得承载，哪些可以有根据地停下

这是独立候选判断，尚未对照作者章界；不是要求把所有“区间题”塞入同一章，也不把每个下列名字自动变成一道必修实现。

| 关系 | 独立建议与理由 |
|---|---|
| 最大保留→最少删除；并集→长度/空隙/可覆盖判断 | 结果直接复用，几乎不增加前置，实用价值明确；不宜为短稿而消失，也无需重复一整套模板 |
| 单资源数量→权重收益 | 目标只改一处就导致贪心失效，真实需要状态与DP；在本候选主题承诺“收益”时是关键方法替换，不能只有反例而没有可运行去向 |
| 占用峰值→最少资源方案 | 同一结构下的上下界与构造闭合；如果承诺占用/安排，应完成计数与方案的关系，不只列两个库容器 |
| 刺穿点→连续目标覆盖 | “覆盖”最易混淆的两个方向；两个贪心规则的交换对象不同，适合作为核心对照 |
| 单资源→k资源最大数量 | 与现有结束排序/资源状态紧邻，能引出有序前驱选择和重复资源；建议实际解决，或给出比“新结构/下一章”更具体的章界理由 |
| 加权选择→至多k项收益 | 一项充分状态扩展，约束明确支持O(nk)；可作本版深化，但若只作边界线索，不计入已教授覆盖 |
| 离线点查询P13 | 已有堆后增量较小，有用且不需动态树；值得认真比较收益/负担。若核心严格限定全局调度/覆盖优化，可以明确排除“每点查询输出”，不能说静态区间只能用前几种贪心 |
| 包含布尔P14→包含计数P15 | 布尔极值扫描可作为低增量观察；计数引入秩/累计频数，允许以输出统计和新摘要为边界单独处理。不能因为长得像包含就声称同一扫描已解决计数 |
| 单天参加P16 | 活动只是可选日期窗口，选择的是区间内一个点。适合明确指出模型变化；若实际展开，按日期维护已开始活动、优先最早截止的可选项。可以排除出“固定整段占用”主核，但必须说清窗口不等于占用，且这不是P1换皮 |

## 4. 有区分力的条件与失败边界

这些条目来自上述具体读件，不是每章套用的通用清单。

- **同端点的四种答案。** P2接触可衔接；P4同日不可复用；P6闭端点能命中；P9闭端点相接需合并。只有P3还主动排除了同刻事件。正式代码若统一用一个 `<`/`<=`，将至少改变一种原题语义。闭日的单点与半开空区间也不能视作同物。
- **谁是排序中的“后续”。** 结束排序不保证开始时刻单调，P5资源选择反例和加权前驱不单调都由此产生；不能只写“留给未来”而不确定未来顺序。
- **扫描状态保留什么。** 合并要保留当前分量的最大右端，不能见嵌套短区间就缩回；最少片段覆盖要先看尽所有能接上的候选再作一次选择；刺穿要维持已选点是否真的落在后续闭区间内。
- **重复值不是同一个对象。** P2有完全重复区间；P14/P15不允许完全重复。P5同一释放时间可能对应多个资源，不能用集合去重。排序能相同不等于资源/任务身份可丢弃。
- **覆盖度和测度不同。** 对同一批连续区间，事件计数给占用峰值，累计相邻坐标差给长度；离散闭整数长度是r-l+1。坐标压缩保序但不保长度，不能用压缩下标差代替原坐标差。
- **输出方案的原序身份。** P4必须按输入顺序输出房号，最优方案不唯一；P13查询排序后也必须还原原序。验收应判断可行性/最优值，而不只比较任意一种输出文本。
- **有界坐标只是某题提供的机会。** P7时间≤100、P8花园长度≤10^4，桶/坐标DP可合理；P1/P4/P10端点达10^9，直接按天开数组不再合理。不能把教学中挑的小坐标当作题族保证。
- **数值与比较。** P6两端跨越整个32位有符号范围，右减左或以差作为比较器都可能超范围；P10收益和远大于32位。它们是实际原题需要，不能只写一句“用long long更稳”而不推导谁需要宽化、何时宽化。
- **无解与空解。** P7/P8有明确无法覆盖返回-1；P12是至多k而非必须k。若公共helper允许空输入或负权，那是另订合同，不能伪称原题要求，也不能让拓展外壳淹没算法主线。
