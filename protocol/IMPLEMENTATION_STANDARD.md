# 实战作者与实现标准

遵循共同协议。围绕实际任务、决定算法的条件、关键思路、相邻C++代码与实质变种组织。避免纯基础课，也不能压缩为只能看编号的模板索引。

## 实现比较

- 手写针对当前算法/关键结构，可以正常用vector/string等存储。标准设施路径需说明替代了哪一层，不把heap算法包装说成手写下滤。
- 同方法实现共享题目合同；不同算法分别解释成立条件与代价。稳定性、重复值、修改输入、返回状态、无解、数值、在线/离线、严格/非严格都可能改变合同。
- 标准库没有整题替身时，真实写核心算法，并介绍可用容器/算法/数值设施；不凑劣质第二解，不强制每题实现通用容器。
- 当前算法默认C++17以便形成可移植基线；需要20/23时就地标明并真实编译。GNU扩展、工作草案、新提案和实现经验不冒称所有平台保证。

## Q与阅读

每个必要知识问题一份编号主讲。主讲写相邻显式 `<a id="q000001"></a>` 和 `### Q000001 · 标题`。后续只写 `[[Q000001]]`；关系登记不复制讲解。问题粒度按实际触发、规则及选择组织，不将整个容器当一个空名词，也不按每个token拆卡。引用、初值、类型、范围、比较器、失效、寿命与接口必须足量说明。

主讲源码从cpp BEGIN/END装配；代码文字不能被排版器改写。同一代码区域有唯一权威展示。局部片段、完整编译目标、平台适配和故意错误示例的角色清楚；不把下载整份参考cpp冒称可原封不动提交到任意题目。

## 核验

先根据原题约束推导数值和操作上界，再实现。每个登记实现有实际源码区域、符号、最低版本、Q依赖、复杂度和验证目标。测试应实际调用全部声明实现，以独立参考/枚举/性质核验；缺失分支、共享错误、平局多解、跨例残留等需选择有区分力的检查。

对读者能否定位和理解、是否重复讲解、方法是否强套等进行语义审阅，记录真实观察/修订。机器仅验证模型和引用，不凭字段齐全认证质量。构建/载体变更跑相应检查；真实手机验收与模拟视口分开。
