# 内容研究与建设协议

本协议是第二算法的内容工作权威入口。目标是为求职算法题及 C++ 本身建立可持续扩张的问题、方法与机制基座，并将研究转化为可直接查阅的中文讲解与 C++ 参考代码。协议要求真实内容与实际结果，不要求固定来源数量、固定研究轮数、固定字数或复杂文书。

[研究部协议](RESEARCH_DEPARTMENT.md)规定全局选题、动态范围与目标交接；[算法工程线](ALGORITHM_TRACK.md)和[C++工程线](CPP_TRACK.md)分别规定目标承接、深入内容研究与必要核验。三者都是本入口的组成部分，共同的来源、身份、构建、发布与恢复规则只在本入口及其引用的工程文档维护，不复制多套平台。

客户阅读载体与增量发布见 [docs/READER.md](../docs/READER.md)。展示登记只消费真实交付状态，trial与正式chapter分开；文件数不决定章数，上线不替代范围核验。后端手动发布，前端不承担研究部与制作管理职能。

## 范围与完成的含义

正式范围包括算法上机题、必要数据结构、方法变种、复杂度与实现条件，以及 C++ 语言和库的系统性实战问题。用户基础良好但未规范系统学习；C++ 按与算法章相同的研究方式建设，不降为零基础补课，不预设八章或其他篇幅上限。本项目不负责初学编程课程、英语、机器学习原理或系统设计面试。题库难度标签和社区热度可作线索，不能独自决定纳入与排除，也不能冒充目标岗位的出现概率。

范围是可版本化的研究结果，不是开工时随手列出的章节目录。初始入口可以覆盖排序与搜索、数组链表、栈队列与堆、哈希、双指针与窗口、前缀和与差分、回溯、贪心、动态规划、树图、字符串、位运算与数学；材料中发现的结构仍须独立判断，不能因没有旧目录位置而消失。

完成状态必须说明对应的范围与来源版本。可以核对某个指定清单是否逐项处理，以及已经纳入的模式是否有真实承载；不能证明整个互联网或未来招聘题目零遗漏，不编造全网覆盖率。发现新的相关模式、重要条件或外部反查失配时，重新打开受影响的内容缺口。

## 章的形成与逐章推进

算法和C++分别逐章建设，用户的交付单位是章。全局可以提前维护来源、教材和粗略知识地图；它们不是最终目录，不要求先研究完整册再发布，也不允许据此默认批量编写未来章节。章数、顺序和两线交替比例均不预先锁定。

研究部以全部已知资料基座、当前研究与真实已发布内容为输入，比较下一步的内容价值和关联，实际调查并动态形成下一章的研究范围，向对应工程线交接有依据的明确研究目标。全量视野不等于全库正文已读；已有缺口和旧稿只是输入，不直接决定下一章。目标保存在当前任务README中，带可追溯的版本或修订日期，不另建目标数据库。

工程线以目标为行动基线继续深读、归并、实现和编写。发现会改变章界、主题、体量或归属的新证据时反馈研究部，更新同一目标再继续；局部实现和方法细化不必回到全局选题。发布结果、未决项与新材料回流研究部，为后续目标提供依据。部门是职责，不是审批层或常驻服务。

**研究入口不等于章。章名、主题、边界、体量、内部组织及邻章关系本身都是研究产物。** 不能先认定“第一章是类型与调用”，再只在该框内找材料；也不能将已有七份稿或教材目录直接改名为最终章节。

默认按下列工作推进；它们是实际工作关系，不是强制表单或固定次数的状态机：

| 工作 | 主要责任 | 需要形成的实际结果 | 何时返回研究 |
|---|---|---|---|
| 综合全局资料与内容状态 | 研究部 | 下一步候选及价值、重复、关联与优先理由 | 只依据旧目录、最近稿或gap顺序选题 |
| 从候选线索发现问题 | 研究部 | 实际问题、约束／合同、出处与未知项；允许此时没有正式章名 | 入口只有名词相同，实际内容并不相连 |
| 动态形成范围并交接目标 | 研究部 | 有依据的研究问题群、边界、已有内容关系和工程目标版本 | 新证据支持改名、合并、拆分或撤销原划分 |
| 深入问题与方法 | 对应工程线，范围变化反馈研究部 | 主要结构、重要变种、替代方法、正确性／语义依据及真实实现差异 | 条件推翻归并、关键材料未定，或原章框架妨碍真实解释 |
| 组织作者稿和代码 | 对应工程线 | 已研究内容的清楚讲解、相邻参考实现和必要关联 | 空占位、无实际承载、过度膨胀或压缩得无法阅读 |
| 独立反查、实现和阅读核验 | 对应工程线及审阅 | 对冻结版本的不同证据、具体检查及修订 | 发现新结构、错误前提、实现反例或不合理章划分 |
| 发布当前章并回流全局 | 工程线交付，研究部吸收结果 | 明确的章范围、多稿组成、研究与验证版本、可用入口及剩余问题 | 会影响本章实战使用的已知问题被悄悄推给未来 |

章假说不在中途永久冻结；内容深读与反查都可以改变它。一次正式发布有明确边界，后续仍可修订。候选未定、关联扩展待判断、来源未取得和本章实质遗漏必须分开；不能为了完成指标只保留已经写出的内容，也不能把全部进阶候选都变成用户学习义务。

同一章可以由多个阅读文件共同承载，多章也可以引用同一主讲解。文件数、题目数、模式数、代码块数与章节数分别计；阅读组织不应成为人为的学习边界。

默认按当前目标推进工程交付，不批量铺写未来章；研究部可以在任务范围内结合进行中的内容调研后续候选，但不能将未完成内容当已发布。并行Agent服务实际研究目标的不同证据路径、实现或审阅，不各自擅定未来章生产。用户明确指定多项工作时按其范围执行，两条线不互相阻塞，也不机械交替。

用户只要求范围研究、内容研究或讨论时，交付相应结论、依据和下一步，可进行必要的验证原型，但不自动扩为多章作者生产。“全流程研究探索”不是全册批量成稿授权；“制作／发布一章”则在其范围内推进到可用交付。“继续”恢复当前实际阶段。正常阶段转换不另设用户审批。

2026-10-26前期七份C++稿保留为研究资产与候选作者稿，不认定为七章正式发布。现有二分三份阅读文件也不等于三章。已有读件、分析、代码和真实验证不删除，后续按研究形成的范围复用，不以旧稿存在替代范围研究。偏航与有效经验见[日志复盘](../research/2026-10-26/workflow-retrospective.md)。

## 来源池与材料

`catalog/sources.json` 是来源池权威。每个来源要交代用途、原始入口、语言、出处关系及实际观察；同一网站的学习计划、方法目录、题目正文和源仓库可以是不同入口。核查围绕具体入口和范围进行，不能用一个网站级 verified 标签代表全站已读。

分别保存以下事实：来源是否采用、入口是否真正可读、清单是否完整取得、哪些正文实际读取、哪些候选已分析以及哪些模式已有正文和代码。页面只返回简介、执行只检查了部分结果、或列表仍有分页，都如实保留，不能改写为“无相关内容”或“全量完成”。

来源角色各有边界：原题用于核对目标与约束，方法资料用于理解算法，社区整理用于发现别名与替代观点，教材用于系统研究。官方原题不自动认证某份解法，转载数量不代表独立证据数量。保存镜像、翻译与上游关系，不把同题复制件重复计算为新问题。

书籍优先选择落实到具体题目与实现的实战资料，按目录与相关章节实际读取。用户提供的原件保留本机，公共仓库只保存允许公开的元数据、定位、原创研究与必要引用，不上传付费书籍、商业题库全文或个人旧手册原件。

旧Claude手册单独作为产品形态参照研究，只吸收直接对应、相邻代码等有用组织方式；其复试临考用途、分类、篇幅和原有解法不作为新册章节范围、覆盖程度或算法正确性的依据。它不替代新来源调查与独立判断，原件及隔离读件不混入主教材基座。

C++ 来源区分实际实现题、代码诊断／改写题、参考解法、语言与库规则、实现证据和实验工具。Cookbook 的配方不是待解习题，源码仓库不是自动取得全书，编译工具不是题库；不把这些数量混算。问题与例程用于发现机制，关键结论回到对应标准版本、库契约及必要的实现资料核对。工作草案和提案不自动代表已经发布的 C++17／20／23 标准。

材料使用已取得版本及实际读取范围。读取失败不能证明内容不存在。摘要可固定字节身份，不能证明模型读过或理解正确；只下载原件、只看到标题或只记录链接，均不能升级为正文已读。

## 发现与检索

研究组合使用四条路径：选定目录完整枚举；按算法名、目标、关键约束、组合方法及中英文别名查询；沿读件中的关联题、前置与替代方法扩展；从未参与目录构建的材料反向检查现有分类。

每个枚举任务要明确入口、范围、筛选与分页。结果中保留外部稳定身份及出处；目录枚举与正文阅读分开。相关和不明确的候选需继续读取题干及约束；明显不相关的组可按有理由的范围规则处理，不为每个条目复制相同文书。

查询计划与实际执行记录分开。保存真正使用的查询、入口、限制、取得范围与重要发现；不逐命令制造无价值日志，也不把计划中的查询列为已执行。用于校准搜索词的已知案例不能重复充当独立挑战证据。

增加来源是常规研究动作：先核查实际入口与用途，进入候选或采用池，按现有结构保留其取得方式与未知项。没有自动适配器的来源可以手动读取和登记，不虚构自动全量能力。新增付费、账号授权或后台定时活动不因加入来源池而自动获得授权。

## 归并与内容去向

题目身份、算法模式与阅读章节分开。不同题目共用方法时保留各自原题与条件，只归并教学内容；同题的翻译或镜像保留同源关系。一个模式有一个主要讲解位置，同时可以从多个相关专题定位。

归并必须比较目标变换、成立条件、核心判定和实现差异。相同外层循环不能证明同型；正负数、重复元素、连续与不连续、静态与动态、恰好与至多等条件可能改变整个算法。凡改变识别、正确性依据或实现的差异，均应有去向；不生成无依据的条件笛卡尔积。

已分析候选的去向可以是已有模式的佐证、局部变种、新模式、其他专题实际承载或明确排除；尚不能判断的保留待定。用足以恢复判断的简短理由说明，不强迫逐句建立断言台账。跨章目标不存在或尚未讲清时，仍是缺口，不能仅填一个专题名就算完成。

## 作者稿与参考代码

正文围绕题型条件、关键思路、相邻 C++ 代码和必要变种组织。保留决定比较、计数、状态转移或区间更新的解释；避免完整基础课，也避免把解释和代码拆成需要远距离拼接的索引。表格服务于局部对照，不取代连续、清楚的说明。

C++ 正文同样围绕具体代码问题、决定行为的机制、可参考实现及实质变种组织。来源中的写代码、分析行为、找错修复、重构和实现取舍可相互补充，不能将全部内容收缩为“猜输出”或背诵条款。区分标准保证、未定义／未指定／实现定义行为、平台实现及作者建议；单次编译运行不证明可移植语义。默认算法代码保持 C++17，语言专题按需使用更高版本并就地标明，不能将新特性悄悄加入旧版本代码。

每份正文与代码保持一个权威版本。阅读版从作者稿及同一份源码装配；代码块与源码对应，重要修改后重新核对受影响题型。复杂度要结合原题规模和前提判断，不以编译成功代替算法正确。

验证选择能检验真实风险的办法，例如与独立枚举、排序合并、已知正确结果对比，或构造能区分关键条件的反例。不为可逆小改动制造大量镜像测试；历史测试通过与本次实际运行结果分开报告。

## 审阅与封存

内容准备封存时，回到范围与实际材料核对：指定候选是否有去向，纳入模式是否真正讲清，重要条件与变种是否保留，代码和正文是否一致，关联章节是否存在。再从外部案例独立分析，检查当前分类是否遗漏或硬套，并审阅读者能否顺畅定位和理解。

外部挑战的独立只指未参与本轮目录构建，不声称模型训练中从未见过。挑战用于修订以后转为建设材料，不能继续宣称仍是保留挑战。材料不足或仍有新模式出现就继续研究；不以固定几轮、固定候选数或“字段全部绿色”结束。

封存绑定范围、来源材料、记录、正文与代码版本。只报告有实际分母的处理进度；它不是全网召回率、学习效果或面试通过率。当前二分试章保持草稿及已知遗漏，不因导入仓库、CI 通过或重新构建而升级为完整章。

章发布状态由章的阅读入口明确说明，并链接其范围研究、组成稿件和实际验证；Git提交固定具体版本，修订时更新当前状态。过程细节留在研究层，不挤入阅读正文。目录捕获、模式authored／reviewed、构建摘要、CI结果与GitHub传输各有自己的事实含义，不能相互替代为“正式章节已发布”。现有CLI没有自动章节发布认证，不虚构此能力，也不新增发布数据库。

## 工程与恢复

工具负责确定性枚举、缓存、规范化、身份和引用核对、候选去重提示、缺口报告、代码装配与构建。语义相关性、模式归并、算法判断和阅读质量仍由模型实际完成。工具可以拒绝结构缺失，不能自动认证语义正确。

保留清单快照与成功基线；新获取失败记录为本次失败，不以空结果覆盖 last-good，不清空历史题目。新快照不再出现某个身份时保留历史及本次差异，不自动删除内容或排除题目。

中断后恢复同一任务的实际材料、研究结论、权威稿与具体下一步，不默认重新全网搜索或重写全文。具体恢复位置与操作见 [docs/RECOVERY.md](../docs/RECOVERY.md)；物理组织及模块分工见 [docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md)。这些文档解释工程，不另立内容语义权威。

所有新增实际数据、缓存、下载、编译产物与本地教材由 D 盘承担。公共仓库不保存凭据、个人路径和不应外发的原件；索引和报告是可重建派生物，不与来源记录、作者稿形成第二套权威。
