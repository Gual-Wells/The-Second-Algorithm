# 第二算法内容研究与发布：唯一共同协议

目标是在真实求职上机任务中学习算法、手写实现与C++设施。当前只有统一实战生产线；不先写完整C++课程，不将代码理解推给未来补课。章节产品标准见 `CHAPTER_STANDARD.md`，材料到采用的工艺见 `QUALITY_WORKFLOW.md`；研究、实现和发布职责各按对应协议。字段权威是实际JSON和校验实现，说明见 `../docs/CONTENT_MODEL.md`。

## 研究形成范围

每次结合全部已知资料基座、真实已发布内容及用户目标判断下一步。全量视野不等于每次重读全书，更不声称目录即正文已读。实际阅读原题目标/约束、方法、库合同和相关反例，动态形成章界；发现新证据可以拆并、改名、增减范围。用户交付单位是章，不预设固定章数/代码块数/题数，不批量铺满未来章节。

来源记录在 `catalog/sources.json` 与书目/实际读件记录。区分原题、方法、社区、规则、实现与工具；镜像/转载不算独立证据。记录真实取得的版本、范围和失败，保留last-good。商业材料只公开元数据、允许的短引用和原创分析，不能上传原件。当前草案/提案、旧书、特定实现经验分别标明，不自动当目标C++版本保证。

研究必须形成章级合同：难度高度、范围广度、系统闭合与读者组织分别可检验。支架不变算法上限，不以微型题单自证完备；按实际原件独立反查章界。`catalog/chapters.json` 连接合同、正文和当前审阅；它不替代learning或复制教材。旧章首次采用新标准时如实记缺口，不能追认通过。

## 一份内容中的关系

实际任务有明确输入、输出、边界、可修改政策与来源；方法有成立理由和适用条件；同一方法可有手写和标准设施实现，同题也可有不同方法。分别说明时间/空间，不用相同循环外形或更短代码证明等价。优先主动发现可用设施，避免只在读者已经知道函数名时才展示它。

`catalog/learning.json`保存任务/方法/实现/Q/验证目标关系，`carrier/publications.json`只登记当前阅读顺序和可发布读件。作者稿及权威cpp通过区域标记装配正文。一个区域不是一道题或一个完整提交；库替代与手写的操作层次必须清楚。

## C++问题只讲一次

每个实际依赖的C++知识问题分配全局唯一Q号，不按章节重置、不以文件位置命名。首次需要且上下文可理解处完整讲清，包括手写代码所用语言机制和库合同；必要前置不能无解释存在。

一个Q一份完整主讲，后续仅 `[[Q000001]]` 编号/标题引用并跳回主讲，不复制或重新内联解释。新增机制/边界经判断修订原问题或新增Q；同类例子、改标题、挪位置不新编号。新题仍解释自己的算法依据。后期补C++从相同Q索引恢复，已讲内容只定位，未覆盖问题再研究，不能假定算法覆盖完整C++。

并行作者用临时语义键，由整合者去重并赋号。构建拒绝重复号、多个主讲、悬空引用与前置环；标题计数不认证解释质量，读位不认证掌握。

## 工程、验证与真实审阅

原始目标/材料问题空间 → 章级合同与独立范围反查 → 作者稿/权威代码 → Q/实现关系检查 → 读者连续稿 → 范围/承诺/可读性回查与独立代码验证 → 修订及当前章级采用 → 当前输入绑定的发布准备 → 部署与线上核验。它们是工作依赖，不是要求用户逐步审批的流程。

验证必须针对实际权威代码。两版互相同意可能共享错误，要用独立枚举/朴素模型、性质或原题证据；多解按合同检查，不强求文本一致。有意不合式程序只检查诊断、不执行UB。声明标准分支必须真的编译，不把跳过视作验证。说明实际环境、范围、未测项，不编造全网覆盖率或面试通过率。

Agent进行真实来源理解、归并、算法论证和语义审阅，笔记登记accepted只是对实际工作的留证。程序检查合同、实际位置、材料/证据字节和输入绑定，不能自动证明其真实性、完整性或教学质量。章级open/gap、缺失或过期审阅阻止prepare/check-release；现有generic accepted和编译通过不得绕过。发现needs-work必须真实修订，不能重填状态绕过。

## 发布和恢复

使用research任务CLI保存目标、研究/审阅证据与独立验证。输入变化使旧证据/验证/准备包过期；失败保留last-good但最新失败阻止借旧成功发布。任务独占锁和部署锁防并行覆盖，异常恢复先查真实进程/输出，不删除别人锁。

正式出版只消费当前schema2统一章节；旧稿为历史测试素材，无迁移兼容义务。来源采集工具保留，历史cases/patterns不证明当前正式覆盖。正文不进入D1，依赖不扩成内容服务或向量数据库。新增费用、账号授权或定时活动不从本协议自动获得授权。
