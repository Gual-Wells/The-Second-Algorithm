# 算法工程线：目标承接、内容研究与发布

本文件是[共同协议](CONTENT_PIPELINE.md)的算法分线。目标是面向求职上机的题型、算法思路、重要变种与相邻C++参考代码；不给用户增加基础课程、临考仪式或固定练习量。下列阶段可往返，章的主题与范围是研究产物。

## 1. 接收研究目标，取得并复核现实问题

上游由[研究部](RESEARCH_DEPARTMENT.md)综合资料与内容全貌，向本线提供有版本的研究目标。开始前读取目标的问题群、范围理由、已有内容关系、材料和关键未知项；目标尚未形成时，先承担研究部的选题职责，不从旧目录随意挑一项开写。同一Agent可以完成两种职责。

用户问题、旧缺口、题目和教材分类都是上游研究线索。“二分”“区间”“计数”只是可能入口，不直接认定为最终章名或题型列表。工程按目标继续取得和复核实际问题。

先查本仓库来源、案例和模式，复用已读材料；再实际取得代表题干与约束。组合使用有限目录枚举、目标和约束检索、中英文别名、方法替代与关联题扩展。只搜自己已知的算法名不能完成范围发现；教材分类和题库标签也不能决定某题必须使用该算法。

目录记录、题干、题解与方法资料分别标明取得范围。原题暂不可读时，保留身份和未知条件；书中提示或其他题解不能悄悄冒充已经读到原题。新来源按共同来源池登记，不另造算法专用来源库。

产出是有出处的问题及条件集合、候选关联和未知项，暂时没有正式章节也正常。

## 2. 深入问题关系，复核并反馈章范围

逐组比较以下决定解法的事实，而不是机械填写条件笛卡尔积：

- 求存在、最优值、计数、排名或构造方案；输入是数组、区间、树图、隐式状态还是连续量。
- 有序、单调、局部结构、非负、重复、静态／动态、单次／多次查询等前提；改变它们会失去哪一步依据。
- 核心转化、正确性理由、实际判定或状态维护；相同循环内部是否已换成另一个算法。
- 直接解法、替代方法与组合依赖；哪些共同内容集中讲更清楚，哪些需要拆开才不混淆。

据此复核研究目标的**章主题、纳入边界、内部问题群、组合内容、邻章关系和体量**，用代表问题和关键差异补强判断。若证据要求改名、合章、拆章或放弃原入口，反馈研究部修订当前目标；不要求固定备选数量，也不为维持旧目标硬写。

章不能只是“已有模板的集合”，也不能无限吸收所有相关图论、DP和数学。组合问题若对理解当前方法有实质价值，应给出决定性的判定与实现，或关联已经存在的主讲解；尚不存在的邻章标题不能代替内容。编纂需要研究更多资料，不等于要求用户逐题刷完或先掌握整章才进入其他章。

本阶段结论保存在同一工作记录，标明承接的目标版本。后续深读和反查仍可修改；局部方法细化直接进行，改变范围的发现按共同交接回路处理。

## 3. 深入内容，同时修正范围

对暂定纳入的问题群，读取足以判断目标、约束与方法的实际材料；研究为什么成立、何时失效、复杂度是否适合原题，以及实现差异是否值得独立承载。

归并时保留原题身份。只换故事和变量的不重复抄解法；负数、严格／非严格、连续／不连续、恰好／至多、重复边界等若改变正确性或实现，必须有明确去向。不同的check不能只用一个函数占位，排名计数、前缀窗口、图搜索等也不能因共享外层二分就被当成同一内容。

若实际最自然的主解是算术、扫描或其他方法，如实采用；不要为维护章名或来源标签强套算法。发现新的独立结构，重新判断它对章划分的影响。重要条件未能核实时保留待定，不能把范围缩成恰好已经写完的部分来宣布完成。

## 4. 研究成熟后组织作者稿

由已形成的问题群决定小节和阅读顺序。默认呈现为“题型条件 → 决定性思路 → 相邻C++参考 → 必要变种”。解释足以辨认条件、理解关键维护或更新步骤；不扩成初学课程，也不压成难读的模板编号。

一种方法有一个主要讲解位置，多个题型可共用代码；需要不同正确性依据或关键步骤的差异不能被删掉。局部表格用于对照，不用表格替代所有讲解。代码用于观察、理解和记忆实现，不机械增加“怎么复制运行”等操作说明。

正文与同名`.cpp`为权威，阅读版从它们装配。按本章理解与查阅需要决定是一份还是多份阅读文件，不能按文件数认定章数或学习进度。

## 5. 用不同证据反查，并验证实际实现

保存当前范围和内容版本，再用未参与本轮分类构造的材料独立分析问题，检查本章能否正确接纳、排除或关联它。先分析外题，再看现有类别，避免只在自己拟定的清单中找支持。重叠材料不能重复计作独立挑战，使用后即成为建设材料。

代码验证针对真实风险选择独立枚举、朴素算法、排序或其他可靠结果对照，以及能区分条件的反例。核对实际生产源码，不能只测研究原型；重点包括数值端点、空／极小输入、重复、符号、状态恢复及复杂度。没有固定断言数量或每块必配镜像测试的要求。

发现新判定、反例失败或缺少会改变结论的条件时，返回内容研究；若其改变章主题与组织，返回章形成。重新研究受影响处，不默认推倒整册。

## 6. 发布一个已经明确边界的章

发布前核对：本章声称覆盖的问题群有真实讲解和代码；关键组合有承载；排除与待定有理由；阅读顺序、相邻代码、目录及跨稿关联可用。不能以全网不可穷尽为由放任已知实质遗漏，也不需要等待所有进阶候选都进入主章。

构建、检查、版本绑定与Git传输沿用共同协议及[现有工程](../docs/ARCHITECTURE.md)。章入口说明实际范围、多稿组成、研究记录和当前发布状态；发布版本由Git固定，不在正文复制过程台账。后续可以修订已发布章。

交付时将真实完成范围、可复用主讲解、新发现及未决项回流研究部，供下一次目标研究；不自行按旧目录续写下章，也不因还有许多候选而并行铺写未来章节。

## 当前资产的使用边界

二分三稿是同一候选专题的阅读组织。现有101道已读原题、70组代码、14项明确缺口和21条未取得原题是历史阶段结果，见[实际研究](../research/2026-10-26/binary-full-cycle.md)；它们既不证明全网完备，也不自动决定以后必须如何分章。继续时先判断剩余内容对本章边界的影响，保留真实读件和有效代码。
