# C++工程线：目标承接、内容研究与发布

本文件是[共同协议](CONTENT_PIPELINE.md)的C++分线。用户已有计算机基础，需要把不系统的语言与库认识整理成实战参考；不按零基础课、标准目录或算法模板附录建设。章主题、边界、体量与内部组织都由实际研究产生。

## 1. 接收研究目标，进入具体代码任务

上游由[研究部](RESEARCH_DEPARTMENT.md)综合全量资料基座、当前与已发布内容，交接有版本的研究目标。工程先读目标的具体代码问题、范围依据、已有内容关系、材料与关键未知项；尚无目标时先承担上游职责，不直接指定“类型与调用第一章”等目录。同一Agent可以依次承担研究与工程职责。

用户需求、实现障碍、已有候选、教材练习、课程实作、修错题或真实库问题提供研究线索；工程围绕交接目标进一步取得和研究实际任务，不将既有七稿当作下一章顺序。

优先取得需要实现、修复、改写或比较选择的具体任务，核对接口、目标、可用操作、输入限制、资源责任和失败行为。输出谜题、规则条目和配方可以补机制，但不能替代实作主体；配方也不伪装成待解习题。

复用现有教材与来源基座，实际读取相关题干、方法、解答和代码；书籍入库、目录可查和原页可回看不等于全部语义已读。PDF／EPUB提取中的代码、公式或图像有疑点时回原件，不把无乱码当成正确代码。第二版可用的资料不因找不到新版而停工，新版差异按本次问题需要补证。

## 2. 从任务关系复核并反馈章节假说

比较哪些任务因共同的语言／库合同而相连，哪些只是术语相同。围绕实际差异研究：

- 值、借用、独占或共享所有权；对象及其存储、引用、视图和迭代器何时仍有效。
- 初始化、推导、转换、重载和调用怎样改变接口或结果；复制、移动和泛型能力要求是否相同。
- 正常结果之外的异常提交、清理与状态不变量；线程同步、版本和翻译单元条件是否改变实现。
- 同一机制的不同接口，或同一目标的不同实现策略；哪些适合共同贯穿实作，哪些必须独立解释。

据实际任务复核交接目标的章主题、边界、内部分组、组合实作及跨章关系，补充为什么一起学或拆开更清楚的证据。资源、对象、模板、容器、并发等参考目录只是发现线索，不能预先各占一章。既有七稿也不能反过来支配章节划分。

后续发现关键区别时允许重分章，反馈研究部修订同一任务的目标版本和理由；局部实现细化不必重新选题。不要把所有可查到的新标准特性或高级系统分支都升级为必修，也不能只保留几个安全小例子而失去系统性。

## 3. 深读方法，按版本核对合同

对纳入问题实际比较参考实现、替代选择和失败反例。关键结论区分语言／库保证、设计建议、实现策略、平台行为，以及未定义、未指定、实现定义和不合式情况。相同观察结果不代表语义相同，单次运行也不证明可移植规则。

以具体C++版本核对相关标准资料和库契约；工作草案、后续缺陷修正、提案及滚动草案的适用范围分别说明。旧书或旧文章的`auto{}`、复制消除、求值顺序等结论不得直接继承为C++17；实现在旧模式补入DR时，也不当作所有旧编译器的保证。

研究须落实到决定实现的合同。例如概念满足不证明比较器严格弱序；nothrow move不证明复制不抛；单个optional的异常保证不自动保全外围槽位与下标。出现新合同或实质变种时，修订内容关系和章范围。

## 4. 编写实战参考而非语言条款表

默认呈现为“具体代码问题 → 决定行为的机制 → 相邻参考实现 → 实质变种”。需要时用贯穿实作集中展示多个机制，保留最有区分力的局部例子；不为每个术语复制一份小程序。

核心应有真实实现、修错或重构价值。简短辨析可以没有独立模板，长实作也可承载多个问题；代码块、题目、机制和章节不是同一计数。标准规则用于解释选择，不能替代代码问题本身。

C++17为算法参考的默认基线；C++专题需要20／23时就地标明。原型、权威源码、分文件片段和作者稿保持清楚关系；展示片段不必各自成为完整程序，但验证须对应实际源码及所声称的接口。公共阅读版不混入研究过程或大量非必要操作说明。

## 5. 按真实风险验证与独立反查

选择适合当前问题的检查，不要求所有章节都搭配全部工具：

| 当前问题 | 有区分力的核验方式 |
|---|---|
| 类型推导、重载与能力要求 | 实际实例化、类型断言；失败案例独立编译，区分规则要求与编译器诊断表现 |
| 所有权、生命周期与异常安全 | 借用边界分析、存活对象计数、失败注入、移动专属类型及状态不变量 |
| 容器、迭代器、解析与数值 | 空和边界输入、独立模型、能力约束、长度和失效条件、比较关系反例 |
| 翻译与链接 | 真实多文件编译／链接；不能把多个片段拼成单文件来证明ODR或可见性 |
| 并发与同步 | 同步关系分析及可区分的运行检查，必要时独立进程和超时；运行通过不证明全部交错安全 |
| C++20／23分支 | 在对应模式下真正实例化并运行适用分支；旧模式预处理跳过不是验证成功 |

不运行UB来猜标准答案；不合式案例用于隔离的编译／链接检查。标准不要求诊断的ODR违反等也不能因“没有报错”判为合法。

范围与内容留下版本后，从未参与本轮分类构建的代码任务或实际回归案例先独立分析，再检查现稿是否正确承接。既检查机制遗漏，也检查章节划分是否有误。标准正确而本机工具链失败时分开记录，不将失败改写为通过；必要的跨平台结果也分别保存。

真实反例推翻实现时修代码；推翻分类或合同理解时返回研究。用过的挑战转为建设材料，不能继续宣称是未见材料。

## 6. 单章发布与后续

发布当前研究形成的一章，核对已声明范围的实质承载、版本条件、代码与讲解一致性、阅读体验及待定项去向。一个章可含多份稿；Git推送、模式authored和CI绿色都不自动创造正式章发布。

沿用共同工程装配阅读版和保存发布证据，将真实完成范围、可复用内容、新发现与未决项回流研究部，供后续目标研究。后续新资料按影响修订，不重新铺写全册。用户只要求范围或内容研究时，交付该阶段结论与依据，不将其自动扩成全域作者生产。

## 当前资产的使用边界

四套本地教材、来源池、七份候选稿和真实验证保留复用。七稿不是七章，103块不是103道独立题，133条authored不是133个已完成章节；局部author-map也不是全局唯一真相。Pimpl已有跨域承载而深复制等变种仍可能未做，须按实际代码核对。28项gap包含待判断扩展，不自动成为后续必修清单。历史事实见[阶段研究](../research/2026-10-26/cpp-full-cycle.md)。
