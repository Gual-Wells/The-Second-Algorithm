## 1. 先重新界定这个产品

第二算法应让用户顺畅完成：

> 找到一章 → 理解本章结构 → 连续读问题、推理与实现 → 就近看必要知识或提问 → 回到原来的文字。

它不是展示研究设施的首页，也不是笔记工作台、代码管理器或知识图谱。它可以拥有复杂的编纂、验证、授权、离线与任务设施；读者不应因此承担更多界面学习。

第二语言中最有价值的产品成果，是每增加一项能力，都要回答：它属于哪个对象？在哪个时刻才需要？打开后怎样离开？回来会不会丢位置？按钮是否承诺了真实结果？这组判断要移植过去。

### 对实施模型的首要要求

- 不从“当前有哪些 DOM 和按钮”反推产品必须长这样。
- 不把已有控件数量作为要保留的功能数量。
- 不把编纂的文件、合同、类型、编号和验证步骤直接当读者栏目。
- 不为了页面简洁删掉完整推理、代码或必要知识。
- 不用进入纯净阅读解决常态布局本身过重的问题。
- 用户否决的是版面，不授权删除私人原件、草稿、冲突副本或收费资产。

## 2. 明确移植什么、不移植什么

| 第二语言经验 | 第二算法中的落实 | 不能机械复制的部分 |
|---|---|---|
| 深蓝工具壳、蓝银实体控件、白色读面 | 同系材质、层级和按下反馈 | 不把全部页面套成词条卡或满屏渐变 |
| 读书器为默认工作面 | 有真实读位时直接续读；明确链接直接打开目标 | 日期、七日条和日历按用户后续明确要求移植，不复制每日自动生产 |
| 章节册每章一个清楚入口 | 真章名、出版顺序、必要的续读信息 | 不在每章卡上展开一排功能按钮 |
| 原位索引和静态定位 | 层级目录、知识浮窗、稳定目标揭示 | 不复制词条/USE编码和三部分切换 |
| 纯净与常态共享正文和控件 | 同一纸宽、字号、正文身份与原控件 | 不复制英语句子点读和自动提问手势 |
| 设置按用户任务分组 | 阅读偏好、本章文件/离线、应用与账户 | 不复制没有业务需要的余额、语音、认证艺术等面板 |
| 问题与对应答复配对 | 版本会话、幂等、未读、草稿、晚到答复 | 不共享账户、数据库或原项目运行队列 |
| 新功能融入已有视觉系统 | 在唯一原生样式中补足相同职责的控件 | 不把第二语言整份CSS连同废弃实验选择器搬来 |

**尤其不要复制三个历史包袱：**小字号和小触点、全局禁止缩放、多种教学手势。算法书应优先保护原生选文、复制、横滚与系统缩放。

## 3. 我推荐的整体组织

### 3.1 三种主页面，四种临时窗口

主页面：

1. **章节册**：找到真实出版章。
2. **章入口**：辨认这一章，选择从头或继续，查看本章完整目录。
3. **正文**：完整逻辑章的连续阅读。

临时窗口：

1. 本章目录；
2. 知识解释；
3. 本章答疑；
4. 阅读设置及其少量详情。

主页面构成书籍对象层级；临时窗口是阅读过程中的辅助。不要把所有东西都做成弹窗，也不要每次看一个术语都跳到另一张主页面。

章节册进入章入口是普通浏览路线；明确正文链接与真实续读可以直达正文，不强制绕章入口。切回章节册要保存原读位，选择另一章也不抹掉前一章的位置。

### 3.2 常态页头：保留身份，增加有用的章级入口

推荐在现有约一行半的高度内组织：

```text
第二算法                       目录  答疑  设置
第一章 · 二分 ▾
────────────────────────────────────────────
                 正 文
```

这是职责示意，不是已验收视觉稿。实际右侧控件可以保留同系小图形和短中文，但不能因此把页头做成三个巨大方块。

- “第二算法”是稳定书籍身份。
- 第二行明确显示当前章，作为可发现的章节册入口；无需另增一行章名工具条。
- 当前没有打开章时，第二行显示章节册身份，不虚构“最近学习”。
- 目录是最频繁的导航辅助；答疑是当前章服务；设置只承接偏好和应用操作。
- 不再让低信息量的英文全名占据唯一的章级上下文位置。系列英文标识可以在登录/安装等合适位置保留。
- 不靠把章名伪装成普通文字链接来节省空间。它应有明确方向符号、焦点和按下反馈，触点应足够大。

### 3.3 常态下栏：撤掉四向控制台

推荐先做一个简洁版本比较：

```text
上一节      一、有序数据的边界、计数与前驱 ▾      下一节
```

具体语义固定为：

- “上一节/下一节”只走H2层级的正式节序，PRE也在该顺序中；在本节中段点击上一节，去前一节，不临时改成回本节开头。
- 中间显示当前H2标题，点击打开目录并定位当前真实H3/H4项。
- H3/H4的精确选择在目录内完成，不再永久并列“一级/任意级”两套邻居。
- 首尾无目标时保留必要几何并禁用对应动作，不虚构一份目标。
- 不显示百分比、学习完成度或完整三层小字父链。

初始可在约48–56px下栏、44px级触点的范围调试；字号较大或标题换行时允许合理适配，不得裁字。当前100px下栏在402×874模拟视口中拿走100px正文空间，而父链仍只有约11.5–12.5px，这一比例不值得保留。

如果实际连续阅读证明下栏的前后节并不常用，可以继续删减；不要为了证明它有用增加用户需要理解的层级开关。当前推荐先把它收敛为可理解的一种语义，再比较。

## 4. 移植视觉语言的具体方法

### 4.1 从真实来源提取，而不是根据“2008”重新猜

可核对的第二语言参考固定为：

- 仓库 `Gual-Wells/The-Second-Language`；
- 提交 `6fc3a272155f78d8c7cc440bce883f4a126e4d30`；
- 主要读取 `web/styles.css`、`web/index.html`、`web/DESIGN.md`、`protocol/READER_INTERACTION.md`。

注意源文档包含历史增量；当前逐义语境正文优先，不能从历史条目复活旧功能。

| 视觉部位 | 实际参考 | 第二算法适配 |
|---|---|---|
| 画布/壳/纸 | `#cbd8e6`、`#e8eef5`、`#ffffff` | 白纸是主角，条纹只在外部衬底，避免把阅读纸改成奶油色或玻璃面 |
| 蓝色身份 | `#174b84`，页头从浅高光转深蓝，46%/47%附近有明确折面 | 保持实体工具感；别把整篇正文染蓝，也别每块说明都铺深蓝 |
| 结构边线 | `#7897b7`、`#a7bad0`及相近浅蓝边 | 层次靠必要边线分工，不靠粗框层层套住正文 |
| 普通按钮 | 白→浅蓝银、49%/50%附近折面、约3px圆角、上沿高光和小阴影 | 工具按钮同材质；行导航无需像凸起主按钮一样厚重 |
| 主按钮 | 较深蓝、白字、清楚边框 | 仅用于真实主操作，不能为展示样式在每页制造“开始学习”大CTA |
| 选中/按下 | 持续选中与瞬间按下有区别，按下有内凹感 | 当前项、开关已开、正在按住分别表达，不能共用一个蓝色填充 |
| 窗口 | 深蓝标题带、浅色内容、细边、有限阴影 | 目录、知识、问答、设置用同一窗体语法，各自按职责组织内部 |

提取后清理第二算法现有冲突规则，在唯一 `web/styles.css` 中形成明确的原生规则。不要继续在文件尾部叠第N套同名选择器，也不要新增“新主题.css”覆盖旧主题。

### 4.2 相同材质，不同控件职责

只需要少量稳定种类：

| 种类 | 用途 | 必要表现 |
|---|---|---|
| 工具按钮 | 目录、关闭、复制、前后节 | 短标签、清楚边界、按下/禁用/焦点；同角色同尺寸逻辑 |
| 导航行 | 一章、一项设置详情 | 整行可点、左标题、右侧单个方向标识，允许长标题换行 |
| 值编辑 | 字号加减、选择当前值 | 标题与值编辑分区；值用等宽数字对齐，不能看成进入详情 |
| 开关行 | 代码折行、打开时下载 | 原位值变化，作用范围清楚，不附导航箭头 |
| 主动作 | 登录、明确发送、必要确认 | 对象和后果清楚，有进行中与失败状态 |
| 只读状态 | 下载完成/失败、离线、同步异常 | 与相关动作邻近；不假装可点，不占主操作视觉重量 |

不要做一个拥有几十个参数的通用组件平台。用现有HTML/CSS和少量语义明确的渲染辅助即可。

### 4.3 字体和空间的起始建议

以下为iPhone标准版样稿起点，不是最终固定值：

| 角色 | 初始建议 | 重点 |
|---|---|---|
| 正文 | 17–18px，约1.75–1.85行高，系统中文字体和深字 | 先建立连续阅读舒适度；避免全篇粗黑或过浅细字 |
| 章题 | 22–26px，明确字重 | 只在章入口/真正章题处承担章身份，不在每个小段重复 |
| H2节题 | 19–21px，同系浅蓝带或清楚分隔 | 让节序可辨，长标题可自然换行 |
| H3 | 18–19px，中等至半粗 | 具体学习内容胜过类型前缀 |
| H4 | 17–18px，依间距与适当字重区分 | 不靠继续缩小一级来制造层次 |
| 普通窗口内容/设置 | 15–16px，输入16px起 | 不让工具栏的小字继承到长说明和输入 |
| 辅助元数据 | 通常12–13px | 当前节等主要导航不能退成9px状态注脚 |
| 代码 | 约13.5–14.5px独立等宽，可调 | 清楚缩进、自己的横滚，不靠缩字塞进屏幕 |

普通正文先用合适的正常字重；若字体实际偏细再调整到可用的中等字重。必须检查iPhone真实字体映射，不能认为CSS写500就一定比400好，也不能把Windows模拟的观感当作iOS结论。

外壳可沿现有约8px边距，纸面左右约14–18px内边距试配。窄屏优先减少壳的空耗和辅助信息，保持正文字号；不要把每层容器各留16px，最后让代码与正文只剩窄条。

## 5. 启动、登录和第一眼

第二语言的经验是让每个等待和失败都留在同一套产品语法中；不是为启动增加更多页面。

推荐路线：

1. 明确深链接存在时，先解析其真实对象；无效目标应诚实说明，不悄悄跳到另一章装作成功。
2. 核对身份。已登录且有可用的真实读位时，尽快打开对应正文。
3. 无读位时进入章节册；用户选章后到章入口。
4. 临时网络问题与需要登录分开；不能把超时当作未注册。
5. 下载、设置、未读汇总等非必要工作不串行挡住正文。

登录卡片只留下产品身份、简短状态、真实主动作和必要安装说明。不要再造宣传首页、品牌动画、功能卖点卡或假进度条。

离线必须依已有owner和资源白名单规则判断，401/403不能回退到旧私人内容。离线缺件时保留可读部分和明确重试，不要求重新登记通行密钥。

## 6. 章节册与章入口

### 6.1 章节册

- 页面标题就叫“章节册”，不叫模糊的“第二算法”或“学习中心”。
- 一章一条完整导航行：章号和真实章名是主信息。
- 可有真实续读位置作为次信息；它不是百分掌握率，也不是阅读打卡。
- 只列真实出版章，不画未来章锁卡，不用进度墙填空。
- 无需把算法/C++拆成两册；知识解释仍就近服务算法主线。
- 不为每章放“目录/阅读/代码/问答/下载”一排按钮。
- 普通选章进入章入口；当前阅读返回保持位置。

### 6.2 章入口

上半部只需要清楚的章题与一条开始/续读动作：

- 没有读位：显示“从头阅读”。
- 有读位：显示真实位置摘要及“继续阅读”；“从头阅读”可作为普通次动作。它只把这次视图定位章首，不额外删除历史记录；用户实际继续读后，按正常规则更新本章当前读位。
- 其下是本章完整目录。

不要做巨大开始卡，不复述整章已包含多少设施、验证和实现。教材自身的导读属于正文内容，不另写一套前端宣传摘要。

目录与正文共用同一份真实标题树，不分别维护导航用短标题与正文权威标题。必要的显示省略仅属于视图，并保留完整可读名称。

## 7. 目录：完整，但不把完整性变成一堵文字墙

当前《二分》实际成品有38个H2入口、214个H3、26个H4。不能为了短目录删掉学习单元，也不能把278个标题默认全部摊开。

推荐表现：

- H2是父组，具体题型/节名承担主识别。
- H3在展开组内清楚呈现；H4继续缩进，但不缩成难读细字。
- 打开时定位当前真实项，当前父组可展开；之后尊重用户主动收起和浏览，不被每次正文滚动强行重置。
- 当前直接标题唯一高亮；所属父组可以轻提示，但不能一组里好几个都像当前位置。
- 展开按钮与标题导航是不同触点。标题点击进入正文，展开点击只展开。
- 每个必要练习仍是可定位条目；知识浮窗内部标题不混入章目录。
- 不急着加全书搜索/知识门户。先使真实层级本身可浏览。

**类型前缀退到第二视觉层，具体内容处在第一视觉层。** 例如“（2）推导：从一次查找建立边界”，不能让括号和“推导”比“从一次查找建立边界”更抢眼。

如果需要拆分样式，应由同一标题渲染数据生成可见层次，不用前端正则猜出标题的新含义。不要为样式改显式锚点或制造另一份标题权威。

## 8. 正文：把教学结构变成阅读层次

### 8.1 应当保留的组织

问题和目标 → 关键机制 → 推理与边界 → 相邻的实现与解释 → 必要选择比较 → 相关练习。不同题型按真实内容变化，不要求每节套齐相同栏目。

理论、证明、代码与工程条件都需要保留。设计可以改表达层次，不能把难内容挪走让章首显得简洁。

### 8.2 不要从第二语言词条卡复制算法正文

词汇天然有重复条目，因此独立词条块合理。算法推理天然依赖连续论证，如果每个段落都进一个卡片，阅读会不断重启。

- H2可用浅蓝节带建立结构。
- H3/H4主要依靠字重、间距、缩进关系区分。
- 普通段落留在白纸上，不逐段加边框。
- 引用、警示或关键不变量只有真正需要区分时才使用浅色框/左线。
- 不把所有边界、复杂度、机制和结论都加粗；否则“重点”失去意义。

### 8.3 内容名称与制作名称分开

“手写边界查找”“标准设施查找时间前驱”比孤立的Hcode/Scode更接近读者行为。若确有保留缩写的教学价值，让其成为次级标记，不主导标题。

正式标题若改名，要在权威作者源/共享格式器中完成，目录、正文和下载一同消费；保持显式身份和旧链接。不要只在前端替换几个英文字符串形成两套书。

## 9. 代码、表格和知识链接

第二语言没有一套可以直接搬来的C++代码阅读规范。这里需要保留系列材质，同时按代码用途独立设计。

### 9.1 代码块

- 浅色代码面与白纸相协调；语法颜色有限，关键字、注释、文字均要可读。
- 语言标识与复制在自己的工具条中；复制触点约44px，视觉可以紧凑。
- 工具条只在该代码块范围服务，不变成第二个全局顶栏。
- 代码默认保持缩进与原生横滚；折行是用户可选偏好。
- 整个页面不得被长签名撑宽；也不能靠外层裁切把被撑宽的纸面藏起来。
- 局部复制与下载完整C++用途分清。复制按钮必须复制它所承诺的范围，不拿删节视图冒充完整源码。
- 长代码的阅读问题先靠讲解就近、真实方法边界和章内目录解决，不立即新增运行器、独立代码库或三栏对照平台。

### 9.2 表格

- 用清楚的浅蓝表头、细格线和适当内距，延续第二语言的业务表格语言。
- 让宽表自身横滚，保留行列关系。
- C++标识符不随意断开；不能为避免横滚把表格字缩成注脚。
- 不把本来连续的推理改成一张很宽的对照表。

### 9.3 知识链接

- 使用可理解技术名称，不向读者暴露Q编号。
- 首次必要知识可就近讲清，后续打开同一权威解释。
- 打开不改变正文读位；关闭返回原术语附近。
- 窗内前置知识使用同窗内容栈，不一层层叠遮罩。
- “返回”回窗内上一项，“关闭”回正文；不能都叫完成。
- 离线缺件应明确提示，不把空白窗口当作一份已打开知识。

## 10. 纯净阅读：移植几何目标，重写学科手势

我建议保留用户在第二语言明确提出的纯净阅读理念：**常态美学保留，阅读时能让外围控件暂退。**

对第二算法应落实：

1. 始终使用同一正文与同一控件，不渲染第二份“纯净正文”。
2. 纸宽、字号、段落排版不变，只改变壳控件占流和显隐。
3. 双击明确安全的正文空白进入/退出；代码、表格、链接、输入、控件、正在选文的区域优先保留原生行为。
4. 纯净时轻触空白可短暂唤出原工具，交互中延长可见时间；按住或操作控件时不能突然隐藏。
5. 隐藏控件不占文流，不可点击或键盘聚焦；不能只设透明度却仍挡住文字。
6. 切换保持当前文字在屏幕的绝对位置；原生首尾滚动边界是自然例外，不能全程把用户拽到新的顶部。
7. 不使用全屏API制造系统切换，不增加常驻退出条。

**不要直接搬 `web/pure-reader.js`。** 它包含英语整句点读、长按解析、句中词双击提问的仲裁。第二算法应在现有 `reader-runtime.js` 中保留/修正纯净几何，排除代码交互；没有证据需要时，不接管原生双击选词。

当前 `overflow-anchor:none`、显式 `minmax(0,1fr)` 和恢复竞态处理是在解决真实位置问题。换布局不要把这些当作多余技巧清掉，但也不要拿它们给不合理的下栏布局作背书。

## 11. 所有临时窗口的统一设计

### 11.1 窗体

- 同一蓝银标题带、边框、关闭位置、焦点与阴影。
- 标题说清对象：“本章目录”“阅读设置”“本章答疑”；知识窗用真实名称。
- 长标题允许合理换行；不要为了挤入所有控件把标题缩小。
- 标题区与内容区明确分行，内容使用受视口约束的内部滚动；不能只加max-height然后让内容被flex压成一条。
- 打开后焦点进入窗口，关闭后回原触发点或合理续读位置；背后正文不能同时响应。
- 默认纯关闭就用“关闭”或可识别×；“保存”“发送”“返回”各自独立。

### 11.2 内部结构按任务区别

| 窗口 | 固定区 | 滚动区 | 应保留 |
|---|---|---|---|
| 目录 | 标题/关闭 | 层级目录 | 当前项、展开选择、返回读位 |
| 知识 | 标题/必要返回/关闭 | 知识正文和局部代码 | 窗内浏览位置、正文原位置 |
| 答疑 | 标题/章语境、底部输入发送 | 成组消息 | 草稿、问题顺序、未读与晚到回复 |
| 设置 | 标题/必要返回/关闭 | 分组设置或详情 | 尚未提交的编辑、真实状态 |

统一窗口不表示四个内容区都塞同一种卡片，也不要求它们有相同高度。

## 12. 重新组织设置

当前测试版中，全宽设置行、内容宽大按钮、下载链接和状态交错，章节册还同时出现DOM箭头与伪元素箭头。应从职责上重整，而非再补几个margin。

推荐结构：

```text
阅读设置
  阅读
    正文字号            − 17 ＋
    代码字号            − 14 ＋
    代码折行                  开关

  离线与文件
    打开时下载本章            开关
    下载本章供离线阅读        动作
      已可离线/正在下载/未完成
    本章文件                  ›

  应用与账户
    检查更新                  动作
    添加到主屏幕              ›
    退出登录                  动作
```

- 章节册和本章目录回内容导航，不继续放这里。
- “本章文件”详情再承接C++、Markdown与完整源码查看，避免主页按钮墙。
- 所有行宽、分隔、标签基线统一；值编辑和开关无导航箭头。
- 一行只产生一个方向图形；DOM与伪元素二选一。
- 正常连接状态不必永远霸占一行；异常和未同步时应清楚说明。
- 自动保存的偏好不额外配一个“保存全部”；需要明确提交的编辑才给保存。
- 下载和更新有自己的进行中/成功/失败状态，不能总用通用“完成”。

不要同时建设高级缓存配置、服务商额度卡和存储迁移工具来显得完整。本轮先把已有阅读服务组织好。

## 13. 章节答疑：应移植完整承诺，而不是聊天外观

### 13.1 当前缺口必须先被看见

当前 `createReaderQuestions` 支持可选transport，但载体尚未提供真实处理服务。它点击发送后会明确未发送，没有伪造成功；问题是界面直到那时才暴露不可用。

测试期间打开窗口就应说明未连接，保持草稿可写/可保留，发送状态与能力一致。若用于纯视觉测试，标明本机预览，不能制造排队、回复或红点。

### 13.2 正式接通时借鉴第二语言的这些结果

| 阶段 | 要做到什么 |
|---|---|
| 打开 | 知道当前章和不可变版本，读已有会话；打开本身不发送 |
| 编辑 | 草稿按账户、章和版本隔离，离开可恢复；本机保存失败要提示 |
| 发送 | 固定提交时文本和UUID；真实受理才出现相应状态 |
| 继续编辑 | 允许写下一问；前一问成功只能清理仍与该次提交匹配的草稿 |
| 丢响应 | 复用同一请求身份核对/重试，不偷偷新建另一问题 |
| 晚到回答 | 插入对应问题下，按提问顺序排列，保住当前正在读的旧回复 |
| 未读 | 只表示真实新回复；打开事务与新抵达回复区分，避免旧汇总重新点亮或吞掉新未读 |
| 显示回答 | 安全排版，不执行模型HTML、脚本或任意远程资源；代码保留缩进和复制 |
| 服务错误 | 明确可重试或尚未处理，已成功内容保留，不画成一个空答案 |

上下文由服务端按该版本装配：完整章节、必要权威代码/知识和用户问题；可以附选中内容辅助定位，但不能让用户手工拼上下文。不要为每个问题在D1重复存整章，也不要把第二语言的数据库或后台队列直接拿来共用。

界面与正式服务分阶段建设，不能用一个外观完善的输入框宣称功能已经上线。实际处理服务属于明确的后续工程，不在本设计指导中假报完成。

## 14. 按钮和文本的统一语义

| 位置 | 推荐文案/行为 | 不应发生 |
|---|---|---|
| 章级入口 | 当前章名+方向，打开章节册 | 普通身份文字暗藏无反馈导航 |
| 章入口主动作 | 无读位从头、有读位继续 | 无真实位置也写继续；从头顺手删除旧位置 |
| 下栏 | 上一节/下一节，只走一种节序 | “上一”一会儿回本节、一会儿去前节 |
| 下栏中间 | 当前节名，打开目录定位 | 看起来三段分别能点，实际整组做另一动作 |
| 目录父标题 | 进入该标题 | 同时展开或收起 |
| 目录展开符号 | 展开/收起 | 把用户送到正文 |
| 窗口关闭 | 关闭/× | 假装保存、发送或完成一个任务 |
| 窗内返回 | 返回上一层 | 连正文也回到旧章或重置读位 |
| 偏好 | 作用明确、保存结果真实 | 代码折行同时更改正文字号等无关状态 |
| 下载 | 下载已有内容、确认完整性 | 当作生成新材料；部分完成报全章可离线 |
| 问答发送 | 真实受理、失败保草稿 | 服务未连却先报已发送 |
| 内容更新 | 有新版本再提示，保留当前编辑 | 页面一醒来自动重载并清草稿 |

工具栏中文短而明确。错误说明给用户可采取的动作，必要时保留详情；不在常态页面展示内部提示词、合同字段和执行日志。

## 15. 具体工程移植地图

| 第二语言来源 | 第二算法落点 | 移植方式 |
|---|---|---|
| `web/styles.css` 的根变量、页头、bevel-button、sheet、settings-row | 现有 `web/styles.css` | 提取材质/角色，按新语义整理；不导入整份主题覆盖 |
| `web/chapters.js:createChapterBook` | `web/app.js` 的章级路由/章节册呈现 | 继承每章一入口、读位与从头区分；用算法章顺序替换日期语义 |
| `web/settings.js:installSettingsNavigation` | `showSettings`及必要详情 | 继承分组、单窗返回、不同职责；不照搬按数组下标绑定业务的具体写法 |
| `web/pure-reader.js:installPureReader` | `web/reader-runtime.js:createReaderRuntime` | 只继承纯净几何与控件显隐结果，排除英语教学手势 |
| `web/reader-jump.js:createReaderJump` | 现有 `go`、`showReader`、装载/恢复流程 | 保留旧画面、待目标稳定后揭示；不默认复制整棵长章DOM作每次跳转的实现 |
| `web/questions.js`、`web/question-pairs.js` | `web/manual-questions.js`与未来独立服务 | 借鉴身份、事务、配对与草稿规则；不同项目使用自己的权限、API和队列 |
| `web/context-translations.js` | 无默认移植对象 | 只借鉴用户+内容版本隔离状态；不把遮蔽译文变成代码遮蔽功能 |
| `web/audio-library.js`的现成/生成区别 | 现有离线章节包与下载状态 | 已有文件下载不能误触生成服务；不把音频包业务硬套算法资源 |
| 章节/雅思/答疑的独立生命周期 | 已有发布白名单、读位、私人草稿 | 各对象有各自身份；界面精简不成为清数据的理由 |
| 第二语言隔离UI旅程 | carrier浏览器测试与升级测试 | 迁移有价值的失效场景，换成真实算法对象，不靠截图数凑验收 |

当前第二算法已存在 `setChapter`、`capture`、`settle`、`go`、`tocHTML`、`scrollCurrentToc`、`setPure` 等运行器能力。应当在这些职责清楚的入口调整，而不是再建一个并行阅读控制器。

后端、编纂、权威代码与读件版本设施已有价值；本次视觉收敛没有理由更换框架、重建数据库或引入第三方UI服务。

## 16. 实施顺序与每步完成条件

### 第一步：重新形成一份常态主读样稿

保留当前完整《二分》与真实代码/知识；调整页头章级入口、简洁下栏和正文层次。选择章首、长推理、长标题、手写/标准代码相邻段四个位置比较，不能只交章首一屏。

完成条件：不用纯净也愿意长读；章身份、目录与返回可理解；没有为了好看藏掉实质内容。

### 第二步：把对象与导航路线接完整

章节册、章入口、正文和目录使用同一章节/标题权威。所有常态入口可达，展开和导航分开；明确链接、继续、从头分别正确。

完成条件：能独立完成找章→看目录→读某节→查知识→回原句，不需要解释接口术语。

### 第三步：设置、知识、问答沿同一语法收敛

先修复重复箭头、行宽和任务分组；让所有临时窗口有稳定标题、关闭、有效阅读高度与返回焦点。问答未接通状态前置。

完成条件：同一类操作看起来和用起来相同；没有未完成服务伪装正常可用。

### 第四步：验证状态与版本，不牺牲前面的观感

验证字号、纯净、位置、慢请求、离线、刷新、旧客户端和更新。现有私人原件保留，不能借移除旧入口顺手清理。

完成条件：真实阅读动作在异常状态下也可靠；失败不会变成空页或假成功。

### 第五步：用户按真实使用验收

交付同一版、同一真实长章在几个关键位置的可操作结果；如实说明浏览器与实体iPhone的验证边界。用户没有接受时，继续修设计，不用测试数量、代码规模、协议字数证明它应被接受。

采纳后的结果再同步现有设计/交互文档与必要回归。本文的候选布局不能未经使用检验自动成为下一份冻结协议。

## 17. 适合沿用的回归场景

这不是要求新增一大套形式化测试。现有测试应围绕设计真正可能损坏的结果更新：

| 场景 | 需要守住的结果 |
|---|---|
| 正常→纯净→唤出→退出 | 同一文字绝对位置和纸宽；隐藏控件不挡字、不获焦点 |
| 目录展开/标题跳转 | 展开不导航，导航不额外展开；当前位置与真实正文一致 |
| 看知识后关闭 | 回原句与触发焦点；窗内滚动不写坏正文读位 |
| 代码横滚、选文、复制 | 原生操作优先，不误切纯净或提问；复制范围准确 |
| 字号/视口变化 | 恢复到语义附近，长标题不撑宽纸面，不靠扩大误差容忍伪装修复 |
| 快速切章/慢响应 | 旧请求不覆盖新选择；失败保留可读旧画面与草稿 |
| 发送后继续输入/晚到答复 | 成功只清对应草稿，答复归对应问题，不强拉旧消息读者 |
| 未读打开与新回复并发 | 打开前边界可定位，之后新回复不被吞掉，旧汇总不重亮 |
| 离线缺件/更新/退出 | owner与白名单边界正确；未完成下载不报成功，私人原件不被误清 |

WAI模态窗口的焦点进入/约束/返回，以及WCAG文字缩放和触点要求，可以辅助核验可用性；它们不规定蓝银风格，也不替用户判断是否好看。44px级触点是这里的调试建议，不能误称WCAG 2.2 AA在所有场合强制44px。

## 18. 实施中最容易重犯的错误

1. **把我的建议重新写成不可讨论的硬协议。** 本轮的目标是更好的实际产品，不是又冻结一份测试稿。
2. **只借颜色。** 蓝银外观下仍摆着同样的控制台，没有完成移植。
3. **只借组件。** 导入章节册、设置和问答，却没定义对象、返回与状态。
4. **用常驻按钮解决所有可达性。** 结果再次失去正文；优先利用正确的对象入口和临时层。
5. **为了减少按钮而隐藏动作。** 章名无反馈可点、长按偷偷提交，用户仍需猜测。
6. **为了现代而换成淡字、大圆角和玻璃卡。** 这没有延续用户已认可的系列美学。
7. **为了复古而复制9px小字或禁缩放。** 系列风格不需要这些代价。
8. **为了完整把目录全展开。** 需要保留完整结构，不需要同时展示所有节点。
9. **为了省篇幅删掉难内容。** 版面工作不能偷换成缩减教材。
10. **重复造读位、路由或内容权威。** 保持一个正文身份和控制职责，UI不同不意味着数据副本不同。
11. **拿一次点击测试代替使用体验。** 能点到不代表好理解，页面不横溢不代表比例合适。
12. **让用户为尚未接通的服务写完一段后才知道不可用。** 把边界说明移到行动之前。

## 给接手模型的最后一句话

我希望你继承第二语言反复迭代后形成的判断力：**让复杂能力在用户需要它的时刻自然出现，让正文在其余时间安静、稳定而好读。** 蓝银材质是可辨认的外观；正确的对象、动作、返回和状态，使这套外观真正成为一个成熟产品。先做好一份愿意用的算法书，再让工程完整地支撑它。
