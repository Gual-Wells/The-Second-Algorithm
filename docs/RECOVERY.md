# 工作恢复与来源失败处理

内容处理规则遵循 [CONTENT_PIPELINE](../protocol/CONTENT_PIPELINE.md)。恢复的目的，是从实际已完成的材料和判断继续，避免重复搜索、丢失候选或把失败伪装成完成。

## 重新进入仓库

先查看 README、Git 分支及工作树状态，再阅读当前任务留下的材料与待办。存在未提交工作时，辨别归属与成熟度，保留仍在进行的内容，不为了目录整洁重置或清理。

依次确认：

1. 当前任务的范围、来源和已采用材料版本。
2. 来源池中实际采用的入口，以及已取得清单或读件所在位置。
3. 已形成的题目与模式判断，哪些仍待判、待读或待补。
4. 正文与代码的唯一权威稿，以及最后实际验证的版本。
5. 恢复记录中明确的下一步，而非从头重新生成一份计划。

工具入口使用 `python -m second_algorithm --help`，不从旧对话猜测参数。历史结果可以作为线索，但只有本次实际执行才报告为本次验证。

## 任务中断时保留什么

在任务工作资料中保存一个简短、可直接续作的记录即可：

```text
任务与当前目标：
固定的范围/内容基线：
实际读过的来源及版本：
已确定的归并与内容判断：
尚未判断或未取得的材料：
权威正文和代码位置：
最后实际执行及其结果：
下一步具体动作：
```

不要求把所有命令输出复制进笔记，也不为每个状态另造一份台账。引用实际文件、身份或材料摘要，必要时保留足以恢复判断的片段和定位。正文不带入过程记录。

## 来源请求失败

临时超时、HTTP 错误、验证码、空壳页面或解析失败，记录为本次观察失败或部分取得。保留最后成功清单、其摘要和已发现题目；不能用零条新结果覆盖它们。

当前失败观察在 `.local/failures/`，成功或待审查的取得记录在 `.local/runs/`。规范化快照在 `catalog/inventories/`，`catalog/inventory-heads.json` 指向当前成功基线；原始页面在 `.local/materials/<摘要>/source.html`。干净 checkout 没有私有页面缓存是正常情况，已有的缓存文件若损坏则需按摘要核查，不能当作原件继续使用。

先判断是网站不可访问、入口变化、页面加载方式不同，还是适配器无法提取。首页可开不等于目录取得；文本视图无题目也不证明原站不存在内容。可使用同来源的公开替代入口或手工阅读，但注明实际采用方式，不悄悄改成另一个来源冒充原件。

同一入口重新成功后，比较原身份集合、标题与链接变化。新增记录进入待处理；本次未出现的旧记录保留历史和差异，不自动删除或认定已排除。若源材料内容改变，重新核对相关判断，不能只替换摘要就继承旧审阅结论。

发现旧身份减少时，取得结果会要求审查，成功基线继续保留。先看实际差异与来源变化，再按 `collect --help` 中的接受变更选项办理；不能为了消除待办直接接受缺失。

如果 `.local/collect.lock` 存在，先核对其中进程身份和开始时间，确认是否仍有同一收集任务运行。确为中断遗留后才清理该锁，不强制终止其他对话或仍在工作的进程。

## 清单或导入中断

先定位最后成功的快照与导入输出。检查记录数、去重身份、分页或范围条件是否闭合；只有部分页时保持部分状态。重复处理同一快照不应重复创建题目，也不能给已发现条目自动增加阅读或归类进度。

若本次输出不完整，保留可诊断的失败记录，恢复到最后成功基线后继续未完成部分。不要用手工改成 complete 来绕过缺页、缺记录或解析错误。

## 内容修订中断

恢复权威作者稿与同一版本 C++ 源码。判断新材料影响的是已知变种、模式前提、实现，还是章节归属；优先修订实际受影响处，并重新核对相关案例和交叉链接。

跨章内容尚未存在时保留缺口。模板编译通过只能说明相应代码验证结果，不能将未完成讲解、未知条件和范围研究一并改为完成。新修订可以在新版本继续，不回写旧版本曾经采用的事实。

## 路径与公开仓库

本机新增数据、教材、缓存、依赖、下载与构建由 D 盘实际承担。新环境恢复时以仓库相对路径及可配置的本地材料位置为准，不复制旧机器专用的运行时位置、目录联接或凭据。

推送前检查暂存内容，避免上传教材原件、商业题库全文、本地个人手册、密钥、缓存、可执行文件和依赖目录。无法从公开仓库恢复的本地教材应明确为外部输入，不能假装已经随 Git 保存。
